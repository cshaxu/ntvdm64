# softpc family

Same-shaped reached SoftPC/CCPU/SAS facade. It may use typed `adapter-bochs`
operations but never a Bochs type or global.

## Registered divergences

| ID | Original purpose | Reason | Implementation | Files |
| --- | --- | --- | --- | --- |
| ADAPTER-SOFTPC-001 | Define the historical SoftPC host error-table `ERROR_STRUCT`, `EH_*`, and `EV_*` declarations consumed by host bodies. | The byte-exact `softpc.new/host/inc/error.h` documents but does not declare these forms; the matching declarations survive in the byte-exact `softpc.new/base/inc/error.h`. | A build-island-only force-included same-shaped declaration bridge; no original mirror header or body is edited. | `include/error_abi.h` |
| ADAPTER-SOFTPC-002 | Preserve an original x86 MVDM host-pointer identity in a 32-bit DTA/FCB field. | `demsrch.c` directly stores `PFFINDLIST`; that pointer is neither width-safe on x64 nor permitted in guest/MVDM state. No original call-shaped identity API exists. | `mvdm_host_identity_*` resolves only through the thread-bound session's existing `host_resource` mapping instance. It publishes, resolves, reverse-looks-up and releases opaque surrogate32 values, retains `FFindId` as numeric source data, and never acquires guest memory. | `include/mvdm_host_identity.h`, `mvdm_host_identity.c` |
| ADAPTER-SOFTPC-003 | Retain a 16:16 guest address across a historical DEM callback and subsequently dereference it through SoftPC/Sim32. | A native `GetVDMAddr` pointer cannot survive across callbacks on x64 or across a bounded guest-memory lease. | `mvdm_guest_location_*` retains only segment/offset numeric data and obtains a fresh bounded lease from the thread-bound session for each access. It does not create a mapper, token or host pointer. | `include/mvdm_guest_location.h`, `mvdm_guest_location.c` |
| ADAPTER-SOFTPC-004 | Return mutable SFT/JFT pointers from the historical VDD file-handle APIs. | Original NTVDM permanently aliases guest RAM and stores a native `HANDLE` in a 32-bit SFT field; neither is legal on x64 or across bounded guest leases. | `mvdm_vdd_sft_shadow_*` returns session-owned host shadows only for the synchronous original caller, commits explicit final writes through fresh bounded leases, validates pointer lifetime with the existing host-resource map, and stores host HANDLE identities as opaque 32-bit values. | `include/mvdm_vdd_sft_shadow.h`, `mvdm_vdd_sft_shadow.c` |
| ADAPTER-SOFTPC-005 | Supply reached original `softpc.h` 16-bit `get*`/`set*` monitor imports for COMMAND and XMS source bodies. | The original CCPU register storage is excluded in favour of Bochs, but the original source retains these exact call shapes. | `mvdm_command_registers.c` keeps the reached source names and widths, including `getCS` required by `xmsNotifyHookI15`, and calls only selector-blind typed `adapter-bochs` mechanics; guest bytes remain separate bounded leases. | `include/mvdm_command_registers.h`, `mvdm_command_registers.c` |
| ADAPTER-SOFTPC-008 | Supply the reached historical SAS A20 imports used by original XMS code. | CCPU/SAS is Bochs-replaced, but the original XMS helpers call the exact SAS spellings. | `mvdm_a20.c` preserves the three historical call forms and translates only the mechanical line state to `adapter-bochs`; it has no XMS dispatcher or UMB policy. | `include/mvdm_a20.h`, `mvdm_a20.c` |
| ADAPTER-SOFTPC-009 | Supply the reached x86 `xmsmem86.c` commit/decommit/move exports. | The source casts a 32-bit XMS linear address to `PVOID` and uses host VM APIs; this cannot be safe on x64 or target Bochs RAM. | Keep the original exported names, widths and status contract.  Check numeric linear ranges through typed machine mechanics and copy only through fresh session guest-memory leases; no host pointer, extra mapping manager or XMS policy is introduced. | `include/mvdm_xms_memory.h`, `mvdm_xms_memory.c` |
| ADAPTER-SOFTPC-006 | Copy a short guest C string into host-local storage or copy a known host span to guest bytes for source bodies that formerly used `GetVDMAddr`. | The historic raw-pointer macro has no span or lifetime contract on x64. | `mvdm_guest_location_copy_c_string` takes one-byte synchronous leases until a supplied maximum/terminator; `copy_to_guest` uses one exact write lease. Both use the existing thread-bound session `guest_memory` instance. | `include/mvdm_guest_location.h`, `mvdm_guest_location.c` |
| ADAPTER-SOFTPC-007 | Declare original monitor `getPE()` for the reached `nt_bop.c` IRET-hook branch. | The selected CPU_30-style historical header declares the protected-mode accessor only when the excluded CCPU executor is selected. | Keep the original no-argument, integer-result declaration as a declaration-only carrier. A typed Bochs-backed implementation belongs to the later monitor package; no BOP selector is enabled by this carrier. | `include/mvdm_command_registers.h` |
| ADAPTER-SOFTPC-008 | Original `v86/monitor/i386/sas.c` exposes scalar/string guest-memory operations while treating a numeric VDM address as a host pointer and reserving low process addresses. | That NT4 process-layout assumption is invalid on x64 and would bypass Bochs RAM bounds/ROM handling on both architectures. | Preserve the reached `sas_*` names, fixed numeric argument widths, little-endian scalar results and no-op/failure direction. The source-derived facade forwards only checked numeric reads/writes to `adapter-bochs`; it does not allocate a second SAS map, map host memory, create a mapping manager or expose a guest pointer. Its historical `*_no_check` spellings deliberately retain the same scalar result but still enforce the only safe Bochs bounds/ROM guard. | `include/mvdm_sas.h`, `mvdm_sas.c` |

Any machine operation must use typed `adapter-bochs` mechanics; this family
never includes a Bochs type or calls `bochs-core` directly.
