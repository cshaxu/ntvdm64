# T483 S9 P3 compatibility footprint audit

Source baseline 4617041ab. The inventory uses tracked working-tree physical lines including comments and blank lines. The 14 C files have 846 lines / 36,146 bytes and the 25 headers have 1,452 lines / 56,768 bytes. README is 233 lines / 46,213 bytes and contains historical exception records. These figures measure source, not linked image size or working set. Twelve OpenNT-derived WOW C units account for 477 lines of the 846.

## Demonstrated source reduction

- environapi.h includes nt.h, whose local NTSYSAPI binding includes original ntrtl.h. That header declares RtlCreateEnvironment, RtlDestroyEnvironment, RtlSetCurrentEnvironment, RtlSetEnvironmentVariable and RtlQueryEnvironmentVariable_U with the same parameter types and NTAPI. Remove five lines; retain OpenNtRtlRefreshEnvironmentSnapshot.
- ntrtlp.h includes nt.h and then repeats ntrtl.h and nturtl.h. Remove two include lines; keep both surrogate type bindings.
- Build evidence: stage only these two altered headers in a temporary include root; compile original and candidate using the product worker Ninja compile flags for mvdm_base_vdm_environment.obj, environ.obj and error.obj. MSVC /showIncludes confirmed the intended candidate header in all three. GNU objdump -dr output (excluding the input filename banner) matched pairwise for x86. Raw COFF files differed. This checks the selected consumers; final headers, x64 composition, tests and published images have not been validated with these edits.

## Next candidates and stopping points

- thread_start_compat.h: opennt_create_cdecl_thread and opennt_create_void_cdecl_thread each declare seven lines and forward to an existing named form with NULL in common/worker-thread/bridge.c. The non-definition uses found are tests. The product generator and generated x86 worker source search found no direct unnamed calls. Convert the session fixture cases to the matching named forms with NULL; inspect the heartbeat fixture's local stub and verify the actual link inputs and any exports before deleting the two wrappers. Potential 14 header lines plus the two forwarding bodies outside compat. The third unnamed form has an explicit caller in nt_rflop.c; check whether that source is selected separately. Preserve callback signatures and WINAPI/cdecl differences.
- opennt_support_rtl.c: the environment refresh can allocate and copy two snapshots on the first call in a thread: opennt_support_thread initializes one and refresh immediately allocates a replacement. Other TEB/PEB consumers can initialize TLS first, and a failed replacement preserves the previous snapshot. Evaluate allocation counts and freshness in both orders before selecting one initialization path. This is a conditional runtime saving, not a proven steady-state leak or a projected source-line saving.
- Test native RTL candidates separately. Example: 64-bit Windows ntdll RtlOemToUnicodeN with input ASCII AB and room for one WCHAR returned 0x80000005, stored A, and reported two bytes. With room for both it returned success and four bytes. The current compat implementation computes four required bytes and exits before writing on the short-buffer path. The real consumers include nt_keycd.c, vrnetapi.c and xsunicod.c. Determine their required behavior and compare the original and x86 host before changing the provider. Keep allocated strings paired with the corresponding free contract and the worker TLS scratch behavior.
- conapi.h and the worker-private console_client.h both declare MvdmCreateFileA/W and MvdmGetFileType. The former binds Win32 names to worker endpoints; importing that entire header into a provider changes names, while the reverse imports private session and graphics dependencies. A new header merely for these three declarations is not a demonstrated net saving.
- Preserve the small original WOW units unless an existing production implementation is shown equivalent. Physically combining translation units would combine distinct preprocessor selections or require new guards. Keep the console grid cell-copy semantics. For nt.h retain by-value USER layouts and treat status/SDK fallback cleanup as a per-toolchain compilation exercise.

This is an audit. No production sources, mirror files or published components changed.
