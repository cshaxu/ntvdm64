# S12 macro-boundary remediation

The selected original interfaces and their providers remain authoritative. This change does not ban original header macros globally.

- `NTVDM`: six authored NTVDM units consume the original `host_def.h`. An x86 preprocessor comparison that immediately restores the incoming macro after that header compiled in all six cases, but changed selected output in text-video and mouse units. Preserve that header's original contract rather than claiming a blanket removal is safe; the four other units had identical normalized preprocessing in this experiment.
- WOW: `WOW_ORIGINAL_THUNK_BUILD` is selected on the original WOW thunk source edges only. DIV-542 keeps the original private USER and menu redirects in those units, but removes them from authored clients of `precomp.h`. The two-mode `wow-macro-boundary-test` compiles against both profiles. Actual x86 Ninja command inspection found 77 original WOW source commands selected and 70 authored WOW source commands unselected (command counts, not unique files).
- CSR: `_CSRSRV_` remains on original server sources and on the authored local CSR export provider `base_process.c`; other authored service clients no longer inherit it. Actual x86 bindings and x64 service, worker, frontend and launcher command inspection found only `base_process.c` with that selector among authored service source commands. The original declarations and their ABI are not replaced.
- SAS: the generator copies the unconditional original `SasVector` declaration prefix from `sas4gen.h`, validates that it contains no conditional directives, and tracks the input as a CMake configuration dependency. The original complete generated header remains for original users.
- PIF: include the actual SDK property-sheet declarations instead of defining `NTVDM` to suppress the original declarations. Build and create/show/update smoke checks passed.

Validation and delivery are recorded below only after the product gates finish. The six-unit preprocessing check compares normalized text, not runtime behavior; the WOW gate proves only the selected macro boundary, not full Win16 correctness.

The coherent ten-image candidate was compared with the previous tested package: every `.text` section is byte-identical. Raw hashes differ; after normalizing only the main PE timestamp and checksum, 16–18 bytes per image still differ in `.rsrc` and, for seven images, `.rdata`. This is not recorded as byte identity or asserted to be solely a timestamp difference.

Delivery: x86 and x64 cached product builds and the two WOW macro-boundary compilation controls passed. The PIF candidate passed create, read, update, and checksum checks; its `.text` matches the previous release. Product `Full` passed its selected gates, including actual Winmine, Solitaire and Write windows, DOS/native transitions, RPC and frontend-loss cases. The external DOS4GW/NESticle fixture was not supplied and was explicitly skipped. The coherent ten-image candidate was installed and SHA-256 verified at both `assets/release` and `O:/winnt/system32`; PIF was separately staged to `assets/release` with its add-on manifest. Guest code and images were not rebuilt or modified.
