# Remote slave-PC floppy: original NT applicability

The current host-candidate inventory snapshot lists `softpc.new/base/disks/gfi_ibm.c`, `gfi_sflp.c`, and `base/inc/gfisflop.h` as pending. Their current bytes match the compared OpenNT files. This is source/build-profile analysis, not a real serial or floppy test; no ledger, product or guest was modified.

The original capability is not an ordinary local disk driver: `gfi.c:294–352` selects a separate `C_SLAVEPC_DEVICE` configuration and `GFI_SLAVE_SERVER` only under `SLAVEPC`. `gfi_sflp.c:141–230` owns activation, remote login/reset, and GFI function-table registration; `gfi_ibm.c` sends controller packets through `host_rpc_action`; `gfisflop.h` defines that legacy serial protocol, including a Unix `/dev/ttya` default. Original CMOS/control/termination calls to this device are also conditional. In the compared OpenNT MVDM build `sources`/`.inc` search, no SLAVEPC definition was found, and the retained selected NT worker commands do not define it. The actual three selected source-object outputs for `gfi_ibm`, `gfi_sflp`, and diagnostic `gfi_test` have no global implementation symbols in the captured product configuration. A bounded source search found calls but no implementation of `host_rpc_action` under the current MVDM SoftPC C/H tree.

The current original NT GFI/FLA path delegates activation to `host_gfi_rdiskette_active` and `nt_rflop.c` for local removable devices; that is an independent backend with actual-object dispatch and no-media guest reset evidence, **not** an implementation of the slave-PC wire protocol. See `gfi-legacy-provider-review.md` and `vflop-real-header-selection-review.md`. The current product can therefore not be said to support this remote serial controller on the basis of local floppy tests.

| Exact path | Original distinct role | Registration recommendation |
|---|---|---|
| `base/disks/gfi_ibm.c` | RS232 RPC client packet construction and controller operations for the separate slave-PC server. | Physical-file **excluded from original NTVDM worker profile**, with the separate remote-controller capability explicitly retained as outside that profile/conditional S17 scope decision. No claim remote behavior is restored. |
| `base/disks/gfi_sflp.c` | Slave server activation, floppy selection and GFI callbacks using those RPC functions. | Same bounded exclusion and S17 remote-profile obligation; actual local-floppy provider remains partial in S13. |
| `base/inc/gfisflop.h` | Protocol declarations and constants for those slave-PC functions. | Same bounded exclusion; do not bind the fixed Unix path to production. |

These recommendations are grounded in original architecture, entry conditions, missing RPC owner and original/current NT configuration, not simply a release flag. They are not a blanket conclusion that no historical SoftPC profile needs this capability. If S10's physical `excluded` label instead means excluded from **all original source profiles**, keep the three pending until that scope is formally resolved; do not flatten a profile-qualified recommendation into that stronger claim. Existing code remains available and untouched.
