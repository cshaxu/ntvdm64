# Native ALU guest oracle: ADC / AND / INC review

The retained producer is `tests/observation/ccpu_alu_oracle.c`, SHA256 `CFB5909506354617AF76E53F691078006C7309044E3275EE364D00424A570B35` at this review. Its optional x86 MSVC `/W4 /WX` CMake target is `ccpu-alu-oracle`. The prior shard-local prototype was removed after consolidation; the initial shard-local review did not build or execute either producer and did not launch a guest; the main-session run is recorded separately in `ccpu-alu-guest.json`.

For ADC and INC each 0/1 variant sets incoming CF using native BT immediately before the arithmetic opcode; BT is not CLC/STC, but its indexed bit is guaranteed 0 or 1 by the variant table and sets the same required CF. No intervening flag-changing instruction occurs before ADC/INC. ADC overwrites all six recorded arithmetic flags; INC overwrites the other five and preserves incoming CF. AND uses native AND and masks native flags with `0x08c5`, explicitly writing AF=0 for the original CCPU convention, not asserting native AF is defined. ADC/INC mask `0x08d5`. PUSHFD immediately follows each actual opcode, before the recorded result is masked to width. All output status/value originates in native instructions, not a C mathematical reimplementation.

Records are 14 bytes (little-endian lhs/rhs/result u32 plus flags u16), with ADC0/ADC1 and INC0/INC1 stems plus AND; INC ignores rhs in the actual opcode while retaining it in the input record. Byte files exhaust 65,536 ordered pairs; 16/32-bit files have 14x14 masked boundary pairs, including newly added FFFFFFFF, plus 1,000 pairs from the specified LCG seed and recurrence, for 1,196 records (16,744 bytes). Each 8-bit file has 917,504 bytes. Files are binary, exact 8.3 names, and write/close errors lead to nonzero process exit. Whether an assembler/compiler actually emits these instructions and whether generated bytes match guest results must be checked by the main session's build/run and negative controls; inspection alone is not a pass.

Original `c_main.c` dispatches ADC/AND register/memory/immediate families and INC register/group operations. The retained selected-object native byte differential in `ccpu-flags-audit.md` is separate; it does not prove wide operations, decoder memory/fault behavior or real guest execution. The subsequent main-session build, native corpus and actual guest comparisons are recorded in `../ccpu-alu-contracts.md` and its linked input/result records; the accepted full leaf classifications rely on that combined evidence. No production or original guest file was changed.
