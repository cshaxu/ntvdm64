# GFI floppy trace shim and real provider boundary

Scope: shard-3 `softpc.new/base/disks/gfi_test.c`, frozen byte-identical OpenNT. This is a static review of current selection and past evidence; no new runtime/guest or product change.

Despite the name, this file is not a disk format detector. It contains a development GFI trace shim: diagnostic helpers log commands, report generic success or fixed drive values, and are called by `gfi.c` only under `#ifndef PROD` when `io_verbose & GFI_VERBOSE`. `gfi.c::gfi_fdc_command` invokes the logger before dispatching actual work through `gfi_function_table`; it does not use the diagnostic helper's return value as the result. Other drive helpers have the same conditional tracing pattern. Hence omitting this shim from production is not evidence of missing real-media read/write, and enabling its synthetic-success return would not be a valid production media implementation.

Current Ninja graph compiles `gfi_test.c` into `original-softpc-disks.lib`, but the `cc` flags define `PROD` and the file surrounds all helper definitions with `#ifndef PROD`: its production object contains no active `gfi_test_*` function body. NTVDM map has no such functions. Actual real-floppy operations are selected through `nt_rflop.c` registration of `gfi_function_table[drive]` callbacks; empty/slave providers are separate and depend on configuration. The previously recorded source-linked floppy close failure-seam (`disk-close-failure-audit.md`) exercises the real host close function, not `gfi_test.c`.

T420 S28 real guest tested INT13 hard-disk reset with no attached media, followed by COMMAND return; it did not test floppy real media, format/read/write, diagnostics, or current package. Its phrase “test provider” should be read narrowly as this inactive debug trace shim, not a real independently selected floppy service. Debug trace capability and other configurations remain separate from the selected PROD profile; row remains pending until T-wide diagnostic disposition. No absent test shim implies disk operations are fully restored.
