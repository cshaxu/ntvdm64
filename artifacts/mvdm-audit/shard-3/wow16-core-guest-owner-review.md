# Win16 core guest source/resource candidates — shard 3

`wow16-core-guest-owner-review.csv` lists 26 exact-hash source/declaration/resource candidates with per-file original make object dependencies, selected object lists/link responses, and direct INCLUDE or RC resource chain. They cover COMM driver, GDI, MMSYSTEM and USER. Original recipes use MASM/CL16 and link16; MMSYSTEM has explicitly distinct debug/retail and locale resource branches, and its `messages/usa/mmsystem.rcv` is copied by make then included by `messages/usa/mmsystem.rc:8`. USER `k/daytona/userk.lrf` is an actual historical response file, not proof this exact configuration made the shipped image. Guest filenames and conditions are recorded, not extrapolated into execution evidence.

Remaining pending rows include binaries and raw resources without verified role, additional conditional/implicit objects, standalone system/envect and keyboard/sound materials, and language resources with no complete direct chain. No candidate proves its source built current immutable image or that guest feature works. All are proposed only as `guest-build-source-file-only`; no original guest or product was modified, rebuilt or run and the main/combined ledger is unchanged.
