# WOW32 multimedia alias and disabled converters audit

`wow32/wmmalias.c` and `wow32/wmmedia2.c` are byte-identical to the selected original, and the WOW32 x86 graph compiles both objects. Graph selection alone does not mean the original functions remain executable: `wmmedia2.c` globally places its structured MIDI and wave bodies under `#if 0`, and `wmmtbl2.h` registers `WMM32CallProc32` rather than those disabled functions. `wow32.dll.map` has no `WMM32midiOut*` or `WMM32waveOut*` symbols. Do not reactivate these bodies solely to increase file coverage; their callback/header lifetime ownership is different from the active path.

Original Win16 mmsystem `ThunkInit` resolves private WINMM 32-bit driver message procedures, and Win16 thunk code calls them through MMCALLPROC32; original Win16 code manages callback data and task teardown. `wmmedia.c::WOW32ResolveHandle` also forwards multimedia resolution to host WINMM, while `wmmalias.c` contains a separate historical `hiMMedia` map protected by `mmHandleCriticalSection`. `walias.h` contains references to Get/FreeMMedia; whether any active consumer still selects each alias operation needs direct tracing and cannot be inferred merely from macros. The current map does not list the GetMMedia16/32 or FreeMMedia16 function symbols; it does contain a `FindHMap16` static datum in wmmalias.obj. Distinguish absence of mapped functions from proof of all runtime paths or correctness of host conversion.

T466 S2 documents original `WMM32CallProc32` execution with the exact synchronous timeGetTime packet and host WINMM export lookup; T466 S3 confirms 11 host export resolutions but explicitly does not demonstrate wave/MIDI device open/close, completion, MCI, callback or task teardown. These are valid bounded evidence for the synchronous bridge, not proof of disabled converters or all historical multimedia ability. `wmmedia2.c` remains pending: its original direct 32-bit converter role is inactive by design, but guest-equivalent capability and integration are not comprehensively proven. `wmmalias.c` also remains pending until active alias consumers, identity reuse and teardown are traced and tested. No new runtime test was performed.
