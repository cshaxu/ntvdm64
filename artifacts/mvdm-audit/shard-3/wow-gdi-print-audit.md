# WOW32 GDI 3.1 and print-setup audit

`wow32/wgdi31.c` and `wow32/wgprnset.c` are byte-identical to pinned OpenNT and each is selected for the current x86 WOW32 DLL. `wow32.dll.map` attributes StartDoc, EndDoc and AbortDoc to `wgdi31.obj`, and DeviceMode, ExtDeviceMode, DeviceCapabilities to `wgprnset.obj`; `src/mvdm/wow32/wgtbl2.h:465–472,556–558` registers the corresponding GDI ordinal thunks. Source and map establish selection and dispatch registration, not execution of each entry.

The original `WG32StartDoc` converts guest structures, synchronizes DOS current directory where needed, invokes the existing native HDC/provider and preserves original abort callback handling; document/spool resources belong to native GDI/provider. `wgdi31.c` also contains many unrelated geometry, font, bitmap and glyph thunks, each with its own parameter conversion and return contract; printing evidence alone cannot cover the file. The original `WG32DeviceMode`, `WG32ExtDeviceMode`, `WG32DeviceCapabilities` copy 16-bit data and release transient flat pointers before potentially reentrant WINSPOOL/fax provider calls; original conversions remain the behavior owner while the provider owns its device state. `wgtbl2.h` is a dispatch declaration carrier, not an independently executable subsystem.

`docs/etc/evidence/m0-t468-s2-hdc-print-witness.md` records a real Win16 HDC normal/cancel print to named Microsoft Print to PDF provider, with SetAbortProc, StartDoc/EndDoc and related calls, callback/DC cleanup, and a generated PDF. That establishes only that named route, not all of `wgdi31.c`. The same evidence explicitly records the DeviceCapabilities endpoint as unavailable/not accepted after original provider-load/call did not return in the observation budget; 15 imported WINSPOOL names available are surface evidence, not proof of device configuration success. Inspect later T468 evidence before treating that historical limitation as current. Raw OpenJob no-profile behavior and PrintDlg each exercise different entries, and must not be counted as WG32DeviceMode success.

No test was executed during this audit. Both source rows remain pending: broad GDI 3.1 functionality, device-setup conversion/reentry/error/cleanup and current accepted provider coverage remain unproven per source file; no basis for whole-file full restoration or exclusion.

A follow-up search of all current docs/etc/evidence/*t468* found no later DeviceCapabilities result beyond S2's documented non-acceptance; this is absence of a located record, not proof that no other test or later fix exists.
