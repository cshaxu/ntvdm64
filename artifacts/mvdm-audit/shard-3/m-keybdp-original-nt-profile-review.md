This is a physical file role review only; no guest, device, product or shared ledger was modified.

File-name inventory of both available MVDM trees likewise finds this header only. Thus the exact original upstream X consumer/build target is **not present in these inspected trees**; it is supported to identify an X keysym table, but not to assert it was exclusively a SoftWindows driver or reconstruct its absent original application.

The captured worker commands compile all three, and the dependency inventory does not show the `base/inc/m_keybdp.h` exact path. Neither these NT sources nor the worker graph and generator contain `KeySymTable` or `XK_*` use. Existing `../input-native-role-review.md` binds selected original NT input objects and controlled translation tests, while separately retaining S13 scan-code boundary, layout and lifecycle coverage. That NT path is a different Windows input source; the tests do not prove X keysym behavior.
