# XMS service ABI, pool ownership and edge cases — shard 3

Scope: pending `inc/xmssvc.h`. `xms-service-observer.py` and captured JSON compare source with both original trees and record observed worker map entries. The header, corresponding assembler constants, dispatcher, XMS initialization and HIMEM source match both references; current xmsblock.c and nt_bop.c have local changes. No build, guest modification or runtime execution was performed.

Guest `himem4.asm:155-201` finds a free handle and uses `XMSSVC XMS_ALLOCBLOCK`, records returned base/length and marks it used; corresponding service values appear in both `inc/XMSSVC.INC` and `inc/xmssvc.h`. `nt_bop.c:354-364` reads the guest service byte, calls `XMSDispatch`, then advances guest IP. `xmsdisp.c:16-29,44-60` maps service numbers to the original handlers. `xms.c:30-100` initializes shared ExtMemSA and fails startup if pool initialization fails; `xmsblock.c:37-101` allocate/free through that pool, while `himem4.asm` owns guest-visible handle bookkeeping. DPMI additionally uses that same pool under registered MVDM-HOST-DIV-224; see `dpmi-allocator-role-review.md` for distinct task-owned XMEM bookkeeping. Do not conflate the two lifetimes. Existing worker map records MS_bop_2, XMSDispatch, XMSInit and block handlers from original owner objects; this is link evidence, not proof of runtime or latest release identity.

Static edge observations, not established runtime defects:

* Dispatcher checks index >= XMS_LASTSVC only in the DBG branch; selected release would have no such check if DBG is off. This source condition alone does not establish that a normal HIMEM request issues an out-of-range service. Verify active flags, guest entry and failure contract before deciding.
* xmsAllocBlock only assigns BaseAddress when size is nonzero but subsequently reads it; historical HIMEM allocation code shown at `himem4.asm:155-201` issues the allocation BOP without an obvious local zero-size check. Determine whether its calling contract or an earlier entry filters DX=0 and reproduce before classifying.
* xmsReallocBlock similarly leaves NewAddress uninitialized if sizes are equal, but HIMEM `ReallocExtMemory` explicitly returns success before the BOP for equal sizes (`himem4.asm:440-460`). Thus this source observation does not prove the normal guest path reaches the branch; other callers, if any, require separate evidence.

Proposed disposition for xmssvc.h: **pending**. Header identity and selected linkage are confirmed, but source-to-installed HIMEM identity, ABI, valid/invalid request handling, pool exhaustion and cleanup remain unproven. No guest behavior, established crash or restoration percentage is asserted from static observations. Review the local xmsblock and nt_bop divergence ledger separately; this does not automatically make the otherwise original header or service missing.
