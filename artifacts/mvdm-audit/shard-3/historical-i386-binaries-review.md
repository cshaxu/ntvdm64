# Historical i386 binary inputs: shard 3

This batch covers the 58 rows in `historical-i386-binaries-review.csv`: current-only `obj/i386` files whose review was pending, with extensions OBJ, LIB or RES. Every row's repository file under `src/mvdm` exists and matches the frozen SHA-256. Exact absolute and repository-relative paths are absent from `ninja -t inputs` closures for the current x86 worker `ntvdm.exe`, x86 `wow32.dll`, and worker `VDMREDIR.dll`; raw output hashes and target directories are in `historical-i386-binaries-review.json`. Every old artifact's whole-file SHA-256 differs from all 83 files recursively present in `build/package-uuid/package-c` at inspection time. CSV records exact paths and full hashes. No file was executed, imported or modified.

All 58 are therefore `excluded` **as these historical binary inputs** from these three inspected target graphs and as exact standalone files from this package. This does not prove identical bytes cannot occur inside a linked archive/image, nor that every other product target or configuration was inspected; it is not a decision that their original features or source are excluded. Source, linked replacement objects, firmware/guest and functional behavior retain independent audit requirements. In particular names such as `cmd.obj`, `win.obj`, or a sample resource are not treated as proof of their corresponding guest program or sample capability. Retain all frozen rows and refer to the companion CSV for per-row evidence.
