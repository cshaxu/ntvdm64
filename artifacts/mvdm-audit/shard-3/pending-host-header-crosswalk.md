# Pending base/inc and host/inc crosswalk

`pending-host-header-crosswalk.csv` is a reproducible, **provisional** inventory of the 77 `host-candidate` pending C headers under the two requested directories in the captured `host-ch-scope/inventory.csv`. The companion `build-pending-host-header-crosswalk.py` reads that inventory, the prior normalized VALID dependency index, current source and the checked-out OpenNT comparison. It collects candidate report names by **basename**, so reports with same-named headers must be checked against the full path before use. Original-role excerpts are source comments, not proof of an implementation or behavioral contract.

The inventory yields 14 device/BIOS/input/video, 11 DOS/host services, 19 execution/CPU and 30 profile/host-support rows. These groups and proposed S11/S12/S13/S17 assignments are navigation hints based on filename; the coordinator must confirm the actual owner before accepting an assignment. The comparison found all 74 local files byte-identical to the OpenNT counterpart. This does not establish feature equivalence, exact compiled inclusion, runtime behavior, or compatibility with OpenNT 4.5.

Only three rows have exact captured C-dependency hits: `chkmallc.h` (1, `stubs.obj`), `gispsvga.h` (2), and `host_hfx.h` (4). The prior reports respectively identify the `check_malloc` call in an unselected `MONITOR` branch, GISP declarations gated by `GISP_SVGA`, and HFX declarations gated by `HFX`; do not promote any solely from inclusion. All remaining rows have zero exact hits in this particular index; this does not exclude other configurations, generated inputs, assembly or alternate names.

The crosswalk deliberately preserves **pending** for every row; it is a complete scope and source-evidence index, not a claim that all 74 have been semantically audited or individually assigned. Several reports recommend a narrower file-level exclusion for the observed profile; evaluate their exact source evidence before the coordinator updates the ledger. Likewise, selected related providers and tests can justify their own partial status without proving a same-named header is selected. For disk/input/device examples see `pending-device-headers-partial-check.md`, `disk-input-pending-header-reconciliation.md`, and `rom-mono-hercules-selection-review.md`.
