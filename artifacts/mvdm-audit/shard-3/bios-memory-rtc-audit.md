# BIOS conventional memory and RTC handler review

Scope: shard-3 `softpc.new/base/bios/mem_size.c` and `rtc_bios.c`, both frozen exact-original source rows. This review is source/previous-evidence only; no product or guest change and no new test.

| Entry | Actual owner and lifecycle | Evidence and remaining boundary |
| --- | --- | --- |
| Conventional memory | `bios.c:159` registers `memory_size` for BOP 12; selected `mem_size.c:44-54` loads mutable BIOS data area `MEMORY_VAR` and writes AX. The cached product map includes `original-softpc-bios:mem_size.obj` at `_memory_size`. The guest/firmware owns the BDA, not an independent host cached memory value. | T420 S26's `tests/observation/bios_capability.asm` executes INT 12h and compares AX with BDA 40:13; its cited historical transcript contains `S26_MEMORY_SIZE_OK`. It did not intentionally change BDA before a second call, exercise reset/re-entry, or prove a current-package run. Exact source and symbol extraction are not whole-behavior proof. |
| RTC IRQ BIOS handler | `bios.c:389` registers `rtc_int` at BOP 70; `dos/v86/doskrnl/bios/spckbd.asm:1980` contains the original BOP 70 entry. Under NTVDM, `rtc_int` reads/acknowledges CMOS C, intersects flags with B, decrements BDA user wait count on periodic cause, on underflow clears PIE and writes the user's completion byte, simulates INT 4A on alarm while saving/restoring CS/IP, then sends EOI to slave and master PIC. Product map includes `original-softpc-bios:rtc_bios.obj` at `_rtc_int`. | T420 S24 `system_capability.asm` enables PIE and observes CMOS C periodic flag; that is device/port evidence, **not** in itself proof BOP 70 was dispatched or its countdown, INT 4A callback, EOI, re-entry and failure paths work. S26 describes these as the same provider, but its listed guest witness does not assert those handler outcomes. `pic_reset_eoi_test.c` tests real selected PIC/device reset and mocked host edges, not this BIOS handler. Current targeted handler evidence is therefore insufficient. |

The most direct bounded follow-up is an isolated test-only real DOS guest or source-linked fixture: set a known BIOS wait and user flag, exercise periodic IRQ8 through actual ROM/BOP 70, assert countdown/completion and slave/master EOI; separately use an INT 4A test handler for alarm and assert exactly one callback plus CS/IP restoration. Exercise neither production guest modification nor synthetic success. Compare original/current package identity and safely restore CMOS/PIC and guest-owned BDA. Such a fixture must explicitly distinguish device register C evidence from entry into `rtc_int`. The rows remain pending; no unsupported functional failure or complete RTC restoration is asserted.
