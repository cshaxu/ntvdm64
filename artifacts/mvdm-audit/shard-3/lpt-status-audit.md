# LPT status original-provider and diagnostic difference audit

`src/mvdm/softpc.new/host/src/nt_lpt.c` SHA-256 `C2C77BCD2A9151BFAB0DADD3CCD3A30259DD79C904AA2E3D02BC66AE7E500449` differs from pinned OpenNT only by adding the termination header and three `mvdm_softpc_report_setup_hardware_probe` calls around original `host_read_printer_status_port`. Current worker Ninja selects `obj/host/nt_lpt.obj`; `ntvdm.exe.map` attributes the function to `original-softpc-host-roots:nt_lpt.obj`. `base/comms/printer.c` routes a status port read in `STATE_DONGLE` to this original host routine; it reopens inactive port, flushes pending buffer, calls original VDM parallel status IOCTL, and returns zero on IOCTL failure. These establish source and link paths, not their execution under every controller state.

The added reporter in `mvdm_softpc_termination.c` SHA-256 `D1285E26CEC1B839866B0CF199531FE8E7328F8C3F69353932E5D9E7015F8F77` caches the diagnostic path per thread; with path unset it still checks once and restores host LastError but performs no file write. With tracing enabled it synchronously creates/appends/writes/closes a bounded log and restores LastError, so “observational” does not establish unchanged timing/reentrancy. Unlike the CCPU far-diagnostic discrepancy, arguments are already available scalar values; no extra guest descriptor reads are inserted. Whether a real VDM parallel IOCTL device exists or behaves identically requires a concrete device.

T420 S30's real DOS `L30.COM` fixture sent byte 0x5a through the original INT17/LPT1 path to an observer-owned named pipe; this is a byte-output witness, not an IOCTL status/dongle, physical printer, device reopen or error/cleanup witness. Static evidence does not establish that the stated `STATE_DONGLE` status path was exercised. Required follow-up is a narrow host-boundary fixture using the actual `nt_lpt.c` body and controlled open/flush/IOCTL results, testing status success/failure, buffered flush, disabled/enabled logger and LastError, followed by real device status only when a suitable endpoint exists. Avoid substituting a named pipe byte-write pass for IOCTL behavior.
