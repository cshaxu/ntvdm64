# Active guest-source build edges: bounded shard 3 candidates

`guest-source-active-edges.csv` identifies 14 paths whose actual same-directory original DOS utility makefile contains a non-comment dependency from the exact source/include to a named object, and from that object to a named `dest` guest executable; the recipe runs `link16` for the target. Original `dos/v86/make.inc:44,54,84-91` supplies `masm`/`cl16` suffix rules. For the four `.inc`/`.h` entries, the exact source `include`/`#include` is also identified by path and line. Rows include frozen SHA and exact recipe dependency lines. This is stronger than filename occurrence but does not assert the historical target is the current archive binary.

Candidates are DOS APPEND, DEBUG, EDLIN, EXE2BIN, FASTOPEN, MEM and SETVER source/build declarations. The proposed disposition is `guest-build-source-file-only`: these are materials for the original 16-bit guest build, and current policy prohibits rebuilding/modifying existing guest; their runtime guest application, data, inputs, error handling and host interaction are still independent audit owners. Header declarations can also affect guest ABI and are not proof their consumers are verified. This is a bounded candidate group for main-session integration, not a change to `file-review.csv` or an assertion the other 209 candidates lack owners. No product/guest changed or guest built/run.
