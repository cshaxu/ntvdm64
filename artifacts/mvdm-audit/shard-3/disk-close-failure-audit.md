# Host floppy/fdisk failed-counter close transition

`nt_rflop.c` (`D8E469A3AC2F35EB0205894F9C9F44404B6F3C797A295AB68281E54C009B53FA`) and `nt_fdisk.c` (`691EF629BB953A15F8C5A3BDFEE2D492BBCC534D14303FB03BF1CA988A79F4A7`) add DIV-006 current-PDB lease and DIV-111 SCS FD-access-counter lease to the original disk providers. On open both establish a native handle and increment original per-provider count, then roll all of them back if the counter update fails. On close both close and invalidate the native handle before attempting the decrement; if it fails, both return FALSE before decreasing their provider open count. Floppy additionally retains its old owner/lock and density flag; fdisk clears owner/lock before that return. `get_drive_handle`, `get_fdisk_handle`, and termination loops do not consistently act on close failure. Original OpenNT raw pointer decrement was not a fallible lease API; compare its behavior without assuming the old persistent pointer is safe.

`disk-close-failure-probe.c` SHA-256 `DAA3148AAB59D6AF055668E2BC77231B05E41217DEF39E7A4BD2E44CD5FB8273` uses actual selected original-softpc-host-fixture-roots `nt_rflop.obj`/`nt_fdisk.obj`, two real event handles as closable host handles, and overrides only `mvdm_command_guest_state_add_fd_access` to return failure. The inherited worker fixture graph uses `/force:multiple`; map `build/t473-s10/shard-3-ccpu/disk-close.map` attributes `nt_floppy_close`/`close_fdisk` to their actual provider objects and counter function to test seam. Focused return 0 reports: floppy close FALSE, native-handle field INVALID_HANDLE_VALUE, lock 1, owner 1234, open count 1, density flag 0; fdisk close FALSE, handle invalid, owner 0, open count 1. This proves the actual called source-object state transition under injected counter failure, not that an actual session lease necessarily fails at a particular user lifecycle or that an original guest triggers it.

The fixture's C struct projections are layout-critical. Isolated copies of the current provider C sources were compiled using their actual worker Ninja compile flags with compile-time offsetof assertions: FL handle 0, lock 13, owner 14; packed FDISKDATA handle 4, lock 3, owner 32. The fixture has the same explicit compile-time assertions and compiled `/W4 /WX`. These checks establish only the fields used, not global ABI for other fields. Two earlier fixture attempts called Win32 handle-inspection on already-closed values and the process exited 0xc0000008; they were discarded, not counted as product behavior or proof of a second close. The final witness calls each close only once. A subsequent second close ignoring count is source-derived, not dynamically asserted.

A minimal recovery direction is to retire native handle, owner/lock and native open-count exactly once even when guest counter decrement fails, propagate the counter error separately and define what NTSRV/worker should do with an unavailable authoritative guest counter; handle changes and scalar updates must not falsely claim full success or reopen admission. Validate success/failure, reopening, double close, termination and lease loss for both provider families with actual session-bound location where feasible. This audit changes no production code, guest or user device.
