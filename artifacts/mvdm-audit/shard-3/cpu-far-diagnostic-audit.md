# DIV-308 far-transfer diagnostic side effects — static audit

Current `src/mvdm/softpc.new/base/ccpu386/c_xfer.c` SHA-256 `20701465C5DB30FB728EB9FFE6258D3A96B88A9067CD974C128B3585964D8FD2`; compared original `O:/repos.external/OpenNT/base/mvdm/softpc.new/base/ccpu386/c_xfer.c`. Original validates selector table bounds, reads only access-rights byte, then checks descriptor type, privilege and presence. Current invokes DIV-306 reporting immediately afterward, evaluates two `spr_read_dword` arguments before the reporter can test environment, then DIV-308 reads the same two dwords again, derives a candidate linear address, and calls `xtrn2phy(...,0,...)` before calling a reporter that checks the environment/selector. C argument evaluation and ordinary statements occur even when tracing is disabled or selector filter does not match. The comment's “already validated destination” means only table-bounds validation has happened; descriptor type/privilege/presence and call/task-gate handling are still below these calls.

`c_page.c` SHA-256 `466CA443C7CF3B32808F28D2EBD0090EE616D768FE272699D05D02A6BF5BC09D` documents supervisor reads may cause #PF; with paging enabled `spr_read_dword` performs `lin2phy` and if it spans pages may perform separate word reads. Those extra reads can translate pages/set page access state or produce a guest page fault before original GP/NP decisions for descriptors on boundary or mappings that differ, and can add physical reads. This is a code-derived semantic risk, not a reproduced guest failure. Separately `c_tlb.c` SHA-256 `A83A7DD3F7E3FBB83723047AACDDBD22D4001591C6D444D4BD6D45DD73E38FD8` says `xtrn2phy` does not take #PF or change the TLB; the access_request=0 call does not enter the optional accessed/dirty write branch. It does search cached TLB state and, on a miss, reads physical PDE/PTE; the caller does not check CR0.PG before invoking it. Thus do not conflate xtrn2phy with `lin2phy`, or assert that xtrn2phy itself unconditionally changes A/D bits. Whether any particular physical read reaches a side-effectful device needs a concrete mapping and is not established here.

`mvdm_softpc_report_wow_fetch_translation` in `mvdm_softpc_termination.c` SHA-256 `D1285E26CEC1B839866B0CF199531FE8E7328F8C3F69353932E5D9E7015F8F77` checks trace path and selector only after its arguments have already been calculated. Minimal corrective direction is a shared cheap enabled+selector gate *before* all DIV-306/308 diagnostic argument reads/translation; review whether to avoid faulting diagnostic reads even when enabled and ensure paging-off identity handling, including call-gate semantics. That remedy has not been implemented or approved as semantically complete. No test has been run; prove disabled-mode original exception/order with cross-page descriptor and page-state fixture before claiming restoration. This audit changes no product or guest.

## Minimal exception-order construction (source-derived, not run)

Use existing real CCPU `tests/mvdm-host/ccpu_bounded_execution_fixture.c` paging setup and selected c_xfer/c_page/c_tlb objects, with diagnostic path and selector environment absent. Give GDTR base `0x0ff3`, limit at least `0x000f`; GDT selector `0x0008` produces descriptor address `0x0ffb` by `selector_outside_GDT_LDT` arithmetic. Map supervisor-readable linear page 0x1000, place access-rights byte `0x00` at descriptor+5 = 0x1000 (invalid super-type); make page 0x0000 nonpresent. Selector is nonzero and descriptor passes table limit. Under the pinned original, `spr_read_byte(0x1000)` succeeds and invalid descriptor super-type takes `GP(selector, FAULT_FAR_DEST_BAD_SEG_TYPE)` before any lower descriptor read. Under current source, the first of the unconditionally evaluated DIV-306 `spr_read_dword(0x0ffb)` crosses a page; its first `spr_read_word(0x0ffb)` calls `lin2phy` on the nonpresent page and sets CR2/PFLA and raises #PF before the switch can issue original #GP. The exact call evaluation order among two report arguments is unspecified in C, but the high dword is on the mapped page, and the low read is still required before the reporter call; either evaluation order eventually faults on the same low dword. DIV-308 repeats the read and is not reached in that case. A separate mapped-two-page comparison can check A bits and count physical reads even with logger absent.

`ccpu_bounded_execution_fixture.c` already creates page directories, uses actual xtrn2phy/spr_read and initializes original CCPU; adapting an independent copy could exercise this scenario, but its installed exception delivery/longjmp and cross-page GDT fault interception must first be verified. No proof from that existing high-page success test may be substituted for this unexecuted comparison. A close test should execute original and current c_xfer object on identical fixture setup (or record original result from source and assert current #PF), log exception vector, fault linear address and access-bit changes, and include aligned valid selector control. Existing guest files need not change. No product or guest code was altered in this audit.
