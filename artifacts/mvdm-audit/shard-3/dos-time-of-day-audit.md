# DOS time-of-day and RTC call ownership

Scope: shard-3 `softpc.new/base/support/time_day.c`, frozen byte-identical OpenNT. This is a static recheck against historical evidence, with no new test or product/guest change.

`bios.c:172` binds `time_of_day` to BOP 1Ah; the cached NTVDM map selects the original support object for both `time_of_day` and `time_of_day_init`. Under the selected NTVDM profile, AH=00 reads tick words and overflow from guest BDA and clears overflow; AH=01 writes guest BDA ticks and clears overflow. The non-NTVDM branch that recomputes host timestamps on each access is not the selected path. NTVDM `time_of_day_init` excludes the non-NTVDM initialization body; `nt_timer.c::host_init_bda_timer` instead reads host local time, initializes BDA and RTC in the heartbeat reinitialization path under the ICA lock. The heartbeat/PIC owns ongoing tick delivery, while the BDA remains the guest-visible time state; do not assume the AH=00 handler itself polls host time.

AH=02/04 read RTC time/date through CMOS unless update-in-progress; AH=03/05 write the RTC, AH=06/07 handle alarm. Under NTVDM `UpDateInProgress` loops on CMOS register A with `Sleep(0)` until UIP clears, returning FALSE. This is original source behavior, not newly invented NTVDM64 timeout/polling; a stuck UIP could cause an unbounded wait, but no evidence here establishes that condition in the selected real provider or justifies removal. Alarm, RTC register behavior and delayed IRQ8 belong to `cmosnt.c`, whose evidence is separately tracked in `cmos-rtc-device-audit.md`.

T420 S27 `support_capability.asm` made a real guest AH=00/01 tick round trip, restoring original high/low counter, and checked AH=02/04 return carry clear. Its historical transcript has `S27_TIME_TICKS_OK S27_RTC_TIME_OK S27_RTC_DATE_OK`. It does not validate RTC value accuracy, overflow clear, day rollover, AH=03/05/06/07, host clock jump, stuck or transient UIP, concurrency, or heartbeat restart; it belongs to its recorded historical package rather than today's cached NTVDM. The tick fixture reads and clears overflow but does not restore it, so it is not evidence of overflow preservation. A bounded source-linked fixture with real selected time and CMOS bodies and controlled host time/guest BDA can cover overflow, UIP transition, alarm and reset, followed by a separate isolated real guest for normal RTC/tick behavior without changing the host clock or guest media. Keep the row pending; no claimed production failure or semantic change follows from uncovered cases alone.
