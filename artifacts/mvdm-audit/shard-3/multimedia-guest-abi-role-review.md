# Win16 multimedia ABI and callback ownership — shard 3

Scope is pending `inc/WOWMMED.INC`; `multimedia-guest-abi-observer.py` and captured JSON compare it, its guest include consumer and related multimedia sources to both original trees and capture the observed WOW32 map entry. All six sources inspected are byte-identical to both references. No build, guest modification or playback/device test occurred.

`WOWMMED.INC` defines 16-bit multimedia structures, including AUXCAPS16, JOYCAPS16 and MCI parameter layouts. Historical `wow16/mmsystem/stack.asm:38-39` includes it alongside WOWMMCB.INC, but inclusion alone does not prove each structure is referenced or any specific offset/layout is used by that file. Its original `DriverCallback` at `:774` branches between posted window/task notification and a guest procedure, and explicitly avoids switching stacks under WOW because the comment assigns this to DPMI. This is a historical source chain, not evidence that this exact source was built into installed MMSYSTEM.DLL.

The active broader source ownership and previous focused host witness are documented in `docs/etc/evidence/m0-t466-s3-async-multimedia-owner-audit.md`: original guest mmsystem resolves private WINMM endpoints and retains its original callback ring and device/task ownership; the project WOW32DriverCallback forwards to WINMM. `wow32/wmmedia.c:312-324` implements this forwarding, and the observed WOW32 linker map includes that function from wmmedia.obj. The prior evidence records resolving private exports and a synchronous tid32Message timeGetTime witness, not a real asynchronous wave/MIDI/device completion. Its audit also says structured MCI is not activated by the selected WOW32 table. The observed map is not independently bound here to the latest released DLL.

Proposed disposition: **pending** for WOWMMED.INC. The file is an original guest ABI input; host Ninja dependency absence must not exclude guest capability. Its source identity and historical use do not establish deployed image provenance, all ABI layouts or actual callback behavior. Real immutable guest timer cancellation, callback reentry/task loss, wave/MIDI device completion and teardown remain separately stated acceptance boundaries in the T466 audit; do not infer all multimedia unavailable or all restored. No restoration percentage is inferred.
