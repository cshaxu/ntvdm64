# PIF configuration retention and command lifetime audit

`softpc.new/host/src/nt_pif.c` current SHA-256 `0A7933AAF0FA43D1865419781C6AD6DDD908B3D0A09B5DFCEAD66217A7FB78D8`; pinned OpenNT SHA-256 `4AE2C1D2C4A66DC63C9B2DDD673FCAE067F2FBDAB953DC8D96AECFCF03C262BC`. DIV-157 replaces modern host system-directory defaults with the selected immutable system-media root and retains PIF CONFIG/AUTOEXEC override strings beyond their first read. Original consumed/freed each path after its first lookup. The reason is concrete: `config.c` -> `nt_msscs.c::init_lim_configuration_data` reads CONFIG before SAS, and later `cmdconf.c::ExpandConfigFiles` reads it for DOS boot; T420 S35 documents the original first-read consumption regression and a real isolated CONFIG/EMS guest witness. DIV-278 converts expanded OEM override paths into ANSI for consumers. `cmdconf` still handles absent/bad file through its original fatal path; PIF parser owns its PIF_DATA output and host retains only strings.

Current process-static `pchConfigFile`/`pchAutoexecFile` are freed and replaced only when `GetPIFData` reads an NT extension while `IgnoreConfigAutoexec` is false. Defaults, absent/malformed PIF, no NT extension, or the ignore path do not retire previous strings. `SetPifDefaults` resets only `PIF_DATA`, not these pointers. The later `cmdpif.c::cmdCheckForPIF` can call `GetPIFData` on a non-first PIF, setting `IgnoreConfigAutoexec=1`; that does not itself prove a stale override bug: those later commands may correctly preserve the already-booted worker's configuration, and no evidence here shows `GetPIFConfigFiles` is called again after that selection. Nor should clearing on every parse be assumed correct, as it could break the intended initial LIM/DOS shared two-read contract. Model selection scope and actual call chronology before any fix.

Concrete follow-up: existing direct parser test `tests/legacy/opennt/trace/fixtures/pif_default_parser_fixture.c` covers only default fields; `tests/mvdm/oemuni/oemuni_pif_caller_fixture.c` explicitly stubs GetPIFData and cannot establish retained-path lifetime. Independently prove whether later command requests can execute `cmdGetConfigSys`/`cmdGetAutoexecBat`, and determine which task or worker owns the original startup selection; test no partial pair after allocation failure as an explicit decision. Preserve the known two-read CONFIG/EMS guest control. Do not classify any hypothetical stale result as a user-visible regression before that proof.
