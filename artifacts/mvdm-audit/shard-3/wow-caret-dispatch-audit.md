# WOW32 caret thunk and dispatch-table audit

`wow32/wucaret.c` is byte-identical to pinned OpenNT and is selected as `obj/wucaret.obj` in `build/.ninja/msvc-x86-release/wow32/build.ninja`; the corresponding `wow32.dll.map` lines 739–746 contain all eight `WU32` caret function symbols and the `wucaret.obj` owner. This proves code and symbol inclusion, not guest invocation or complete semantic equivalence.

`src/mvdm/wow32/wutbl2.h` contains the original USER dispatch registrations, including CreateCaret, DestroyCaret, SetCaretPos and GetCaretPos at lines 210–212 and 234. `WU32CreateCaret` maps 16-bit HWND and bitmap (preserving special values 0 and 1), converts dimensions and calls host `CreateCaret`; the other wrappers use host caret operations and parameter/coordinate conversion. `GetCaretPos` uses `PUTPOINT16`, while the other paths also have function-specific return and argument handling. Native USER owns caret state; this is not an independent WOW caret engine.

`tests/mvdm-host/wow_page_domain_fixture.c:460–462` calls `wow_native_CreateCaret` and `wow_native_SetCaretPos`, and checks host `GetCaretPos`; it is a native binding/ownership witness, not a call through `WU32CreateCaret` or the ordinal dispatch table. `tests/adapter-mvdm-host-out/wow/wow_native_input_focus_fixture.c` exercises native focus/caret ownership, not the 16-bit thunk. The T457 S2 evidence records a real guest dialog and edit-key probe but explicitly identifies the dedicated keyboard/caret desktop fixture as an environment non-pass; it does not establish full caret thunk coverage. Current inclusion and real dialog evidence therefore do not prove all 8 APIs, bitmap aliasing, special values, 16-bit coordinate truncation, blink timing, task ownership, error paths or teardown. Keep both rows pending; no new test was executed for this audit.
