# Selected CCPU leaf declaration ABI closure — shard 3

The frozen shard contains four headers corresponding to the 23 already-full selected leaves: `adc.h`, `cmp.h`, `dec.h`, `stc.h`. `header-abi-closure.csv` records each complete sole IMPORT declaration, frozen/current/OpenNT SHA equality, and exact selected worker Ninja VALID dependency consumers. Each is included by `c_main.obj` and its corresponding leaf object. `cmp.h` also appears in VALID `cmpxchg.obj` dependencies; that original source's CMPXCHG bodies and calls to CMP are under `SPC486`, whereas the selected worker defines `SPC386`, so header inclusion is not proof of an additional active 486 execution path.

In the selected ANSI configuration `host/inc/insignia.h` defines IMPORT as `extern` and IPT0/2/3 as actual typed prototypes. `IU32` is unsigned long (32 bits in the selected MSVC x86 ABI) and `IUM8` unsigned char; these declarations and matching IFN definitions compile with the default x86 C calling convention. The PE decoder reference and complete actual leaf object, plus real guest evidence, are separately retained in `full-selected-leaf.csv` and its sign/ALU contracts. Header dependency confirms an include and ABI closure, not standalone proof of guest behavior.

Every one of these headers consists only of comments and that single corresponding function declaration; no additional unverified interface is hidden in the file. The four rows are thus full/100% **for the selected original declaration files**. This does not close other CPU profiles, wider decoder contracts, memory/fault behavior or asynchronous lifecycle. No product/guest modifications or guest runs occurred during this review.
