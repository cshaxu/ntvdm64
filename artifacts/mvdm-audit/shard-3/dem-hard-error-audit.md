# DEM DOS hard-error and retry path

Scope: shard-3 `dos/dem/demerror.c`, frozen byte-identical to original OpenNT. Review is static and historical-fixture inspection; no new execution, product edit or guest modification.

`demdisp.c:150-151` publishes `demSetHardErrorInfo` and `demRetry` in the SVC dispatch table. DOS kernel first supplies DS:DX and DS:BX guest addresses, retained as `pHardErrPacket` and `pDeviceChain`. Filesystem/directory/handle SVCs call `demClientError` after host failure. `demClientErrorEx` reads host thread `GetLastError` (zero maps to ACCESS_DENIED), ordinary failures set guest AX if requested and CF if requested. For WRITE_PROTECT through GEN_FAILURE or WRONG_DISK it marks the guest hard-error packet, calculates drive and INT 24 error, saves guest registers plus `CurrentISVC`; `demRetry` restores these then invokes `apfnSVC[CurrentISVC]`. For WRONG_DISK this code maps to GEN_FAILURE before conversion. Retry safety relies on the original stated DOS contract: INT 24 handlers do not call DEM and failing SVCs do not pre-modify argument registers. These are original assumptions, not independently verified modern-thread/re-entry invariants.

Selected cached `ntvdm.exe.map` contains `_demClientError`, `_demClientErrorEx`, `_demRetry`, `_demSetHardErrorInfo` from `original-mvdm-dem:demerror.obj`. Selection and exact bytes do not establish successful guest initialization, host error propagation, packet lifetime or retry behavior.

Historical `tests/component-integration/fixtures/t230_s8_demerror_lock_direct_import_fixture.c` seeds RetryInfo and invokes a dispatcher with a test guest buffer and handle manager, and separately issues hard-error setup; source comments explicitly state full hard-error continuation needs whole dispatcher binding. It uses a historical overlay composition and is not current production-path or actual DOS hard-error evidence. `tests/legacy/opennt/trace/fixtures/original_demerror_register_fixture.c` is designed to check ACCESS_DENIED AX/CF with CPU seams, but no execution result was established here. Neither can be counted as a current-package end-to-end pass.

Unresolved: initialize the real guest hard-error packet before hard failures; lifetime under guest teardown and re-entry; `bSetRegs=FALSE`; correct original user-selected retry after an actual host failure; remote/no-drive and device-name lookup; host error identity across intervening calls; and failure mapping on supported media. A bounded source-linked controlled-host seam can first check non-hard, hard and retry state while retaining actual `demerror.c`; then an independent DOS guest with a deliberately controlled failure and INT 24 handler should test fail/retry against a pinned isolated package. No physical media or existing guest image needs alteration. The row stays pending; no observed bug is asserted from the original assumptions alone.
