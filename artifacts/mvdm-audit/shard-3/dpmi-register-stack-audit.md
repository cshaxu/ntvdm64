# DPMI register width and DOSX stack audit

Scope: shard-3 `dpmi32/register.c` and `dpmi32/stack.c`; frozen inventory identifies both as byte-identical original OpenNT. Static source and historical evidence only; no product or guest edits or fresh execution.

`DpmiInitRegisterSize` runs from `dpmi32.c` after setting `CurrentAppFlags` from guest AX. It selects 16- or 32-bit AX/BX/CX/DX/SI/DI get/set function pointers. SP is deliberately different: `IgetSP` selects SP vs ESP from the active SS descriptor's Default_Big bit for either app flag; do not simplify it to client bitness. The source relies on original x86 calling convention for its 16-bit setter casts. Product `ntvdm.exe.map` attributes `_DpmiInitRegisterSize` to `original-mvdm-dpmi32:register.obj`; that proves linking, not all selector or switching cases.

`stack.c` switches to DOSX real/protected stack and decrements the shared frame pointer on entry, increments on exit. `xlathlp.h`'s `DPMI_EXEC_INT` selects real DOSX stack -> builds a real-mode interrupt return frame through `DpmiPushRmInt` -> `host_simulate` -> releases the frame. `buffer.c` also uses protected-mode DOSX stack switching. `DpmiSimulateIretCF`, used by many `int21map.c` handlers, takes IP/CS/status from the protected stack and merges current CF only, restoring SP by six. This is distinct from other real guest IRET handlers. All four symbols map to `original-mvdm-dpmi32:stack.obj`.

Historical T420 S38 documented real 16/32-bit guest paths, INT21 pointer/FLAGS observations and interrupt-return tests; the retained `tests/observation/dpmi_pointer_trace.c` forwards the original IRET helper after observing it, while `dpmi_ioctl_boundary.c` substitutes a test seam. These provide named-path evidence, not proof that every stack helper, nested DOSX frame, invalid descriptor or edge SP was exercised on current product. T420 S38 records several differently hashed workers; its results must remain tied to their own named package, not reattributed to the present cached build.

Important bounded risks to verify rather than assert as bugs: both client bitness and SS Default_Big combinations, active selector change across nested transitions, `DpmiPushRmInt` stack-end/wrap (the original source explicitly marks wrap as a question and ASSERTs `SP > 6`), restoration after simulated return/failure, and frame-pointer balance on nested interruptions. In particular an ASSERT in source does not establish release-build behavior. A source-linked fixture with original register/stack bodies and controlled actual descriptor/guest-memory seams can assert width selection and exact frame/CF transitions, followed by an independent Win16/32 DPMI guest case using a hash-pinned isolated package. Do not modify existing guest or infer broad equivalence from selected objects. Both rows remain pending.
