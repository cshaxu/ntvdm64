# Keyboard BOP diagnostic reads and vector owner

Pinned OpenNT `keybd_io.c` SHA-256 `C17523F12F895EB144B38692F4D91DC97D539106A8D3E4B8CF23BC4338CD4896`; current SHA-256 `F5992EF1FF275D53C689D97D8263AFADB5993954901810D8DF48E0E6590262C1`. Current `keyboard_io` has DIV-325 setup traces that unconditionally compute effective SS:SP and read four `sas_w_at` words before dispatch, even with logging disabled; the original BOP 16 code in `bios.c` directly enters the AH dispatch. The reporter's own later environment gate cannot suppress argument calculation. `c_sas_w_at` can translate paged addresses and, if absent, reaches original BIOS virtualisation or a no-selector early return; protected-mode `effective_addr` may read descriptors. These sources show extra work/reentry possibilities, not by themselves an observed actual page fault.

Source-linked comparison: independently built original and current full translation units with the selected worker compile flags plus `/Gy`; original object SHA-256 `782F47771E5E44B4FEE489A427A166F602B62E592807C19DEC1E23CF2AC81F95`, current object `E7F6AF1D4C6A4F2441EE293A4851DF4317CAF2769775B8042E086402C5CE2C5F`. Test harness `keyboard-trace-seam-probe.c` SHA-256 `8E698ECA9DE58B7B34CDB88A7A9BF4990FA530FF97542DDA503D6645D286BCB3` uses `AH=1` original idle-poll dispatch; substitutes CPU register getters, `effective_addr`, `c_sas_w_at`, trace reporter and `idetect` with explicit counters. Both executables use the existing full worker CPU fixture link graph and inherited `/force:multiple`; maps attribute `keyboard_io` to the intended original/current object and these observer seams to `keyboard-seam.obj`. The reporter stub records invocation but never logs; C evaluation means this does not disguise the extra reads.

Results:
- Original normal: reads=0, translations=0, trace calls=0, dispatch=1; original with injected fault-on-read: same, because no read occurs.
- Current normal: reads=4, translations=1, trace calls=3, dispatch=1.
- Current injected fault on the first mocked read: reads=1, translations=1, trace calls=0, dispatch=0, caught by test-only longjmp.

These reproduce the extra call/ordering difference with actual source bodies and explicitly model a failing read; they do not prove that actual SAS/guest state produces that error or identify an actual exception vector, and no production or guest was modified. Follow-up should use real CCPU/SAS fixture state with invalid/unmapped page or side-effectful physical mapping, confirm any fault/reentry and compare an off/on trace-safe candidate before changing semantics. The trace output itself may rely on stack evidence; a simple gate protects default-off path but does not prove enabled tracing inert. DIV-059 vector-table address conversion is independent; T420 real DOS/EDIT and 8042 fixture evidence must not be conflated with all keyboard BOP dispatch/error paths.
