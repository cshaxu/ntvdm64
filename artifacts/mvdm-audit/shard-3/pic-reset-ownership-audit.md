# PIC ICW1/EOI ownership audit

Pinned original `softpc.new/base/system/ica.c` ICW1 path clears IRR, ISR, count, mask and state without notifying device EOI hooks. Current SHA-256 `A2C983FEEDAF8E121D0F47A1EC12C019EB826F3B8AC75655C882D6B4B1C429EA` has the registered DIV-460 host-specific addition: under `NTVDM`, it takes the existing ICA lock, snapshots IRR|ISR, performs original reset, then calls `host_EOI_hook(irq,-1)` once per snapshot bit before unlocking. A new request produced by a callback after the snapshot is not among the retired requests. The original PIC remains owner of its masks/queue; each timer/RTC/mouse/keyboard hook owns its own state, and callback -1 is cancellation rather than a synthetic normal EOI. Two PIC controllers retain their own reset ownership.

It covers pending/in-service, empty/repeated reset, master/slave, callback requeue, automatic EOI, timer, real RTC/mouse cancellation; some IRR/ISR states are directly seeded by the fixture and do not prove all hardware races. The related 46-assertion keyboard/PIC test is separate; T460 retains an actual DOS IRQ0 reset and no-reset control, not freshly repeated here. Neither evidence proves all concurrent device callbacks, physical device behavior, an untested guest/profile or equivalent timing. Input graph and map link prove no complete system lifecycle by themselves.
