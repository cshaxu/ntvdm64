# COMMAND BOP guest ABI and host continuation — shard 3

Scope is pending `inc/CMDSVC.INC`. `cmdsvc-abi-observer.py` and its captured JSON compare six source files to both original trees, compare decimal service constants, and preserve a worker linker-map excerpt. All 17 service values plus the `SVC_CMDLASTSVC` boundary match between assembler and C source; this is a source declaration check, not an executed ABI test. CMDSVC.INC, cmdsvc.h, guest tcode.asm and cmddisp.c match both references byte-for-byte; current cmdmisc.c and nt_bop.c differ. No source mutation, guest build or runtime test was performed.

The original guest `dos/v86/cmd/command/tcode.asm:557` uses `CMDSVC SVC_CMDGETNEXTCMD` with DS:DX pointing at its command record; the source macro in CMDSVC.INC emits BOP_CMD and the service byte. `softpc.new/host/src/nt_bop.c:388-398` reads the service byte, invokes original `CmdDispatch` and advances guest IP. `dos/command/cmddisp.c:15-34,44-58` selects `cmdGetNextCmd`, `cmdExitVDM`, `cmdReturnExitCode` and other service handlers. The map snapshot records these handlers and dispatcher in the expected command/host-root objects; it is not independently bound here to the latest deployed image.

For DOS, `cmdGetNextCmd` copies the guest CMDINFO through a bounded guest-memory lease, extracts the previous ReturnCode, initializes first-command/session handling, and uses `GetNextVDMCommand`; it later copies results back, sets CF on invalid guest address and clears CF on success (`cmdmisc.c:38-128,264,450-472`). WOW takes a distinct `GetWowKernelCmdLine` branch before this path. The original C and ASM CMDINFO fields are visibly paired but exact structure packing, allocated storage and all failure paths were not dynamically checked here. The guest remains responsible for its own source-level buffer growth after carry (`tcode.asm:557-570`).

The changed host continuation carries registered DIV-009, 108, 111, 160, 192, 194, 324 and 331 adaptations, including guest pointer lifetime and separate WOW boot handling; see `src/mvdm/dos/command/cmdmisc.c` markers and existing T473 S2 reconciliation. Matching service constants must not be mistaken for source identity across these implementation and lifecycle boundaries. As in original XMS dispatcher, COMMAND's range check is conditional on DBG; whether any valid or faulty guest can actually reach an invalid service, active flags and desired failure semantics require independent verification, not a presumed runtime defect.

Proposed disposition: **pending** for CMDSVC.INC. Exact source identity, source-level service values and map ownership establish a narrow static connection; guest executable provenance, program execution/completion and cross-worker failure/teardown semantics remain separate evidence obligations. No complete behavioral coverage or restoration percentage is claimed.
