# DOS and WOW UART routing audit

Scope is shard-3 `softpc.new/base/comms/com.c` and `softpc.new/host/src/nt_wcom.c`; frozen reconciliation records both as byte-identical OpenNT. This is a source and historical-evidence review, not a new serial test.

`nt_reset.c` selects `VDMForWOW`, then `com_init` registers COM port inputs/outputs with `io_define_inb/outb`: DOS uses `com_inb/outb`, WOW uses `wow_com_inb/outb`. `com_init` locks and temporarily disables host opens, installs handlers, resets original host and controller state, re-enables opens and unlocks; `com_post` writes COM address/timeout into the guest BIOS data area. `com_close` deactivates its configuration while holding host lock. DOS controller owns emulated registers, interrupt selection and controller loopback; `nt_com.c` owns real host port open, I/O, locking and close. `ntvdm.exe.map` names `com.obj`, `nt_wcom.obj`, and `nt_com.obj` with the relevant symbols, proving selection/linkage, not real I/O.

WOW adds a distinct port bridge rather than reusing all DOS register behavior. `nt_bop.c` loads WOW32 and resolves both `GetCommHandle` and `GetCommShadowMSR`; a missing export invokes `TerminateVDM`. If `GetCommHandle` is null, `wow_com_inb/outb` delegate to DOS `com_inb/outb`; otherwise they obtain the OpenComm-owned handle from WOW32, synchronize line settings, use shadow modem status, and handle certain invalid accesses according to original code. WOW32 `wucomm.c:2224-2258` returns NULL for an unopened/invalid port and obtains modem state from the WOW port object or host. In PROD, original diagnostics for invalid access are omitted; no success behavior is assumed for this case. The source does not by itself prove ordering under concurrent initialization, export failure, port close/reopen or all WOW guest callers.

Historical T420 S29 guest exercised INT 14h initialize/status with absent COM and original Ignore recovery, not transfer. S30 guest exercised COM3 hardware open and UART-local 5A loopback; host CTS was false, external send took original timeout. The source-linked `nt_com_mock_fixture.c` tests open/write/read/close against simulated Win32 medium; it is not a real peer. Neither establishes WOW `OpenComm` bridge behavior, CTS-capable external transmit/receive, pending IO close, hot unplug, or a current isolated-package run. Historical T420 documents are evidence at their own package identity, not current product proof. No production defect or complete external COM support is claimed.

Finite next verification: source-linked WOW bridge seam for absent and present exports/handles and line/status error branches, then independently a real Win16 OpenComm/close probe with a permitted CTS-capable peer; correlate device receive/send and retirement, never present local loopback or mocked medium as external transfer. Probe package identity and ownership should be pinned; no existing guest is modified. Both files remain pending pending those semantic and lifecycle witnesses.
