# External NT4 display, keyboard and font provider boundaries

This is a bounded architecture review, not an external-ledger bulk classification. The frozen external inventory contains 604 `windows/core/ntgdi/displays`, 300 `windows/core/ntgdi/fonts`, 370 `windows/core/ntuser/kbd` OpenNT rows plus 1,274 corresponding `nt/private/ntos/w32/...` OpenNT-4.5 rows. Do not exclude all 2,548 from path names. The companion CSV identifies five individually inspected OpenNT examples with frozen IDs and actual upstream SHA-256; matching editions, every source file, generated inputs and all resource assets were not independently proven. Exact upstream source read only; no binaries imported or guest run.

Original `ntgdi/displays/vga/sources` declares `TARGETTYPE=GDI_DRIVER`, a host video driver, not Win16 VGA emulation. The selected standalone CPU40 owns its guest VGA state and original C-VID logic; NTCON/window render host surfaces through Windows APIs. Original WOW `wgdi.c` translates 16-bit arguments/handles and calls public `BitBlt`/`CreateDC`; modern GDI/USER and the actual display driver own real host DCs and physical graphics. Therefore the specifically inspected NT4 VGA driver *build recipe/provider role* need not be imported as this product's host driver under non-invasive modern-Windows GOAL. The original VGA emulation, 16-bit GDI conversion, geometry, rendering behavior and custom NTW16S boundary are separate; the provider conclusion cannot be turned into a graphics pass. Shared `displays/inc` headers, test utilities or helpers may have non-driver consumers and stay unclassified pending per-file call and ABI review.

Original `ntuser/kbd/tmp/kbdus/sources` declares a `kbdus` `DYNLINK` from `kbdus.c`, resource and generated headers; `all_kbds/sources` is a pass-zero generator list and `kbdus.txt` provides US scan/VK/shift layout data. The inspected provider recipe is host layout construction; selected WOW `wkbman.c` retains guest marshaling while calling host `VkKeyScan` and `MapVirtualKey`. Modern Windows owns the real host keyboard layout. DOS keyboard scan/BIOS and guest code-page/layout behavior have separate original owners (`cmdkeyb.c`, guest KEYBOARD.SYS/DRV and keyboard controller). Replacing original keyboard provider is not proof that all Win16 or DOS mappings, dead keys, AltGr and layout-switch lifecycle are correct. The text layout source remains a candidate for behavioral comparison, not silently excluded. The 301 tmp rows include heterogeneous generated files and recipes, requiring per-file distinction.

Original `ntgdi/fonts/trmn/sources` builds `tmsre32` as a FON resource DLL. That specific NT4 system font package recipe is not the selected guest font conversion provider: original WOW `wgfont.c` uses host font APIs and tracking, and `wgdi31.c` calls `GetGlyphOutlineWow` through a public-resource adapter with the T456 recorded rotation compatibility seam. The modern host owns actual font resources; guest font handles, ownership and conversions remain original WOW/adapter responsibilities. **Do not bulk-exclude font data**: a historical FON/FNT/TTF may be an explicit compatibility input, and exact package/loader identity has not been traced for each. `Generate-FrontendFont.ps1` uses pinned V7VGA ROM bitmap offsets 0x2230/0x3990; this is an admitted embedded data slice and is not evidence that all `ntgdi/fonts` files are unused or replaceable. The inspected `8514sys.fon` remains pending hash/provenance comparison.

Actual current graph has no exact external display/font/kbd recipe paths in the NTVDM/WOW32/VDMREDIR Ninja closures for these inspected examples; configuration-time generation and explicit resources must be checked separately before excluding any other file. The three named provider recipes have a defensible **provider-role-only** exclusion in current non-invasive product; their original client-facing semantics remain open unless independently evidenced. Source-policy and immutable guest restrictions forbid treating opaque historical driver binaries as new default runtime providers. No combined/external ledger row was reclassified. For broader closure, (1) enumerate each selected public/client dependency before classifying headers and per-file role, (2) compare identity of any FON/FNT assets with explicit package and loader, (3) separately audit keyboard conversion and lifecycle, (4) validate guest GDI/font rendering and callbacks under current PE identity. No product, guest or other shard modified.
