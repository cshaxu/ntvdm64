# FDC session integration: reusable fixtures and test matrix

This is a test plan grounded in source, not a new runtime result. No real media, guest, or product file is modified.

`tests/adapter-mvdm-host-out/thread_start_session_fixture.c` initializes and binds a real test-owned session and calls the real `opennt_create_void_cdecl_parameter_thread`, matching the source signature of `fdc_thread`; it checks owner binding, bind rejection and terminal unbinding. It currently runs its own callback, not FDC. `tests/adapter-mvdm-host-out/basesrv/t394_s4_command_scalar_state_fixture.c` uses a real active session, in-memory guest callbacks, and the real scalar-state API, including failure after memory teardown; it has neither FDC nor native I/O. `disk-close-failure-probe.c` links actual disk provider objects and controlled closable event handles but overrides the scalar update itself, so it cannot prove real session-backed accounting. Their setups and independently validated seams are reusable; simply running these three tests together does not establish the missing integration.

Construct one bounded host fixture around the actual selected `nt_rflop` object and the real session, guest-location and command-scalar providers. Use initialized test-owned floppy state, in-memory guest backing and the historical FDC command/result structures; interpose only native open/media/close and device/DMA edges so every handle is owned by the fixture and no physical path is opened. The thread seam must invoke the real void-cdecl-parameter binding adapter, with event gates allowing deterministic observation; verify object/map ownership and ABI. Check the actual build's provider selection rather than compiling a copied FDC implementation. Start the FDC under the same creator session that registered the scalar; use joinable test thread ownership before session teardown. Release events and join in every test cleanup. Do not implement a product timeout or prescribe global termination merely for the test.

Suggested finite matrix:

1. **Pre-fix negative:** real source thread creation plus a fake successful new native open; observe current session absent, scalar update fails, fake handle is closed, count and ownership roll back, and thread remains waiting until its controlled reset. This is still a controlled fixture, not a guest or physical-drive reproduction.
2. **Session-aware success:** fresh open after fake media arrival, real bound session and scalar `+1`; verify media check, close `-1`, subsequent read/write result, one completion IRQ and terminal unbind. Observe all owned handles and source counters; no DMA to arbitrary guest memory.
3. **Cached handle:** enter with a valid fixture-owned cached handle; cover matching and changed PDB/lock, and check close accounting separately from first-open rollback.
4. **Failures:** fake open failure, controlled bind rejection, memory read/write/commit failure at the scalar boundary, close failure and thread-start failure; assert native handle state, guest count, owner/lock, open count, outward failure, and absence of a false completion. Do not assume every hook failure leaves a particular LastError.
5. **Reset and retirement:** event-gate the no-media thread, reset while waiting, immediately attempt a new command, and verify old thread cannot touch reused parameters or guest state; cover session shutdown and repeated reset. Define the actual ownership/join contract before asserting it; `CloseHandle` alone does not wait for thread exit.
6. **FDC result contract:** controlled short reads and writes must produce FDC status bits, with explicit write-protect versus other write error; do not apply DEM's AX/CF assertions to FDC. A separate synchronous DEM test covers zero-byte return, mapping and CF on its bound calling thread.

The finite product-repair boundary is correct owner binding with the appropriate calling convention, safe lifetime/parameter retirement for that existing FDC worker, and consistent handle/counter rollback when guest state operations fail. Select the smallest implementation only after this test reveals which underlying existing lifecycle facilities are usable. Do not assume wrapper injection alone solves the lifetime race. Existing fixture failures are fault injections, not proof that a real guest reaches those conditions.
