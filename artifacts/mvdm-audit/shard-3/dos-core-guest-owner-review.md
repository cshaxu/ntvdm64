# DOS core and device guest build source candidates — shard 3

`dos-core-guest-owner-review.csv` contains 29 candidate paths with frozen/current source SHA and concrete original non-comment make object dependencies, direct includes where applicable, link-response membership and guest target/link16 edge. The original `dos/v86/make.inc` supplies MASM/CL16 suffix rules; BIOS `makefile` links NTIO.EXE and relocates it to NTIO.SYS, DOS kernel `makefile` links NTDOS.EXE then relocates/strips to NTDOS.SYS, ANSI and keyboard makefiles construct their device binaries. Shared `psdata.inc` also has a concrete original COMMAND link path; shared includes can have additional consumers and this single edge is not a complete consumer inventory. Keyboard layout object selection and guest target depend on original profile/build options; no layout coverage is inferred.

Each is a `historical-guest-build-source-file-only` candidate: the recorded chain proves a role in a historical 16-bit target build, not the distributed binary's provenance, code reachability or functional success. Other 40 examined pending paths—including existing HIMEM.SYS/KEYBOARD.SYS immutable runtime assets, additional keyboard variants, source/headers without a proven linked consumer, and resource metadata—remain pending. Matching target names or filename references alone were not accepted. Existing guest binaries must not be rebuilt or modified; no guest/product/combined ledger changes or tests occurred. The companion source lines may include original comments after real INCLUDE directives; those comments are not treated as evidence of execution.

## Actual link-response correction

The initial CSV incorrectly cited `msbio.lnk` for several NTIO candidates. The BIOS makefile actually calls `link16 @msbio_4.lnk`; its use of `spcmse_4` differs from the older response and the two cannot be interchanged. All seven BIOS-linked candidates were independently checked against the actual `msbio_4.lnk`, and the exact corrected line is now in each CSV row. All remaining rows were also checked against the literal `@response` on their actual recorded makefile `link16` line (`msdos.lnk`, `ansi.lnk`, `keyboard.lnk`, or `command.lnk`); every recorded object is present. No candidate was removed; count remains 29. This confirms historical link membership only, not runtime image identity or guest function.
