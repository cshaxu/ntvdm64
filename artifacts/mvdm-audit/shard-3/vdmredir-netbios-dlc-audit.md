# VDMREDIR NetBIOS, DLC buffers and DLL lifetime

Scope: shard-3 `vdmredir/vrnetb.c`, `vrdlcbuf.c`, `vrdll.c`; frozen rows record exact OpenNT bytes. Static review and historical evidence only; no new run, guest or product change.

Current worker Ninja `VDMREDIR.dll` input closure explicitly compiles and links all three original objects; its link rule enters `mvdm_vdmredir_dll_entry@12`, whose adapter forwards to `VrDllInitialize`. Process attach runs `VrInitialize`; detach runs `VrUninitialize` then `TerminateDlcEmulation`, which closes original DLC adapters. `vrdll.c` does not initialize its local return value on thread attach/detach; Windows thread notification return is not a normal process-attach admission result, but the observable adapter return and notification/teardown ordering remain untested. Do not equate linked source with all lifecycle paths.

`vrdisp.c` dispatch 0x25 routes `VrNetbios5c`: convert guest ES:BX NCB, copy to host heap, submit `Netbios`, copy/free synchronously or transfer asynchronous NCB ownership to `Netbios32Post`. A guest post routine makes completion queue under `PostCrit`, then `VrQueueCompletionHandler`/network interrupt hands control back; absent guest post copies results and frees directly. Race with guest teardown, immediate async submission error, outstanding callback and protected-mode callback deserve independent handling proof; no source-only claim of a failure is made.

`vrdlcbuf.c` initializes a critical-section-protected per-adapter/SAP DOS buffer pool, used by `vrdlc5c.c` create/delete/receive routes. Its original segment-increment/offset-preservation choice matters to existing DOS clients. Actual allocation, frame copying, cancellation and reclamation cannot be inferred from the DLL load or error path alone. Historical T420 S20 on a named package observed DOS NetBIOS NCBENUM and real async NCBADDNAME guest post/IRET followed by MEM/exit. Its attempted cancellation returned NRC_CANCEL because completion had already occurred, so it did not prove cancellation of a genuinely pending request. The same historical DLC probe reached original dispatch but returned 07 when required host DLC provider was unavailable; it did **not** exercise a successful DLC buffer pool/frame. Modern provider availability must be rechecked before any runtime claim; no unauthorized provider should be substituted.

Follow-up: source-linked deterministic async NetBIOS seam for immediate failure, real pending cancellation, callback with/without guest post and teardown synchronization, followed by pinned isolated real guest where a real LANA is available; and source-linked DLC buffer create/get/copy/free/retire tests independent of a fabricated external provider. A real DLC success claim additionally requires a supported actual DLC stack, not a test buffer fake. All rows remain pending; historical guest evidence stays tied to its package identity.
