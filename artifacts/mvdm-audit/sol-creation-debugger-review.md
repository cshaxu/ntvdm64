# Bounded SOL creation-error debugger observations

These are diagnostics on the retained production candidate, not a repair,
ordinary completion acceptance or evidence that the earlier failures are fixed.
The [input/outcome manifest](sol-creation-debugger/observations.json) binds the
observer sources, actual reports, process owner records and candidate identity.
All three full diagnostic invocations ended nonzero and are retained as such.

The established private-desktop SOL probe discovers the actual Options command
and preserves the original guest and on-disk ten-image candidate. A derived
CaptureFault observer uses the existing DebugActiveProcess/event loop on the
owned worker. Hardware execution observations affect only SOL's native window
thread; no target instruction bytes, API arguments or return values are
rewritten. It restores the prior debug registers before detaching. This is
bounded debugger attribution, not Computer Use or foreground automation.

## Observations

1. An observation at the public SetLastError entry captured 5023 on its 71st
   visit, with a return address in the worker's project-window-graph commit.
   The source deliberately presets ERROR_INVALID_STATE before fallible helpers.
   This was a sentinel write, not proof that a helper failed. Stopping there
   was therefore not a causal failure witness; owned close later did not
   complete and the runner failed.
2. Continuing through the observation interval recorded 25,887 public entry
   visits and 1,270 writes of 5023 from five distinct return sites. The modal
   dialog did not complete under that debugger observation and the runner
   failed. These error writes include pre-set/restored error values; their
   mere presence does not establish an erroneous API result. This heavily
   observed run is not equivalent to an ordinary candidate failure.
3. The exact DLL map and bounded disassembly locate four **failure-only**
   GetLastError-return sites in project `claim_explicit`: enrollment,
   encoding/facts, client-state initialization and final borrow acquisition.
   Four local hardware execution observations at those hash-bound sites
   incurred no normal SetLastError-entry stops. All sites were verified in
   the staged process before arming. None was hit. Options modal creation,
   close and parent recovery passed, but launcher completion after owned close
   did not; the entire invocation remains non-pass.

The project disassembly and source, rather than a guessed NT4/native USER
layout, define these addresses and the bounded project creation-scope fields.
The diagnostic refuses an already enabled native debug-register owner.
Observed source/ASLR addresses are tied to the retained exact map and package;
they are not portable product hooks or a new runtime interface.

The existing T463 attribution design already distinguishes debugger capture
from ordinary host-message delivery. The mixed modal/retirement observations
here reinforce that limitation; they cannot establish a new ordinary exit
regression, exonerate all four creation stages, or qualify a release.
Earlier ordinary bindingError=5023 failures remain unexplained. No guard is
removed and no production correction is selected from these observations.

After joining the three diagnostic supervisors and the earlier native-CBT
supervisor, the single repository cleanup tool previewed and removed their
four exact temporary output trees: 33 generated files, 1,106,736 bytes.
The used ownership manifest, preview and result are retained in the input
manifest above. The pre-deletion CIM scan failed, and its empty pipeline
result was incorrectly recorded as absence; that claim is expressly
superseded by the retained cleanup correction. An actual desktop-capable
post-deletion CIM scan succeeded with no matching executable and all four
paths absent. This later observation is not backdated as pre-deletion proof.
Quiescence before deletion was established by joined terminal job handles;
the cleanup owner separately checked exact target membership, hashes and
path/link/Git safety. No cache, candidate or accepted package was removed.
