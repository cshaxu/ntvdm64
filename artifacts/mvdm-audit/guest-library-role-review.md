This S10 checkpoint compares against `12f877ef7`. It accepts
[28 exact-path roles](guest-library-role-dispositions.csv): 27 retained
OMF import/static archives and APPEND's MASM macro source `sysmac.lib`.

Excluded means the retained historical guest build input is not a current
host implementation input, not that its guest capability is discarded.

## Evidence and main review

Every disposition retains primary-original, frozen and current byte identity,
a specific original production or consumption edge, and recorded absence
from the selected host input/dependency observations. The
[observations](guest-library-role-observations.json) bind the three prior
shard tables, 17 original recipe/response inputs and independent
[32-file format observations](guest-library-format-observations.csv).
The recipe response under RASAPI16 is an identity-verified admitted
supplemental historical file; the actual primary makefile also explicitly
emits its library path before invoking link16. This is not supplemental
native-runtime admission.

The main review distinguishes `mciole/olecli.lib` from `lib/olecli.lib`:
the former is consumed locally by MCIOLE16; the latter occurs in WRITE's
real link response. OLE client's debug/retail generated outputs do not
prove either checked-in archive's derivation. Likewise the native COFF
`softpc.new/base/system/obj/i386/system.lib` is outside this cohort; its
basename cannot supply evidence for `wow16/lib/system.lib`.

LIBH's actual consumer expands COMMDLG's `WINLIB=..\\lib` and default `.lib`
suffix. XMM's local and parent archives have explicit lib16/copy roles;
the debug and retail OLESVR import libraries have separate conditional
implib output paths. LIBW combines guest import libraries, and HELLO's
SLIBCEW input is an original independent guest test rather than a claim
about the current production guest. These are original input roles, not
proof that the frozen binaries were generated by the retained sources.

Source-to-member derivation, dictionary/trailer semantics, historical link
success, installed guest image lineage and guest behavior remain unproved
by archive inspection. No code-restoration percentage is inferred from
binary size or number of members. The unchanged APIs' actual host/guest
providers remain separately audited under the T-wide worklist.
