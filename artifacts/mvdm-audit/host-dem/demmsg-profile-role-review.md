# DEM debug-message C/H: supported release boundary

`demmsg.c` and `demmsg.h` retain byte-identical OpenNT sources; their hashes are in `pending-dem-source-evidence.json`. `demmsg.h` defines the message IDs used by calls in directory, file, FCB, handle and drive handlers. `dem.h` declares `demPrintMsg` only under `#if DBG` and otherwise expands it to an empty macro. In the original DBG branch `demmsg.c` defines the message strings and `demPrintMsg`, which formats and emits through `OutputDebugStringOem` only when `fShowSVCMsg` is nonzero; `dem.c` sets that flag on its original `-d` option path. These are debug diagnostics, not a replacement for the ordinary error-return and lifecycle paths.

The repository `CMakePresets.json` offers the four MSVC **release** presets; `tools/build/New-T310OriginalSoftpcNinja.ps1` constructs the worker flags with `/DPROD` and no `/DDBG` option or debug-profile parameter. The current cached `build/.ninja/msvc-x86-release/worker/build.ninja` selects `demmsg.c` into `obj/dem/demmsg.obj`; its effective flags contain `/DPROD` and no `/DDBG`. Inspecting that actual selected x86 COFF object with i686 `objdump -t` showed only directive/debug/checksum metadata and no `_demPrintMsg` function or message array. Object SHA-256: `870CCB698029573AB6737A31EE56D813A7B2FF80960F3D1A6D208F6E41CC1B2B`; generator SHA-256: `7884E96510B3A1C05222140AADABC84DC24997A5B48E209FD344C62E1E5F148C`. The existing dependency census `shard-3/header-inclusions.csv` reports 11 selected object dependencies on `demmsg.h`: include dependency alone does not prove active debug code.

This establishes the original non-DBG branch for the inspected release object, not a current-package hash binding or all possible externally supplied build flags. It does not show that a supported debug profile exists, nor rule out a separate profile or dynamic diagnostic path beyond the examined generator and presets. No DBG-enabled product object was built or exercised. A debug-capability requirement or explicit approved release-only scope is needed to make a final file-level disposition. Until that scope is resolved, keep both rows pending rather than claiming full debug restoration or excluding their functionality merely because it is disabled in this release.
