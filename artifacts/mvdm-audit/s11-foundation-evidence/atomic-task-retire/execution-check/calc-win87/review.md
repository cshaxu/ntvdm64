In an isolated copy of atomic-execution-retire-package, its Calculator window appeared, About Calculator opened and closed, the parent recovered, and the launcher exited normally. The candidate WIN87EM.DLL hash was 30D6B965D45EDDF306268C9526B01494DF4841B8B530BAB2654C379E1CF49DB2. No guest was changed or rebuilt.

The initial probe falsely selected WOWExec and its About dialog; invalid-first-probe.txt is a non-pass. The probe was corrected to require the Calculator title and the independent rerun produced probe.txt and result.txt. This is indirect evidence of ordinary import startup, not an observed module-load identity, numerical or FPU test, or the special pre-Windows-3.0 loader branch. It is not the Full suite.

After adding the Calculator-specific title filter, the existing Notepad mode was rerun on the same candidate: Find opened, closed, parent recovered, and launcher completed (`notepad-regression.txt`). Exact final test script SHA-256: 0A9A55DF327EA707AB0CAD2E22A5887D5B50DAB3E3BD3A6AC786045B83884228; C probe SHA-256: 7FBD226AC7F202BAF75BECFDA5C8ECB634F426CC707BCEB54C5BD059955431CB. This is a single normal-path regression, not an exhaustive probe self-test.

A subsequent exploratory probe recorded Calculator's visible child controls (`control-census.txt`) and another About/exit pass. The main numeric display is a Static control; digit buttons are not exposed as named child controls in this census, so the result is not a numerical operation or FPU assertion. The diagnostic enumeration was removed from the reusable probe; no guest or runtime change was made.

Two exploratory arithmetic probes sent WM_CHAR for `1/2=` to the Calculator main window and tried to read the first `Static` child: both obtained an empty string and failed the expected `0.5` assertion. They terminated the owned test runtime during cleanup. Neither probe established that the selected Static was the numeric display, that WM_CHAR reaches the intended input path, or that its return content was valid; therefore these are test non-passes, not an established Calculator/FPU failure or numerical success. The experimental assertion was removed from the reusable probe. Further validation needs an independently verified input and display identity, while preserving the unmodified guest.

A third diagnostic selected a Static child by its initial visible `0.` text and read `0.` after synchronous WM_CHAR messages `1/2=`. This eliminates the earlier empty-first-Static observation but still does not prove the program processed the input; direct window messages bypass normal queue/accelerator handling. The test remained a non-pass, and its experimental code was removed. No calculator numerical or FPU conclusion is drawn.
