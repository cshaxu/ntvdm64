# GFI alternative providers: retained disk capability and finite validation

The three pending `softpc.new/base/disks/gfi_ibm.c`, `gfi_sflp.c`, and `gfi_test.c` compile to objects in the inspected PROD graph, but their useful bodies are guarded by SLAVEPC or non-PROD, as documented with object hashes in `host-ch-scope/gfi-alternative-provider-review.md`. This is not a claim that an alternate configuration is supported or that floppy behavior can be excluded. The SLAVEPC files implement a serial RPC route to a physically separate IBM PC/8272 controller; `gfi_test.c` is a diagnostic pseudo-provider whose synthetic success cannot prove a floppy works.

## Actual selected provider ownership

Original BIOS `diskette_io` and `diskette_int` select the original floppy function table; original `floppy.c`/`fla.c` construct controller commands, DMA buffers and interrupt/result phases. `gfi.c` owns the per-drive function table and selected host configuration; `gfi_mpty.c` supplies absent-drive responses. `nt_rflop.c::host_gfi_rdiskette_active` initializes or terminates the actual host real-floppy provider and substitutes the empty provider on deactivation. Host Windows owns native handles; the original controller owns command/IRQ semantics; the project adapter owns its bounded guest counter/owner leases. `disk-native-role-review.md` records selected-image vector binding and an actual-object GFI dispatch fixture; T420 S28's real guest evidence is an INT13 no-media reset, not attached-media read/write. `gfirflop.h` is an old declaration carrier without an observed exact selected dependency, not the sole authority for the active host provider.

## Concrete lifecycle candidate, not a confirmed customer defect

`shard-3/disk-close-failure-audit.md` records an actual-object failure-seam run for both `nt_rflop.obj` and `nt_fdisk.obj`: injected failure of the project guest FD-access counter decrement occurs after the real native handle closes, but the provider's open count remains one; floppy retains additional owner/lock state while fdisk clears its owner/lock. This seam run used `/force:multiple` and separate layout assertions as described in its report. It proves the exercised state under injected callback failure, not that an initialized real worker experiences the same lease failure or that a physical device is broken. Original raw-pointer counter behavior is not a safe substitute for a new fallible lease failure contract.

## Finite S12/S13 handoff and evidence gates

1. In an isolated host-object fixture, bind the real currently selected provider objects and their actual initialization/termination state. Repeat open/close with success, an injected counter-acquire failure, counter-release failure, native close failure, duplicate close and reopen. Count actual handle, owner/lock and open-count state exactly once. Test the original sequencing and resulting errors separately for floppy and fixed disk. Explicitly distinguish the test seam from a real guest counter and preserve the observed failure until corrected.
2. Bind the same cases to an isolated worker/guest session with test-owned media and the real guest state provider, if that failure is reachable without changing the immutable guest. Test task exit, worker shutdown, provider deactivation and stale/reused handles. Do not manufacture a failing lease as proof of a customer path or hide it behind timeout/polling.
3. The retained actual GFI and no-media tests establish only empty/dispatch/reset behavior. For real attached media, independently gate on an explicitly owned disposable disk image or device: read/write/verify, geometry, partial sector/error, media change/eject, FDC DMA and IRQ/EOI, provider deactivation and restart. If no suitable backend exists, record the acceptance gap instead of mutating a user disk or pretending no-media proves it.
4. For SLAVEPC, first decide whether the external serial device is in product scope and map the original command/frame/timeout and reset/close ownership. If admitted, retain that provider as a separate transport and use a controlled test-owned peer; if outside the approved product profile, record that specific backend exclusion without excluding normal disk operations. Diagnostic gfi_test is never substituted for either backend.

A possible cleanup fix is to separate irrevocable host-handle retirement from the fallible guest counter update and return the failure without claiming a full handoff; apply it only after matching failure semantics and lifecycle authority are established and any source mirror exception is registered. This is a design direction, not an implemented or accepted fix.
