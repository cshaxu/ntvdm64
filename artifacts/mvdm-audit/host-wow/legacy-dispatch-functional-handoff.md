# WOW legacy dispatch headers: function owners and finite verification

The pending historical headers `wktbl.h`, `wutbl.h`, `wgtbl.h`, `wkbtbl.h`, and `witbl.h` declare separate `aw32Kernel`, `aw32User`, `aw32GDI`, `aw32Keyboard`, and `aw32Internal` tables. Current WOW32 source search finds each of those names only in its declaration. Original `wow32/sources` leaves the old individual table C files under `!IF 0`; the selected original `wowtbl.c` instead includes per-family `*tbl2.h` entries in `aw32WOW`, separated and offset by `InitThunkTableOffsets`. This is a source/profile distinction, not an assertion that every API in each family is implemented. `m0-t422-s1-dispatch-definition-audit.md` records a source-definition closure census of 1,786 rows: 668 selected host bodies, 182 `LOCALAPI`, and 936 `UNIMPLEMENTEDAPI`; those historical selected-profile counts are not runtime pass counts.

| Historical header | Selected original family and example actual owner | Existing bounded evidence | Remaining finite verification |
| --- | --- | --- | --- |
| `wktbl.h` | `wktbl2.h` -> `WK32ExitKernel`; `LOCALALLOC`/`LOCALFREE` are `LOCALAPI` and guest/callback-owned, not old WK32Local bodies. | `m0-t420-s42-w1-w2-lifecycle-binding-ledger.md` records a specific historical route ending in `WK32ExitKernel`; separate task/worker owner rules are in T448. | Bind current guest ordinal and installed image; independently test allocation failure/reuse and task-only versus worker-wide exits. Do not treat an exit as proof WRITE or every KERNEL function works. |
| `wutbl.h` | `wutbl2.h` -> `WU32CreateWindow` / `WU32CreateWindowEx`; original USER callback and the current approved host service adapters retain separate ownership. | `m0-t447-s2-message-boundary-audit.md` documents a specific dispatch witness for `WU32CreateWindow`; other records explicitly distinguish cases which did not enter that thunk. | Current image/guest binding; creation failure, nested callbacks, destruction, handle reuse and control-specific owner behavior. A merely visible window is insufficient. |
| `wgtbl.h` | `wgtbl2.h` -> `WG32CreateDIBitmap` and other original GDI thunks; native GDI owns host objects, original conversion owns guest mapping. | `m0-t422-s2-user-client-lifecycle-ledger.md` records repeated original `WG32CreateDIBitmap` dispatch on a historical traced candidate. | Repeat current matching-package guest DIB and palette success/failure; verify mapped buffer and GDI handle lifetime, reentry and destruction; do not generalize to printing. |
| `wkbtbl.h` | `wkbdtbl2.h` -> original `WKB32ToAscii`, `WKB32AnsiToOem`, `WKB32OemToAnsi`; its first entries explicitly distinguish `LOCALAPI` from unimplemented. | T422 definition audit proves selected-source bodies for selected table rows, not real per-thunk execution. DOS keyboard controller guest tests exercise a different layer. | Use an immutable Win16 guest to call the exact keyboard thunks with layout/code-page cases and controlled invalid parameters; validate original provider values, callback ownership, task switch and current image. |
| `witbl.h` | Separate old `aw32Internal` declaration has no literal current WOW32 consumer; the observed unified table has no corresponding internal family. | Source/graph observation only; cannot infer all internal services or alternative generated profiles. | Identify the original guest `SETTABLE`/internal owner and any legitimate call path; demonstrate whether the active profile reaches it before classifying the capability. |

For the first four, recommend excluding the **legacy separate declaration role only in the inspected unified-table profile**, after coordinator review, with each functional family retained in its owning implementation tasks. `witbl.h` remains pending until its original consumer/alternative is resolved. Do not physically delete the old headers solely from the captured graph or characterize any `UNIMPLEMENTEDAPI` entry as newly implemented.

`winspldl.h` is another pending old declaration set: source and selected dependency evidence in `cross-369/spool-header-disposition.md` point to original `wspool.c` plus its shared `spoolerapis` provider rather than those old function-pointer declarations. The historical HDC-print witness is separate from raw OpenJob; its missing-profile negative must not be mistaken for raw-print success. Retain current provider resolution, request/carrier identity, real optional printer availability, error/cancel and teardown as explicit S16/S17 obligations; no simulated provider success.

No new runtime or guest test was performed, and no shared ledger or guest was changed.
