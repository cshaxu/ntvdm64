# Shard 0 support-source ownership

The [20 accepted candidates](guest-support-owner-review.csv) have exact
current, frozen and primary-original source identity. The
[inspected inputs](guest-support-owner-inputs.json) identify original
makefiles, link response and local include sources. DDEML uses its explicit
OBJ1/OBJ2/ASMOBJ groups, CL16/MASM rules and 16-bit link response; REGEDIT
uses its COMMON/OBJ1 groups and REGEDT16/REGLOAD rules. SHERLOCK's actual
response selects DRWATSON objects before link16/RC16. Generated or ambiguous
source names are not guessed.

WIN87EM has an actual EMULATOR.ASM -> win87em.obj -> WIN87EM.DLL path,
but it is not the host SoftPC floating-point engine. The same source also
supplies distinct historical libraries. Each recorded literal include and
its internal conditions must remain distinguishable from default emitted
object code. No file membership implies that every conditional body enters
the Windows DLL; no DOS/OS2, MTHREAD, old-Windows or small-emulator profile
is activated by this audit. Historical input role does not prove original
source-to-installed-guest derivation, behavior or current image compatibility.

Only shard-0 pending support-family paths were proposed. No native DDEML
test, CTL3DV2 file lacking a closed consumer, binary, map or symbol is
classified merely from its directory or extension. The source selection
review modifies no product or guest and executes no guest build.
