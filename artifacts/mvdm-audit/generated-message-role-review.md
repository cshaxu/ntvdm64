## Message files are source, not ordinary logs or compiled objects

Original `dos/v86/make.inc:109-116` invokes the message generators.
`sysmsg.inc:387` expands `MSG_UTILNAME` into an actual control-file include;
`:429,463-466` routes a message-class argument through `$M_INC` to `INCLUDE`.
Thus a filename hidden behind a MASM macro must be traced, not declared
unused after a literal include scan.

APPEND, DEBUG, EXE2BIN, Graphics, KEYB, MEM and NLSFUNC have actual class
arguments and guest link targets. The COMMAND control file is consumed by
`tdata.asm:1060` and `tprintf.asm:80`; the DOS kernel's `MSDOS.CL3` is reached
through MSDOSME -> DOSMES -> YESNO. The DOS and SoftPC BIOS recipes separately
identify their direct message includes and real-mode generation steps.
These are source-role traces; none of those tools or guests was rebuilt.

For retained `COMMAND.CL3`/`.CL4`, `command.skl` declares classes 3/4 and
`buildmsg.c:406-430` constructs the class filenames and matching MASM
directive shape. That establishes the generated-table role. It does **not**
establish that the selected COMMAND objects consume these resident tables,
nor that the current file bytes were generated by a particular executable.
Their retained-artifact disposition makes neither claim.

Their hashes are absent as whole files from the current tested package and

The HPSCAN and MSCDEX objects have complete OMF framing; stored-zero and
inconsistent nonzero checksums are distinguished. Their original MASM,
LINK16 and guest-target chains remain separate from VDD runtime behavior.
The two PCH files have an observed `VCPCH0` prefix and explicit historical
host compiler configuration. This is a signature observation, not a full
PCH parser or a claim that a current compiler can use them. They are not
misclassified as guest-generated objects.

REGEDT16's temporary definition file is byte-identical to `regedit.def` and
has an actual `type` copy recipe. WRITE's `insert.tmp` has 17 literal DBCS

It is historical index text, not compilable C or proof of exact generation
