# DOSX HP Vectra BIOS mapping: original profile and ownership

`dpmi/dxhpbios.asm` is a 286 protected-to-real mapping for selected HP Vectra extended BIOS services; it owns a callback and guest selector/segment bookkeeping, not a generic mouse implementation. The historical makefile provides an object build rule, but `dosxi.lnk` does not list `dxhpbios.obj`. Both `dxboot.asm` variants install `HPxBIOS` at protected interrupt 6Fh only inside `ifndef WOW_x86` and `ifdef NOT_NTVDM_NOT`, and after the HP Vectra flag check. The 486 startup source has a commented-out corresponding assignment. These are precise source/recipe facts: the rule does not prove the shipped DOSX contains the object or that any alternate HP machine profile is irrelevant.

The owned `dxhpbios.asm`, `dxboot.asm`, and `486/dxboot.asm` should remain pending for actual variant applicability and prebuilt image provenance; no original guest feature is declared excluded based on one link response. No current hash-bound HP BIOS or callback execution witness was located in this review. A meaningful future applicable-profile witness must establish selected binary/profile, interrupt-vector installation, mapping/callback entry and return, guest memory lifetime, failure/teardown, not merely presence of a file. Whether the project promises HP Vectra hardware is an authority/profile question rather than an inferred defect. `dosx-hp-bios-observer.py` records current and both-original hashes for the sources, makefile and response; no guest, product, build or shared ledger was modified.
