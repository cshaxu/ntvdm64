# MMTASK NE entry and original search route

`mmtask-ne-observer.py` parses the NE header, string resource and name tables: the retained MMSYSTEM.DLL, which matches its ZIP member, has RT_STRING block 126, ID 2000 value `mmtask.tsk`; MMTASKCREATE is exported at ordinal 900. `mmtask-ne-entry-observer.py` translates ordinal 900 through the NE entry and segment tables to 4:0cce / file offset 19630. The separately retained mmsystem.map labels MMTASKCREATE at 4:0cce and BWINEXEC at 4:0d94. `mmtask-ne-code-observer.py` disassembles the image's 16-bit bytes: pushes 0x07d0, conditionally exits after the first far call, constructs parameters, calls a far address with offset 0x0d94, and distinguishes return values <=32 and >32 in the same shape as task.c. These facts substantially connect the retained image to the original implementation, but far call fixups, identity of the map's image and live execution are not established merely from the matching addresses.

Original `bwinexec.asm:200-213` calls LoadModule, returning the task handle on success. Original WOW kernel `ld.asm:1360-1389` applies known-DLL lookup then MyOpenFile; `ldopen.asm:91-105,247-344,1123-1230` describes non-boot default search as current directory, Windows directory, 16-bit system, system, Wx86 system, application directory, then DOS/Novell PATH; paths and special-known-DLL conditions matter. The real session's effective values, all file aliases and successful guest call remain unobserved. Missing from the ZIP alone cannot prove unavailability in every session. Guest and product untouched.

All three `mmtask-ne-*-observer.py` scripts only print JSON; corresponding `*-evidence.json` are captured snapshots. Re-run with `PYTHONDONTWRITEBYTECODE=1 python -B` and capture separately. The disassembly observer also needs `ndisasm` on PATH.
