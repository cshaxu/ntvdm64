# MMTASK executable search: bounded installed-context follow-up

`mvdm_softpc_firmware.c:11-34` projects initial WOW guest SYSTEMROOT using `common_system_root_a`; `src/common/system_root.c:16-40` derives the product root by removing system32 and executable name. `src/common/guest_environment.c:5-45` replaces SYSTEMROOT while explicitly retaining WIN16DIR. Original WOW kernel `ldboot.asm:1889-1910,3055-3140` prefers WIN16DIR when supplied, otherwise SYSTEMROOT, and constructs its 16-bit system directory by appending `\system`. The exact original lookup order and BWinExec to LoadModule chain are in `mmtask-ne-search-review.md`.

Read-only path search found `O:/w31/SYSTEM/MMTASK.TSK`, `O:/winnt/W3P/SYSTEM/MMTASK.TSK`, and other installed Win3.1/test copies. The first two hash to `3a7f024e2afa38dccc916bb60a0a507da2f1e344aacc68beadd7274946a3eb2a`, different from the retained OpenNT stub (`76d140...`). `O:/winnt/system/mmtask.tsk` and `O:/winnt/system32/mmtask.tsk` were absent at capture. These installations are not automatically part of the WOW process search order; their presence means a configured WIN16DIR, current/app directory, or PATH may supply a candidate, not that it is always loaded. No assertions about Win3.1 vs WOW stub compatibility follow from names.

A repository search for mmTaskCreate in tests/observation, tests/app and src/addon found no direct pre-existing test. A ZIP raw-name scan found only MMSYSTEM.DLL containing `mmtaskcreate`; ordinal imports do not require a name string, so this does not exclude consumers. We did not compile or modify guest. Feasible future non-interactive evidence is a preexisting, identity-frozen Win16 consumer that imports ordinal 900 and reports callback completion via an existing host observer, plus read-only capture of its effective WIN16DIR/system/current/PATH; compare task-creation result and callback with and without an already-authorized stub in an isolated image. No such ready-to-run consumer or capture was established here; no success/failure is claimed. Do not alter installed Win3.1 or copy guest files into production to force this test.
