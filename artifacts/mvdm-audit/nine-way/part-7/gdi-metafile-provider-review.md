Owned `wow16/gdi/{meta.c,metarec.c,metasup.c,gdi16.h,GDI.RES}` are retained original guest material. The original `gdi/makefile:83,122-124` builds/stamps GDI.EXE from sort, gdi, layer, muldiv, fontres and resource objects, and does not list the three metafile C files. This is the original recipe; current packaged NE source provenance and every alternate configuration remain unproven.

This distinction matters: the old C recording implementation is not sufficient proof of the active WOW path. Host-provider witness `tests/adapter-mvdm-host-out/wow/wow_metafile_host_fixture.c` explicitly exercises public native GDI operations only; it is not a Win16 guest/thunk or nested-callback test. The separate DDE fixture exercises selected metafile cleanup but does not close this functional family.
