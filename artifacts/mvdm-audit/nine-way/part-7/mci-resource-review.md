# Win16 MCI command-resource source and packaged NE

Owned `wow16/mmsystem/messages/usa/mci.rc` defines the original non-localizable CORE RCDATA command grammar; `messages/usa/mmtask.rc` includes the task's version resource. Original `mmsystem/makefile:115-122` copies the configured resource source and builds MMSYSTEM.RES, and `mmsystem.rc:193` includes mci.rc. The delivered MMSYSTEM NE, already established byte-identical to ZIP, has an RCDATA resource named CORE at file offset 76800, aligned size 1536. `mmsystem-ne-resource-observer.py` parses the NE resource table and prints JSON; its evidence records exact resource payload hash. Resource presence is not byte-equivalence to the textual source and does not prove that any guest invoked it.

Original `mciparse.c:232-368` lazily ensures CORE exists, optionally loads a type-specific `.mci` module, resolves and locks RCDATA, counts commands, allocates an index and registers the table. Failure to lock frees its resource; failures after locking release the lock and resource. `mciFreeCommandResource` at 423–499 refuses to free CORE or tables associated with existing device entries, then releases resource, index and external module. These source-level lifetime rules are distinct from native MCI provider behavior; the selected source-to-NE relation, external module failure paths, reentrant table usage and task exit remain untested. Existing native multimedia inventory checks host capability/error reporting, not Win16 grammar parsing or resource lifecycle.

Classification suggestion: the two owned `.rc` files and `MMSYSTEM.RES` are retained original guest resource-build inputs, packaged NE CORE presence is directly established; do not infer full command compatibility or cleanup from resource presence alone. No product or guest modification or runtime test.
