# Win16 LZEXPAND interface versus kernel ROM decompressor

Owned `wow16/inc/lzexpand.h` declares the public 16-bit DLL/optional LIB LZStart/LZDone, LZOpenFile, LZCopy, LZRead, LZSeek and LZClose contracts, including negative failure codes; `lzdos.h` is the explicitly obsolete LIB wrapper around that header. These are interfaces, not a provider implementation or proof of handle lifecycle.

The current manifest `assets/winnt-guest-manifest.json:508-519` supplies retained `src/mvdm/bin86/lzexpand.dll` as a 16-bit NE guest component; its SHA-256 `faf467ce496dd59655ccd91c26c8ea694551f54fa6bbf5f480f398fc54d12fdd` equals `WINNT/SYSTEM32/LZEXPAND.DLL` in ZIP. This is exact binary identity, not proof the APIs are reached or of the source lineage. A different `wow16/kernel31/lzexp.c` implements an internal LZDecode for compressed kernel segments under `#if ROM`, with ring allocation/free if no buffer was supplied. The historical makefile lists lzexp.obj but that does not establish its guarded code in a particular kernel, and it is not evidence of public LZEXPAND.DLL behavior.

`tests/component-integration/szdd_roundtrip_test.ps1` exercises the separate project SZDD writer against host expand.exe, including input lengths and failure preservation. It does not exercise guest LZEXPAND handles, seek/read behavior, compressed input errors, lifetime or exit cleanup. No current runtime or guest test performed. Classification: both owned headers are original guest interface/build declarations; retain separately pending actual guest consumer, public DLL behavior, malformed input and resource lifetime verification.
