# Original Win16 scheduler source versus selected WOW scheduling path

Owned `wow16/kernel31/schedule.asm` contains the historical cooperative queue scheduler: at 125 onward it consumes `TDB_Yield_to`, checks pending task events, observes LockTDB and in-DOS restrictions, and moves runnable entries; when none is dispatchable it invokes DOS/Win386 idle interrupts. This file's source algorithm is not evidence that the delivered WOW kernel uses it: original `kernel31/makefile:235-280` lists `tasking.obj` and `kthunks.obj`, but not schedule.obj. The packaged KRNL386.EXE manifest identifies a preserved ZIP baseline, not a build from this source, and its hash differs from the retained debug3/retail3 kernels; loaded-image disassembly and other build profiles remain pending.

Current original WOW32 thunk table (`wktbl2.h:46,49,193`) routes Yield, WaitEvent and DirectedYield through WK32 routines; `wkman.c:160-164,644-710,3087-3106` shows the adapter's creator-thread handshake, idle blocking, pfnOut yield and task-ID conversion. `tests/observation/verify-wow-output-composition.ps1:64-65` identifies pfnOut slots as xxxDirectedYield and xxxUserYield. Existing `wow_task_order_fixture.c` and `wow_user_task_lifecycle_fixture.c` exercise bounded adapter scheduling and lifetime; `verify-win16-message-probe.ps1:368-399` defines an actual guest native-extension yield witness, but this static audit did not run it or establish the current release result. No single fixture proves the entire original task queue, directed yield, task death or nested callback contract.

Suggested classification: retained historical scheduler guest source, not listed in the examined WOW kernel recipe; preserve as comparison material and independently audit the selected guest thunk + WOW32 + host scheduler provider semantics. No guest/product or shared ledger modification.
