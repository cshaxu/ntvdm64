# Win16 spool declarations and selected raw-spool provider

Owned `wow16/inc/{spool.h,printer.h,spl_wnt.h}` are distinct original guest interfaces: spool.h and printer.h declare legacy GDI spool job operations; spl_wnt.h defines Windows for Workgroups print-manager/network administration structures and is included by `wow16/wfwnet/locals.h`, with a makefile dependency at wfwnet/makefile:106. Do not treat that WFWNET metadata as the actual native raw-printer provider.

The raw GDI thunk table (`wow32/wgtbl2.h:302-305`) maps OpenJob, WriteSpool and CloseJob into original `wspool.c`, which loads WINSPOOL.DRV, resolves a legacy device name, opens the real host printer, starts a document and projects its host handle into a guest local allocation. Close ends document, closes printer and only then frees the carrier on success. Current captured WOW32 map contains all three corresponding `wspool.obj` symbols. `shard-1/wow-spool-carrier-review.md` provides release-byte binding for eleven mapped functions and a historical guest case without a matching legacy mapping; it does not establish a successful printed job or task-loss cleanup. `cross-369/spool-header-disposition.md` documents additional source-level failure boundaries.

Current wspool.c and the two original OpenNT editions have identical SHA-256 C76BEC31AE9020EA0173C20D42986F36E6888A315A5D27E91E5CBF2579CB2AD8. Existing audit already records unclosed OpenPrinter on visible StartDoc failure and partial WritePrinter return handling as candidates, not reproduced product regressions. These belong to inherited source unless and until a specific change is justified and exception recorded. Effective call reachability, failure injection and cleanup semantics remain pending. Classification: owned files are original guest spool/print-manager declarations, with source-level selected raw-spool chain established separately; no guest, product, or shared ledger changes.
