# Part 5: external source-envelope per-key evidence

The companion `external-envelope-owned.csv` records each of the 4,758 part-5 external keys **other than** the 15 separately treated in `multimedia-external-review.md`. Each row carries its frozen edition, exact path, original catalog role/reason, catalog Git blob, raw SHA-256 and size, file-type description, same-directory recipe/resource/INF/DEF filename leads with line text, exact captured x86 worker/WOW32 graph path hits, and ZIP basename observation. All 4,758 catalog blobs verify: 1,180 directly and 3,578 after CRLF-to-LF normalization. There are 736 rows with a same-directory literal build lead, and no exact original external path in the captured graphs or basename in the captured ZIP.

This inventory spans 3,693 host provider-envelope records, 1,055 device/provider context records and 10 separately catalogued format/client/recipe/image contexts; they must remain distinct. Basename/file-type or local recipe findings do not prove an actual selected host seam, indirect include, dynamically loaded driver, external system component, test usage, or semantics. ZIP basename absence does not exclude embedded resources, renamed files or OS-supplied services. **Each row remains relevance pending** rather than excluding or importing a directory. The 15 named multimedia dependencies are audited separately and must not be reduced to ordinary envelope rows. Runtime ownership, lifecycle and user-visible feature requirements remain open until tied to actual entry/call and behavior evidence.
