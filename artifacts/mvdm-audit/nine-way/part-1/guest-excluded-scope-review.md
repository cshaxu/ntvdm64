# Shard 1: scoped guest-input exclusions versus overall status

`combined-initial-status.csv` is the frozen initial aggregate. Its shard-1 `excluded` joins to 216 rows in `shard-1/file-audit.csv` whose exact `classification_basis` starts: “Historical immutable guest build source/resource only; excluded as current host implementation input, not as guest functionality.” These same rows leave source-to-distributed-image provenance and behavior separate. `guest-excluded-scope-observer.py` emits exact paths and original row evidence as JSON; `guest-excluded-scope-evidence.json` captures the result. Selection is a deterministic textual predicate, not a fresh complete review of all exclusions.

Examples are `dos/v86/cmd/command/{command1.asm,copypr2.asm,path1.asm,tfor.asm}`: the original guest COMMAND recipe references these sources, whereas checking host build inputs says only that immutable guest code is not host-compiled. Current COMMAND execution alone cannot attribute all packaged instructions to these sources. Other returned paths cover DOS drivers, redirector and Win16 MMSYSTEM/OLE resources and code; each has its own prior `evidence` and `next_required_evidence` copied in the JSON. Do not infer actual guest feature completion, defect, or irrelevance from the source-file identity.

If an aggregate `excluded` is interpreted as the entire source/functionality having no remaining applicability, recommend restoring these 216 to **pending overall**, retaining their narrowly proven historical-guest-input/not-current-host-compile role as a separate field. If the ledger explicitly guarantees `excluded` means only that specific host-input role and still tracks all guest capability elsewhere, its role status can remain without misrepresentation; coordinator owns schema and disposition. This recommendation is conditioned on the field's meaning, not a claim any one old guest file must be compiled now.

The audit did not mechanically reclassify 166 historical guest object/listings, 66 old architecture objects, 29 recipes or other excluded categories: some may be valid artifact-only exclusions. They require separate semantic/ledger check. This snapshot does not establish all other shards/rows or later live changes. No guest, product, shared ledger or runtime execution modified.
