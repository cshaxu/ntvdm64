# Part 1 handoff: evidence coverage is not semantic completion

`coverage-observer.py` compares the frozen nine-way ownership against independent per-key receipts: 120/120 assigned MVDM keys and 4,773/4,773 external keys appear once, with no missing, duplicate or out-of-scope keys (`coverage-evidence.json`). This proves evidence-index coverage only. Many external records have a hash, bounded dependency/owner lead and a pending status, not an individual function/behavior proof; none should be silently promoted to complete or blanket excluded by this count. The coordinator owns shared-ledger updates and cross-family adjudication.

Evidence-backed functional paths and limits:

* BDE is an original separate debugger extension whose commands call target memory/stack/symbol helpers; no current delivered BDE DLL or full debugger contract established (`bde-review.md`).
* DOS COMMAND, KB16, COUNTRY.SYS and several guest images have source/ZIP/exact-installed identity evidence; original compile recipes and input variants do not prove runtime behavior. KB layout-specific variants remain distinct, and GRAPHICS.PRO is delivered byte-identical while printer output is untested (`dos-keyboard-review.md`, `dos-graphics-review.md`, `dos-utilities-review.md`).
* Historical bin86 runtime/configuration files have per-key identities; installed AUTOEXEC/CONFIG and root SYSTEM.INI differences are configuration facts, not automatic defects; bin86 COUNTRY.SYS and WRITE.HLP differ from shipped variants (`bin86-review.md`).
* Project BASE client/server has actual selected candidate source edges with large bounded source diffs, not proof of all worker lifecycle semantics (`external-base-review.md`). RTL has three selected project candidate families from two distinct original editions, exact hashes/diffs recorded; their semantic/exception analysis remains pending (`external-rtl-review.md`).
* Current WOW wrappers invoke host GDI and printing. The original external display, raster and PostScript provider data remain per-key specific compatibility obligations; none is excluded merely by directory (`external-display-review.md`, `external-hprasdd-review.md`, `external-psprint-review.md`, `external-printer-other-review.md`, `external-gdi-engine-review.md`). Named PDF witness is not universal printer proof.
* External EGA.CPI is byte-identical to ZIP and installed guest data; source only attempts CPI load when registered and output codepage is not 437; map does not prove release execution. Other codepage/font semantics, actual locale and DBCS remain unverified (`external-font-review.md`, `external-nls-review.md`, `external-crt-review.md`).
* Fifteen external header keys have byte-identical project copies with VALID dependencies, and three basename-collision compile candidates are demonstrably different. Do not dismiss external source roles wholesale or infer lineage from names (`external-native-other-review.md`). Twenty priority loader/sound/I/O/CRT keys have specific provider chains but still require actual lifecycle semantics (`external-priority-review.md`).

Current tools are read-only probes; no guest, product, provider, build tree or shared ledger changed. Known independent cache defect fixtures and ROM failure candidate from prior shard-1 work remain separate evidence for coordinator reconciliation; this handoff does not claim they are repaired. Continue to part 4 according to the assigned plan.
