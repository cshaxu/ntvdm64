# DOS FCB wildcard deletion: source, witness and failure-path candidates

NTDOS `fcbio.asm` issues `SVC_DEMDELETEFCB`, DEM dispatch routes to `demDeleteFCB`, and original DEM enumerates with OEM FindFirst/FindNext, filters extended-FCB attributes, optionally clears read-only, deletes matching names, and closes the search. Guest DOS owns FCB arguments and result; DEM owns enumeration/attribute policy; OEMUNI converts OEM names; Windows owns file and enumeration handles. The T420 S37 documented guest probe `tests/observation/oem_file_contract.asm` created two disposable files and verified normal-FCB wildcard deletion plus no-match in direct and nested COMMAND routes on its recorded formal candidate. It does not establish extended-FCB read-only handling, failures, hard-error cleanup or latest release identity.

Two actionable **source-level candidates**, present in original OpenNT as well as current, need isolated verification before any change:

1. In the extended-FCB read-only branch, `SetFileAttributesOem(...) == -1` is used to decide whether to skip. Its declaration and OEMUNI implementation return BOOL, whose failure is FALSE (zero), so a conventional FALSE would not take the intended skip and the code would proceed to DeleteFileOem. This establishes a type/branch mismatch, not whether a real applicable guest request causes a different observable result.
2. After FindFirst succeeds, DeleteFileOem failure with errors WRITE_PROTECT through GEN_FAILURE, or WRONG_DISK, calls `demClientError` and returns before the only normal `FindClose(hFind)` below the loop. This source path can leave the search handle open; whether an actual supported file/device setup reaches it and whether another owner later releases it must be demonstrated. Normal no-match and rename paths do not prove this failure exit.

Finite safe validation: link the real current `demfcb.c` object into an isolated x86 fixture with test-only register/guest-memory and Win32/OEM boundaries, fake an extended FCB + read-only match and return FALSE from the attribute setter; assert whether deletion is invoked, caller CF/AX and cleanup. Independently supply a fake acquired enumeration handle and force one of the listed hard errors; count `FindClose` exactly once and test a following operation. Include normal two-file and no-match controls and use no real disk devices. A separate immutable-guest disposable-directory integration probe can validate guest FCB result/attributes with a version-bound coherent release; injected host failure and source-to-guest image provenance remain distinct. Record baseline behavior rather than assuming the desired result; compare the original and authorize any mirror deviation through existing governance.

`dem-fcb-delete-observer.py` hashes current/original sources and existing test/evidence inputs. No fixture was run, no product/guest/ledger modified, and these candidates are not represented as already fixed or reproduced.
