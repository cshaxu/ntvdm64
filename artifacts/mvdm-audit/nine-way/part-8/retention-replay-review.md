The earlier audit incorrectly treated empty estimate fields in frozen-file-reconciliation.csv as absence of a separate code-retention estimate. The canonical current table `artifacts/mvdm-audit/mirror-diff-code-retention.csv`, its summary, and `tools/audit/EstimateMirrorDiffRetention.py` already provide it. The isolated replay uses `replay-retention-observer.py`, which copies four input authorities into `build/t473-s10/retention-replay/` and redirects only the generator's AUDIT output there. The regenerated CSV hash is exactly `84FEC94BD6474E16CB646D69FBC6778E320A7E62D10038EDC106DB9F92605C40`, identical to the canonical summary at this run. The generator verifies original bytes and each live difference's partial ledger status. It reads current, not frozen, source bytes. The output is 208 differences, 207 measurable source files and one non-source `obj.vdm/sources` without a percentage.

The previous 205-file observer selected only rows already different from both frozen reference hashes. The canonical generator instead compares every currently present file with primary OpenNT (then 4.5 or the registered supplemental source when the primary is absent). All 205 previous paths occur in the canonical table; three further paths are `softpc.new/base/video/v7_ports.c`, `softpc.new/base/video/vga_mode.c` (post-freeze differences), and `softpc.new/obj.vdm/obj/i386/ntvdm.def` (supplemental original provenance). This is a scope difference, not three missing behavioral fixes. Six current files drifted since freeze: these two Video7/VGA sources plus `dpmi32/modesw.c`, `softpc.new/base/video/v7_video.c`, `softpc.new/host/src/nt_bop.c`, `softpc.new/host/src/nt_graph.c`; the previous four were only the drift among its already-different set. Canonical rows capture the actual current and original SHA-256 and frozen current SHA-256 separately.

The single common estimate is the existing generator's original nonblank, non-comment source lines matched in the current source, divided by the original such line count; Python SequenceMatcher uses autojunk=True. The extractor strips leading/trailing whitespace, strips line/block comments where it recognizes them, and preserves quoted contents. It is heuristic rather than a compiler/parser: macros, unusual strings or assembly syntax, line rearrangement, equivalents and inactive preprocessor branches can distort results. Do not label it restored functional behavior, branch coverage, runtime correctness or a measure of what percentage of a feature is working.

For `wow32/wsdata.c`, three different metrics must not be conflated: frozen all-original-lines heuristic 99.25%, our all-lines recomputation 98.78%, and canonical filtered-code-lines 1082 / 1095 = 98.81%. The code result is independently reproduced in the byte-identical replay. The freeze generator's differing all-line value has not been reverse-engineered; it need not be forced to match the canonical filtered metric. For drift examples, the canonical values are modesw.c 44/46 = 95.65%, v7_ports.c 514/516 = 99.61%, v7_video.c 283/285 = 99.30%, vga_mode.c 347/350 = 99.14%, nt_bop.c 556/573 = 97.03%, nt_graph.c 1414/1424 = 99.30%; their current hashes are in the table. None proves function completeness.
