# DOS byte-range locking: guest, DEM and host ownership

The original guest `dos/v86/doskrnl/dos/lock.asm::$LockOper` implements INT 21h AH=5Ch operations: it rejects AL > 1 before forwarding, resolves the DOS handle to its SFT, extracts the host NT handle, and passes operation, offset and length to `SVC_DEMLOCKOPER`; carry selects original DOS success or error return. The original DEM `demdisp.c` dispatch table binds that service to `demLockOper`; `demlock.c` reconstructs handle and 32-bit offset/length, delegates to native `LockFile` or `UnlockFile`, and invokes `demClientError` on failure. The guest owns handle validation and DOS error return, DEM owns register translation, while Windows owns actual handle, lock and contention state. The source path does not establish the prebuilt DOS kernel was built from these exact guest sources.

The documented current ledger retains `dos/dem/demlock.c` partial; that is appropriate even when original text is unchanged: partial is a limited feature evidence status, not a claim of a modified source. `shard-2/parallel-review-current.md` and its retained evidence bind `demLockOper` to an inspected released image, subject to that image's recorded version; do not extrapolate it to a newer image without rechecking the hash. `tests/legacy/opennt/trace/fixtures/original_demlock_register_fixture.c` uses actual LockFile/UnlockFile and CPU register inputs for a one-byte happy path on a temporary file, but does not execute guest, DEM dispatch or a DOS app; it aborts instead of validating `demClientError` on error. It is source evidence for a historical fixture, not a newly run test or end-to-end guest proof.

The finite unproved matrix is concurrent contention between separately opened handles/processes, exact DOS error/CF for invalid handles, repeated unlock, zero and boundary lengths/offsets, handle close/task death and cleanup; plus evidence that the exact shipped guest image reaches this service. Test on disposable files and record guest, worker and image hashes; Win32 documentation or a linked symbol alone does not establish guest semantics. The unguarded host `else` means a direct invalid AL reaching DEM would unlock, but the original guest checks AL first; no bypass or user-visible defect is established. The observer captures identities for guest, DEM dispatcher/implementation/error handler, test fixture, retained image-binding evidence and observed Ninja graph. No test, product, guest or shared ledger changed.
