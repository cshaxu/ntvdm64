# FDISK open/close failure path: original and adaptation

This refines `dem-absolute-io-review.md`. The complete current static read chain has two direct `nt_fdisk_read` consumers: (1) `demDasdRead` for non-removable media, called by DOS INT25 via `demAbsReadWrite` and `demIoctlDiskGeneric::IOCTL_READTRACK`; returned bytes are converted to sectors and the callers compare requested count, then map `GetLastError` to DOS error/carry; (2) `demIoctlDiskGeneric::IOCTL_SETMEDIA`, which reads a boot sector and checks both byte count and signature before writing metadata. Failure fallthrough therefore matters to more than absolute read. This is a source-level consequence, not evidence that a false success was observed. Both original editions also omit return after `get_fdisk_handle(..., FALSE)` failure; C supplies no defined return value, so a single run returning zero cannot prove correctness.

Original `cmdmisc.c` sets `pFDAccess` to the original guest word at DS:CX; original `get_fdisk_handle` increments `(*pFDAccess)` and `fdisk_open_count` after opening; original `close_fdisk` closes, invalidates and decrements both. Current `mvdm_command_guest_state_add_fd_access` reads and writes the guest word through an active session/epoch-checked numeric lease with unsigned 16-bit wrap. Its operations can report failure, unlike the original unchecked pointer increment. Current get-handle rollback closes and invalidates the new handle and decrements local open count if increment fails; it does not explicitly set a fresh Win32 error for that case. `nt_fdisk_read` then reaches its original missing return. `current_pdb` lookup separately returns zero early if its lease fails; this is not the missing-return path.

On close, current `close_fdisk` closes and invalidates the native handle before decrementing the guest word; if that update fails it returns FALSE before decrementing `fdisk_open_count`. A later `FdiskTerminatePDB` / `fdisk_heart_beat` can therefore observe a positive count without that handle, and those callers ignore the close result. This asymmetry is directly visible in current source; whether it occurs during an actual supported session teardown, or produces a user-observable defect, remains unproved. A failed write/release may also require knowing whether the guest word committed before proposing recovery. The native object must never be closed twice, and `fdisk_open_count` should describe live local handles even if guest state is no longer available; no repair is authorized by this report alone.

Existing fixture boundaries: `t394_s4_command_scalar_state_fixture.c` exercises actual COMMAND guest scalar provider, 16-bit wrap, wrong-session and invalid/expired lease, but not fdisk. `contained_media_fdisk_test.c` resolves nt_fdisk symbols to `tests/legacy/opennt/archived/legacy-adapters/contained_media_fdisk.c`, a substitute, not current real object. `t236_s4_ntfdisk_readonly_fixture.c` is a historical host-capability test on an explicitly authorized disposable fixed volume; it checks success and restoration, not failure injection or current ABI identity. T230 direct-import adapter is likewise not current product graph. None is a sufficient exact failure witness.

Executable next test: build a standalone x86 fixture with the **actual current nt_fdisk.c object** and explicit test-only controlled Win32/guest-location boundaries (or its real guest-state provider with session-memory fixture); never open a real disk. Supply in-memory registered fdisk data and a harmless test file/controlled handle. In separate cases force CreateFile failure and force guest-counter increment failure after successful open; record read result/last error, open/close counts, guest word, handle validity, and verify no accidental disk read. Force counter decrement failure after a successful tracked open, invoke close and `FdiskTerminatePDB`, and verify local count, guest outcome and exactly-once handle close. An outer DEM fixture should exercise absolute-read, READTRACK and SETMEDIA with sentinel buffers, CF/AX and an explicit last-error value; keep SETMEDIA from reaching actual write. Add normal open/read/close, reopen, owner switch and modulo counter cases as controls. Baseline missing-return is undefined, so verify source/control flow and actual captured outcome rather than requiring a particular wrong number; repeat after an agreed minimal fix with deterministic failure semantics. Bind object/fixture hashes and test current release separately. Avoid transient retries and never use arbitrary real drives.

No fixture, binary, guest, disk, source or ledger was modified in this audit; this is a proposed validation, not a claimed pass.
