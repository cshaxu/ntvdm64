# Original DEM FCB open, metadata, I/O and close

The DEM table dispatches FCB open/create to `demFCBCommon`, read/write to `demFCBIO`, and close to `demCloseFCB`. The original path translates guest filename and sharing mode, creates the Windows handle through OEMUNI, queries DOS-compatible time/size, then returns the host handle through guest registers; the guest must subsequently close it. `demFCBIO` leases DTA memory for the operation and releases it on success and read/write failure; do not conflate that project adapter with the original guest FCB semantics. Windows owns the opened handle; DEM owns publication and failure cleanup, and guest owns an already-published FCB handle.

T420 S33's `dem_capability.asm` was documented as executing real guest FCB open/read/close alongside other file operations and reports the transcript marker. Its result is bounded to the reported package and happy path, not a current-release failure/lifetime guarantee. Existing S37 evidence on FCB wildcard delete is a separate operation and does not establish open/create failure cleanup.

Current and original `demGetMiscInfo` contain source-level failure candidates. `GetFileTime`, a BOOL API, is compared to -1 rather than FALSE, so ordinary FALSE does not follow the written error branch; the following `FileTimeToLocalFileTime` result is not checked. Also `demFCBCommon` obtains `hFile`, then returns when metadata helper returns FALSE without publishing it to the guest; the helper closes that handle only in the written GetFileTime == -1 branch, not after failed DOS-time conversion, failed GetFileSize or nonzero high file size. Those paths therefore have no visible close in these functions. This is concrete source control flow inherited from the original, not proof a real guest reached the branch or that metadata conversion failure naturally occurs. Debug assertions or host process termination can change observations; test the actual release build policy.

Finite isolated validation: link the real current object in an x86 fixture with controlled Win32/OEM and CPU/guest-memory boundaries; supply valid fake acquisition then independently force GetFileTime FALSE, local-time conversion FALSE, DOS-time conversion FALSE, GetFileSize error and high-part nonzero. Count handle acquire/close/publication, original error conversion, return registers/carry, and successful open/read/close controls. If size sentinel is used, also test valid 0xFFFFFFFF low size with zero/nonzero last-error before asserting its semantics. Keep files disposable; follow with version-bound guest integration only for safely reachable cases. Do not auto-fix historical code or assume identical NT error state. `dem-fcb-open-observer.py` captures original/current and guest/fixture/evidence hashes; no runtime test, product, guest or ledger was changed.

The observer requires the two pinned read-only source trees at its recorded O: paths. Presence of demfcb.obj alone does not prove its independent linking or execution; its external CPU and OEMUNI dependencies require controlled boundaries.
