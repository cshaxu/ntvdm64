# Mirror-diff per-file estimates: frozen versus live identity

Reproducible observer `mirror-diff-estimate-observer.py` reads `frozen-file-reconciliation.csv` (SHA256 F73FFD45DFF44FCA4ECEFC49EF769BEAB5C085542CD04FFE4D6A7B5F942E3196), selects current hashes differing from both reference editions, verifies selected-edition and current files against frozen hashes, and writes the 205 per-file records in `mirror-diff-estimate-review.csv`. It uses Latin-1 `splitlines`, SequenceMatcher `autojunk=True`, and matched original lines divided by original lines; the denominator, choice of selected edition, matcher policy and byte identities are recorded. This number is a text-retention heuristic, not executable code coverage, a measure of feature restoration, or a release acceptance result. All 205 frozen entries have empty `estimated_restored_code_pct` and `pending-selection-and-semantic-review`; no per-file behavioral restoration percentage is supported by this inventory.

201 of 205 live identity pairs match the freeze and have independently recomputed textual values. Four current source files changed after freezing: `dpmi32/modesw.c`, `softpc.new/base/video/v7_video.c`, `softpc.new/host/src/nt_bop.c`, and `softpc.new/host/src/nt_graph.c`; the matching upstream files remain identical to the freeze. Their frozen metrics cannot be represented as current source results. For matching pairs, most values agree; `wow32/wsdata.c` is 98.78% with this observer versus 99.25% in the frozen table. The matcher choice and input handling must be reconciled with the original generator before choosing either number; no observed behavior conclusion follows. The two further cent-level discrepancies may reflect rounding/method; they likewise cannot justify a behavioral claim.

## Actual COMMAND host/guest path and why percentages cannot establish recovery

The original DOS COMMAND launch and redirection paths reach host `cmdCheckForPIF` and the original `cmdPipeOutThread`/`cmdPipeInThread` bodies; project-owned changes map the PIF guest scalar through an epoch-bound session lease and bind a session in the WINAPI thread boundary. The retained product link map shows those original bodies selected, and the PIF OEM fixture calls the real PIF function; however, the fixture stubs the scalar writer. Thus link selection plus a high text match do not establish a real current guest PIF launch, missing/stale guest memory handling or cleanup, nor pipe EOF, cancellation and session retirement. Concrete source, host-provider and limited existing fixture references are in `shard-2/command-state-pif-redirection-review.md`. Its three changed files remain partial. These are evidence gaps, not asserted regressions.

No build, new runtime test, product, guest or shared ledger was changed. Observer results represent the filesystem at execution time; re-run and compare hashes before subsequent use. Different selected editions, newly modified files, binaries, inactive preprocessor branches and linked-but-unreached functions all need their own review. Function restoration cannot be converted to a truthful whole-file percentage without an agreed set of behavior cases, version-bound results and explicit weighting.
