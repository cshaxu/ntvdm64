# GISP video declarations versus NT/Video7 mouse owner

Owned `softpc.new/base/inc/gispsvga.h` declares GISP ROM helpers only when GISP_SVGA is defined. `bios.c` includes it and the normalized dependency inventory identifies bios.obj, but that is not proof those declarations are active. The original BOP table (`bios.c:560-575`) selects NT/XWINDOW host mouse installation wrappers for C8/C9 before its alternate GISP branch. Independent `bios-image-observations.json` binds candidate slots 200/201 to `_v_host_mouse_install1` / `_v_host_mouse_install2` through original object relocation and image pointers. This is candidate composition evidence, not every later image or live guest operation.

The separately documented Video7 driver uses a different V7VGA selection; `video7-pointer-review.md` and its receipt describe scoped historical full-suite plus graphical guest tests with injected frontend input and later user manual acceptance, including identified package differences. Physical Raw Input was specifically unverified there. Original BIOS/Video7 resource packaging is independently documented in `shard-1/rom-cmos-family-review.md`; embedded ROM identity alone is not a mouse witness. Avoid equating GISP_SVGA with Video7 or promising all graphical mouse behavior based solely on slot symbols.

Suggested classification: historical conditional GISP helper declaration retained, present in selected BIOS include graph; particular captured NT candidate dispatches C8/C9 through host mouse wrappers. Other profiles and callback/reentrancy/lifecycle details remain pending. This review does not rerun products or alter guest, product, or shared ledger.
