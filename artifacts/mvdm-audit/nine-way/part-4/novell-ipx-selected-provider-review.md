# Legacy Novell/IPX declarations and independent current network services

Owned `softpc.new/base/inc/novell.h` defines legacy ODI transmit/receive control-block layouts, and `ipx.h` defines another legacy IPX interface. The earlier `shard-3/novell-tcp-interface-role-review.md` records conditional NOVELL includes and termination, exact dependency search and the bounded observed profile. `bios.c:225-240` conditionally places Novell functions in BIOS BOP slots 34–39. The independent captured candidate BIOS initializer relocation results in `bios-image-observations.json` show slots decimal 52–57 all target `_illegal_bop`. These are original BIOS slots, not a proof that all global BOP dispatch or every network provider is inactive. The exact owned header interfaces, alternate profiles and external network semantics are not covered by a current runtime test.

The project has distinct networking routes: T420 S20 documents separately versioned real guest NetBIOS and local networking witnesses through DOS redirector/VDMREDIR; `shard-3/wfwnet-guest-input-role-review.md` traces a different conditional Win16 WFWNET→VWIPXSPX VDD route and notes its provider was absent at the one inspected system32 path. The latter remains unverified, including search paths, registration and teardown. Neither NetBIOS nor Winsock verifies ODI/IPX, and lack of legacy SoftPC BIOS slot selection cannot be used as a blanket exclusion of networking or WFWNET.

Suggested classification: original legacy Novell/IPX interface declarations; Novell conditional BIOS vector is not selected in the captured candidate, while actual legacy profile applicability and other IPX providers remain pending. No guest/product/shared-ledger modifications or new runtime test.
