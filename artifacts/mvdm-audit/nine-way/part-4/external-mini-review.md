# Part 4: NT4 raster printer mini-driver source census

Scope: 4,773 assigned OpenNT-4.5 `nt/private/ntos/w32/ntgdi/printers/rasprint/mini` files. `external-mini-evidence.json` contains each owned key, path, SHA-256, size, extension and bounded exact dependency/ZIP-basename observations. All 4,773 source paths exist. No exact path appeared as a VALID dependency in the four observed Ninja graphs; no identical basename appeared in `assets/winnt.zip`. Neither result proves that a compatible printer provider is unavailable: the host spooler, driver packages and alternate identities are outside that search.

Largest groups are pcl5ms (849), pcl5e (843), pcl5mse (800), pcl5ee (689), star24e (409), star9e (235), seiko24e (195). 1,354 `.ifi` and 1,282 `.pfm` files are the largest groups; the original mini/readme explicitly says IFIMETRICS are generated from Windows 3.x PFM data with `pfm2ifi` and rebuilt into minidrivers. GPC, CTT, resource/build files and other model-specific assets cannot be declared independent merely by extension. Printer calls and device support cannot be proven by finding those assets: no actual driver selection, spooler routing or print execution was observed.

Reproduce with `PYTHONDONTWRITEBYTECODE=1 python -B artifacts/mvdm-audit/nine-way/part-4/external-mini-observer.py`, capture stdout separately. Evidence is a source census, not provider semantics: all keys retain `pending-specific-provider-semantics`; the generic role field and basename match are hints, not an ownership or capability determination. No guest or product modification or execution.
