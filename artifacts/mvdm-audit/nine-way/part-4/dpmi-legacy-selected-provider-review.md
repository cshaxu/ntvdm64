# SoftPC DPMI header versus selected NT DOSX/DPMI32 provider

Owned `softpc.new/base/inc/dpmi.h` defines a legacy SoftPC DPMI TSR host interface including selector, callback and memory-allocation state. A bounded search of current SoftPC and NTVDM source `.c`/`.h` files found no exact `#include` of this basename; part-4 normalized four-graph VALID dependency census likewise found none. This only bounds the observed paths and builds; it does not prove all generated/alternate historical configurations are absent.

Original BIOS table in `bios.c:217-225` places DPMI_2F/31/general/int at BOP 30–33 only under DPMI; otherwise it selects illegal_bop. Independently `bios-image-observations.json` binds captured candidate slots decimal 48–51 to `_illegal_bop` through the original BIOS vector and image relocation check (`bios-native-role-review.md`). It does not follow that protected-mode/DPMI support is absent: this product's DOSX→BOP 53:0B→DPMI32 path and XMS-owned CPU40 memory pool are analyzed in `part-2/dpmi-provider-comparison-deep-review.md`, including its documented DIV-224/DIV-272 and a historical real guest 0500/0501/0502 witness for a specifically hashed worker. That witness is not the current release, nor proof of all sizes, callbacks, failures or task retirement.

Suggested classification: retained legacy SoftPC DPMI declaration, exact current profile dependency not observed and its captured BOP slots are inactive; retain actual NT DOSX/DPMI32 provider and all capability/lifecycle obligations separately. Do not delete or claim universal exclusion from this bounded profile. No guest/product/shared-ledger modifications or new runtime test.
