# Legacy HFX redirector header versus selected NT redirector

Owned `softpc.new/base/inc/hfx.h` defines SoftPC HFX redirector structures and interfaces only under `#ifdef HFX`. `bios.c:48-49,209-215` includes it and selects HFX BOP 2E/2F only under the same macro; otherwise those entries are illegal_bop. The part-4 evidence records the exact header in the current bios.obj dependency list, but inclusion alone does not imply active declarations.

Unlike a mere compile-flag inference, `bios-image-observations.json` independently records mapped candidate BIOS vector slots decimal 46 and 47 (2E/2F) both bound to `_illegal_bop`; `bios-native-role-review.md` describes the original object relocation-to-image verification and its captured candidate scope. This establishes those slots for that candidate only; it does not make a claim about every product variant, startup mutation or the overall network redirector.

NT VDMREDIR is a distinct route. `docs/etc/evidence/m0-t420-s20-vdmredir-operation-matrix.md` identifies original DOS redirector TSR and 50-entry VrDispatchTable, and records real guest witnesses for bounded local NetAPI, pipe and NetBIOS paths on specific matching/historical packages. Its explicitly approved RAP/DLC exclusions and still-open individual rows are separate. Legacy SoftPC HFX header should be classified as an original conditional declaration included in bios.obj; the captured image selects illegal BOP targets for HFX slots. Runtime redirector capability, version/packaging identity and future HFX profile applicability remain independent pending obligations. No guest/product/shared-ledger change or new runtime test.
