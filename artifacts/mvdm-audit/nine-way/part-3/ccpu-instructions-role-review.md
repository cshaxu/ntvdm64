# Part 3: CCPU 386 instruction family

The twelve owned `bswap`, `cmpxchg`, `invd`, `invlpg`, `wbinvd`, and `xadd` `.c`/`.h` keys are enumerated individually with original/current SHA-256 and current x86 formal Ninja source-line hits in `ccpu-instructions-observations.json`; reproduce with `python artifacts/mvdm-audit/nine-way/part-3/ccpu-instructions-observer.py`. Source-path hits are normalized for slash direction and are observations of the on-disk graph, not proof the present released image was linked from it. Header source graph hits being absent does not prove a header is unused: Ninja dependency logs/preprocessor includes are separate.

The original `softpc.new/base/ccpu386/c-files` lists all six C implementations, and they implement their namesake instruction functions (`bswap.c:38`, `cmpxchg.c:39,67,95`, `invd.c:37`, `invlpg.c:38`, `wbinvd.c:37`, `xadd.c:42`). Their matching headers provide the corresponding declarations; each is an original instruction-family input, not an independent emulator. The on-disk x86 formal `build.ninja` declares object build edges for all six. These should remain available in the selected CPU40 package pending evidence about exact opcode selection and image extraction, rather than be excluded merely because of a historical non-extraction.

Historical T420 audit `docs/etc/evidence/m0-t420-s1-ccpu386-package-audit.md` observed these six objects compiled but not extracted in its T419 linked map. That is a historical image result only; it does not prove extraction status of a current build or execution of any instruction. No instruction guest fixture, cache invalidation behavior, page-table effects or CPU exception behavior was run in this review. Classification suggestion: retain original package inputs, keep runtime behavior and current released-image binding **pending**. No numerical functionality claim is made.
