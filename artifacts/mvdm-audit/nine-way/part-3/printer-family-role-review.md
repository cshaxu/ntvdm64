# Part 3 external RasPrint minidriver inventory

`printer-owned-files.csv` supplies the frozen external key, exact source-edition path, existence, SHA-256, and per-file resource-script basename candidate references for all 4,772 owned rows; all 4,772 files were present. Reproduce with `python artifacts/mvdm-audit/nine-way/part-3/printer-owned-observer.py` (output is rewritten in this part only), then `python artifacts/mvdm-audit/nine-way/part-3/printer-family-observer.py` for family build text and RC filenames. The latter records actual source contents and SHA-256; its output is `printer-family-observations.json`. A basename hit is only a candidate: resource-relative paths, preprocessing and build variants must be checked before claiming a dependency.

The 29 family `sources` files individually declare `TARGETTYPE=DYNLINK` and their own target, normally listing `code.c` and an RC file; they are NT printer minidriver packages, not by themselves evidence of MVDM host or guest functionality. In particular, the directory names `kyox` and `oescp2ms` correspond to target names `kyocerax` and `escp2ms`. The 2,841 per-file basename hits are useful starting points, not proof that every candidate is compiled or shipped. The remaining 1,931 files have no such basename hit; absence is not proof they are irrelevant: generated resources, includes, alternate build configurations, and binary references are not resolved by this search.

The six owned root files have distinguishable roles: `ifiin.bat`, `ifiout.bat`, and `ifisync.cmd` invoke IFIMETRICS source-control/synchronization helper commands; `mk_ctt.cmd` invokes `_mk_ctt`; `mk_ifi.bat` describes IFIMETRICS regeneration from PFM; `modinit.c` supplies the generic minidriver initialization and optionally RasDD callback setup. These are historical printer package sources/build helpers, and actual consumers must be established per build configuration. No invocation of the scripts was performed.

Disposition: **pending per item** for the coordinator's relevance/ownership decision, including current Windows printing and Win16 printing flows. Family build evidence is not a license to exclude a whole family or import it as a guest dependency. No runtime printing, installed driver inventory, resource expansion, generated artifact identity, or historical-versus-modern provider equivalence was tested. No claim of complete printer coverage or numerical runtime restoration follows from these observations. See also `hppcl5ms-role-review.md` for more detailed examination of that family.
