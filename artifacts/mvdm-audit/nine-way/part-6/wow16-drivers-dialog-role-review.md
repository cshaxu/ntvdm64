# Part 6: Win16 drivers and common dialog

The owned keys for `wow16/drivers/{comm,display,keyboard}` and `wow16/commdlg` are listed with exact edition hashes in `mvdm-identity-observations.json` (reproduce using `mvdm-identity-observer.py`). The respective original makefiles provide source/resource/link dependencies; they are build descriptions only and were not executed. The 13 communication-driver keys include `comm.def` API ordinals, `comm.rc`/`COMM.RES`, the `ibmcom`, `ibmint`, `ibmlpt` and `commmsg` assembler paths, their headers/includes, and `ddkmake`. `comm/makefile` compiles and links `comm.drv` from its named object list; `comm.def` imports system timer services. `ibmcom1.asm` and `bimodint.inc` are not individually named in that displayed link recipe; their actual indirect/variant use remains pending.

The keyboard-owned `kbd.def` and `keyboard.asm` belong to the original keyboard driver: `keyboard/makefile` builds `keyboard.obj`, combines it with `kbdlocal.obj`, and uses WOW-related includes. The display-owned binary/config/list assets and `vga.drv` must be assessed separately; source presence does not prove which guest driver is active or establish runtime semantics.

The `commdlg` owned files comprise actual dialog implementation input (`font.c`), header declarations, dialog bitmaps, string source `sz.src`, exports `STRIPPED.DEF`, retained resource `COMMDLG.RES`, and retained `COMMDLG.DLL`. `commdlg/makefile` shows generated language resources and the DLL recipe; that establishes a historical build relationship rather than proving the present DLL was compiled from these exact files. Resource naming and locale variants require their own test.

`guest-package-observer.py` compares exact SHA-256 of `assets/winnt.zip` members and mirror candidates: COMM.DRV, KEYBOARD.DRV, VGA.DRV and COMMDLG.DLL match each respective mirror binary. The separately retained `wow16/ddeml/debug/DDEML.DLL` has no same-named package member in this ZIP. This checks package identity only, not loaded module identity or binary-to-source provenance, and does not imply all Windows 3.1 installations use this package. See `docs/etc/evidence/m0-t459-s2-common-dialog-consumer-acceptance.md` for the earlier common-dialog consumer evidence.

All of these are potentially guest-relevant: preserve original source/resource and deployed guest identity; do not infer absence of capability from exclusion from the host build. No guest was modified or compiled. No serial hardware, WOW interaction, keyboard, display mode or dialog behavior was newly tested. Keep unresolved individual roles and compatibility claims pending, and do not assert a restoration percentage.

The remaining owned `wow16/bin/rcpp.err` is the historical resource-compiler error-message input associated with 16-bit toolchain lookup; the original driver makefiles explicitly discuss RC 3.1's path sensitivity. It is a tool support artifact, not a runtime guest driver, but the exact compiler execution path has not been exercised here.
