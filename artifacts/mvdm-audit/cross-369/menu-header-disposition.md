# S10 part 9: selected WOW menu interface

The sole owned key here is `wow32/wumenu.h`; all body/dispatch files are read-only dependencies. `menu-header-observer.py` captures source and edition hashes, the current WOW32 graph edge and the `VALID` dependency for `wumenu.obj`; reproduce with `PYTHONDONTWRITEBYTECODE=1 python -B artifacts/mvdm-audit/cross-369/menu-header-observer.py`. No guest, product or ledger was changed.

The header matches both original editions and declares the original Win16 menu thunk entrypoints. `precomp.h` includes it and the selected `wumenu.obj` dependency names the exact header. `wutbl2.h` binds menu ordinals to original `wumenu.c` implementations, including create/destroy, set, load, append/insert/remove and popup operations. The original resource load uses `ConvertMenu16` and passes the converted representation to the existing USER provider, then releases temporary conversion buffers; modern USER owns native HMENU lifetime while original WOW owns guest data translation. Removed submenus and deleted submenus have distinct ownership consequences. Header identity alone cannot prove those paths are correct.

The prior `shard-2/wow-menu-owner-lifecycle-review.md` records S8's bounded source-level menu/resource fixture and actual later Solitaire/WinMine application witnesses. It also records owner-draw, remove/delete distinction and rollback limits. `m0-t458-s4-consumer-acceptance.md` explicitly says its desktop-denied suite did **not** reach the provider, so it is a non-pass rather than supporting evidence. These records bind their own historical artifacts and do not independently establish all current-image guest menu operations.

Recommendation: `wow32/wumenu.h` is **partial, selected original interface**, with dispatch and bounded behavior evidence. S15 retains real named/ordinal/indirect menu resource conversion, owner-draw and guest itemdata, popup remove versus delete, nested tracking and cancellation, stale/reused identity, error/rollback and window/task retirement. Use actual selected caller/provider and bind guest/DLL identity; no original mirror modification or alternate menu state store is proposed by this audit.
