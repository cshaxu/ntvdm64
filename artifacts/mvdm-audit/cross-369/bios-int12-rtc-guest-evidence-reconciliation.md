# BIOS INT 12 / RTC: real-guest evidence and provider boundary

The two byte-identical original host sources `softpc.new/base/bios/mem_size.c` and `softpc.new/base/bios/rtc_bios.c` are already marked partial; this review does not alter their classification. It separates historical guest observations that the earlier whole-unit report grouped together.

`tests/observation/bios_capability.asm:19-31` invokes guest INT 12 and compares AX with BDA `40:13`. `docs/etc/evidence/m0-t420-s26-bios-capability-baseline.md` records the `S26_MEMORY_SIZE_OK` marker after a formal package run and attributes the ROM BOP 12 to original `memory_size`. `src/mvdm/softpc.new/base/bios/bios.c:159` registers that function, and original `dos/v86/doskrnl/bios/spckbd.asm:1427-1429` shows an INT 12 vector issuing BOP 12. This is credible **bounded historical guest-path evidence**, not evidence the currently installed guest used that exact historical source, or that all reset, BDA mutation and error paths work. The S26 document identifies the product artifact hash receipt at `O:/winnt/logs/m0-t420-s26-formal-artifacts.json`; that receipt is absent at this recheck, so the present analysis cannot independently pin its historical worker hash. The current cache map's `mem_size.obj` is a different observation and must not silently be joined to that historical run.

`rtc_bios.c` is different: S26's broad claim that the S24 CMOS/periodic witness proves the same BOP 70 handler is not established by the cited guest assertions. `shard-3/bios-memory-rtc-audit.md` documents that the guest observed CMOS register C but did not separately assert `rtc_int` entry, BDA wait countdown, completion flag, alarm INT 4A, or two-PIC EOI; `shard-3/cmos-rtc-device-audit.md` separately covers device IRQ/reset callback evidence. CMOS device ownership and BIOS handler execution are distinct. Existing PIC callback fixture does not prove BOP 70 guest handling. Preserve the partial selected-source classification without upgrading this handler's runtime evidence.

For a bounded continuation, use a test-only guest to exercise normal boot and ROM BOP 70 with known wait count/user flag, check terminal flag and slave/master EOI, then an alarm callback with CS/IP restoration. Retire the task/worker, restart, and repeat with known CMOS/PIC/BDA state; bind actual guest/worker/ROM hashes. This is not a claim of a reproduced RTC defect. No source, guest, shared ledger, or test state was modified.
