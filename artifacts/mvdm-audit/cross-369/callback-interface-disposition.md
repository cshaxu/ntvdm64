# S10 part 9: original callback and local-memory interfaces

The owned keys are `wow32/wcall16.h` and `wow32/wcall32.h`. Their consumers and implementations are read-only dependencies. `callback-interface-observer.py` captures edition hashes and the normalized cached `wcall16.obj`/`wcall32.obj` Ninja dependencies; reproduce with `PYTHONDONTWRITEBYTECODE=1 python -B artifacts/mvdm-audit/cross-369/callback-interface-observer.py`. No source, guest, build graph or ledger was modified.

Both headers match both original editions and are selected through `precomp.h`; each appears in the `VALID` dependency closure of the selected callback objects. `wcall16.h` declares guest local/global-memory and segment/resource operations plus `CallBack16`; its local allocation/locking wrappers call `CallBack16` with original return IDs. `wcall32.h` declares the reverse native-side local/global and dialog/edit services; it is not the same entry direction. Original callback frame and guest state remain in `wcall16.c`; `wow_user_native_extension.c::CallBack16` enters the bounded native-call scope and invokes `wow_original_CallBack16`, consistent with the registered DIV-343 seam. The outer scope cannot itself replace the original callback-frame and CPU owners.

`docs/history/m0-t447-s2-foundation-closure.md` records passing bounded foundation, guest-entry and selected retirement groups for its published artifact, plus an explicitly unresolved common-dialog witness; it does not claim all application or nested-message behavior. The later `m0-t447-s4-message-source-audit.md` traces preparation, live simulation and returned-frame failure as different states and records actual original-body fault doubles and separate guest witnesses within that historical batch. Those receipts bind their own artifacts and do not prove every current callback or task lifecycle branch.
