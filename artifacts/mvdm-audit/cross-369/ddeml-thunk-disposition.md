# S10 part 9: historical DDEML thunk vs retained Win16 DDEML

This review proposes role dispositions only for owned `wow32/wddeml32.c`, `wow32/wddeml32.h`, and `wow32/wddetbl2.h`. The separate `wow16/ddeml` sources and binaries are read as cross-part dependencies, not classified here. `ddeml-thunk-observer.py` records edition hashes, sorted source references, and cached graph hits; reproduce with `PYTHONDONTWRITEBYTECODE=1 python -B artifacts/mvdm-audit/cross-369/ddeml-thunk-observer.py`.

The three owned files describe an original historical host DDEML thunk: `wddetbl2.h` maps DDEML ordinals including initialize, connect, transaction and data handles to `WD32*`; `wddeml32.c:53` calls native `DdeInitialize` and supplies a callback that later calls back to Win16, and its header declares this interface. All three match both reference editions. The checked original `wow32/sources` lists classic `wdde.c` but not `wddeml32.c`; the current cached WOW32 graph also has no `wddeml32` or `wddetbl2` input. The bounded reference search finds thunk/table references within these historical files rather than a verified active dispatcher. No inference follows about other archived OpenNT configurations, binary distributions, or third-party source consumers.

This is not evidence that all DDEML capability is absent or can be dropped. The separate retained `wow16/ddeml/makefile` links a Win16 DDEML DLL from guest implementation objects; its `ddeml.def` exports `DDEINITIALIZE @2`, and `ddeml.c:90,351,2257` implements init, uninit and name service on the guest side with message-based interactions. Those source recipes do not prove the provenance or selection of a specific shipped DDEML DLL. `shard-2/ddeml-register-probe-evidence.md` has an actual app-local W31 DLL identity and a bounded client/server no-register init/uninit control; its registration attempt stalled at a call boundary and did not establish a root cause or working transactions. That is a meaningful but limited guest route, not equivalence to the unused host thunk.

| Owned key | Suggested role classification | Remaining feature ownership |
| --- | --- | --- |
| `wow32/wddeml32.c` | Excluded as unselected historical host DDEML thunk in the inspected profile. | S14 retains actual guest DDEML, original DDE message transport, callbacks, peer failure and teardown. |
| `wow32/wddeml32.h` | Excluded as private declaration for that unselected thunk, subject to uninspected configurations. | Preserve guest/host ABI where active; no inference about all DDEML headers. |
| `wow32/wddetbl2.h` | Excluded as the unselected historical host ordinal table in the inspected profile. | Establish selected guest DLL ordinal handling and original message route independently. |

These are coordinator recommendations, not permission to remove the files or to claim capability completeness. Required S14 follow-up: match a deployed guest DLL and all native/guest providers by identity; independently reproduce/init/uninit, register/unregister, connection and transaction paths; cover callback reentry, cross-task/process peers, handle ownership, cancellation and participant death. No product or guest was executed or changed in this audit.
