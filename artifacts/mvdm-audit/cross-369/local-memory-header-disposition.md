# S10 part 9: historical host-local declarations and active memory callbacks

The sole owned key here is `wow32/wklocal.h`. `local-memory-header-observer.py` records original/current hashes and selected callback/message-heap graph/dependency observations; reproduce with `PYTHONDONTWRITEBYTECODE=1 python -B artifacts/mvdm-audit/cross-369/local-memory-header-observer.py`. This is read-only source/graph work; no guest, product or ledger was modified.

`wklocal.h` matches both original editions and declares historical `WK32Local*` thunks. The checked original `wow32/sources` and current cached graph do not select `wklocal.c`; original `wktbl2.h` marks guest LOCALALLOC/LOCALFREE as `LOCALAPI`, not those host functions. The selected and separately compiled original `wcall16.c`, `wcall32.c`, and `walloc16.c` are a different cross-boundary path: `wcall32` chooses native Local operations or guest callbacks based on instance; `wcall16` supplies original guest local-memory callbacks; `walloc16` owns the separate small message heap and callback-stack allocator. Nonselection of `wklocal.h` cannot justify dropping the guest KERNEL's actual local heap functionality.

`shard-2/wow-callback-memory-helpers-review.md` traces the original local instance distinction and realloc mapping update; `shard-1/wow-message-heap-review.md` binds small-heap objects to release code but explicitly does not prove guest execution or complete synchronization. The latter also references a separate actual-object EDIT word-break overrun counterexample; it is a caller length issue and must not be relabeled as a proven general allocator defect.

Recommendation: `wow32/wklocal.h` **excluded as an unselected historical host-thunk declaration in the inspected original/current profile**. Preserve the original guest local heap and selected callback/heap interfaces; check other configurations before physical removal. S11/S14/S15 need normal allocation/realloc/free and pointer mapping, failure rollback, nested callbacks, task/segment retirement and real guest heap ownership tests, including the separately identified word-break boundary. No new runtime test or broad memory-semantic claim is made here.
