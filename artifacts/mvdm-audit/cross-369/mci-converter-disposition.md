# S10 part 9: original multimedia converter and selected guest route

Only owned `wow32/wmmstru2.c` and `wow32/wmmstruc.h` receive proposed dispositions. `mci-converter-observer.py` records pinned-edition hashes, the cached compiled object's COFF symbol table and current VALID include dependencies; run with `PYTHONDONTWRITEBYTECODE=1 python -B artifacts/mvdm-audit/cross-369/mci-converter-observer.py`. No guest, product, graph or ledger was altered and no runtime test was performed.

Both files match both original source trees. `wmmstru2.c` is in original `wow32/sources` and current cached build, but the actual MCI unthunk functions are inside the source's original enclosing `#if 0`. The selected `wmmstru2.obj` has no defined MCI conversion function in its COFF symbol table; its incidental unresolved named-pipe symbols and metadata must not be mistaken for MCI behavior. `wmmstruc.h` is included through `precomp.h` and appears as a VALID dependency of that object. Its typed conversion declarations/macros are real source inputs, but textual uses such as wave/MIDI header updates in `wmmedia2.c` are also in the latter's enclosing `#if 0`. Include/dependency alone does not prove active macro expansion, and this sample does not exhaust every possible consumer or configuration.

The separately retained Win16 `mmsystem/init.c` resolves native WINMM entrypoints including `mci32Message`; `mci.c::mciSendCommand` contains separate 16-bit and 32-bit driver branches. `docs/etc/evidence/m0-t466-s3-async-multimedia-owner-audit.md` traces the guest-to-`MMCALLPROC32` protocol and the original guest task rundown; its host-boundary fixture resolved 11 exports and invoked only the synchronous timer packet. This supports a distinct selected protocol, but neither source nor export lookup proves MCI device command completion, callbacks, failure or teardown. In particular, the historical note that the old structured host converter is inactive must not be broadened into an unsupported claim that every MCI route is unavailable.
