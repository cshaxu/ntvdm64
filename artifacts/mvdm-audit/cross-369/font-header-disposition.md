# S10 part 9: font enumeration interface and callback boundary

Only owned `wow32/wgfont.h` receives a classification recommendation. `font-header-observer.py` records source/reference hashes, selected `wgfont.obj` VALID dependency and bounded callback-name references; reproduce with `PYTHONDONTWRITEBYTECODE=1 python -B artifacts/mvdm-audit/cross-369/font-header-observer.py`. No guest, product, graph or shared ledger was changed.

The header matches both original editions and is selected through `precomp.h`. The original GDI dispatch table names font creation, enumeration and add/remove-resource thunks. `wgfont.c::W32EnumFontHandler` selects native `EnumFonts` or `EnumFontFamilies`, carrying per-call `FNTDATA`; the selected native enumeration calls original `W32EnumFontFunc`, which converts font/metric structures to guest callback storage and invokes `CallBack16(RET_ENUMFONTPROC, ...)`. The original WOW owner controls conversions and guest callback frames, while modern GDI owns the font, DC and enumeration. Original task retirement calls the finite `UnloadNetworkFonts` projection; it is not a new font authority.

The original header declares `W32FontFunc`, but the observed implementation defines and passes `W32EnumFontFunc`; the bounded source search finds no use of the former spelling. This is a historical declaration mismatch, not proof that the actual callback is broken. `m0-t456-s1-font-text-metafile-owner-matrix.md` and `shard-2/wow-gdi-text-font-metafile-review.md` record selected providers and prior font-tracking/host-glyph tests; they explicitly do not establish all guest enumeration callbacks or failure/retirement paths.

Recommend `wgfont.h` **partial, selected original interface**. A concrete failure path needs controlled verification: `W32EnumFontFunc` stores the callback result in local `iReturn` but does not check `CallBack16`'s Boolean return; the current wrapper can return FALSE before invoking the original body when callback scope admission fails, without visibly writing that output. The subsequent short conversion/compatibility branch reads `iReturn`. This is a source-level conditional concern, not a reproduced product crash; determine callback failure contract and native enumeration stop semantics with selected-body fault injection. Also test temporary stack allocation failure and movement, native early-stop, nested/reentrant callbacks, task death and font resource unload without claiming that a public glyph fixture proves guest enumeration.

S11/S16 should bind guest, WOW and host provider identities, exercise successful real enumeration and the above failures/cleanup, preserve original callback ordering and register any actual mirror correction. No runtime test, new font registry or guest rebuild is proposed.
