# S10 part 9: OLE foreign-task alias interface

Only owned key `wow32/wole2.h` receives a disposition recommendation here; related source paths are dependencies read for this audit. `ole-alias-observer.py` captures current/OpenNT/OpenNT-4.5 SHA-256, the current cached WOW32 source edge, and actual Ninja dependency status for the selected `wole2.obj`. Reproduce with `PYTHONDONTWRITEBYTECODE=1 python -B artifacts/mvdm-audit/cross-369/ole-alias-observer.py`; no source, guest, build graph or ledger was changed.

`wole2.h` is byte-identical to both original editions. `precomp.h:139` includes it, and the selected `wole2.obj` has a **VALID** Ninja dependency on that exact relative header path and precompiled header; normalization against the WOW32 build directory resolves to `src/mvdm/wow32/wole2.h`. `wow32/sources` and the cached graph both select `wole2.c`. The header defines `ISTASKALIAS`, the scalar selector-shaped task-alias test, and declares the selected owner's add/find/remove/get and bounded process-name operations. It is therefore an active original interface, not an unused guest source or permission to reconstruct OLE.

Original `walias.c::ThreadID32toHtask16` selects actual WOW task state for known worker threads and otherwise finds/adds a foreign-thread alias; `Htask16toThreadID32` dispatches alias-shaped values to `GetHtaskAlias`. Original `wuwind.c` consumes the alias for foreign window ownership; `wkernel.c` obtains the bounded process image name. `wole2.c` is the sole 32-slot original alias table owner. The host owns live thread/process identities and observations; the record stores IDs and creation time. T452's registered `MVDM-HOST-DIV-450` adjusts only the query/copy boundary and is in `wole2.c`, not this unchanged header.

`m0-t459-s3-ole-alias-consumer-boundary.md` and `m0-t452-s3-alias-winoldap-audit.md` record an actual selected-body fixture: selector shape, bounded names, 32-slot oldest replacement, stale PID/time rejection and explicit removal passed. This is a real, bounded provider witness, not proof of guest OLE client/server interactions, every failure or concurrency. Recommendation for `wole2.h`: **partial / selected original interface**, retaining known exact source and dependency and the concrete alias witness; do not call the whole OLE feature full. Header-only byte identity is not a numerical runtime coverage estimate.

Static edge cases require S14 follow-up: `GetHtaskAlias` dereferences `lphtaskalias[iSlot]` after checking alias-shaped range and slot but does not itself check whether the table was initialized; whether an externally supplied alias-shaped value can reach it before allocation is unproved. `GetThreadIDHTASKALIAS` assigns fields following `NtQueryInformationThread` without checking that query status and also ignores the success of `GetThreadTimes`; a failed observation could leave identity data untrustworthy, but this review did not induce either API failure. Test reachable invalid/uninitialized selector, native observation failure, ID reuse, concurrent add/find/remove and exact 32-slot eviction against original observable semantics; preserve failure and thread/process handle cleanup. No new registry or guest patch is proposed.
