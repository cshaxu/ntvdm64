# S10 part 9: raw spool interfaces and historical loader declarations

Only owned `wow32/wspool.h` and `wow32/winspldl.h` receive proposed dispositions. `spool-header-observer.py` records comparison hashes, cached WOW32 source edge and `VALID` Ninja dependencies of `wspool.obj`, plus bounded historical declaration-name references; reproduce with `PYTHONDONTWRITEBYTECODE=1 python -B artifacts/mvdm-audit/cross-369/spool-header-observer.py`. No runtime/guest/ledger changes or tests occur here.

The two headers match both original editions. `wspool.h` is included by `walias.h`, is a VALID dependency of selected `wspool.obj`, and declares the original GDI raw spool operations, 15-entry shared provider table and Win16 job-carrier helpers. `wgtbl2.h` binds OpenJob, WriteSpool, CloseJob and related ordinals to `wspool.c`; its `WG32OpenJob` first loads the shared native WINSPOOL functions and resolves the original `[devices]` profile, then starts a native printer job and returns a local 16-bit carrier containing the native handle. The native spooler owns the real handle/job; the original WOW local allocation owns the guest carrier. Device setup and fax use distinct consumers of the same provider table; do not reassign ownership to a new spooler subsystem.

`winspldl.h` instead declares separate `lpfn*` globals and `LoadWinspoolAndGetProcAddresses`; bounded searches of the current sources and the OpenNT reference WOW32 directory find those names only in this file. No matching dependency appears in the selected `wspool.obj`. That supports an unselected historical interface for these profiles, not the absence of printing or a conclusion about all alternate binaries/configurations.

Prior `m0-t468-s2-hdc-print-witness.md` records a real Win16 normal/cancel PDF HDC route and a separately observed raw `OpenJob=0` when the required legacy profile is absent. These are distinct entrypoints: the HDC pass does not prove raw job success, and the negative profile test does not establish provider failure cleanup. The named provider and historical test artifact must remain attached to those claims.

Static failure boundaries: `WG32OpenJob` acquires guest argument/string mappings before a library-load failure returns directly, bypassing the normal release sites; establish mapping semantics and test actual acquisition/rollback. If native `OpenPrinterA` succeeds but `StartDocPrinterA` fails, the visible branch does not close the native printer handle; if starting succeeds but `GetPrn16` cannot publish a valid carrier, determine cleanup responsibility for both document and handle. `Prn32` declares an uninitialized `h32` and returns it if guest lock/mapping fails; prove whether malformed or retired carriers reach this path before claiming an observed defect. `WG32CloseJob` overwrites its EndDoc result with ClosePrinter's and frees the carrier only on successful close: validate original caller-visible return semantics and repeated-close/failure cleanup, without inventing an alternative policy. These are source-level cases, not reproduced customer failures.

S16/S17 should use selected original thunks with controlled provider/allocation/guest-mapping faults plus a separately identified available native printer and unmodified guest. Cover missing/partial provider exports, empty/missing/valid profile, partial writes, native start/close failures, invalid or reused carriers, cancellation and task death; preserve normal/no-profile behavior and record any mirror divergence.
