# S10 WOW16 ownership follow-up

Scope: the 240 `wow16/` C/H rows marked `role-pending` in `host-ch-scope/inventory.csv` at observation time, not all WOW16 sources. There are 70 C and 170 H. The accompanying `s10-followup-wow16-ownership.csv` provides every exact path, current SHA-256, comparison to the primary OpenNT original, both historical catalog entries, any established guest witness and ambiguity notes. `s10-followup-wow16-ownership-scan.py` reconstructs that list read-only, without running Ninja or modifying caches or ledgers.

## Findings and proposed treatment

* **66 headers: bounded guest-build candidates**, not general proof that all host configurations cannot consume them. Each has the same current content hash as the primary original and the earlier `guest-header-round4-evidence.json` recorded a direct same-directory include in a guest C translation unit with a named Win16 target and recipe; this follow-up rechecked the source/header hashes and the include line. The earlier audit found no same-basename host include and no exact path in its four recorded build graphs/dependency snapshots. Group counts: WRITE 36, MMSYSTEM 8, REGEDIT 7, COMMDLG 3, DDEML 3, OLE 3, MCIOLE 2, SHERLOCK 2, TOOLHELP 1, USER 1. Conditional preprocessing, alternate/generated profiles, and runtime image lineage are **not** proven. Recipe and witness details are in the pre-existing JSON; exact paths and witnesses are in the new CSV. These are suitable candidates for the same bounded guest-source classification as the prior rounds, subject to the main audit owner's ledger decision, not unconditional exclusion from all future audits.
* **174 remain unresolved**, comprising all 70 C plus 104 H. A guest folder, identical original hash, or absence from four recorded graphs does not prove either exclusive guest construction or lack of host/shared use. This partition does not assert these files execute in the host, nor that they are fully reviewed. Per-file entries are retained in the CSV. `wow16/inc/print.h` has a concrete guest-use witness in `src/mvdm/inc/wowfax.h:72-78` under `_WOWFAX16_`; that single conditional use does not settle all consumers or change its current unresolved classification.
* Seven of these headers have **basename collisions**, not proven shared identities: `commdlg/commdlg.h`, `mciole/shellapi.h`, `mmsystem/debug.h`, `sherlock/str.h`, `user/user.h`, `write/debug.h`, `write/str.h`. The CSV records host include locations. Include resolution and any other configuration must be checked before classifying them shared or exclusive. A collision alone cannot prove the local header was included.
* No exact host/shared dependency has been positively established for these 240 in this follow-up. This is **not** a claim that none exists: the earlier observer only captured four specific graphs/dependency snapshots, with no coverage of every target/configuration, and this pass did not execute tools or resample dependency databases.
