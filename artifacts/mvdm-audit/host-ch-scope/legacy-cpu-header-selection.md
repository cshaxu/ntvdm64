# Legacy CPU 2.x and 3.x header selection

This is a bounded disposition of two physical header paths, not of CPU instruction, exception or interrupt capabilities. `softpc.new/base/inc/cpu2.h` identifies itself as the SoftPC 2.0 CPU register interface; `cpu3.h` identifies itself as the 3.0 interface. Each matches both frozen OpenNT editions in its ledger SHA-256. Neither is evidence that a 2.x or 3.x CPU is active in the product.

The current `softpc.new/host/inc/host_def.h:40-44` maps `CpuH` to `cpu.h` for `MONITOR` and `cpu4.h` otherwise. A case-insensitive literal search of all files under `src/mvdm` found no `cpu2.h` or `cpu3.h` references except their own identification comments. The previous [header family observer](../shard-1/softpc-header-family-review.md) found no direct C/H/INC/CPP include and no VALID worker dependency for `cpu2.h`; the [header crosswalk](../shard-3/pending-host-header-crosswalk.md) recorded zero VALID worker dependencies for `cpu3.h`. The source search and cached dependency observations are bounded to this checkout and captured build, not proof about absent external build profiles or runtime behavior.

Disposition: exclude these **two physical historical header paths** from the selected NT host implementation audit; do not delete them or infer that their functional obligations are excluded. The current CPU4/monitor owners and instruction, interrupt, register, fault, reset and lifecycle coverage remain in S11. A future profile selecting either historical header reopens its own applicability. No source or guest image was modified, and no behavioral test was run for this disposition.
