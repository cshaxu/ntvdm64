# Original WOWFAX property sheets: host ownership and failure boundaries

The latest host-candidate inventory keeps `fax/wowfaxui/wfsheets.c` and `wfsheets.h` pending. These are a separate original WOWFAX printer UI DLL, not generic WOW32 common-dialog implementations. Earlier [fax inventory](../nine-way/part-2/fax-boundary-review.md) identified the recipe but did not trace the individual dialog/cleanup path below. Both current files match both retained original editions: `wfsheets.c` SHA-256 `C43B25CB761CD8A3CA6DD95C3E4707B9A118544A1BCBC014CA5C780A40F0AAC6`; `wfsheets.h` `262CCB34768EABC0E64C6EA30096356C3823E5872A790991785CEA0B72CFCF0C`.

Original `wowfaxui/sources:28,53` selects the separate UI DLL and source; `wowfaxui.def:15-16` exports `DrvDocumentPropertySheets` and `DrvDevicePropertySheets`; `fax/printer.inf` associates that UI with WOWFAX. The checked current host graphs do not select the original separate DLL. Current WOW32 `wgprnset.c:89-96` instead delegates printer operations to dynamically resolved `WINSPOOL.DRV`; this is not proof that Windows actually installed or loaded the original WOWFAX UI, or that generic dialog code replaces its property sheet. Both exact physical files remain **pending** until the applicable printer/provider contract and product scope are established; S16 owns this feature boundary.

`wfsheets.h` defines `UIDATA`, with borrowed printer/devmode pointers and property-sheet callback/page handles plus start/end sentinel validation. `wfsheets.c` allocates and populates it in `FillUiData`, adds a `FaxOptionsProc` page in `AddDocPropPages`, stores it as property-sheet user data, handles `PSN_APPLY`, and invokes cleanup on error/destruction; its `MyGetPrinter` allocates and frees a spooler-info buffer. No generic dialog owner is a substitute for this private state or documented ownership without further evidence.

Two precise **source-level original failure candidates**, not reproduced product defects: (1) `FillUiData` declares `pPrinterInfo2` without initialization; if the first `LocalAlloc` fails, short-circuit evaluation skips assigning it, but the later `if (pPrinterInfo2) LocalFree(pPrinterInfo2)` reads it. (2) `FreeUiData` frees the two copied name fields but does not visibly `LocalFree(pUiData)` itself, including after a successful allocation and later cleanup. Determine the full ownership/callback lifetime before calling this a measured leak; these files are not shown active in the product. Test each allocation and spooler failure, page-add rejection, normal destroy, repeat/reentry, callbacks and borrowed printer/devmode lifetime using an isolated provider fixture only if S16 establishes this driver is applicable. No tests were run; no product, guest or shared ledger changed.
