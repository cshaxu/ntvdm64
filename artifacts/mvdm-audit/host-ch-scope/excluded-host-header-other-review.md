# Excluded non-generated host headers: original consumers

The EGA trace and HUNTER corrections described below were subsequently applied; this report preserves the earlier review snapshot. This is an exact-path, bounded source/profile check of the remaining non-CVID/non-MIPS/PPC/non-CPU30 excluded host header group from `excluded-host-header-census-review.md`. It does not run product or guest code. Exclusion means physical source role only, and original capability remains independently owned until proved.

| Original physical source(s) | Original use and observed selected owner | Decision / unresolved scope |
| --- | --- | --- |
| `softpc.new/base/inc/egatrace.h` | Original `ega_trcr.c` includes it under `EGA_DUMP`; the tracer defines the video access trace file and remains pending. | **Reopen pending:** the implementation/profile and trace file failure/teardown are still open; see `egatrace-header-reopen-review.md`. |
| `softpc.new/host/inc/nt_hunt.h` | `fprt.c` and `nt_hosts.c` include it under `HUNTER`; it declares `TrapperDump`, written by original `nt_hunt.c` in that profile. Current NT recipe does not select `nt_hunt.c`, but original `hosthunt.h` remains pending and `hunter.h` is partial. | **Scope consistency candidate:** if the original HUNTER diagnostic capability has not been decided, reopen this header and `nt_hunt.c` together; otherwise retain only an explicitly justified NT-profile physical exclusion, with diagnostics behavior tracked. Merely disabling HUNTER in PROD is not a feature proof. |
| `wow32/wgman.h` | Complete file is a comment-only header; `precomp.h` includes it but it contributes no declaration or macro. | Physical exclusion is justified; selected GDI ordinals and guest behavior remain separate. |
| `softpc.new/base/inc/host_cfg.h` and `host_hun.h` | Respectively an empty guard included by NT config and a plain-text historical rename notice, independently checked in `error-config-interface-review.md` and `hunter-rename-resource-review.md`. | Scoped exclusions are justified, not acceptance of NT configuration or Hunter functionality. |
| `swinhelp.h`, `swinmgre.h` | Historical SoftWindows HyperHelp context IDs and SoftWindows CPU-management interface. Exact current source searches found no direct includes in `src/mvdm` or `src/ntvdm-exe`; physical selected NT host context differs. | Do not infer current Windows help/CPU management semantics from these unselected host-product declarations. Preserve unresolved functionality and its selected owner where relevant. |
| `unix_asy.h`, `unix_cnf.h`, `unix_loc.h`, `host_fio.h` | Original Unix-specific asynchronous, config, locking and file host declarations, not a single substitute implementation. The captured NT product does not directly include these exact files. | An alternate-host physical exclusion does not validate NT I/O completion/cancellation, configuration, locks or handles; those remain with their actual NT owners and tests. |
| `hg_stat.h` | Original non-PROD GISP CPU statistics declarations. | Keep optional profiling/debug capability distinct from selected CPU instruction semantics; scope and required functionality must not be assumed from current nonselection. |
| `monsim32.h` | Original `host/inc/sim32.h` includes this only under `MONITOR`; non-MONITOR declares separate Sim32/SAS interfaces. The selected CPU40 product excludes MONITOR by policy. | CPU40 guest mapping, flush/free, failure/lease and lifetime remain mandatory; the MONITOR macro header does not prove them. |

`ccpupig.h`, initially excluded, is separately recommended for reopening in `ccpupig-header-reopen-review.md`. Source hashes were verified in the accompanying census. These checks are evidence-bound and must be reconciled with current ledger state before edits; no product, guest, or shared ledger was changed here.

The later [final-group review](excluded-host-header-final-group-review.md) corrects the original SOFTWIN_API usage of swinmgre.h and records the coordinator disposition; this preliminary snapshot does not supersede it.
