# SoftPC selected host memory and fullscreen declarations

This source and cached-object review covers three `softpc.new/host/inc` headers pending at the review snapshot; host_gen.h and nt_fulsc.h were subsequently marked partial. Each current header has the same SHA-256 as both OpenNT editions. This is static selection evidence; no guest, product, ledger or runtime test was changed.

| Header | Actual original code path and selected object | Decision / remaining evidence |
| --- | --- | --- |
| `host_gen.h` | Original `xt.h:62` includes it. The original `write_intel_byte_string` macro invokes `sas_stores(effective_addr(...))`; `bios/build_id.c:69` uses it to write `Base$` to the guest buffer for BOP 21. The cached `build_id.obj` VALID dependencies resolve the exact `host/inc/host_gen.h`, and the worker map attributes `_Get_build_id` to the original BIOS object. | **Partial:** the original memory-interface macro is selected by a concrete BOP owner. Guest pointer bounds, failures, state/retirement and unrelated macros remain to be tested; this is not proof of full BOP behavior. |
| `nt_fulsc.h` | Original fullscreen/console declarations include `MID_VAL` and VGA heights. Selected `nt_fulsc.c:524-598` uses them in `calcScreenParams`, choosing legacy heights based on actual console dimensions. The cached `nt_fulsc.obj` VALID dependencies include this exact header, and the cached NTVDM map attributes `_calcScreenParams` to that object. Other source references to `MAX_CONSOLE_WIDTH` include blocks under `#if 0`, so their text alone must not be treated as active. | **Partial:** source/macro selection is established, not successful CAF handoff, all display sizes, input, title or cleanup behavior. Current application-facing console/frame sizing must be checked through its actual owner rather than inferred from legacy constants. |
| `host_hfx.h` | Original HFX declarations/error tables are guarded by `HFX`, with its debug text additionally guarded by `!PROD`. Cached `bios.obj` lists the file in VALID dependencies, but observed worker flags do not enable HFX; the separate original `nt_hfx.c` identifies itself as a stub. | **Pending:** determine original host-file-exchange capability and provider closure rather than claiming restored behavior from an inactive include or success-returning stub. |

The presence of `_calcScreenParams` and `_Get_build_id` in the cached map establishes extraction into that built image, not invocation in an installed package or complete behavior. Preserve nonselected profile obligations, source-divergence registration and current-artifact testing in their respective stages.
