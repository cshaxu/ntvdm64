# DEM date/time: selected-object observation

`demdisp.c:120-128` selects the original DEM service handlers in `demgset.c:447-548`. Original guest sources reference date services in `dos/v86/doskrnl/dos/time.asm:45,67` and time query in `dos/v86/doskrnl/dos/file.asm:658`; service numbers are defined in `inc/DOSSVC.INC` and `inc/dossvc.h`. This is source-level reachability, not a guest execution claim.

Reproduce from repository root: `python artifacts/mvdm-audit/host-ch-scope/dem-clock-run.py`. It links the selected MSVC x86 release `worker/obj/dem/demgset.obj`, recording its hash, fixture hash, output and diagnostics in `dem-clock-observation.json`. It copies the object into `build/t473-s10/dem-clock-probe`, rebinding only imported `GetLocalTime` and `SetLocalTime` to deterministic test callbacks. It never changes the host clock. CPU register accessors and the MSVC security-cookie check are test seams; the security check stub does not validate stack protection. GNU ld reports an ignored MSVC `.drectve` warning. Object hashes do not themselves prove correspondence with a later build: rebuild and compare them before reusing the observation.

The actual selected code returned the supplied weekday/date and the hour/minute/second plus truncated hundredths; set-date preserved the fake current time; set-time preserved the fake current date and converted hundredths to milliseconds. Set-date success returned AL=0; set-time success via `ERROR_PRIVILEGE_NOT_HELD` returned AL=0 and another failure returned AL=FF. The latter privilege behavior follows the current original code, but this mock does not establish whether real system clock changes succeed, nor validate date/time ranges, timezone transitions, concurrency, guest interrupt dispatch or other DEM services. No production or guest file was changed. This is bounded evidence, not proof of full `demgset.c` restoration or a reason to classify unrelated functions as complete.
