# Excluded host C roles: memory, DPMI and CMOS provider checks

This review follows the previous `excluded-host-c-source-spot-review.md` and examines five further nonempty current physical source roles. It compares original source/selected provider; no real guest or hardware test was run, and no source or ledger was modified. All five current source hashes match at least one frozen original edition according to the previous 36-file rehash.

| Excluded file | Original role and actual selected provider | Conclusion and remaining capability |
| --- | --- | --- |
| `xms.486/i386/xmsmem86.c` | Original x86 monitor callbacks use `NtAllocateVirtualMemory` on native addresses. Original `xms.c` registers callback names in SAInitialize. `docs/etc/evidence/m0-t420-s15-xms-package-recovery.md` traces the CPU40-specific same-shaped adapter and states why durable direct native aliases are not composable in the standalone worker; XMS allocation policy remains original. | Exclusion is scoped to this direct native-address provider, not the XMS function. Current guest mapping, allocation/failure/zeroing, overlap and teardown still need their S12 tests. |
| `dpmi32/i386/dpmimisc.c` | Original x86 `DpmiDpmiInUse` and `DpmiDpmiNoLongerInUse` have empty bodies. The original `dpmi32.c` dispatch table references those names, and the cached worker map instead attributes them to `dpmimscr.obj`: its selected original bodies enable/disable emulator IRET and interrupt hooks. | This is a profile-specific alternative, not evidence those functions should be empty in CPU40. Verify original DPMI entry/exit, hooks, nesting and cleanup under selected owner. |
| `dpmi32/debug.c` | Original DPMI trace buffer and routines are gated by `#if DBG`. | Excluding the inactive release source body does not prove active DPMI failure diagnostics, guest errors or all debugging behavior. Verify the debug profile separately if required. |
| `softpc.new/host/src/x86_emm.c` | Original EMS/LIM host provider body is under `LIM && MONITOR` and uses the kernel-VDM path; current CPU40 policy prohibits MONITOR. Selected original NT EMS owner is separate. | Do not reintroduce the private monitor route as a substitute for CPU40 mapping; guest EMS handles, mapping, errors and retirement remain active recovery obligations. |
| `softpc.new/base/system/cmos.c` | Original generic CMOS implementation is distinct from `cmosnt.c`. Original NT `base/system/sources` selects `cmosnt.c`; captured worker map attributes `_cmos_init`, `_cmos_inb`, `_cmos_outb` to `cmosnt.obj`. | Only the alternate physical state owner is excluded. CMOS/RTC values, IRQ/EOI, persistence, reset and teardown must be checked against the selected original NT provider. |

No unconditional erroneous physical-file exclusion was established in these five samples. Selected provider mapping and original source identity alone do not establish full functional parity or prove the listed failure paths. Preserve the independent S11–S13 recovery records and actual guest/device checks.
