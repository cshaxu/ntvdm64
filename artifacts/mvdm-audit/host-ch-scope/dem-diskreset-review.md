# DEM disk reset: selected-object observation

Original guest `dos/v86/doskrnl/dos/misc.asm:303-313` calls `SVC_DEMDISKRESET` only when its `SCS_FDACCESS` word is nonzero, then clears carry. Service 23h is defined by `inc/DOSSVC.INC`/`dossvc.h`, and `dos/dem/demdisp.c:135` dispatches to `demmisc.c:608`. The host resets floppy and fixed disk providers in that order and clears the guest counter; current DIV-111 routes the counter write through the project guest-location API and requests termination on failure. This source chain does not prove guest execution in this fixture.

Run `python artifacts/mvdm-audit/host-ch-scope/dem-diskreset-run.py`. It links selected x86 release `worker/obj/dem/demmisc.obj` and substitutes controlled floppy, fixed-disk, guest-state and termination functions. The actual selected handler called floppy then fixed-disk reset and wrote zero on both success and failure; a successful write returned without termination, and a failed write called the termination seam once. The test does not perform physical I/O or terminate a worker. It uses a returning termination seam, so it demonstrates dispatch/order only, not real termination behavior.

Output, diagnostics and source/object/fixture/executable hashes are recorded in `dem-diskreset-observation.json`. GNU ld discards unrelated sections and reports its ignored MSVC `.drectve` warning. Real device reset, guest counter ownership and cross-thread lease binding, actual termination and guest dispatch remain untested here. Prior `shard-1/dem-media-sft-lifecycle-audit.md` and `shard-3/fdc-session-single-owner-design.md` identify the real state-lifecycle risks; this narrow mock is not evidence that those risks are resolved or that full DEM behavior is restored. No product, guest or shared ledger was changed.
