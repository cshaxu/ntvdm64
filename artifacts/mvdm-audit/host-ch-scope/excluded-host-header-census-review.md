# Excluded host C headers: original identity and profile groups

At the beginning of this check the four physical ledgers contained 192 `.h` rows marked excluded outside `wow16/` and `dos/v86/`: 183 current files and nine missing mirror paths. All 183 present files were freshly hashed and match at least one original-edition SHA in `frozen-file-reconciliation.csv`; none showed a current/frozen hash drift. All nine missing paths are CPU30 monitor/scaffold and the corresponding files exist in **both** original trees with hashes matching the frozen ledger. A missing current mirror is not a missing original.

| Group | Check and limitation |
| --- | --- |
| 44 `softpc.new/base/cvidc/*.h` | After comment/whitespace removal, each of the 44 has exactly three lines: `#ifndef`, `#define`, `#endif`; none contains an actual declaration or macro body beyond the guard. These empty physical headers can be excluded without excluding corresponding CPU/video/read/write operations, which must remain at their selected providers. This independently broadens the already retained `../shard-0/cvidc-empty-guards-review.md`; it is syntax/identity evidence, not rendering acceptance. |
| 111 `host/inc/mips/{prod,pig}` and 14 `host/inc/ppc/{prod,pig}` | Original `CDEFINE.INC` chooses those generated paths for non-386 processor profiles. The inspected CPU40 x86 worker dependency output contains none of these exact paths; x86 generated/header roots are different. Existing per-file records `../shard-1/architecture-variant-header-review.md` and `../shard-3/arch-generated-headers-review.md` distinguish path selection from byte identity. For example, MIPS and PPC `prod/gdpvar.h` match one another but differ from both `base/ccpu386/gdpvar.h` and the current generated x86 path; never substitute on basename. Their exclusion describes the alternate physical profile path, not whole CPU/video behavior or compatibility on another architecture. |
| Nine absent `v86/{monitor,scaffold}/i386/*.h` | The original files are present and identity-verified; current policy rules out using CPU30 as the product execution backend. Corresponding CPU40 IRQ, SAS, video, BOP, thread and lifecycle responsibilities remain separate test obligations. |
| Other originally 14 headers | `ccpupig.h` was identified as needing reopening because its old exclusion cited PIG implementations that are now pending; see `ccpupig-header-reopen-review.md`. `host_cfg.h` is a selected include with only an unused guard, reviewed in `error-config-interface-review.md`; `host_hun.h` is a plain-text rename marker, reviewed in `hunter-rename-resource-review.md`. The remaining historical host/Unix/UI/debug declarations need their own owner/profile evidence; this census does not individually certify them. |

Exact-path Ninja dependency searches found two of the originally excluded current headers in the cached worker configuration: `host_cfg.h` and `ccpupig.h`; neither is proof of active original behavior. Ledger edits may already have reopened the latter after the initial count; re-read current authority rather than applying frozen counts. No guest, product, shared ledger or runtime test was changed by this audit.
