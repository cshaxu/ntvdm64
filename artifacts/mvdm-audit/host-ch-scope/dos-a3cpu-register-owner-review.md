# DOS host CPU register provider: A3CPU adapter physical role

This read-only follow-up covers one still-pending host-candidate C path, `softpc.new/obj.vdm/c_regs.c`; the selected `ccpu386/c_reg.c` and CPU access code are already audited owners and are not reclassified here. The original `c_regs.c` describes an assembler CPU register bridge for DEM/WOW32/XMS clients. Its bodies are conditioned on `!MONITOR && A3CPU && !CCPU` and delegate the `c_get*`/`c_set*` API to `a3_get*`/`a3_set*`. Current and primary OpenNT source SHA-256 both equal `9AB5185CD9D8A3CA163BF4654321C31C73ADCF3127BC574A3A4574CC1366DE95`.

The selected product uses CPU40 CCPU, with `base/ccpu386/sources:90` selecting `c_reg.c` and current worker graph compiling `obj/ccpu/c_reg.obj`; no `obj.vdm/c_regs.c` graph edge is present. Observed selected object SHA is `5309A08CDB4A68EF53A2CEBBE0DD7F4B9BF5061DD61B9F40DA7FEB9EC738733B`. Current worker map SHA `E8024EF9250C9834601A1A32674EA6E46D3E9E6526BBC6A0BE864A40E50C3C03` attributes representative `c_getAX`, `c_getBX`, `c_getCF`, `c_getCS`, `c_getCX`, `c_getDS`, `c_getDX`, `c_getIP`, `c_setAX`, `c_setBX`, `c_setCF`, `c_setCS`, `c_setCX`, `c_setDS` bodies to `original-ccpu386:c_reg.obj`. This establishes a concrete selected original provider, not equivalence of the historical A3CPU implementation or all its register semantics.

A separately retained [bounded CCPU/PIC probe](ccpu-bit-ready-probe-review.md) executes the original fixture's `load_sw_cpu_access_functions` checks: actual function slots must select `c_getAX`, `c_setAX`, `c_getCF`, `c_setCF` and the CCPU executor, then AX/CF set/get roundtrip must succeed before the later PIC and bit markers can be reached. Its map lists these four symbols under `original-ccpu386:c_reg.obj`. This is a controlled original-object/fixture observation for AX and CF only, not proof of all registers, guest exception state, A3CPU behavior, latest installed-image identity or lifecycle.

**Recommended disposition:** `excluded` for the physical A3CPU register bridge under the observed selected CCPU product architecture only, if the ledger permits this bounded scope. It is an alternative bridge and is not the actual selected source of register calls; retain the file. S11 continues to own original CCPU register, segment, exception and nested/lifecycle correctness, and S17 must separately assess A3CPU profile if that historical architecture is admitted. Do not interpret the physical exclusion as a statement that original CPU-register functionality is absent, complete or interchangeable across architectures. If the ledger's exclusion means all configurations, retain pending instead.
