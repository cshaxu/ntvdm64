# EDIT tab-stop: three synchronous routes and clean object probe

`WU32CallWindowProc` (`wumsg.c:173,210-248`), `WU32SendDlgItemMessage` (`:1774,1822-1851`) and `WU32SendMessage` (`:1894,1937-1964`) each construct a message context, use `ThunkMsg16`, call the native target, put its result into `mpex.lReturn`, and invoke the class unthunker when `MSG16NEEDSTHUNKING`. Their exact argument and unwind behavior differs and must be tested independently. `wmsg16.c:48-53,154` assigns EDIT `UnThunkEMMsg16`; the accidental fallthrough is in that shared body. These static routes do not alone prove all three were run with EDIT, nor that every PostMessage path is equivalent.
