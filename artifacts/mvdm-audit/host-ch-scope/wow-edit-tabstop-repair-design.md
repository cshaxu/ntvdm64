# S15 EDIT tab-stop unthunk: bounded repair design

## Evidence and cause

`wmsg16.c:48-53,154` selects `UnThunkEMMsg16` for the EDIT class. In `wumsg.c` the SendMessage, SendDlgItemMessage and CallWindowProc paths capture the native result into `mpex.lReturn` and call the selected unthunker. `wmsgem.c:246-252` frees the tab-stop conversion buffer for the same signed positive count used at acquisition, then falls through to the separate `EM_GETWORDBREAKPROC` return conversion. Both retained original source editions have the same fallthrough (SHA-256 `88D05E4770453621472704E90EDCEFD6AD18B618528B4166DA3A9BA1EA1A3619`); current source hash is `251325307C9E698EE579E3493F15F93ABB6DAFE7D289F334AC3714C513566BE9`. This is an inherited original-host defect, not caused by DIV-346.

An actual selected-object seam fixture found native result 1 enters the word-break branch, invokes its callback seam and sets `W32WordBreakProc` to 1; result 0 does not. `/FORCE:UNRESOLVED` limits that historical fixture to its executed branch. Two gated Win16 runs observed the first successful EDIT tab-stop call and same-worker `W32WordBreakProc` changing 0 to 1; the second records staged DLL identity and matching mapped section hashes. These are non-atomic snapshots, not direct entry breakpoints, and neither establishes an ensuing crash. Details and exact hashes: [existing observation](../shard-2/wow-edit-tabstop-unthunk-review.md). `wuman.c:208-219` later calls that global as a function pointer on the word-break thunk path, making the corrupted value a concrete invalid-call risk, not an observed later crash.

The [clean-link object baseline](tabstop-link-route-review.md) repeats the zero/one result against the cached selected object without `/FORCE`, using explicit fail-closed seams for unrelated paths. It also records all three synchronous source routes. It remains a controlled pre-fix witness, not a fresh product build or a complete callback/lifecycle test.

The [controlled release matrix](tabstop-release-review.md) separately exercises twelve count, storage and return-value combinations in the cached selected object. It confirms the observed cleanup predicate and the existing result-one corruption, not constructor reachability, post-fix behavior or real guest lifecycle.

The [three-route evidence review](tabstop-three-routes-evidence.md) distinguishes the existing real EDIT `SendMessage` witness from other-message `CallWindowProc` evidence and the missing `SendDlgItemMessage` EDIT witness; a test-owned NE probe may cover these without modifying an existing guest image.

## Minimal correction

Add a `break;` after the existing signed-condition `STACKORHEAPFREE` inside `UnThunkEMMsg16`'s `EM_SETTABSTOPS` case, with a new narrow registered mirror-diff exception explaining that a Boolean result is not a word-break procedure. Leave allocation predicate, release, result, `EM_GETWORDBREAKPROC` conversion and its callback/identity handling intact. Do not zero or replace word-break globals: an already registered legitimate procedure must survive the unrelated message. Do not modify guest or change the original control's actual tab-position behavior. This removes accidental callback and prevents corruption; it is a documented observable change to inherited behavior, not an assertion the two messages were previously independent in the source.

## Finite acceptance matrix

1. Compile and link actual current selected object in a controlled seam fixture without unresolved imports. Test positive and zero native result, guest counts zero, positive stack-backed and heap-backed, and negative signed count; assert exact result preservation, exactly one applicable heap free, no free for stack/zero/negative, no word-break callback and unchanged `W32WordBreakProc`/`WordBreakProc16`. Exercise failed positive allocation and existing unwind to rule out leaks/double free.
2. Separately test actual `EM_GETWORDBREAKPROC` branches: zero, tagged guest selector including high-bit restoration, native untagged callback success and failure, and already-cached guest procedure. Check returned identity and call count, including nonzero global prestate before `EM_SETTABSTOPS`; ensure nested callback and control/task retirement do not mutate unrelated state or double free.
3. Repeat the existing staged gated unmodified-runtime guest probe with freshly source-bound candidate WOW32 and staged DLL hash, looking for unchanged pre/post word-break state and successful tab set/reset. Run an actual real guest registered word-break/get and tab-stop sequence, native success/failure where possible, plus EDIT/message regression; distinguish process snapshots from entry tracing. No claim of post-fix crash prevention without a witness of that downstream behavior.
4. Verify each existing SendMessage/SendDlgItemMessage/CallWindowProc selected path and exception/unwind ownership independently. Async PostMessage pointer behavior is a distinct contract; do not alter or claim to have tested it merely by this fix. Preserve any successfully applied tab stops; no additional render/layout changes.

The original defect means a new `MVDM-HOST-DIV` registration and normal source-policy review are required. Cached objects and prior guest run identities are witnesses of their snapshots only. No product, guest, or shared ledger changed in this design review.
