# WOWFAX driver/UI shared-data owner

This is a deeper ownership pass for three pending files, complementing the earlier [fax scope inventory](../nine-way/part-2/fax-boundary-review.md) and [WOW32 client trace](../shard-1/wowfax-trace.md); it does not assume a fax printer is installed or execute one. The current and both original editions match byte-for-byte: `fax/faxcomm.h` SHA-256 `3F0EBB1007332C1C02B6B32AF42577992886F5E2447433C0193CC89B988B25F4`, `fax/wowfax/wowfaxdd.h` `B198E348FAD62C416D8451DDD24E25F76132786A1CC8AED6A9C4B481F7518129`, `fax/wowfax/wowfax.c` `CF77AD0A7FAD02C80A872C388EBF5B38D59E69CCA2B84C36D316734C095381D4`.

| Pending path | Original DLL target / contract | Evidence-supported classification |
| --- | --- | --- |
| `fax/faxcomm.h` | Shared `FAXDEV` layout, mapping and `DRV_ESC_*` values included by the driver and separate WOWFAXUI source. It is a true cross-boundary interface, not merely a duplicate declaration. | Keep pending: exact provider applicability, 32-bit layout and pointer/handle ownership require S16. |
| `fax/wowfax/wowfaxdd.h` | Original GDI-driver private declarations, including `InitPDEV`, graphics engine and `faxcomm.h`. | Keep pending with separate GDI driver provider/ABI. |
| `fax/wowfax/wowfax.c` | Original `fax/wowfax/sources` explicitly sets `TARGETTYPE=GDI_DRIVER` and selects this file; driver function table exposes `DrvEnablePDEV`, `DrvDisablePDEV`, `DrvEscape` and rendering functions. | Historical separate provider, not shown selected in current product graph or installed host; preserve S16 fax/printing. |

The driver `DrvEnablePDEV` identifies the UI-supplied client FAXDEV after DEVMODE, allocates a **separate** server FAXDEV with `EngAllocMem`, and `InitPDEV` copies the layout. Its source expressly warns that client pointer values cannot be dereferenced server-side. `DrvEscape` can return the saved client identity, or copy server bitmap bytes to a caller-provided buffer; `DrvDisablePDEV` frees the server allocation and palette. UI `wfhelper.c::InterProcCommHandler` owns its named mapping: it unmaps/closes an existing mapping before replacement, creates/maps a new one and closes on mapping failure; `wowfaxui.c` fills `WOWFAXINFO` and encodes certain payload references as offsets relative to its view. The original guest WOWEXEC fax window and selected WOW32 fax client are a further protocol boundary, not the GDI driver itself. These are source ownership observations; mapping existence, valid cross-process pointer interpretation, synchronization, callbacks and cleanup are not tested.

The [prior trace](../shard-1/wowfax-trace.md) identifies WOW32's registry/client integration and historical absence of named driver files in one package, but does not exclude an external installed provider. S16 must first establish exact loaded driver/UI/guest hashes and legitimate applicability; only then test mapping sizes/offsets, no unsafe server dereference of client pointers, normal and failed enable/disable, view/handle lifetime, nested page callback, peer/task loss and error propagation. Do not import or modify the original guest, invent a second FAXDEV authority or infer successful printing from the source table. No runtime tests or shared-ledger/product edits were performed.
