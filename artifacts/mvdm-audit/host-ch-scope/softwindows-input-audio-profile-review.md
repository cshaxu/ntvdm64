# SoftWindows keyboard, sound and diagnostic host interfaces

This source-owner review covers three pending `softpc.new/base/inc` C headers (`msw_keyb.h`, `msw_snd.h`, `msw_dbg.h`). It does not change guest, product or shared ledger or execute a runtime test. The historical SoftWindows driver BOPs and the selected NT WOW32/runtime device routes are distinct architectures; absence of one does not prove either a compatibility failure or equivalence.

| Original declaration role | Original interface / current profile | Existing selected boundary and executable next step |
| --- | --- | --- |
| `msw_keyb.h` | Original MS-Windows keyboard driver virtual-key and keyboard conventions. `bios.c:453-463` selects `ms_windows`, `msw_mouse`, `msw_copy`, `msw_keybd` at BOP 98–9B only under `MSWDVR`; the current worker profile does not enable that flag. Source search did not identify an implementation of that alternate driver in the inspected current host tree. | Selected original NT input/controller owners include `nt_keycd`, `nt_event`, `keyba`; cached map binds `_host_key_down` to `keyba.obj`. Keep **pending** the original alternate profile's applicability and provider closure. Independently verify required Win16 keyboard layout/virtual-key messages, modifiers, error/teardown through the real NT/WOW path; a source map is not a test. |
| `msw_snd.h` | Original SoftWindows waveform-driver interface, result codes and buffer structure sizes. `bios.c:477-481` selects `msw_sound` BOP 9F only under `SWIN_HAW`; selected profile does not enable it. | Selected WOW32 original `wmmedia` and host WINMM are separate producers/providers, as detailed in `../nine-way/part-5/multimedia-semantic-reconciliation.md`. Its historical synchronous timer witness and map binding do not prove wave output, format/error or callbacks. Keep **pending** alternate profile assessment; independently test real required wave/MIDI open, completion/cancel, failure and task-loss on selected route. |
| `msw_dbg.h` | Original driver trace/error macros become no-op under PROD and active trace under non-PROD/MSWDVR_DEBUG. No direct current selected consumer of this exact header was established. | Keep **pending** until the original debug profile and provider closure are assessed. Real errors, guest exceptions and host diagnostics remain separately owned and need behavioral evidence. |

Do not activate an original BOP or introduce a second guest/host driver merely because historical declarations exist. Conversely, not selecting these SoftWindows-only physical paths does not waive required NT DOS/WOW keyboard, multimedia, debug, lifecycle and failure tests. If a bounded original behavior cannot be carried through the selected architecture, record the dependency and observable difference before any concession.
