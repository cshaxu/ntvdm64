# Alternate terminal and X host UI declaration boundaries

This is a bounded source audit of three currently pending `softpc.new/base/inc` headers. Current, OpenNT and OpenNT 4.5 copies of all three match byte-for-byte. Neither this result nor the selected Windows host object below proves historical X/terminal behavior is reproduced.

| File | Original interface and selected owner distinction | Recommendation |
| --- | --- | --- |
| `dfa.h` | Declares terminal display finite-state routines `dfa_run`, `dfa_load`, `dfa_init`, a 256-entry character mapping and terminal capability state. Searches of the current `src/mvdm` and `src/ntvdm-exe` trees find no source caller or implementation of those named functions and no direct include of this exact header. | **Pending:** identify original terminal provider/caller closure and whether its semantics remain required by the host UI. No conclusion about guest character output follows from the lack of an exact consumer. |
| `host_uis.h` | Declares an original X-style host UI structure using `XtAppContext`, `Widget` and `XmString`, plus dialog/panel constants. No direct include or `PT_WARNING` consumer was found in the current source trees. Selected Windows host code uses a distinct `host/inc/nt_uis.h`, not this same-named interface. | **Pending:** X-provider applicability/closure and any needed visible dialog semantics remain unverified. The Windows header is not a semantic proof of parity. |
| `m_errorp.h` | Declares alternate `X_error_*` functions and an X widget-based button record. No direct include or `X_error_conf` implementation was found in the inspected source trees. Selected Windows `nt_error.c` instead routes `host_error` to `ErrorDialogBox`; cached worker map attributes both names to `nt_error.obj`. | **Pending:** identify original error provider and assess which visible errors/choices matter; symbol attribution does not test error behavior, callback/close or failure propagation. |

No direct dependency on these exact three headers was observed in the cached x86 worker Ninja dependency list. Absence applies to the captured build only and is not a blanket license to remove original code, classify all associated capability excluded, or import an entire alternative host toolkit. `nt_error.c` and Windows configuration have their own separate tests and failure/lifecycle obligations; no new runtime test was performed for this review.
