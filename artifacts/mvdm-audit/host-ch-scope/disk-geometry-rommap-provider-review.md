# Disk-geometry and fullscreen-ROM alternate host interfaces

This source-level review covers pending `softpc.new/base/inc/disk_geo.h` and `rommap.h`; it does not alter guest, product or ledger and performs no real media or ROM execution test. Both current files match both original editions at the frozen ledger identities.

| Original header | Consumer/provider trace | Recommendation |
| --- | --- | --- |
| `disk_geo.h` | Declares original `do_geom_validation` and disk geometry constants; the inspected `src/mvdm`/`src/ntvdm-exe` tree has no implementation or call of that exact function and cached production dependencies do not include the header. `host/src/nt_fdisk.c` independently declares several numerically matching legacy constants, but same values alone do not establish equivalent geometry validation. Its old `host_fdisk_rd/wt` bodies return zero for no disk, while distinct `nt_fdisk_read/write` use the physical DOS drive backend. | **Pending** original geometry provider/caller scope and validation semantics; do not claim this header selected or all disk reads fail/succeed based on another owner. |
| `rommap.h` | Original `ROMMapInfo`/`mapRange` describe a fullscreen host ROM mapping layout; source searches find those exact names only in this header and cached x86 dependencies do not list it. Current `rom.c` and original ROM sources are separately selected, but their existence does not instantiate this alternate host mapping interface. | **Pending** original fullscreen provider and boot/ROM applicability; do not treat this file as a proven duplicate, guest image fix or restored mapping state. |

The selected DOS DEM absolute I/O route reaches `demDasdRead/Write` and `nt_fdisk_read/write` for appropriate non-removable volumes, not necessarily the legacy `host_fdisk_rd/wt` route. Existing `../nine-way/part-8/dem-absolute-io-review.md` and `fdisk-open-close-failure-review.md` document source-level failure/lease boundaries, not successful physical-device testing. Keep real volume reads/writes, unavailable host handle, ownership and retirement in the disk recovery stage; the legacy no-disk stubs are not proof that an observed product request uses them. No production test result was inferred in this review.
