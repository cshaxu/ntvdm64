# S10 DOS floppy service providers: pending physical roles

This is a read-only cross-check of the four current pending host-candidate C files in the original GFI/floppy family. Their live shard decision fields were read separately from the older `host-ch-scope/inventory.csv` status snapshot. No ledger, product, guest, or media was modified or tested here. Existing evidence below is package- and fixture-bounded.

| Physical file | Original implementation / current profile | Supported disposition and owner |
| --- | --- | --- |
| `softpc.new/base/disks/gfi_ibm.c` | `SLAVEPC` client transports commands to a separate IBM PC floppy controller. Original `disks/sources` lists it; selected PROD compiles/archives an object whose useful body is guarded out and has no executable section in the recorded object. | **Pending**: S13 decides applicability of the original external serial/controller capability and, if in scope, tests peer protocol and retirement. Current-product nonselection is not proof a local floppy operation or all profiles work. |
| `softpc.new/base/disks/gfi_sflp.c` | Original `SLAVEPC` FDC/DMA remote control and callbacks; same compile/archive versus empty active body boundary. | **Pending** with the `gfi_ibm` transport as one owner group, not an independent local backend. S13 verifies command/IRQ/DMA and failure/retirement only if the original external provider is applicable. |
| `softpc.new/base/disks/gfi_test.c` | Original non-PROD diagnostic tracer/pseudo-provider is compiled but gated out under selected PROD; the real GFI path does not thereby execute it. | **Pending** until S17 settles diagnostic-profile applicability; current release's inactive physical role is bounded, and synthetic success cannot establish floppy behavior. |
| `softpc.new/host/src/nt_vflop.c` | Original VFLOPPY branch is an OS/2-era file-backed B: implementation with hardcoded image/sidecar names. Original selected NT source manifest and observed current worker do not select it; its image-backed behavior is distinct from real removable drives. | **Pending** on S13 backend applicability, guest contract and format/lifetime evidence. Do not substitute `nt_rflop` for the image-backed provider without per-operation equivalence; do not activate hardcoded paths. |

The selected current path is original BIOS `diskette_io`/`diskette_int` → `floppy.c`/`fla.c` → per-drive `gfi.c` table → `nt_rflop.c` real-media host provider, or `gfi_mpty.c` when no drive is active. Selected source/image and bounded actual-object dispatch evidence are recorded in [disk owner reconciliation](../disk-native-role-review.md); the T420 S28 guest witness is only an INT13 no-media reset, not media read/write/format.

A separate existing [actual-object fault seam](../shard-3/disk-close-failure-audit.md) reproduces, under injected guest counter-decrement failure, both `nt_rflop` and `nt_fdisk` closing the real test handle and returning failure with open count still one; floppy also retains lock/owner, while fdisk clears them. That establishes an actual-object controlled failure transition, **not** that a live session or physical device naturally reaches it. S12/S13 must establish authoritative counter and native-handle ownership, successful and failed close, reopen, duplicate close, teardown, and real-session reachability before choosing a repair. Controlled test seam and `/force:multiple` limitations remain as documented.

The [GFI alternative provider review](gfi-alternative-provider-review.md), [functional handoff](../host-inc/gfi-functional-handoff.md), and [virtual/real owner review](virtual-real-floppy-owner-review.md) contain object hashes, source routes and finite validation. The older `host-tail-role-review.md` calls `nt_vflop.c` excluded as an unselected physical alternative; that is only supportable as a narrowly **observed current-profile** exclusion. It must not be interpreted as proving the original image-backed capability is unnecessary or equivalent; the current live pending decision preserves that unresolved S13 scope. No new physical-file or functional classification is silently applied here.

Future acceptance requires a controlled actual-provider failure/close fixture and, where an explicitly owned disposable backend is available, guest read/write, geometry, media-change, DMA/IRQ, errors and shutdown; no-media or tracing-only tests cannot substitute. Where no such backend exists, report the missing evidence rather than touching a user's device or asserting success.
