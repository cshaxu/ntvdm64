# `wuansi.h` physical role and ANSI thunk ownership

`wuansi.h` consists solely of a comment containing six historical `WU32Ansi*` prototypes. It is byte-identical in this tree and both retained OpenNT source trees: SHA-256 `8F2053340A73F78A3B558B8D27E9AE6F7A7D3F5D34A5B085EA84868142638228`. A bounded literal search of the project and both original WOW32 directories found no `#include` of this file; its appearance is its own comment. It contributes no live declaration even if included. Suggested physical-file classification: original comment-only historical header, not a selected provider. This is not a claim that the ANSI functionality is absent or should be removed.

The six active declarations are in `wulang.h:21-26`, included by `precomp.h:130`. `wulang.c:47,89,125,171,218,260` implements the corresponding thunks; `wutbl2.h:532-539,581-582` places all six in the original USER dispatch table, which is included in `aw32WOW` at `wowtbl.c:45`. The cached `wow32.dll.map:839-844` identifies all six functions in `wulang.obj`. For example `WU32AnsiLowerBuff` maps the guest buffer, calls the host ANSI function, flushes and frees its mapping. These are static selection/call-chain observations, not proof of any executed ANSI conversion. The original spelling is preserved even though the generic host API macro resolves under the selected compile profile.

The cached map may not represent a fresh build from the current source. Real guest calls, code pages/DBCS, single-character versus buffer input, boundary and failed mappings, return values and lifetime must be tested under the appropriate USER/language feature owner; this physical header classification must not erase those requirements. No product, guest or shared ledger was changed.
