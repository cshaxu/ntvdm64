# DEM debugging-state service: selected-object observation

Original guest boot source `dos/v86/doskrnl/bios/sysinit1.asm:875` calls `SVC_ISDEBUG`; `inc/DOSSVC.INC:75` assigns service 3Bh, and `dos/dem/demdisp.c:159` routes it to `demmisc.c:587`. Original guest sources consume `ISDBG_DEBUGGEE` and `ISDBG_SHOWSVC` as distinct flags (`msproc.asm` and `msdisp.asm`); values are defined in `inc/DBGSVC.INC` and `inc/dbgsvc.h`. This is a source call chain only, not a guest execution test.

Run `python artifacts/mvdm-audit/host-ch-scope/dem-isdebug-run.py`. The fixture links the selected x86 release `worker/obj/dem/demmisc.obj`, replacing the native query, CPU setter and `fShowSVCMsg` with controlled seams. For query failure, successful null port and successful non-null port, each with trace flag off and on, the selected object returned respectively AL=0, AL=0, or AL=1/3. It requested information class 7 and a handle-sized result each time. This tests conditional mapping, without attaching a debugger or changing host process state.

Output and SHA-256 of source, object, fixture and executable are in `dem-isdebug-observation.json`. GNU ld discards unrelated sections and warns about an ignored MSVC `.drectve`; a test-only security-cookie stub means this is not a stack-protection test. Real `NtQueryInformationProcess`, actual debugger attach/detach and ownership races, `fShowSVCMsg` initialization, guest boot/INT21 behavior, and installed-image identity remain untested. This narrow test does not establish full debugger behavior or complete `demmisc.c` restoration. No guest, product or shared ledger was changed.
