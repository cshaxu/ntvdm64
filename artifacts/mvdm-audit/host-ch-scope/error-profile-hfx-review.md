# SoftPC selected error constants and alternate profiling/HFX headers

This review addresses three currently pending `softpc.new/base/inc` host C/H rows. It reads source, cached Ninja dependencies and existing object symbols; no runtime, guest, shared ledger or product change was performed.

| File | Original role and observed x86 dependency | Recommendation and remaining proof |
| --- | --- | --- |
| `dterm.h` | Original terminal constants include fallback `EHS_MSG_LEN=1024`. The selected original `nt_error.c:43` includes it before `host_rrr.h`, whose original `EHS_MSG_LEN` has the same value; `nt_error.c` uses the value in message buffers and lookup/format calls. Cached `nt_error.obj` has a VALID dependency on this exact header, and the worker map attributes `_host_error` to that object. | **Partial** for the selected source-level error-size contract, not full terminal or error recovery. Buffer bounds, failed lookup, host dialog and shutdown semantics need targeted validation; unchanged source/include/map is not execution proof. |
| `profile.h` | Original profiling state and event definitions. `base/debug/profile.c` includes it unconditionally; cached `profile.obj` dependency is VALID. With observed profile flags, `PROFILE` is not enabled and `profile.c:3324-3328` emits three empty fallback functions. The cached object defines those functions, while this worker map does not list them. | Keep **pending** for original profiling capability and selected runtime applicability; compile/dependency does not establish live profiling or authorize calling all instrumentation unnecessary. |
| `hfx.h` | Original HFX redirector structures/functions are guarded by `HFX`. `bios.c` includes the file, and selected cached `bios.obj` dependency is VALID; observed profile does not define HFX and original HFX BOP sites are guarded. `nt_hfx.c` identifies itself as HFX stubs and several functions return hardcoded values; do not treat it as a complete provider. | Keep **pending** while original HFX applicability and host provider versus selected VDMREDIR/DOS semantics are resolved; inclusion or alternative redirector presence does not prove equality. |

The x86 object/map observations apply only to the captured build configuration. The candidate provider must not be switched or guest behavior declared restored from these source checks. Existing redirector, original-mode instrumentation, and host error paths retain their independent failure, lifetime and behavior obligations.
