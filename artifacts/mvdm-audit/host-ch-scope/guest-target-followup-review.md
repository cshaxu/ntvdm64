# Follow-up: additional original Win16 targets

This extends `guest-target-candidate-review.md` without changing its original snapshot. `guest-target-followup-observer.py` applies the same per-path checks and hashes the same four host graphs/dependency receipts, with five additional byte-identical OpenNT/current makefiles. The new `guest-target-followup-inventory.csv` still records all 473 original role-pending C/H rows; `guest-target-followup-evidence.json` records input/recipe/graph identities and counts. A repeated run against the same inputs was byte-identical.

The earlier 98 candidate guest-source roles remain unchanged. **45 additional C source paths** meet the conservative observed-profile criteria: MMSYSTEM.DLL 17, REGEDT16.EXE 12, TOOLHELP.DLL 10, WFWNET.DRV 5 and KillWOW.EXE 1. Their exact paths are listed in the CSV and each is sourced from an explicit target object list/prerequisite in a matching historical makefile, has matching original/current bytes, no conflicting same-basename assembler file, and no same-name literal host include or exact dependency/source mention in the four captured host graphs. The MMSYSTEM object names use `$Z` as the original build-directory prefix; REGEDIT includes its `COMMON1`/`COMMON2` objects through the explicit link dependency, not merely their textual appearance. WFWNET target selection is conditional, and debug/profile source branches may differ.

The full snapshot therefore contains 143 observed-profile guest-source candidates and 330 unresolved rows. These are physical-source roles only: they do **not** prove that any installed prebuilt Win16 binary came from these sources, that all code in them executes, or that MMSYSTEM, registry, ToolHelp, WFWNET or WOW task control are functionally complete. They do not authorize guest modification or compilation. Their actual host-side thunk, callback, provider and lifecycle capabilities remain in scope. The unresolved 330 include potentially shared headers, source variants, other target recipes and host-include collisions; no directory-wide exclusion is inferred. No guest, product or shared ledger was modified.
