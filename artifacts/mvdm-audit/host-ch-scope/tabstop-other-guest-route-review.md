# EDIT tab-stop: other two Win16 synchronous routes

## Original USER entry and host selection

Original `wow16/user/user.def` exports `SENDDLGITEMMESSAGE` ordinal 101 and `CALLWINDOWPROC` ordinal 122. `user3.asm:90` and `user.asm:352` declare the respective original `UserThunk` entries. The checked source identifies these guest thunk routes; it does not establish the currently installed USER16 image identity or actual execution.

`WU32SendDlgItemMessage` in `wow32/wumsg.c:1774-1851` obtains the full parent HWND and uses a static parent/item cache or `GetDlgItem`; a missing item returns zero before conversion. For a found item it obtains its 16-bit alias, calls `ThunkMsg16`, performs native `SendMessage`, saves its result, then calls the class unthunker. Its 0x7fff:0000 compatibility special case is limited to EM_GETRECT and is not a tab-stop rule. Test both a cache miss and a repeated cache hit and use a unique nonzero child ID; stale-window/reuse behavior is a separate lifecycle question.

`WU32CallWindowProc` at `wumsg.c:173-261` first runs `IsThunkWindowProc`. A native proc carrier goes through class-specific `ThunkMsg16`, native `CallWindowProc`, and the matching unthunker. A genuine Win16 proc instead goes through `CallBack16(RET_WNDPROC)`; it is a different branch and cannot demonstrate the native EDIT unthunk. Original guest `user/wsubcls.c:43-50` shows `EditWndProc` forwarding through `CallWindowProc`, reinforcing the importance of identifying the actual target. Test the native EDIT carrier retrieved via USER16 `GetWindowLong(GWL_WNDPROC)` and independently establish `IsThunkWindowProc` selects the native EDIT class; merely seeing a nonzero procedure or a successful unrelated button/COPYDATA test is insufficient.

## Correct behavior and finite validation

Original Win16 `user/editml.c:2871-2876` dispatches multiline `EM_SETTABSTOPS` to `MLSetTabStops`. `edmlrare.c:302-374` describes TRUE on success, FALSE for allocation/free failure, zero stops removing previous stops, and nonzero values converted from dialog units by average character width. This source is an original behavior reference, not evidence that the shipped immutable USER image contains these exact bytes or that this guest implementation directly runs in the selected host-control path. The selected host's independently audited edit behavior remains its own owner.

For each of the two actual entry routes run a fresh isolated identity-bound guest test-owned NE program with real multiline EDIT: 64 stops (heap conversion), 1 stop (stack conversion), zero-count reset, and controlled native failure; assert exact BOOL, displayed/queried tab behavior where observable, no spurious word-break callback and unchanged pre-existing word-break identity. For item routing include miss/hit and absent ID; for CallWindowProc include separately a real Win16 proc callback control to avoid confusing branches. Capture source, test binary and staged WOW32/USER image hashes. Pair before/after state snapshots with a controlled actual-object route fixture or non-invasive entry observation to prove the intended entry and native EDIT class. Exercise constructor failure, task/control destruction and callback reentry; no hangs, leaked buffers, corruption or duplicate cleanup. Follow the [probe design](tabstop-three-routes-evidence.md) and [original object controls](wordbreak-object-review.md). Never treat these historical different-message probes as evidence of these EDIT tests.

No new runtime evidence is claimed here. A test-owned NE executable can be created under build and run against unchanged supplied guest images; those images must never be modified or rebuilt.
