# SoftPC host display profile interfaces

Five pending C/H physical roles were compared against original OpenNT and all five match byte-for-byte. This is a source and cached x86 build-profile audit, not a guest display, screenshot, switch, recovery or full VGA compatibility test.

| File | Original role and selected-profile evidence | Remaining boundary |
| --- | --- | --- |
| `mda.h` | Declares the monochrome display adapter `mda_init/term/inb/outb`. `gvi.c:176-180,257-261` gates its MDA calls under `DUMB_TERMINAL`; the observed x86 worker profile does not pass that definition. | Original monochrome hardware/profile applicability and real producer/provider closure remain pending; no claim about monochrome applications running through VGA. |
| `herc.h` | Declares Hercules adapter entry points; `gvi.c:68-71,198-201,269-272` gates its include and calls under `HERC`. The cached `gvi.obj` VALID dependency list does not include `herc.h`. | Original Hercules profile and its functions are not established by selected VGA drawing; decide capability separately and do not silently exclude guest graphics modes. |
| `hwvga.h` | Defines hardware-VGA interfaces under `GISP_SVGA`; historical `vga_mode.c`, `ega_vide.c`, `mouse_io.c`, `reset.c` have gated includes. The cached `vga_mode.obj` VALID dependency list does not include this exact header. | Alternate GISP hardware provider is not demonstrated; preserve the original body and establish its dependency closure before any decision. |
| `gispsvga.h` | Original declarations are guarded by `GISP_SVGA`; `rom.c` and `bios.c` include this header unconditionally, and their cached VALID dependency records both list it. The unconditionally included header may compile to no declarations under this configuration; an include alone is not the hardware provider. | `rom.c` chooses its separate GISP ROM path only under `GISP_SVGA`; current V7VGA route and GISP scope are separate. |
| `vgastate.h` | Original struct stores register, plane and extended VGA state; a current source search finds no consumer outside the file itself. | State save/restore is a guest-visible functional question; do not declare it satisfied or absent based only on this alternate structure. Trace selected video/BIOS owner and exercise active save/restore paths. |

The x86 worker Ninja graph compiles the original `gvi`, `rom`, `vga_mode`, `v7_ports` and `v7_video` source objects; cached NTVDM map attributes `_gvi_init`, `_gvi_term` and Video7 extension symbols to their original objects. The observed generic flags include `V7VGA`, not `GISP_SVGA`. A map is evidence of selected object attribution, not runtime execution or equality of display semantics. V7VGA mouse-range acceptance is separately recorded; it cannot prove all MDA/Hercules/GISP or save/restore behavior. Existing C-VID mode, video page/plane, transition and failure work stays in the recovery worklist. No binaries were changed and no runtime test was run.

Replay: inspect `gvi.c`, `rom.c` and the five named headers; run `ninja -C build/.ninja/msvc-x86-release/worker -t deps obj/video/gvi.obj obj/system/rom.obj obj/bios/bios.obj obj/video/vga_mode.obj`; compare against recorded map and compiler flags. Recheck include dependencies for each later build profile.
