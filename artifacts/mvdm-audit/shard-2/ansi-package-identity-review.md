# Original ANSI.SYS package identity and startup boundary

This completes a bounded package identity check for pending `dos/v86/dev/ansi/ANSI.SYS`, complementing `dos-ansi-keyboard-review.md`. The current source-tree image is byte-identical to both original trees. The observer checks every file in the captured `assets/winnt.zip` by length and SHA-256: no archive member is byte-identical to this 9,029-byte image, even under another name, and no member ends in ANSI.SYS. `O:/winnt/system32/ANSI.SYS` is absent at capture. The archive's default `WINNT/SYSTEM32/config.nt` contains no active ANSI.SYS load. This closes the earlier renamed-exact-copy question for this one archive only.

Original ANSI source (`ansiinit.asm` and related files) defines device-driver functionality, while original COMMAND `tcmd2a.asm` refers to `Mult_ANSI` to detect the installed driver. This is a source-level guest call path, not proof that an installed driver was loaded. `config.nt` itself notes that a PIF may select another startup file. A separately supplied driver, changed CONFIG.NT, different archive/media, compressed/rebuilt image or ANSI-like functionality elsewhere cannot be excluded from this snapshot. Therefore do **not** classify ANSI behavior as absent or broken; keep functional availability and actual guest loading pending. At most the exact stock archive-image file role can be marked not packaged for this snapshot, subject to the coordinator's classification vocabulary.

Reproduce with `PYTHONDONTWRITEBYTECODE=1 python artifacts/mvdm-audit/shard-2/ansi-package-identity-observer.py` and compare JSON. It reads source originals, archive, and installed path without modifying them; no guest, product, build tree, process or shared ledger was changed.
