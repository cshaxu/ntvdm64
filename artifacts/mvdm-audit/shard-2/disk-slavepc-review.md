# Disk SLAVEPC FDC backend, current release profile

`softpc.new/base/disks/gfi_sflp.c` supplies the original SLAVEPC remote floppy controller backend (its source describes an FLA to 8272A RPC interface). Both reference editions and current source match byte-for-byte. The worker build explicitly compiles it and places its object in `original-softpc-disks.lib`, but the captured x86 Release object has no executable code section and no map ownership: its body is under `#ifdef SLAVEPC`. `gfi.c` likewise gates activation and dispatch of the slave backend under SLAVEPC. This is an inactive profile-specific backend, not evidence that all floppy functionality is missing or that alternate profiles can be deleted.

The separate active controller entry `_fla_inb`, from `fla.obj`, is present in the release map and binds to the published `ntvdm.exe` over 432 bytes with 40 relocation words masked. Cached and published image executable sections match, although their overall file hashes differ. Entry binding is not a test of command semantics, DMA, actual media, reset, interrupt or runtime backend selection. No guest execution or physical-media test was performed. The reviewer should classify the file as compiled but inactive in this captured configuration, retaining other configurations and floppy behavior as distinct questions.

Reproduce: from repository root run `PYTHONDONTWRITEBYTECODE=1 python artifacts/mvdm-audit/shard-2/disk-slavepc-observer.py` and compare output to the accompanying observations JSON. It verifies the two original hashes, current hash, pending membership at capture, graph, COFF section flags, map, guarded gfi calls and relocation-masked image bytes. No product, guest, shared ledger or build tree was modified.
