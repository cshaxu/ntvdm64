# Shard 2 historical build recipes and current generator inputs

43 unchanged/current-only historical recipe entries are enumerated with exact SHA and individual role in `build-recipe-consumption-review.csv`, from frozen ledger F73FFD45DFF44FCA4ECEFC49EF769BEAB5C085542CD04FFE4D6A7B5F942E3196. Three current Ninja product closures contain none of these exact recipe paths, but that is **not sufficient** to call a file unused: `tools/build/New-T310OriginalSoftpcNinja.ps1` reads seven original `sources` files at generation time via `Get-OriginalSources`. Their entries are classified partial: the original source list is consumed, but the original NT target, include, platform and build directives are not executed as a whole. Their documented selected consumer is configuration evidence, not runtime feature validation. The generator/Ninja graph controls selected source compilation; the old make system is not used to run the current worker.

The other 36 historical makefiles, makefile includes, object-list macros, directory recursion and standalone-component manifests are excluded **as recipe files only** for the inspected product generation/build. Their exact role and original target when present are in the companion CSV. They do not determine whether Fax, debugger, VDD, guest firmware, DOS, video, XMS, or any other corresponding component/capability is supported; those source entries remain separately governed. Independent optional tools must be evaluated on their own merits. No build recipe or source is deleted.

A selected-source generator may consume an original manifest before the emitted Ninja graph exists; future graph changes can change this classification. No product, guest or test execution was changed during this static review. Mirror-different source rows were not reclassified.

The recheck covers both named generators and `CMakeLists.txt`: CMake `ntvdm_generate` invokes T310 at configure time, while its WOW32 custom command explicitly depends on and T404 reads `src/mvdm/wow32/sources` and `wow32.def` (those two paths are not among these 43 shard-2 recipe rows). T310 explicitly reads the seven listed current manifests; no other listed legacy recipe is named as an input by these generator paths. CMake `DEPENDS` must be considered separately from `ninja -t inputs`. This finding is limited to the inspected product-generation path; standalone recipe capabilities remain pending.

The T310 parser extracts C filenames from the original SOURCES block, removes comment lines and stops before architecture or subsequent assignments. It then applies selected CPU40 profile choices and some additions. Seven source-list carriers are therefore partially integrated without claiming that the old NT build script runs, that every member is emitted unchanged, or that any constituent component has passed functional tests.
