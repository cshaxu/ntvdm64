# WOW scrollbar message conversion and call lifetime

Scope `wow32/wmsgsbm.c` in shard 2; frozen SHA-256 F73FFD45DFF44FCA4ECEFC49EF769BEAB5C085542CD04FFE4D6A7B5F942E3196. OpenNT/OpenNT45/current source SHA-256 CF1EA646693339E8C2B03875DAD6C7B4A92576FC80F330407E60231E2689B18E; direct object/map evidence in `wow32-selected-link-inventory.json`. No product or guest edit and no new runtime test; identical source does not justify full capability classification.

`wmsg16.c` class dispatch maps WOWCLASS_SCROLLBAR to the original `ThunkSBMMsg16` and `UnThunkSBMMsg16`; `wumsg.c` has real message entrants using an `MSGPARAMEX` call context. Win16 GETRANGE expects a packed return, so forward conversion passes two locations within the call context's `MsgBuffer` to the host; unthunk combines the resulting words into `lReturn`. SETRANGE sign-extends each packed 16-bit endpoint and maps redraw to the corresponding host message. SETPOS sign-extends position. Other mapped control messages have no pointer conversion; USER-range messages outside this range remain application-defined. The conversion itself does not allocate a persistent resource; its temporary output locations depend on the containing per-call context surviving the native call and any nested callback.

In the opposite direction `wmtbl32.c` selects `WM32SBMControl`, `WM32SBMGetRange`, `WM32SBMSetRange` in `wcntl32.c`: it maps native IDs to original Win16 message IDs, packs SETRANGE, and on GETRANGE return writes sign-extended 16-bit endpoints to the native caller's supplied locations. This is a separate callback direction; successful forward conversion alone cannot prove it. `wcntl32.c` is read-only outside this shard.

The existing table/object selection establishes composition, and broad T447/T457 control/dialog evidence cannot establish all signed range conversion or callback lifetime branches. Required witness: actual Win16 scrollbar/subclass operations in both directions for negative, zero, 0x7fff/0x8000 endpoints; GETRANGE output and SETRANGE redraw; nested message and destruction while call context is live; application-defined USER-range message outside mapped subset. Include one synchronous completion and one failed/retired target, and ensure output pointers are never retained after the call. This is a verification gap, not an asserted defect.
