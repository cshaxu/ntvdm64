# Oversized non-ROM resource close boundary

The earlier [ROM/CMOS source review](shard-1/rom-cmos-family-review.md) identified an original `host_read_resource` failure branch that returns when the opened file is larger than the supplied maximum, before closing the file descriptor. The [fixture](rom-read-failure-fixture.py) compiles the exact extracted current source body with fake file boundaries. Its [receipt](rom-read-failure-fixture-observations.json) records four checks: failed open does not close, a valid read closes once, an oversized file returns zero with no close, and embedded ROM bypasses the file path. This is a controlled source-level counterexample, not an actual leaked operating-system handle or proof that a live session selects such a file.

The [image observer](rom-read-image-observer.py) and [receipt](rom-read-image-observations.json) bind the 261-byte reader body, with relocation masking, to the released and installed worker. Original `cmos.c` invokes the non-ROM reader; ROM resources take the project embedded path. Before any repair, S13 must verify the actual resource location and ownership for a session, the real file and error behavior, and preserve existing original return/error semantics. A minimal repair, if this path applies, would close the already-open descriptor before the existing failure return; normal reads and embedded ROM handling must remain unchanged. Original-source modification requires the project's mirror-difference exception record and relevant DOS/WOW/Win3.x regressions. No product, guest, CMOS file or user configuration was changed by this audit.
