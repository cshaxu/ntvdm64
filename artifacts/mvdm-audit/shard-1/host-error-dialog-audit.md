## Actual path and termination

The original selected `ErrorDialogBox` suspends heartbeat, chooses DOS console or WOW thread window, starts `ErrorDialogBoxThread`, waits on the thread and reply, resumes heartbeat, and on abort invokes `TerminateVDM` for DOS; WOW notifies its task through `pW32HungAppNotifyThread`. CreateThread failure resumes heartbeat and terminates DOS, while WOW does not terminate the entire system. Current source retains this control flow. DOS thread uses `DialogBoxParam(... ERRORPANEL ... ErrorDialogEvents ...)`. WOW thread instead calls `WowErrorDialogEvents` -> `WOWpSysErrorBox` -> `NtRaiseHardError` with STATUS_VDM_HARD_ERROR, four arguments, Unicode mask and three button descriptors. Current `src/ntvdm-exe/win32/wow_private_unavailable.c` recognizes this through `mvdm_wow_hard_error_present`; unmatched requests take controlled unavailable exit. Presenter in `wow_hard_error_dialog.c` validates request shape, copies Unicode strings, decodes button ordinals, presents a public dialog, frees copies and returns only ordinals 1..3 or failure. On presenter failure original WOWpSysErrorBox returns 0, and original WowErrorDialogEvents maps unrecognized result to RMB_ABORT. The presenter is not an ERRORPANEL fallback.
