# Shard 1: CCPU interrupt entry and state transition

`softpc.new/base/ccpu386/c_intr.c` matches both frozen OpenNT sources. The observer binds `_do_intrupt` and four representative callers (`_INTx`, `_INTO`, `_Int0`, `_ccpu`) to the current release NTVDM code and resolves each caller's relative relocation to that exact entry. This connects software INT, INTO, divide fault and the selected CPU interrupt loop at image level; it does not establish a runtime vector occurred. The current exception/interrupt callers contain host-integration branches and must not be represented as byte-identical to original merely because `c_intr.c` is.

Original `do_intrupt(vector, priv_check, has_error_code, error_code)` owns destination validation and guest architectural state transition. In real mode it validates stack room, reads the IVT, pushes flags and return CS:IP, selects the new destination and clears IF/TF. In protected mode it validates gate type, presence, optionally privilege, and destination; task gate, same-level gate and more-privileged gate have distinct stack/frame rules, with an error code only when requested. Successful completion clears the original fault-tracking flags at the end. IRET and external device/PIC ownership are separate paths, so this source does not alone prove successful return or IRQ acknowledgment.

`intx.c` and `into.c` invoke `host_swint_hook` in protected mode before their original `do_intrupt` call; a handled callback returns without that call. `c_xcptn.c` handles divide exceptions and an NTVDM protected-mode hook before vector dispatch. These are caller-level paths, not additional interrupt-object ownership in the audited file. Their full side effects and fault recovery require separate review.

The current source/map proof is insufficient for real-mode IVT behavior, stack faults, nested/contributory/page/double faults, privilege transitions, 16/32-bit gates, task gates, IRET, or concurrent device delivery. The existing `ccpu-core-source-review.md` and shard S11 notes retain those obligations. Do not classify all interrupts as recovered from these four selected static calls. Replay `python artifacts/mvdm-audit/shard-1/ccpu-interrupt-observer.py` for hashed inputs and relocation evidence. No product or guest was run, no build tree or shared ledger was modified.
