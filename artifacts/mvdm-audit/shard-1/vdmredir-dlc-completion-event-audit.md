# DLC worker completion event failure path

Frozen source universe SHA256 F73FFD45DFF44FCA4ECEFC49EF769BEAB5C085542CD04FFE4D6A7B5F942E3196. Current `vdmredir/vrdlc5c.c` SHA256 850F2F1A746EEE3610F06EBF489CB662BCD628F556299E445DAAC7FDD24E9BBF matches frozen OpenNT original. The incorrect check is present in original as well; this is not a new mirror divergence.

`vrdisp.c` selects VrDlc5cHandler at service 0x27. `VrDlc5cHandler` first loads `DLCAPI` and requires AcsLan, DlcCallDriver, NtAcsLan exports; load failure returns LLC_STATUS_COMMAND_CANCELLED_FAILURE before initialization. Adapter initialization reaches `InitializeAdapterSupport -> VrDlcInit -> InitializeEventHandler && InitializeDlcWorkerThread`. The latter creates DlcWorkerEvent then DlcWorkerCompletionEvent but its second failure check tests DlcWorkerEvent again. If first CreateEvent succeeds and second fails, it therefore proceeds to CreateThread with a NULL completion handle, and may return TRUE if that thread starts; VrDlcInit may mark initialized. If thread creation fails, both handles are passed to CloseHandle, including NULL. If the worker starts, DlcCallWorker later calls SetEvent(DlcWorkerEvent), waits on NULL without inspecting the result, and returns the shared Status; worker also calls SetEvent(NULL). This is the source-level control flow conditional on both a reachable provider and injected event allocation failure; scheduling means return status must not be assumed to be a particular value. `InitializeEventHandler` precedes worker setup and its cleanup on failed worker setup deserves separate verification.

`build/.ninja/msvc-x86-release/worker/build.ninja` builds vrdlc5c.obj and includes it in VDMREDIR.dll link; no current output map/PE identity or fresh guest execution was verified here. Historical `docs/etc/evidence/m0-t420-s20-vdmredir-operation-matrix.md` and `m0-t420-s20-vdmredir-package-recovery.md` record real guest VDMDLC.COM reaching the original loader and receiving 07 on the then host lacking DLCAPI/DLC driver. That test did not reach worker initialization and does not establish the current host's provider inventory or show event-creation failure. Whether a future compatible provider can reach full execution remains an explicit capability boundary.

Minimal candidate if that provider path is admitted: check DlcWorkerCompletionEvent after second CreateEvent; on failure close only the valid first handle, return FALSE, and verify cleanup/retry of the already initialized event handler. Test actual extracted original/current owner with injected first-event, second-event and thread failure, and successful creation; separately prove DLC provider/guest integration before claiming runtime repair. Preserve original guest, callbacks and wire protocol. No test or code modification was performed in this audit.
