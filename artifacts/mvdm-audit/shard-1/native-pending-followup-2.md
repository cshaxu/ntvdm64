# Native SoftPC review — shard 1, frozen pending indices 30–89

`native-pending-followup-2.csv` covers exactly the next 60 sorted paths in the intersection of shard-1's original native pending inventory and `ecd4a604a:artifacts/mvdm-audit/combined-initial-status.csv`, with original/current/frozen SHA-256, per-file original role, observed selection/call chain, evidence limits and S11/S13 owner. This set is disjoint from the first 30. The checked source bytes match both frozen OpenNT editions.

Fifteen proposals are partial: original selected CPU providers and their declaration files for LGDT, LLDT, MOV, MUL, PUSHA, ROR, SAR, SGDT, SHR, SLDT and SMSW have bounded existing object/fixture evidence. These tests do not prove all decoding, actual guest state, page/privilege/stack faults, lifecycle or alternate profiles. In particular native MOV is inlined by c_main; the `mov.c` provider handles special registers. The shift tests deliberately omit undefined flags and some counts, and LLDT/stack/descriptor fixtures use test-local stubs. Partial does not imply an estimated restored-code or behavior percentage.

`softpc.new/base/comms/prt_scrn.c` is a distinct positive file-role exclusion candidate: the original file has only a comment stating its function moved to Intel BIOS4.ROM, and current source is identical. The selected graph **does compile** `prt_scrn.obj` and link it into the comms library; it is an empty translation unit, not an unconsumed source. This proposal excludes no Print Screen capability; BIOS ROM identity, INT5 route and output/failure behavior remain S13. By contrast `wait.c` contains a selected no-op `WAIT()` function and is not an empty translation unit; its overall CPU/FPU semantic ownership remains pending.

The remaining 44 paths remain pending. Generated C-VID headers expose types/constants or sometimes guard-only contents; selected or cached inclusion does not establish which conditional declarations or generated drawing vectors actually run. The eleven `sevid` files have selected object/map and historical vector publication/text evidence, but every actual symbol's mode/plane/latch dispatch and guest behavior is not proven. These are S13 work, not bulk exclusion or full restoration. CCPU addressing, stack, descriptor, register/operand and profile questions remain S11.

This pass did not run tests or compilation and changed no source, guest, main ledger or another shard. Previously recorded tests remain tied to their own object/fixture identities.
