## Relocation-aware binding of the candidate failure path

The standalone `_InitializeDlcWorkerThread` section 25 did not match either PE, so its object existence alone must not be reported as linked. `objdump -t` identifies section 23 as `_InitializeAdapterSupport`, containing inlined worker initialization. Its full 686-byte section matches both PEs at file offset `0x6ac0` after masking only the 4-byte fields at its COFF relocation offsets; every non-relocation byte matches. Object relocations at section offsets `0x62` and `0x76` name `_DlcWorkerEvent`; `0x7c` names `_DlcWorkerCompletionEvent`. Both PEs resolve those fields respectively to `184c0310`, `184c0310` and `144c0310` in file byte order. Thus both image code regions retain separate event addresses and the same first-event check. This binds the optimized candidate branch into both checked images, without proving provider reachability, allocation-failure reproduction or actual instruction execution. It does not require standalone section 25 to survive linker elimination.
