# DOS core and device historical guest ownership — shard 1

`dos-core-guest-owner-review.csv` covers 91 pending source/declaration/resource rows in the specified DOS trees, with frozen and checked original hashes. Fifty rows have a candidate historic guest-build-source-file-only role, and 41 remain pending. Candidate counts: NTDOS.SYS 15, NTIO.SYS 8, KEYBOARD.SYS 16, REDIR.EXE 8, HIMEM.SYS 2, COUNTRY.SYS 1. Existing prior review reported no host target input for these source rows; main reviewer must still perform its independent current-graph and immutable-hash checks before merging.

Original make and actual link responses were traced: DOS `msdos.lnk` objects → ntdos.bin → stripz ntdos.sys; BIOS `msbio_4.lnk` objects → ntio.exe → reloc ntio.sys; keyboard `keyboard.lnk` objects → keyboard.exs → keyboard.sys; HIMEM's explicitly linked six objects → EXE → reloc BIN → stripdd SYS; REDIR's explicit OBJS and `.asm{$(OBJPATH)}.obj` MASM inference rule → REDIR.EXE link16; COUNTRY's country.asm includes mkcntry.inc and make builds OBJ→EXE→SYS. Each selected candidate names its exact original source dependency/include site and target lines. Keyboard sources are not included merely for being layout files: linked object membership and non-commented source rule were both checked.

Common `dos/v86/inc` candidates require an actual MASM include from a linked source and the historical make dependency names; include and flags are subject to original assembler conditionals. `redir/usa/redirmsg.inc` requires default or explicitly USA COUNTRY, with make copying it into the source directory before assembling REDIR. Generic include-site evidence does not prove a particular configured build expanded every conditional macro. Files such as prebuilt BIN/EXS, message resources, other locale layouts, C runtime headers and sources lacking a verified link chain remain pending.

These are decisions only on source file role as modern host compilation input, not dismissal of any device, DOS, redirector or locale ability. Original/current image lineage, guest execution, interrupt/host ABI and behavioral compliance remain independently open. No guest or product source changed or was built here.
