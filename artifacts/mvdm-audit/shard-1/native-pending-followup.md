# CCPU original behavior follow-up — first 30 pending shard-1 paths

`native-pending-followup.csv` contains the first 30 lexicographically sorted paths that remain pending in the current combined ledger and were in the existing shard-1 native review. Each row records actual original/current SHA-256, original function, exact observed object or VALID dependency consumers, existing call chain, proposed classification, bounded evidence, finite missing behavior and S11 owner. Both frozen OpenNT editions and actual original/current bytes agree for these rows. The proposal changes no existing ledger.

Ten rows have a **partial** candidate: AAA source/declaration and AAS, ARPL, BSF, signed/unsigned 64-bit multiply source/declaration, LEAVE source/declaration and LGDT source. These proposals require more than selection: existing documented source/object-to-oracle or bounded object/stub fixtures establish a part of the selected original functionality. AAA/AAS have 524,288 native comparisons, ARPL 262,144, BSF has 65,568 extracted-source cases, LGDT 200,000 source-state round trips; LEAVE has object plus test-local stack stubs. The multiplication fixture covers unsigned but not signed helper. None establishes full guest decoding, memory/fault behavior, production state, profile or lifecycle; no restoration percentage is asserted. BSF's evidence is a source-extracted fixture, not a production-object or guest witness. Associated declaration proposals inherit that limited provider evidence, not a blanket full declaration proof.

Twenty remain pending. Examples requiring explicit profile judgment include BSWAP and INVD: selected SPC386 code's 486 instruction path is guarded by SPC486, so inclusion/compilation of a header/object does not mean its guarded provider runs; 486 capability cannot be excluded from the T. `ccpupig.h` has PIG-only declarations even though the header is observed in selected dependencies. `ccpudefs.inc` is a historical CPU30/40 source-configuration carrier whose relationship to the current profile needs source-first reconciliation. Shared effective-address, interrupt, segment and stack headers expose broader exception and nested state contracts than their mere include edges demonstrate.

No behavioral test or compilation was run in this pass, and no product, guest, main ledger or other shard was changed. The earlier evidence remains bounded by its own recorded test and binary identity.
