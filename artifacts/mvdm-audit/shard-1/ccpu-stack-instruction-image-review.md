# Shard 1: PUSHA/LEAVE image and original stack-provider edges

This supplements `ccpu-stack-instruction-audit.md`, which already reported a controlled original-object fixture but explicitly lacked current published-image identity and real stack-provider linkage. `pusha.c` and `leave.c` match both frozen OpenNT sources. The observer binds PUSHA, LEAVE16, LEAVE32 and the original `_ccpu` decoder to release NTVDM executable bytes, then resolves 18 actual call relocations: decoder to all three bodies; PUSHA to the original stack-space validator and eight `spush` calls; both LEAVE bodies to the stack-existence validator, stack-pointer setter and pop. The corresponding functions reside in the selected original `c_stack.obj`.

Original opcode 0x60 uses PUSHA; opcode 0xc9 selects LEAVE16/32 by operand size. PUSHA validates eight slots before pushing registers, retaining the original ESP value for its saved-stack slot. LEAVE validates its BP-based pop before setting the stack pointer and replacing BP or EBP. `c_stack.c` decides stack-address width from SS B and write/read width from operand size; see `ccpu-stack-owner-review.md` for the 13-function image binding and its explicit caveats.

The historical controlled fixture checks call order and a simulated validation failure using substituted register/stack providers. This new image proof does not turn it into a live guest result: actual segment limits, stack wraps, memory access ordering, page faults, nested faults, operand/address size combinations and register state on failure remain S11's integrated obligations. Replay `python artifacts/mvdm-audit/shard-1/ccpu-stack-instruction-image-observer.py`; the companion JSON contains hashed inputs and each resolved edge. No product, guest, build tree or shared ledger changed; no product was run.
