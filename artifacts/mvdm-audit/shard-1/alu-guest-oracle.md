# Native ALU guest oracle: shard-1 independent review

The single maintained producer is `tests/observation/ccpu_alu_oracle.c` SHA256 `CFB5909506354617AF76E53F691078006C7309044E3275EE364D00424A570B35`, built only by the x86 CMake `ccpu-alu-oracle` target (`EXCLUDE_FROM_ALL`). The earlier shard-local prototype has been retired. This review covers shard-1 ADD/CMP/NEG/SUB/XOR; other operations belong to their assigned reviewers.

In `native`, the BINARY and UNARY macros load EAX and, for binary operations, EDX, then `bt carry, 0` establishes the requested incoming carry immediately before actual native opcode. The five assigned variants all select carry zero. Each executes the actual 8/16/32-bit x86 ADD/CMP/NEG/SUB/XOR, then PUSHFD captures the defined flags and MOV stores the result without flag modifications. CMP does not alter EAX, so the recorded expected result is the width-masked lhs; NEG ignores rhs. ADD/CMP/NEG/SUB mask status with 08D5; XOR masks with 08C5, forcing AF zero consistently with the original leaf policy while excluding the hardware-undefined AF value.

Eight-bit files contain all 65536 ordered pairs. Each 16/32-bit file contains 14×14 = 196 ordered boundary pairs including FFFFFFFF, followed by 1000 pairs from seed 12345678 and LCG `1664525*state+1013904223`, taking two successive states per pair. Each 14-byte record explicitly serializes little-endian lhs, rhs, result and 16-bit flags. Operands are width-masked by the generator. File creation, each write and fclose are checked; the requested directory must exist. Subsequent S10 validation built and ran the producer; `ccpu-alu-records.json`, `ccpu-alu-guest.json`, `ccpu-alu-image.json` and `ccpu-alu-image-negative.json` record data, guest positive/negative controls and published PE correspondence. Independent shard review confirms full classification of the five unchanged selected pure leaf contracts only.

The original selected-object native comparisons and their boundaries remain `ccpu-add-mul-audit.md`, `ccpu-cmp-neg-audit.md`, and `ccpu-sub-xor-audit.md`. Guest evidence includes register, memory-destination and memory-source forms, but does not establish faulting addresses, other modes or unrelated decoder paths. No product or guest was changed or run in this review.
