`wkmem.h` declares virtual allocate/free; `wktbl2.h:292-293` registers WK32VirtualAlloc/Free, implemented by selected wkmem.c. Prior `wow-virtual-memory-review.md` documents original nt_mem provider binding and limited valid allocation evidence; invalid/repeated free and failure remain unproved. `wklocal.h` declares WK32Local* but `wktbl2.h:18,20` registers LOCALAPI for alloc/free; do not treat header names as proof that wkLocal.c is selected. Original guest LOCAL behavior needs its own source/behavior evidence.

`wkfileio.h` declares file thunk entrypoints and the mapped-file cache. `wktbl2.h:274,304` registers WK32FileRead/Close; current WOW32 map attributes WK32FileRead, WK32FileClose, W32MapViewOfFile and FreeMapFileCache to wkfileio.obj. Source candidate: `WK32FileRead:441-449` allocates a cache entry and calls `W32MapViewOfFile`; if CreateFileMapping succeeds but MapViewOfFile fails, `W32MapViewOfFile:683-703` closes the mapping handle without resetting its stored hMappedFileObject, then read falls back to ReadFile. Later cache eviction or final file close reaches `FreeMapFileCache:635-660`, which calls CloseHandle on that stale nonzero mapping field. If Windows has reused its value, the later close could affect an unrelated object; if not, it fails. Original OpenNT file contains the same failure branch, although current wkfileio.c as a whole differs from the original and must not be labeled byte-identical.

This is conditional source evidence only: no MapViewOfFile failure was injected, no handle reuse was observed, and map names do not by themselves bind the candidate instructions to deployed PE bytes. A finite fixture should force mapping success/view failure, perform a subsequent cache free/close with and without deliberate handle reuse, check ReadFile fallback and exactly-once ownership, and separately verify current PE linkage. Preserve original guest. Do not declare this fixed or a project-authored regression.
