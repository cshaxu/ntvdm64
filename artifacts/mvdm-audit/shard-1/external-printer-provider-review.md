# External NT4 printer-provider boundary — S10

## Frozen population and explicit boundaries

The frozen `../frozen-external-audit-rows.csv` contains exactly 33,684 entries with `/ntgdi/printers/`, 16,842 per edition. The 93 records of `../external-priority-boundaries.csv` have **zero ID intersections** with this set. This only means the explicit catalog did not flag these rows; it does not prove no indirect dependency. Counts by edition and package are in `external-printer-provider-census.csv`. In each edition there are 14,304 rasprint, 1,077 hprasdd, 871 psprint, 177 msplot, 134 compstui, 133 rasprint.sp1, 70 cheetah, 34 ps50, 25 lib, 16 specs and one dirs. This is a population census, not blanket classification.

## Original build and product authority

Both original editions' top-level printer `dirs` select native provider components (lib, compstui, msplot, psprint, rasprint, hprasdd). The raster `rasprint/rasdd/sources` and PostScript `psprint/pscript/sources` declare `TARGETTYPE=GDI_DRIVER`, name rasdd and pscript, build provider render/escape/font/page source and link NT native provider libraries. Six exact original recipe paths, actual content hashes, and these bounded file roles are recorded in `external-printer-recipe-examples.csv`. These six descriptors are historical native-provider build inputs, not files the WOW worker needs to compile or ship: **their file roles can be excluded from the project recovery source inputs**. This does not exclude printing functions or the driver behavior those recipes list. Other recipes, code, fonts, and resources are not automatically classified by this sample.

`src/mvdm/wow32/wgtbl2.h` dispatches guest GDI STARTDOC and EXTDEVICEMODE to original `wgdi31.c` / `wgprnset.c`. `wspool.c::WG32OpenJob` resolves `WINSPOOL.DRV` and calls `OpenPrinterA`/`StartDocPrinterA`; `wgdi31.c::WG32StartDoc` invokes the existing native HDC. `wcommdlg.c::WCD32PrintDlg` uses native common dialog with existing WOW callback/DC ownership. `docs/etc/evidence/m0-t468-s1-printing-spool-owner-matrix.md` supplies the four original call families, identity conversions, lifecycle and modern provider authority. Immutable guest `WINSPOOL.EXE` is a separate direct input, not any of these NT4 printer subtree recipes. Thus direct required MVDM slice comprises the selected WOW conversion, dispatch, spool and dialog source, guest forwarding input, and their specific public provider interface contracts; do not exclude them merely because native provider files are outside product build.

There is concrete indirect coupling: `wgdi.c` contains a PSCRIPT driver-name compatibility case, and `wow32fax.c` discusses RASDD DPI. These names do not themselves establish that project compilation or a current machine loads these old NT4 provider files, but make wholesale semantic exclusion unsafe. Historical individual-model drivers, mini-driver data, PPD, font metrics and UI resources can be outside the project source build while their old observable behavior may be absent from a modern provider. Provider owner separation is not proof of compatibility.
