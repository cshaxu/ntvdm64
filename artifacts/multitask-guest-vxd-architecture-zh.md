# 多任务 guest 的 VxD 与内部前端桥接设计

状态：候选设计，供与[宿主侧前端扩展与任务链模型](multitask-compressed-io-model-zh.md)并排评审。本文提出目标契约和待验证的实现方案，不是已交付的驱动接口，也不取代项目正式架构与当前状态文档。已有实验支持主要机制的可行性，但不代表完整 Console、生命周期或嵌套已经验收。

范围是 Windows 3.1 的 **386 增强模式**和 Windows 95 guest 内的多个非系统 DOS VM。Win3.1 标准模式不在范围内。不得修改 guest Windows 本身或加入常驻 DOS 代理；可以部署项目自有 VxD。package-owned COMMAND 发出的 `54:08` 和 `54:0A` 因同样执行 `cmdExec32` 均属于目标，其他启动路径须另行审计。

## 核心模型

guest 的每个非系统 DOS VM 是一个内部前端。VxD 是 guest VMM 与承载该 guest 的 NTVDM worker 之间的适配器：它在正确的 VM 上下文取得身份，参与 VM 等待、恢复、输入输出适配及生命周期通知。**VxD 不是内部前端本身，也不负责宿主任务链调度。**

```text
NTCON  ←→  承载 guest Windows 的 NTVDM worker
                         │
                         ├─ 内部前端 A ←→ 子任务链 A
                         ├─ 内部前端 B ←→ 子任务链 B
                         │
                         └─ guest 适配边界
                              ↕  请求身份 / 就绪通知 / 生命周期
                         项目 VxD + guest VMM
                              ├─ DOS VM A / Windows 管理的窗口 A
                              └─ DOS VM B / Windows 管理的窗口 B
```

Windows 继续决定自己的 VM 调度、窗口绘制、活动窗口和焦点。worker 在上游作为后端、在多任务阶段为各内部前端提供连接能力；NTSRV 管理认证、前端关联、任务链交接和生命周期，不转发 DOS 窗口文本或画面。内层多任务 guest 有自己的 VxD/VMM 实例和内部前端，不继承外层 VM handle 的命名空间。

## 职责和边界

| 组件 | 拥有的职责 | 不应承担的职责 |
| --- | --- | --- |
| guest VMM / Windows | VM 创建、调度和销毁；系统 VM；窗口、焦点与显示。 | 为宿主任务分配 worker 或解释 NTSRV 任务链。 |
| 项目 VxD | 注册受控入口；取得当前 VM 的 VMM 身份；提供 VM 生命周期和等待/恢复适配；在合法上下文参与 guest I/O。 | 用全局最近 VM 猜身份；直接管理 NTSRV；从任意宿主后台线程访问 guest。 |
| 承载 guest 的 worker | 保存每请求续体、提供内部前端端点、执行 guest 上下文切换和调度；向 NTSRV 报告与协调。 | 将内部 VM 统一当成上游 NTCON；在一个未返回的调用栈上等待所有子任务。 |
| NTSRV | 对前端和任务链做认证、准入、交接、关闭与故障协调。 | 模拟 guest 焦点、绘制窗口或作为 I/O 中继。 |
| 子 NTVDM / NTVWM | 承载子任务，连接 NTSRV 分配的对应内部前端。 | 绕过所属 guest，直接接管外层 NTCON。 |

VM 存在不等于已有正在运行的子任务；前端发现、可用、交接和撤销须有明确协议。VxD 可报告 VM 生命周期事实，但前端能力的创建、认证和授权属于宿主协调范围。

## 装载、就绪和撤销

同一候选实验二进制已在指定 Win3.1 386 增强模式下静态加载，并在指定 Win95 下动态加载；这是有限兼容证据，不保证其他版本或装载时机。正式交付应优先评估一个共享核心、按系统提供必要初始化适配的实现；能否始终使用同一二进制，以实际 ABI 和加载验收决定，不能以实验结果代替兼容承诺。

| 阶段 | guest 侧动作 | worker 对外可作的判断 |
| --- | --- | --- |
| 未确认 | 尚无可信的本 VMM 实例注册信息。 | 仅凭 callback 缺失，不能推断普通 DOS；允许普通单任务路径的正向判据需另行定义。 |
| 初始化 | VxD 接收适用的加载通知，建立受控入口，准备生命周期与所需 hook。 | 不开放内部前端交接；任一步失败应可诊断且有回滚。 |
| 就绪 | 双方完成版本、能力及本 VMM 实例的绑定；必需入口和通知已可用。 | 可以在对应真实调用中请求精确 VM 身份；具体功能还需按协商能力判定。 |
| 停止接收 | 退出、卸载、失联或不变量失效时拒绝新关联。 | 停止向该实例发新请求，通知 NTSRV 协调前端和子链。 |
| 排空 / 失效 | 撤销定时器及 hook，处理已经进入的回调，等引用释放；无法安全卸载则保持拒绝状态或使用可诊断故障处理。 | 旧实例、旧 generation 和旧请求的通知不再产生 guest 副作用。 |

注册、就绪和撤销必须针对 **worker 实例 + 载荷实例 + VMM 实例**；worker 存活期间 guest 可以退出后再次进入，新实例不能继承旧注册。异常退出可能没有可靠 guest 通知，worker 和 NTSRV 必须能够独立撤销；具体丢通知检测与恢复机制尚未确定。系统 VM 需要单独分类，其 `54:08` / `54:0A` 行为尚待查明，不能把它当作普通内部前端，也不能假定可用 `Suspend_VM`。

## 身份、作用域与请求

内部前端身份至少关联：`worker instance`、`payload instance`、`VMM instance`、`VM handle`、`generation`。请求再关联独立的 `request ID` 和服务号。前端标识的编码、能力凭据和认证由宿主协议确定；裸 handle、PID、CR3、窗口焦点或最近运行的 VM 都不能充当请求身份或授权。

VMM handle 只在本 VMM 实例的生命周期内有意义，并可能在 VM 关闭后复用。generation 必须随 VM 生命周期变化，不能在尚有旧引用或事件时复用同一完整身份；计数溢出和分配失败必须使新关联失败或更换更高层实例，而不是静默回绕。驱动加载时已经存在的 VM 如何登记、漏掉销毁通知时如何确认有效性，仍需实证，不可把一个实验计数器直接当成完整生命周期事实。

对每个 `54:08` 或 `54:0A`，承载 worker 在**与该调用精确对应的 guest 上下文**中进入已验证的 VxD callback，由 VMM 提供当前 VM handle；绑定本次请求后再进行可能切换 VM 的操作。服务号、原始现场和请求 token 都属于本次调用。callback 返回后，宿主根据完整身份关联内部前端及其子任务链；身份未知、回调无效或发生冲突时拒绝或给出可诊断失败，不猜测其他 VM。

候选协议消息按语义分为 `REGISTER/READY`、`IDENTIFY`、`WAIT/RESUME`、`IO_READY`、`VM_RETIRE` 和 `QUIESCE`。它们是设计名称，不是已经存在的 BOP 号、VxD ABI 或现成协议；版本、字段宽度、调用约定、错误码及认证方式需在实现前冻结。每条关联消息至少携带实例作用域、VM 身份和请求 ID，接收方验证生命周期及当前所有权。向宿主传递的数据应是有界副本或经验证的能力，而不是长期缓存 guest 线性地址。

## 请求交接与独立续体

`54:08` 和 `54:0A` 在共同判断路径上执行相同的环境识别、身份绑定与前端选择，但保留各自的 COMMAND 参数、COMSPEC、标准句柄、错误、返回值、标志位及重入语义。共同判断候选在 `cmdExec32` / 宿主执行边界；如该处已无法让 `CmdDispatch` / `MS_bop_4` 的未返回栈退出，则必须向更早的 BOP 分发边界移动并改变返回边界。

```text
VM A: BOP → 绑定 A 的身份和请求 → 准备续体与交接 → 离开该次宿主调用栈
VMM: 继续调度其他可运行 VM
VM B: BOP → 绑定 B 的身份和请求 → 独立等待
宿主: A 完成 → 通知调度器 → 合法上下文恢复 A
      B 仍可等待；之后按 B 自己的状态恢复
```

以上是逻辑顺序，不要求每个 VM 一个宿主线程。**队列或线程本身不能解除栈顶等待**：实现必须证明每个请求的等待状态已脱离未返回的 `host_simulate()` / BOP 调用栈。保存和恢复必须覆盖该服务实际要求的完整 CPU、栈、标志位、guest 内存和返回语义；有限寄存器掩码通过不能替代完整 ABI 验证。VxD 不决定或伪造真实父子任务关系；最终返回交还原调用者。

每请求候选状态如下，宿主状态和 guest 等待状态需要通过协议协调，而不是假设一次状态写入同时完成两边工作：

| 状态 | 必须成立的事实 | 失败或竞态的处理要求 |
| --- | --- | --- |
| `CAPTURED` | 服务号、现场、实例和精确 VM 身份已绑定；请求 ID 唯一。 | 未能证明身份则不启动子任务。 |
| `PREPARING` | 前端及子链准备中；此时完成、关闭或取消可能已发生。 | 任一步失败撤销已取得资源；不得留下无主等待或重复交接。 |
| `WAITING` | guest 等待方式成功建立，续体已脱离阻塞宿主调用栈；子链可独立运行。 | 其他 VM 可继续；等待建立失败不得假装 VM 已挂起。 |
| `COMPLETING` | 结果已绑定当前请求，最终输出、断连和返回条件按协议处理。 | 以同一所有权检查裁决完成与取消，只允许一个终结结果生效。 |
| `RESUMING` | 通过合法 VMM/模拟器入口选择正确 VM，并恢复该请求现场。 | 恢复失败需可诊断和规定回退；不能把子进程退出当作 guest 已恢复。 |
| `DONE` / `RETIRED` | 调用者实际恢复，或 VM 已失效且资源按约定撤销。 | 重复完成、旧事件和迟到定时器只被拒绝或无副作用地吸收。 |

`Suspend_VM` / `Resume_VM` 是候选机制，不是无条件操作。必须处理系统 VM、临界区、嵌套 suspend count、挂起或恢复失败和其他锁；如果选择另一种等待/续体机制，也须满足同样的独立恢复条件。尤其需要证明：完成事件如何在合法上下文触发恢复；不能只向一个已挂起 VM 排入必须由它自己执行的事件，再假定它能自行唤醒。真实 VMM 回调可用性和时序仍待验证。

## 输入、输出与正确上下文

承载 worker 为每个内部前端维持独立逻辑端点。后台读取 stdout/stderr、接收输入或监听子任务退出的代码只操作宿主对象，将带完整身份的事件交给调度器；不得直接修改 guest 内存、寄存器、视频状态或调用要求 guest 上下文的 VMM 服务。调度器再次校验实例、generation、请求及所有权，进入目标 VM 的合法上下文后，才执行 guest 侧操作。

输入由 Windows 的窗口和焦点机制决定归属；VxD 可在已证实的 VKD/相关入口协助把输入送往对应内部前端，但 hook 的安装、调用约定、重复投递、释放、焦点切换竞态及非文本事件必须分别验证。系统 VM 和不属于活动请求的输入应保持 Windows 原有路径，不能以“当前最近 VM”转发。实验中的合成按键和 BIOS 读写是有限证据，不定义最终键盘协议。

输出要按请求和前端归属进入相应 VM 的显示适配，由 guest Windows 继续管理窗口；stdout/stderr 各自顺序、交错、背压、断连和最终输出的交付顺序需定义。真实 NTVWM Console 包括输入记录、屏幕状态、光标、控制事件、编码、尺寸和重定向，普通字节 pipe 或直接写显存不能被假定等价。是否可通过现有 Console I/O 契约实现内部前端，及图形 DOS、音频等能力范围，仍需独立研究；不能以实验文本通道宣称全面支持。

## 关闭、取消与并发安全

以下是需要实现和验证的协议约束，具体锁、引用计数和执行器由实现决定：

1. **关闭入口**：按完整实例与 generation 标记 VM/前端为不可接收新工作，再由 worker 报告 NTSRV；新请求与关闭竞争时必须有明确的单一裁决点。
2. **撤销请求**：对受影响请求取消或终止适用子任务，协调 stdin/stdout/stderr、未消费输入和最终输出；失败必须留下可诊断状态，不能先释放仍可能被访问的资源。
3. **撤销定时器和 hook**：阻止新回调进入，撤销可撤销的定时器，并等待已经进入或已经投递的回调释放引用；取消定时器返回成功本身不能证明所有在途回调已结束。
4. **防止旧事件复活**：每次消费事件重新检查完整身份与终结状态；handle 或实验槽复用后，旧 generation/request 的事件不能写入新 VM。重复完成、关闭和通知必须幂等。
5. **最终释放**：只有调度、I/O、回调和连接都不再持有引用，才能释放对应状态。VM 已销毁时不恢复其 CPU，也不能因它关闭而停止其他 VM。

载荷结束但 worker 存活、worker 非正常死亡、VxD 卸载和更深层子链的清理各有不同的权威来源。worker 死亡不能依靠其发送最后通知；NTSRV 依据可验证的进程与关联状态协调后代。每一层只管理自己 VMM 实例的 VM 和前端，跨层任务关系由 NTSRV 协调，不用 guest handle 跨 worker 定位。

## 验证顺序与验收

1. 在 Win3.1 386 增强模式和 Win95 分别验证装载、版本协商、初始化失败、普通 DOS / VMM 转换、系统 VM 分类和受控撤销；各次核对实验包身份和 guest 环境。
2. 对 `54:08`、`54:0A` 各自证明调用现场到 VMM 身份再到 request ID 的精确绑定，以及完整返回语义；覆盖错误身份、失效 generation 和 handle 复用。
3. 两个 VM 各启动宿主任务，分别让 A、B 先完成：在另一子任务由独立持有的 OS 句柄证实仍运行时，验证正确 VM 的输出和 DOS 调用者确已恢复，记录 ID、时间、返回值和现场。交换完成顺序，并对照子程序退出与 guest 恢复。
4. 验证真实窗口焦点输入、字符及控制事件、stdout/stderr、背压、窗口输出与退出码；分别测试真实 NTVDM 和 NTVWM 子链、重定向及既有单任务回归。
5. 验证 VM 关闭、请求取消、子进程异常、定时器撤销和在途事件、VxD 退出、载荷退出但 worker 复用、worker 死亡及多层 guest 嵌套；确认其余 VM 与外层前端继续运行。

每一项记录 guest/宿主包、VxD、系统版本和证据范围，区分已证实、失败与未验证。只有真实交互、输出路由、并发恢复、返回值、取消、生命周期和要求的嵌套场景都具备对应证据，才能宣称完整目标达成。
