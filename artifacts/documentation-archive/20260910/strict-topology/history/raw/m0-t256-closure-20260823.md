# M0 T256 Closure — Selector-blind protected virtual-access and guest-linear substrate

T256 closes the generic substrate selected from the dependency-driven queue.
It delivered bounded protected copied access, explicit ordinary-RAM capacity
and reservation lifecycle, and a bx-vdm XMEM identity/reallocation adapter.
All contracts preserve the machine/VDM boundary: bx-core owns CPU mechanics,
bx-mantle owns selector-blind RAM lifecycle, and bx-vdm owns compatibility
records.

The final source audit rejected two tempting but invalid reductions:

- DOSX `selGDT`/OpenNT `Ldt` is a historical NT4 process-LDT composition, not
  an adaptable generic mantle descriptor lifecycle.
- OpenNT protected interrupt/fault/IRET hooks are a locked-stack DOSX/DPMI
  lifecycle, not a core callback or a generic machine interrupt API.

The formal Ninja closure (`M0-T256-S15/formal-r1`, 278/278 target build and
passing XMEM fixture) confirms the current generic module closure.  It does
not claim any active `53:xx`, an imported DPMI runtime, paging, or a continuous
protected-mode guest run.

T257 is admitted only for the next source/ABI/failure map of the complete
OpenNT DPMI/DOSX owner package.  Later code must use T256's closed mechanical
contracts without recreating NT4 LDT, CCPU or VDM hooks.
