# M0 T288 closure — original VDM monitor and keyboard/IVT substrate

## Result

T288 is closed as a source-first, local-regression closure. It does not claim
a historical NT4 monitor product shell or continuous guest execution.

- S1 records the 78-file selected monitor/firmware source union and every
  direct-pointer, VDM_TIB, callback and historical-host disposition.
- S2 re-rooted the exact seven-file keymouse mirror and compiled the selected
  declaration island on formal x86/x64 Ninja graphs.
- S3 rejected a duplicate portable VDM_TIB frame: the selector-blind copied
  #UD boundary remains unique.
- S4 recovered same-shaped checked SAS scalar/span operations and records the
  excluded low-address mapper, raw pointers, memory map and CCPU stubs.
- S5 recovered the original `UpdateKbdInt15` IVT 15h cache contract.
- S6 proves the original XMS `xmsNotifyHookI15` reaches that production
  callout, on x86 and x64, without a test-only provider.

## Final audit

- The only new S4/S5 exceptions are uniquely registered as
  `ADAPTER-SOFTPC-011` (SAS) and `ADAPTER-SOFTPC-010` (INT15).
- MVDM-facing sources reach Bochs only through typed `adapter-bochs` calls;
  no selected source calls `bochs-core` directly.
- No T288 source creates a mapping manager. Numeric SAS addresses are checked
  machine addresses, while session retains all mapper/lease ownership.
- Formal source manifests reject `src.old`; the source and test graph contain
  no `src.old` input.
- Remaining monitor execution, `INT15` CPU re-entry, keyboard controller,
  PIC/IRQ, CSRSS/kernel VDM, SIM/WOW and debugger paths retain their original
  source evidence and have named later owner packages. They are not false
  local-success results.
