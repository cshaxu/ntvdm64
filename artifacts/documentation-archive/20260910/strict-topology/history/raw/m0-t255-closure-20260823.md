# M0 T255 Closure — Selector-Blind Protected-Mode Context Substrate

T255 closes the source-mapped protected context seam, not the OpenNT DPMI
package.  Its S2 result adds a fixed-width v2 generic #UD outcome carrying a
bounded execution-mode target, GPR32, selectors, FLAGS and resume RIP.  The
adopted Bochs core applies those values only through native architectural
methods; protected CS uses the native validated branch path rather than a
copied descriptor cache.  The formal CPU5/Pentium-MMX MSVC x64 `/MT` fixture
proves real→protected and protected→real changes, invalid-mode rejection, and
unchanged v1 pending/resume behavior.

S3 records the decisive remaining gap: the original DPMI bodies require
fault-contained protected virtual access and guest-linear mapping identity,
whereas retained `Sim32GetVDMPointer` exposes host pointers and existing
Bochs virtual access faults through CPU exception control flow.  No DPMI
provider or `53:xx` leaf is admitted.  The next owner package is the
selector-blind protected virtual-access and guest-linear mapping substrate,
followed by the original DPMI package only after that prerequisite proves
usable.
