# M0 T280 S17 closure — `demsrch.c` remaining x64 boundary audit

The complete original `demsrch.c` x64-sensitive surface is now classified in
the eight-row S17 boundary ledger. Four source-owner implementation groups
remain: native-width HANDLE sentinel, host-local pathname/device offset,
host-local directory-buffer cursor arithmetic, and the `VdmQueryDir` facade
relocation to its architectural owner `adapter-vdm-monitor`. None uses an
opaque mapping identity.

The only guest pointer boundary is the original synchronous `GetVDMAddr` call
family. It is explicitly reserved for the existing session `guest_memory`
lease through `adapter-softpc`; it is not part of host-local x64 arithmetic.
Non-width compiler diagnostics remain source-hygiene evidence rather than
permission for an unreviewed algorithm rewrite. No directory provider, BOP
route, guest trace or Bochs change was enabled.

The next bounded source-owner task is S18, which may recover the four
host-local groups together but must leave the guest lease and source-hygiene
groups out of scope.
