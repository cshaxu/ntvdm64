# M0 T230 S1 — DEM Functional-Completion Admission Plan

## Binding correction

T229 established a useful local provider/disposition population, but not the
owner's required functional closure. Its use of explicit `deferred` or
`unavailable` terminals, retained Virtual provider code, and a transferred
native observation cannot be used as the completion definition for T230.

T230 owns the complete callable `DemDispatch` range `50:00..48`. No row may
be transferred into another task for the purpose of claiming T230 complete.
A source-proven original no-op remains valid only when the original DEM owner
really specifies that no-op; an unimplemented/deferred adapter terminal is not
a substitute for behavior.

## S1 objective

Produce the implementation-ready, 73-row functional-completion map that
answers for every service:

1. original OpenNT handler, caller, register/guest-memory ABI, ordering and
   failure rule;
2. whether the current Direct and Readonly route actually executes the owner
   contract, merely terminates, or is not runnable;
3. the mandatory recovery ladder result: direct original reuse, smallest
   composable source seam, registered external intrusion, or last-resort new
   behavior;
4. the specific host capability needed for Direct and the source-shaped
   Readonly refusal/observation; and
5. its Virtual code/path/test disposition and its required Overlay ABI seam.

`50:47/48` must be resolved as callable DEM dependencies in the T230 plan.
They may use an independently composable original Redirector fragment or the
smallest source-derived capability seam, but cannot remain Redirector-deferred
when the DEM task claims completion.

## Complete T230 sequence

1. **S1 — Functional map and Virtual graph audit.** Reconcile all 73 actual
   routes against original source; enumerate every Virtual enum, selection,
   provider, backend, token, manifest and test edge that enters the runnable
   graph; define the minimal safe removal/isolation set.
2. **S2 — File/session/FCB/search and pipe completion.** Replace terminal
   shortcuts with source-backed behavior, including `50:47/48`; establish
   Direct and Readonly semantic fixtures.
3. **S3 — GSET/drive/CWD/volume and mutation completion.** Close all selected
   host capabilities and original failure layouts without snapshot or generic
   fallback behavior.
4. **S4 — Misc/lifecycle/console/WOW, error/lock and DASD/IOCTL completion.**
   Implement every remaining callable DEM contract, or source-proven actual
   no-op; no `deferred` classification is accepted.
5. **S5 — Virtual retirement and whole-package proof.** Remove retired Virtual
   behavior from runnable profile parsing, provider choice, backend paths,
   formal source membership and executable fixtures; retain an explicit
   rejected ABI value only if binary/layout compatibility needs it. Preserve
   Overlay's typed but non-enabled extension seam.
6. **S6 — Final integration.** Run the complete Direct/Readonly 73-row matrix,
   negative Overlay/Virtual admission tests, full formal Ninja graph, and one
   bounded native DEM observation. Classify observations in T230; do not
   create a hidden implementation transfer list.

## Completion meaning

A Direct result may be a source-correct operational failure when a real,
selected host capability returns that failure; it cannot be an adapter
`unavailable` preterminal. Readonly must preserve the same ABI/order and
perform its source-shaped refusal before mutation. Every behavior retains the
OpenNT owner contract under the source-recovery ladder.
