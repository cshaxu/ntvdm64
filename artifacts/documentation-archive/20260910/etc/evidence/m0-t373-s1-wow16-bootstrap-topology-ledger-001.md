# M0 T373 S1 — WOW16 Bootstrap Topology Ledger

## Decision

The current CPU40/x86 product has no selected WOW16 execution vertical.  It
has the immutable original `mvdm-host/wow32` and `mvdm-guest/wow16` mirrors,
the source-shaped local Base VDM distinction for a WOW command record, and a
bounded non-fast callback-frame foundation.  Those are prerequisites, not a
linked or staged WOW runtime.

S2 therefore owns one minimal, non-fast, single-session bootstrap cohort.  It
must compose command acquisition, the bounded guest-frame bindings and the
selected task bootstrap body as one source-shaped cohort.  It must not enable
an isolated WOW export, a synthetic NE loader, fast WOW, or the historical
CSR/CSRSS product shell.

## Source and build reconciliation

* `src/mvdm-host/wow32/wkman.c` and `wow32.c` are byte-identical to the
  selected OpenNT mirror.  `wcall16.c` retains the original non-fast order
  (`SETVDMSTACK -> host_simulate -> VDMSTACK`); `MVDM-HOST-DIV-178` changes
  only its raw VDM-pointer lifetime into bounded mapping leases.
* `src/mvdm-host/wow32/sources` describes the full historical WOW32 DLL,
  including private `gdi32p`, `user32p`, NTVDM, and product-shell links.  It
  is not a valid modern application link recipe.
* The current formal CPU40/x86 graph generated by
  `tools/build/New-T310OriginalSoftpcNinja.ps1` selects
  `wow_private_unavailable.c` only.  It selects neither `wkman.c`,
  `wow32.c`, nor `wcall16.c`.  Consequently no current executable can claim
  to execute an original WOW host body.
* `mvdm-guest/wow16/test/shell/WOWEXEC.EXE` and `wowexec.c` are immutable
  original Win16 guest material.  They are guest media, not host objects.
  The current `Stage-OriginalSoftpcRuntime.mjs` stages DOS and SoftPC
  firmware only; it stages no WOW16 kernel, USER/GDI, driver or WOWEXEC
  artifact.  Missing selected media is therefore the first physical runtime
  blocker.

## Selected S2 cohort

S2 is admitted to establish the original command-and-task bootstrap binding,
not full NE execution.  Its finite cohort is:

1. an immutable, manifested minimum WOW guest-media selection, kept separate
   from the host link graph;
2. an app-owned source-shaped `BASE_VDM_COMMAND_WOW` declaration/publish path
   that carries copied command, application, environment, current-directory
   and task metadata into the existing local Base VDM record;
3. the original `WK32WowGetNextVdmCommand` algorithm as a mirror true subset
   only if its required guest ranges can all be represented by existing short
   mapping leases, without a raw `GETVDMPTR` alias crossing into host code;
4. the existing original-name Base VDM call and the current `CURRENTPTD`
   numeric task projection boundary; and
5. local positive, empty-queue, wrong-owner and insufficient-capacity proofs.

The true subset condition is deliberate: `wkman.c` is a whole historical DLL
translation unit whose unrelated task, USER, thread and private-shell bodies
cannot be made a prerequisite for proving the first command record.  Any
selected subset keeps original function order and names, records every
omission as a mirror divergence, and does not become a new provider.

## Deferred owners

* **S3:** selected original non-fast `CallBack16` recursion and nested CPU40
  stop/return proof, after S2 establishes the task lifetime.
* **S4:** original Win16 Kernel/NE module/task launch and normal return;
  this includes the immutable guest media and the host callback table needed
  by the selected vertical.
* **Later WOW packages:** general USER/GDI message/object conversion,
  shell/OLE/print/multimedia/network, separate WOW/PIF, fast WOW and private
  product shells.  They are not silently represented by a successful S2.

## S1 closure

Every immediate bootstrap, task, callback and NE edge now has an owner and a
source/build/runtime disposition.  The next change is limited to the S2
cohort above; it requires a new active packet.  This evidence neither runs
the product nor claims that WOWEXEC, a Win16 NE image, `CallBack16`, or a WOW
provider currently executes.
