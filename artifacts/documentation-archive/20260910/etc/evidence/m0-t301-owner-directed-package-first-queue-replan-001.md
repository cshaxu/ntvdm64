# M0 T301 owner-directed package-first queue replan

## Question

How should recovery proceed after the source-ledger work established that
MVDM has substantial external host boundaries, without converting the product
roadmap into an unbounded series of whole-program BFS and classification tasks?

## Inputs

- `docs/QUEUE.md` before this replan, whose first twelve candidate packages
  were global audit, classification, static-closure and build-graph gates.
- `docs/etc/operations/package-recovery-program-20260827.md` before this
  replan.
- The active `M0 T301 S1` physical-source evidence and its bounded scope in
  `docs/STATUS.md`.
- The already imported original BaseClient/BaseSrv VDM source slice under
  `src/opennt-host/base/win32/`.

## Procedure

Compared the ordered candidates with the source-first recovery rule and the
owner direction that BOP work must recover complete original owner packages,
not wait for a serial audit treadmill or follow trace hits.

## Observation

- The former queue made whole-program one/two-degree expansion, source-absence
  classification, perimeter reconciliation, generic support/ABI, generic
  Win32, generic OpenNT-host and generic Ninja closure mandatory predecessors
  of every first functional package.
- Those activities produce reusable evidence, but none independently restores
  an executable OpenNT package contract.
- Base VDM command protocol is the first source-proven shared contract needed
  by the existing DEM/COMMAND direction and has a finite immediately auditable
  boundary: the original BaseClient/BaseSrv VDM slice, public modern APIs and
  explicit CSR/CSRSS product-shell exclusions.

## Decision

Keep `M0 T301 S1` bounded and active; do not change its static-audit exit
criteria.  Replace the serial audit-gate queue with owner packages.  Before
recovering a package, its S1 performs only the immediate original caller,
file, declaration and external-boundary audit needed to preserve the original
algorithm and assign an existing or newly admitted narrow adapter.

The first candidate is Base VDM command protocol.  The following candidates
are ordered by its prerequisite mechanics, ingress, the DEM/COMMAND vertical
slice and controlled guest execution; remaining owner packages follow only
after that vertical slice establishes the relevant shared contracts.

## Limits

This does not admit BaseSrv/CSRSS as a modern host shell, does not authorize a
second machine executor, does not enable a BOP merely because its trace is
observed, and does not treat an adapter as permission to replace an original
algorithm.  Cross-package ledgers remain mandatory evidence and are updated
per reached package boundary.

## Follow-up

On admission of the next T packet, create the concise Base VDM S1 brief in
`docs/STATUS.md`; it must name the BaseClient/BaseSrv source files, the
private/public stop boundary, the selected same-shaped modern bindings and the
explicit deferred CSRSS, cross-process and WOW broker behavior.
