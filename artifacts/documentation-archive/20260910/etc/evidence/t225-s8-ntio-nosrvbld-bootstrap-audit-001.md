# T225 S8 NTIO NOSRVBLD Bootstrap Audit 001

## Question

Can the tracked historical `NOSRVBLD.EXE` reproduce the generated NTIO message
classes needed by the original `dosmsg.cmd` / `bios/makefile` contract?

## Inputs and procedure

In a disposable `build/M0-T225-S8/ntio-nosrvbld-probe-r4/` directory, the
following unmodified primary-source inputs were copied from
`O:\repos.external\OpenNT` revision
`5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`:

- `base/mvdm/dos/v86/doskrnl/bios/msbio.skl`;
- `base/mvdm/dos/v86/messages/usa-ms.msg` and `usa-ms.idx`.

The tracked MS-DOS 4 tool copies were then run under local DOSBox 0.74-3 in
the original command order:

```text
BUILDIDX USA-MS.MSG
NOSRVBLD MSBIO.SKL USA-MS.MSG
```

`BUILDIDX` reported that the message and index files were unchanged.
`NOSRVBLD` opened the SKL, MSG and IDX inputs and emitted `MSBIO.CL3` through
`MSBIO.CL6`.  External OpenNT-tree class files were read only for a hash/text
comparison; none was copied into the stage or passed to a tool.

## Observation

All four generated files differ from the source-tree comparison bytes.  The
first substantive difference is in `MSBIO.CL3` line 62:

| Generated by tracked NOSRVBLD | Required comparison text |
| --- | --- |
| `f DB    "Error in CONFIG.SYS line ","$"` | `toomanydrivesmsg DB    "WARNING! Logical drives past Z: exist and will be ignored",13,10,"$"` |

The generated and comparison CL3 files have the same line count (62), so this
is a parser/semantic difference rather than a missing trailing record.  The
other three class files also have different byte counts and hashes.

## Interpretation

The available historical `NOSRVBLD.EXE` is a real DOS tool and follows the
documented invocation contract, but it is not byte-compatible with the
OpenNT NTIO message-class output required for the locked primary `NTIO.SYS`
identity.  It must not be silently promoted into the NTIO build, and the
generated CL files must not be substituted for the source-tree outputs.

## Follow-up

S8 remains open.  A conforming route needs either the exact historical
OpenNT-compatible NOSRVBLD tool or a separately admitted, source-derived
message-generator seam whose output is proved against all four required class
files.  The archived `nosrvbld_class_extract.c` remains evidence-only under
the local-code governance ledger and is not activated by this audit.  No
NTIO assembly/link, fixture, guest trace, BOP, Bochs or runtime behavior was
run or changed.
