# T228 S1 P2 Immutable Terminal Instruction-History Admission

## Decision

Use the existing registered scalar history mechanic only as a default-off terminal observation in a fresh current-source diagnostic graph. The observation is evaluated only after the existing watchdog has stopped the CPU loop; it copies no guest RAM and does not alter the loop, a BOP result, or a CPU state.

## Rejected Existing Recipes

The historical T198 probes use retained link responses, old build roots, and fixture-specific generic-UD stop assertions. They cannot prove the T228 immutable CLI terminal. They are source evidence only, not a build or runtime input.

## Boundary

The diagnostic graph enables the existing instruction-history compile switch for the full current CPU5 closure and adds the existing project-owned history translation unit to that derivative only. Provenance remains disabled.

The mantle copies at most the already fixed-capacity scalar records when the existing terminal-position condition is true. The CLI flag can enable, copy, and print that record list only in the diagnostic executable. It names no selector, BOP, OpenNT service, DOS path, guest address, opcode, or host capability.

## Recovery Ledger

1. Original source reuse: not applicable; this is project-owned diagnostic machinery around an adopted CPU loop.
2. Smallest adapter/shim: existing mantle terminal observation is the owner of an already-returned watchdog terminal; CLI only formats copied values.
3. External-code intrusion: no new intrusion; BX-CORE-071 is the existing compile-time capture seam.
4. Newly authored behavior: one default-off copied terminal-report ABI, with no execution semantics.

## Acceptance

A passing result may classify only a complete guest/control-flow or CPU/machine owner domain. It cannot create a BOP implementation task or justify a leaf opcode repair.
