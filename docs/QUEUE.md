# Queue

This is the authoritative ordered queue of **unnumbered candidate T task
packages**. A candidate gains its next global numeric `T` identifier only
when the owner selects it and admits it to [STATUS.md](STATUS.md). The active
package and its single active S are recorded only in Status; S/P planning does
not belong here.

| Order | Candidate T package | Boundary | Admission evidence |
| --- | --- | --- | --- |
| 1 | Bochs native lifecycle closure extraction | Define and then extract the smallest Bochs-internal mantle that assembles `bx-core` without the historical product shell: SIM, logging, no-device PC-time, CPU/decode, RAM and default port-space only. No `bx-vdm`, BOP, OpenNT, DOS, GUI, plugin, BIOS loader, CMOS, or device assembly enters the mantle. | Complete current owner/symbol/configuration map; explicit native lifecycle contract; negative retention proof; one separately admitted minimal build closure. |
| 2 | Holistic BOP host-service and machine-composition runtime closure | Continue the complete BOP route only after the native mantle/build closure and current boundary-repair package close. The package resumes adapter-owned selector/service routing and provider disposition, plus adapter-owned machine-composition selection for admitted historical handler islands. | Closed native lifecycle and boundary-repair packages; source/ABI ownership map; one bounded observation with no selector semantics in Bochs and no claim beyond observed execution. |
| 3 | Engine-owned declared DOS terminal-result transport | Expose a captured, fixed-width DOS status to the CLI only after normal `54:11` return is runtime-proven and a distinct engine/Bochs transport ABI is designed. | A real normal-return trace, source/test proof of its continuation, and a fixed-width transport that does not overload process exit codes or introduce host broker semantics. |

Queue order expresses priority only. It is neither approval nor a numeric T
reservation. Do not add an active packet, an S/P entry, a technical baseline,
or a per-BOP implementation backlog here; use `STATUS.md` for the admitted
T/S packet and `TODO.md` only for unplanned debt.
