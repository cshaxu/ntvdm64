# OpenNT VDM Artifact Plan

## Scope

The target is the complete set of **OpenNT-produced** VDM/DOS runtime,
device, command, redirector, monitor and support artifacts required by the
chosen OpenNT revision, not merely a hand-picked list such as NTIO or HIMEM.
This includes every OpenNT-modified DOS program and system file found through
the `base/mvdm` build graph: keyboard, mouse and display support; locale/NLS
data; drivers; command utilities; editor/QBasic payloads; redirectors; and
their host-side service counterparts. The artifact inventory, not an example
list in this document, is the scope authority.
Prebuilt third-party or Windows product files referenced only by `binplace`
are recorded as inputs, not falsely claimed as rebuilt from OpenNT.

## Build-Input Classes

1. **Present OpenNT sources:** all entries above now have their full repository
   context at revision `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`.
2. **Historical tools to reconstruct or supply:** `build`, `link16`, `mapsym`,
   `reloc`, `dosmsg`, `rc16`, `binplace`, and 16-bit compiler/assembler
   components. The `NTIO.SYS` makefile explicitly names several of these.
3. **Generated locale inputs:** message class files generated by `dosmsg` from
   skeleton/message files and the selected US message resources.
4. **External/prebuilt inputs:** `bin86/makefile` lists components it only
   places, including several Windows DLLs. They must be separately identified;
   absence from OpenNT source is not a build failure to paper over.

The source/binary status of the historical tools is maintained in
`OPENNT-BUILD-BOOTSTRAP-AUDIT.md`.

## Execution Order

1. Reproduce the historical build environment in an isolated disposable VM or
   container-like build image, never the host system directories.
2. Build the host tools required by real-mode targets, recording version,
   command line, input hashes and output hashes.
3. Build guest foundations in dependency order: message generation, NTIO,
   NTDOS, device drivers (including input/display/locale families), DPMI/XMS,
   commands, editor payloads and redirector.
4. Build host DEM/DPMI/XMS/redirector/monitor and `ntvdm` surfaces.
5. Create an artifact manifest that identifies every output as OpenNT-built,
   generated-data, external input, or absent; no unclassified binary enters a
   runtime profile.
6. Only then connect manifest-verified outputs to the independent non-invasive
   engine path.

This inventory is intentionally broader than a fixed NT4 EN-US BYOB profile;
the latter becomes one compatibility/test profile after reproducible OpenNT
outputs exist.
