# M0 T232 Closure — Unified Host-Handle Manager

## Outcome

M0 T232 closes on 2026-08-20. It replaces every active non-v1 DEM and
COMMAND private host-handle/token table with the adapter-owned
`bx_ntvdm_host_handle_manager`.

## Delivered Contract

- External Win32 `HANDLE` values stay host-private on both x86 and x64.
- Guest-visible values are opaque, nonzero 16-bit IDs with two indexes,
  monotonic allocation, idempotent publication, and explicit owned/borrowed
  cleanup.
- DEM preserves its historical `AX:BP` layout and rejects nonzero high-word
  input before lookup.
- COMMAND preserves its historical `BX:CX` layout, publishes a zero high
  half, and rejects a nonzero high half during launch/redirection lookup.
- No non-v1 product route or formal fixture retains a private
  host-handle/token table.

## Verification

- The full `build/M0-T232-S1/formal-r1` MSVC x64 `/MT` Ninja graph built
  successfully (82 incremental actions).
- Seven focused manager, DEM, and COMMAND fixtures exited zero; their exact
  results are recorded in [S3](../etc/evidence/t232-s3-command-unified-handle-migration-result-001.md)
  and [S4](../etc/evidence/t232-s4-non-v1-handle-cleanup-result-001.md).
- A source sweep verified that the remaining `HANDLE roots[26]` declarations
  are drive-root projection state, not a guest-token map.

## Boundary And Transfer

This is a representation/lifetime closure, not a DOS JFN/SFT implementation,
XMS allocation-handle implementation, or a claim of native DEM/COMMAND
concurrent execution. When a combined native session is admitted, it must own
and inject one instance of this manager. Future owner packages consume the
manager rather than recreate token tables.

Retained `bop-v1` comparison material and unrelated untracked S58 research
were intentionally excluded from this task.
