# M0 T270 Closure — mirror-component conformance reconciliation

## Objective and result

T270 implemented the owner request to govern mirror conformance one component
per S. It was a source-layout/ownership task only: no BOP route/provider,
guest, firmware, CPU, device or host capability behavior was admitted.

- **S1 `bochs-core`:** 177 exact and 28 registered changed files. The finite
  port-space source body returned from `adapter-bochs` to the matching private
  `bochs-core-overlay`; no external overlay consumer remains. Fresh external
  formal Ninja and focused native-PIC/checked-RAM fixtures passed.
- **S2 `opennt-guest`:** all 730 production files are byte-identical selected
  OpenNT inputs. Current staging/provenance verification produced 113
  artifacts; the old standalone build recipe is separately recorded as a tool
  closure issue.
- **S3 `opennt-host`:** six selected originals are exact and four registered
  divergences remain. The three over-threshold retained subsets moved to
  `opennt-host-overlay` behind same-signature mirror boundaries; formal Ninja
  and focused host fixture passed.
- **S4 `opennt-bop`:** 177 production inputs have a per-file disposition.
  Fifty-three selected-original inputs are exact or below threshold; six
  over-threshold bodies reside in `opennt-bop-overlay`; 118 BOP-owner route,
  observation and composition files are explicitly source-derived BOP
  implementation rather than falsely claimed mirror files. All overlay
  consumers are matching mirror translation units only. Formal Ninja and
  focused DEM, COMMAND, SoftPC and Redirector fixtures passed.
- **S5 `opennt-softpc`:** all 37 production inputs are exact selected OpenNT
  files. The current inventory consumer successfully read the re-rooted
  `bios.c` and `bios.h`; no overlay exists and no machine behavior changed.
- **S6 `opennt-utils`:** all eight retained `suballoc` inputs are exact
  selected OpenNT files. No overlay exists and the package has no current
  source/build/formal-link consumer.
