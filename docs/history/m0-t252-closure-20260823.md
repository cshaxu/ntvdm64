# M0 T252 Closure — OpenNT guest SFT opaque-token publication

## Result

The required SFT token seam was already code complete.  No guest overlay,
adapter replacement, Bochs change or new handle manager is justified.

The retained OpenNT guest source keeps the original four-byte `sf_NTHandle`
layout.  Existing v2 imported DEM Open/Create returns a shared opaque token in
the original `AX:BP` order; original guest source stores it low-word then
high-word.  DEM consumers reconstruct the token in `AX:BP`; Redirector's
original `MapNtHandle` reconstructs it in `BP:BX`.  The existing session-owned
manager resolves and releases only that token, never a host `HANDLE` from
guest memory.

The NT4 VDD `VDD*NtHandle` helpers remain excluded as intended: they require
the unavailable SAS/flat guest-pointer product composition and would cast raw
handles.  No admitted BOP route needs them.
