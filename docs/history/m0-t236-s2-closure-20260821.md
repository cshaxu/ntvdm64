# M0 T236 S2 Closure — COMMAND Historical Worker Recovery

## Scope And Result

S2 closes the one-session recovery of the imported OpenNT COMMAND historical
worker.  `cmdCreateProcess` is now compiled from the OpenNT mirror and is
called by the imported `cmdExec32` flow.  The retained body owns its original
environment conversion, current-directory lookup, suspended process creation,
resume/wait, exit result and reentrancy ordering.

Three narrow divergences remain:

- the worker executes within the active typed BOP call instead of a detached
  CCPU thread;
- its three standard streams are attached only to the child rather than via
  process-global `SetStdHandle`;
- it returns instead of calling `ExitThread` so checked guest-copy state stays
  valid through the result boundary.

The related `RtlUnicodeStringToAnsiString(..., FALSE)` compatibility seam was
corrected to preserve OpenNT's existing-buffer contract.

## Verification

- Formal MSVC x64 `/MT /W4 /WX` compiles succeeded for all changed owner and
  shim sources.
- The focused T236 fixture passed Direct/COMSPEC child execution, invalid
  opaque stream failure, anonymous-pipe transport, balanced reentrancy and
  CLI standard-handle isolation.
- Retained T231 lifecycle and T234 current-directory fixtures passed using the
  same source-current archive.
- The formal Ninja graph dry-run passed.  The known executor-side `cmd.exe`
