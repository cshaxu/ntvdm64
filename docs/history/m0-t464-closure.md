# M0 T464 closure — WOW hard-error responses

T464 closes the first remaining WOW32 response-recovery candidate.  It
preserves immutable guest media and selected original OpenNT ownership.

## Delivered sequence

- S1 established the original producer, descriptor, cancellation and
  caller-tail ledger.  It excluded DOS INT 24 and unavailable private
  CSRSS/USER server composition.
- S2 delivered the smallest receiver seam: sparse descriptor decoding,
  original source-slot preservation, default selection and cancellation
  mapping.  `ntvdm.exe` is the behavioral change.
- S3 proved that each selected returned result reaches one existing original
  continuation or fatal owner and that the receiver adds no second scheduler
  or terminator.
- S4 rebuilt the shared application identity as `0.0.464`, ran the complete
  product gate, published the coherent ten-image package, and recorded the
  finite private-server presentation boundary.

## Published evidence and limit

The final Full product gate passed all fourteen gates in 321,106 ms.  Its
published manifest covers `run16.exe`, `ntsrv.exe`, `ntcon.exe`, `ntvdm.exe`,
`ntvwm.exe`, `ntmon.exe`, `WOW32.DLL`, `VDMREDIR.DLL`, `nthook32.dll`, and
`nthook64.dll`; release and `O:\winnt\system32` hashes match.  No guest image
or guest source changed.

The closure proves the public receiver's source-slot response contract and
existing original cleanup ownership.  It does not assert automated operation
of the unavailable private NT4 hard-error server UI, its private labels, or a
real-modal click sequence.  That limit is intentional and is not transferred
as unfinished implementation to DDE.
