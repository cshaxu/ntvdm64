# M0 T250 Closure — source-built low-memory control-flow provenance

## Outcome

T250 closes the apparent far-target publication question without a code,
Bochs, BOP-provider, or machine-feature change.

The source-built checkpoint's `0000:0A87` bytes are not a valid NTDOS code
entry.  Original `DosInit` deliberately copies `DOSDATA` over the retired
NTIO staging aperture.  The position is `DOSDATA:OPENBUF+0x0F`, an
uninitialised work buffer.  Its accidental `call far [bx+0x326]` decode and
`5859:5F04` target therefore cannot identify a missing BOP, firmware value,
CPU feature, or host provider.

## Disposition

`BOP-DEPENDENCY-115` remains partial only for its actual owner question:
the earlier guest EXEC/parent-return transfer that reaches non-executable
`OPENBUF`.  A later guest-continuity package must investigate that predecessor
with a separately admitted selector-blind observation if source mapping alone
cannot identify it.  It may not repair the accidental target or reclassify it
as a BOP/machine problem.
