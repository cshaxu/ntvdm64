# M0 T254 Closure — DPMI Profile Admission Rejection

## Result

T254 S1 closes with an evidence-based rejection of a premature DPMI source
implementation admission.  No `53:xx` body, v1 route, v2 route, Bochs patch
or trace patch was added.

The retained OpenNT `dpmi32` source package is complete and attributable, but
every bounded DOSX profile depends on protected selector translation,
descriptor/context transition, fault/IRET frames and guest-linear allocation
semantics missing from the current fixed-width integration contract.  Its
historical `Sim32GetVDMPointer`, LDT, `VdmTib`, `NtVdmControl` and host-pointer
assumptions cannot be linked unchanged into the x64 product.

The full source/ABI/failure ledger is [T254 S1 evidence](../etc/evidence/m0-t254-s1-dpmi-profile-source-abi-admission-map-001.md).
It adds `BOP-DEPENDENCY-117`, corrects the tracker’s obsolete v1 wording, and
places selector-blind protected-mode substrate recovery ahead of DPMI in the
candidate queue.

## Transfer

The newly active successor is the generic substrate package.  It must first
establish the smallest machine operations through bx-mantle; it must not
introduce DPMI, BOP, DOS or OpenNT semantics into bx-core or bx-mantle.
