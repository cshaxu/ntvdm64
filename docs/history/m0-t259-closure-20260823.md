# M0 T259 Closure — OpenNT Host and SoftPC/CCPU Source-Shaped Facades

## Result

T259 establishes the required source-first compatibility-facade baseline for
every reached `HOST-01..12` and `MACH-01..09` interface family. Its two
simultaneous gates hold:

1. retain the original OpenNT interface spelling, ordering, data-width and
   observable failure contract wherever source can compose directly or through
   a smallest named facade; and
2. keep the resulting adaptation outside imported OpenNT mirrors and
   `bx-core`/`bx-mantle`, so the adopted Bochs core/mantle stay selector-,
   DOS-, SoftPC- and CCPU-blind.

The authoritative family map is the [T259 interface catalog](../etc/evidence/m0-t259-s1-host-machine-interface-catalog-001.md).
The final reached-seam reconciliation is in [S4 P4](../etc/evidence/m0-t259-s4-p4-final-host-machine-reconciliation-001.md),
and the final PIF/COMMAND dialog correction is in [S4 P5](../etc/evidence/m0-t259-s4-p5-command-pif-dialog-facade-closure-001.md).

## Recovered baseline

| Surface | T259 result |
| --- | --- |
| Win32, OEM and NTDLL/RTL callers | Same-named bounded facades preserve original string, allocation, status, path and error order over public Win32/current `ntdll` where usable. |
| COMMAND child/session routes | Existing OpenNT source ordering remains; public process/event/pipe composition is session-owned and never overwrites parent standard handles. |
| `RcErrorDialogBox` / `RcMessageBox` | One shared source-shaped facade serves DEM, COMMAND and directly imported PIF parsing. Historical `RMB_ABORT=1` is restored. |
| Handle and guest-pointer crossing | T258's one session mapping-manager implementation remains the only admitted host-handle/guest-memory crossing. |
| CCPU and machine calls | Copied CPU state plus typed mechanical effects retain bounded register/memory/interrupt semantics; Bochs remains the CPU and device owner. |
| Historical product shells | CSR/BaseSrv, VDD callback brokers, WOW/Redirector loading, full UMB/media, FDC/DMA/CMOS and durable/protected pointer routes are explicit deferred/unavailable owner work, never silent success. |

## Transfer

T259 does not claim that all historical NT4 product infrastructure is
recreated. The queue and live BOP tracker retain receiving owners for DPMI,
WOW16, Redirector, VDD/debugger/console, device/media and cross-family
integration work. They must consume this common source-shaped baseline; they
may not introduce a second pointer, handle, CCPU, dialog or host-API
substitute.
