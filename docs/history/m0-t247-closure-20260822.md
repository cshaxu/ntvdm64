# M0 T247 Closure — NTDOS guest EXEC entry and parent-return boundary

## Closed scope

T247 recovers and proves the source-defined **entry** boundary of the
guest-owned NTDOS EXEC lifecycle.  It does not claim an ordinary DOS child
return, because the current source-built native run stops first at an
independent selector-blind machine execution continuity boundary.

## Result

- S1 maps original `msproc.asm:$Exec`, `misc.asm:$Dup_PDB`, `alloc.asm`,
  `handle.asm`, `abort.asm`, `pdb.inc`, `$Exit/$Abort/reset_environment`, and
  their existing `50:36`/`54:07/08/0A/0B` contracts.
- S2 composes a fixed 50-byte, checked, read-only PDB observer only after an
  accepted imported `demEntryDosApp` (`50:36`) result.  It neither creates nor
  mutates PSP/PDB/arena/JFN state.
- Fresh MSVC x64 `/MT` formal Ninja fixture proves the PDB prefix decode,
  no guest-byte mutation, typed-stop rejection and out-of-range failure.
- S3's source-built native checkpoint observes original `50:36` with child
  PDB `0BF2h`, parent `8DF8h` and original exit/interrupt vectors.  Thus the
  source guest has completed `$Exec` PDB setup and crossed its child-entry
  handoff.

## Explicit transfer

The run then has accepted source-mirrored `50:1E demWrite` results but reaches
the existing `UNEXPECTED_LOOP_RETURN` terminal before source `$Exit/$Abort`
can restore the parent.  This is recorded as `BOP-DEPENDENCY-115`.  The next
owner is active M0 T248's selector-blind real-mode execution/interrupt/return
package; it must not be repaired by a DEM/COMMAND BOP patch or an adapter
PSP/return implementation.
