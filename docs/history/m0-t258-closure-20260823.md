# M0 T258 Closure — 16/32 Guest to 32/64 Host Mapping Manager

## Result

T258 closes the common mapping prerequisite without enabling a new BOP. One
`bx-vdm` mapping-manager implementation owns three separate fixed instances
for the one supported runtime session:

| Instance | Contract |
| --- | --- |
| `guest_memory` | Checked 16:16 real-mode and 32-bit-linear bounce lease, with address/access/epoch and explicit write-back. |
| `host_handle` | Opaque 32-bit guest ID bidirectionally maps a host-private x86/x64 `HANDLE`; ownership is explicit. |
| `session_data` | Opaque 32-bit ID maps a bounded host-private object with an optional release callback. |

These are independent instances with independent entries/counters, not one
numeric namespace. Only their fixed session accessors are accepted; a
hand-embedded look-alike instance is rejected.

## Source And Boundary Result

The manager is the bounded, OpenNT-shaped facade for unavailable SAS/CCPU
pointer backing. Historical `GetVDMAddr`/`Sim32*` spellings remain in imported
source bodies. Imported DEM handle calls now use `guest_memory` for fixed and
ordinary synchronous spans while retaining the original flush/free order.
No bx-core, bx-mantle or Bochs semantic change was made.

The outer engine now resets all three instances at session admission and every
cleanup path, retiring leases, closing owned host handles and releasing opaque
session data together.

## Transfer

COMMAND multi-buffer/child-worker calls, XMS cross-call A20 state, DEM
multi-span/persistent paths and protected DPMI mappings remain their original
owner packages' explicit migration debt. The manager does not turn them into
raw-pointer or generic host-interface successes.
