# M0 T308 closure — monitor / NtVdmControl user-mode contract

## Result

The directly composable monitor subset is closed. `VdmQueryDir` remains the
only enabled `NtVdmControl` form: it is session-bound, preserves
`VDMQUERYDIRINFO` and propagates the callback's `NTSTATUS`. The source-shaped
`VDM_TIB` carrier is bound only to the current adapter-private TEB on the
session worker thread.

## Verification

`tools/build/New-T308MonitorControlNinja.ps1` built and ran both monitor
fixtures under MSVC `/MT` on x86 and x64. Each architecture passed the
`VdmQueryDir` status/binding contract and the `VDM_TIB` thread-carrier
contract.

## Boundary

The remaining fourteen `VDMSERVICECLASS` values have exactly one recorded
machine, DPMI, VDD/device, broker or hard-unavailable owner in the
[service disposition ledger](../etc/operations/m0-t308-s1-ntvdmcontrol-service-disposition.tsv).
This task did not recreate kernel VDM, CSRSS, a second executor, an app-owned
monitor route, or any BOP behavior.
