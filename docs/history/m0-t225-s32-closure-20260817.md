# M0 T225 S32 Closure — Original Bootstrap/Device-Header Lifecycle Map

## Closed scope

S32 is a read-only, source-first audit of the original NTIO-to-NTDOS bootstrap
and first device-header lifecycle. It made no runtime, guest, BOP/provider,
Bochs, or host-capability change.

## Delivered evidence

- [The lifecycle source/ABI/failure map](../etc/research/t225-s32-bootstrap-device-header-lifecycle-source-abi-failure-map-001.md)
  covers original resident NTIO initialization, `50:11` NTDOS loading,
  temporary `sysinit` relocation, `DosInit`/DOSDATA transition, device-chain
  initialization, and `charinit`/`DEVIOCALL2` inputs.

## Result and transfer

The current `50:11` implementation is proven as a narrow original-shaped
mechanical seam: it writes the authenticated NTDOS image to the guest-selected
real-mode `DI<<4` address and resumes after the four-byte BOP. It neither
selects a DOS load address nor constructs DOSDATA, a device header, a request
packet, or a device chain.

The retained native DS end-of-limit event is post-load but pre-attribution.
It remains compatible with the source-built `DEVIOCALL2` strategy-field read,
but establishes neither dynamic instruction identity nor `sysinit`/`DosInit`
completion. S33 owns only the source/ABI admission of a bounded,
non-invasive guest bootstrap continuity observation. It may not implement a
BOP/provider, preseed original state, or repair CPU/machine behavior.
