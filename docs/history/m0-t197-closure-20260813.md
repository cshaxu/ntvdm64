# M0 T197 Closure -- Native Bochs Core/Mantle Extraction

## Result

T197 is closed.  It makes the first-stage architecture physical:

```text
src/bx-core/     adopted Bochs CPU, FPU, memory and decode families
src/bx-mantle/   finite native Bochs lifecycle composition
src/bx-vdm/      separate typed VDM/BOP adapter
```

The selected fixed profile is CPU5/Pentium-MMX, non-x86-64.  Fresh r12
source-builds 129 named core/mantle inputs into 130 objects, links the
minimal-machine witness with MSVC/x86, and executes the finite lifecycle:
`initialize(1 MiB, 1 MiB) -> CPU5 reset/APIC/CPUID -> cleanup()`.

## Boundary Result

The final closure contains neither `main.cc`, `config.cc`, product SIM,
GUI, plugin/device archives, `bochs.exe`, adapter code nor OpenNT input.
Original CPU decode remains an adopted whole-family dependency; it was not
replaced by a trace-selected instruction subset.  The mantle owns finite SIM,
logging/parameter support, no-device port space, no-product shell behavior
and native lifecycle assembly.  BOP selector/service/provider meaning remains
in `bx-vdm`.

## Transferred Limitation

T197 does not execute an instruction loop or a guest.  A future execution
admission must separately define a reset image/entry, a finite instruction
budget and controlled stop.  It cannot import the historical product BIOS,
devices or GUI as a shortcut.

The next package is the owner-selected holistic BOP host-service and
machine-composition runtime closure.  Its first action is to map and compose
the existing bounded BOP runtime against this new native machine boundary;
it must not turn Bochs into a BOP dispatcher or return to per-service hacks.
