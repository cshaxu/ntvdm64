# M0 T204 Closure — contained startup configuration

## Delivered boundary

T204 replaces the prior fixed `CONFIG.SYS` / `AUTOEXEC.BAT` boot bytes with
one explicit, paired, provider-owned startup-configuration route:

```text
CLI paired paths -> child-only environment -> one bounded installation copy
-> ready contained provider -> namespace and copied COMMAND paths
```

The CLI never opens the two source files. The adapter opens each once during
installation, accepts at most 4095 OEM bytes, requires a nonempty CONFIG,
permits an explicit empty AUTOEXEC, closes both handles, and retains only
provider-owned copied data. The namespace contains declared paths/metadata but
no synthetic file bytes; an unbound declaration is empty.

## Evidence

- Focused strict MSVC x64 `/MT /W4 /WX` reader and runtime-installation tests
  cover copied input, invalid/missing/oversized rejection, source deletion
  after installation, and paired `54:0C` path preparation.
- The strict MSVC x64 `/MT` current source boot-namespace composition closure
  compiles, links and runs after synthetic-byte removal.
- A strict current-source `ntdos64-run` / `runner-engine-probe` exercise uses
  a v6 owned BYOB profile and explicit paired inputs. With inherited source
  variables absent, the child probe receives both values plus profile/root,
  normalized drive policy and the versioned launch plan; it returns its
  deliberate success code `47`.

## Limits

T204 does not prove native guest startup, execution of configuration commands,
top-level `5E` UMB/DASD work, PIF behavior, console behavior, or any Bochs
change. It creates no host temporary file and performs no host-system
modification.
