# M0 T284 closure — historical-interface adapter convergence

## Result

M0 T284 is closed. The historical MVDM host-facing interface surface is
now represented by one classified outgoing adapter root,
`src/adapter-mvdm-host-out`, without making it a generic compatibility layer.

- `win32` owns the migrated historical Win32/NTDLL façade inputs.
- `softpc` owns the four original-call-shaped SoftPC/CCPU/SAS façade sources
  and five declaration carriers.  Its only machine-facing dependency is the
  typed `adapter-bochs` boundary; it does not include or call `bochs-core`.
- `monitor` owns the original-call-shaped VDM monitor declaration and
  session-bound source carriers.
- `redir`, `wow`, `vdd`, and `debugger` are explicit owner families with no
  admitted provider implementation.  Their former empty roots were removed;
  this does not claim those product capabilities are available.

`adapter-mvdm-host-in` remains a separate, selector-blind incoming machine
event bridge.  `adapter-bochs` remains the sole Bochs mechanical boundary.

## Verification

- All twelve focused family fixture executables completed successfully on both
  x86 and x64: host identity, guest location, VDD SFT shadow, COMMAND register
  binding, VDM control, and local VDM command transport.
- Family-specific formal MSVC/Ninja graphs selected and built the SoftPC and
  monitor inputs on both architectures.
- The final live-root scan found no old adapter root.  The sole textual match
  is the intentional historical statement in `docs/STATUS.md` that
  `adapter-win32` is absent.
- The final direction scan found no `bochs-core` dependency from
  `adapter-mvdm-host-out`; the one `adapter-bochs/machine_facade.h` inclusion
  is the explicitly permitted typed SoftPC mechanical seam.

## Recorded non-result

The broad pre-rebootstrap T260 component graph is not a validation target for
this packet.  Its manifest still selects deleted historical experiment and
pre-migration source paths (for example `src/session/session_input.c`), so it
cannot currently generate a complete graph.  T284 deliberately does not
restore those exited inputs simply to make a stale aggregate graph pass.  A
later product-graph reconciliation packet must re-inventory every selected
module before whole-product validation is claimed.

## S9 guest component normalization

The selected DOS/V86 and WOW16/bin86 carries are now one load-only
`mvdm-guest` component with two interior roots: `dos/` and `win16/`.
The S9 identity check found no source mismatch across 676 DOS, 44 WOW16 and
10 bin86 paths; the eight carried Win16 driver products match
`build/output/wow16`. The guest component remains outside every host link
input. See the [S9 evidence](../etc/evidence/m0-t284-s9-mvdm-guest-root-merge-001.md).
