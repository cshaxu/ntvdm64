# M0 T280 S20 closure — DEM persistent guest-location recovery

S20 has removed every reached DEM global which retained a `GetVDMAddr` native
pointer beyond its source callback:

* DTA, extended-error and current-PDB locations retain only their original
  numerical 16:16 form and obtain fresh bounded guest-memory leases;
* the SFT-chain head retains DS:offset numeric data; and
* the original VDD SFT/JFT pointer ABI is recovered through a session-owned,
  synchronous host shadow with explicit source-visible commit/discard points.

The existing session `host_resource` mapping-manager instance owns only
host-local shadow and native-HANDLE identities. It never tokenises a DOS
numeric address. Formal x64/x86 fixtures prove the shadow lifecycle,
stale rejection, session isolation and teardown cleanup; formal DEM source
syntax passes on both architectures.

This is a source/boundary closure only. No DEM/WOW provider, BOP selector or
guest trace is enabled. Other transient `GetVDMAddr` calls outside the reached
retained-global family remain owned by their separately classified packages.
