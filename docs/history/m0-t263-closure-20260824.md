# M0 T263 closure — OpenNT MVDM owner expansion

M0 T263 is closed on 2026-08-24. It changed source ownership and preservation,
not product behavior.

- Architecture now defines six original-code components, four mechanical
  adaptation components and two composition components.
- `opennt-guest` gained the exact original `bin86` package.
- New `opennt-softpc` gained exact original BIOS/ROM input packages without
  becoming a second machine runtime.
- New `opennt-utils` gained the exact original `suballoc` package without
  becoming a generic common layer.
- `opennt-host` retains only actually composed/recovered original host bodies.
  A brief preservation-only import of VDD/debugger/fax packages was withdrawn:
  future owner packages must import them only when their provider is admitted.
- `tools/opennt` gained the exact `tools16` closure as a non-runtime historical
  tool input.

All individual package hashes and boundaries are recorded in T263/S2 through
S6 evidence. The final owner/build check is
[T263/S7 closure evidence](../etc/evidence/m0-t263-s7-mvdm-owner-expansion-closure-001.md).
The subsequent production-boundary correction is the
[T263/S7 P2 withdrawal record](../etc/evidence/m0-t263-s7-unconnected-host-package-withdrawal-001.md).

T263 was reopened by owner direction as S8 for the separate repair of the four
already composed OpenNT host source subsets. S8 is now also closed: the
original logical blocks in `nt_error.c`, `vrinit.c`, `vrnmpipe.c` and
`vrputil.c` were restored through registered same-shaped adapter calls or
explicit whole-block crops. Fresh formal focused fixtures cover both the BOP
59 direct-access route and the VDMREDIR utility/lifecycle/local-pipe path; see
[T263/S8 P3](../etc/evidence/m0-t263-s8-p3-focused-host-mirror-fixture-001.md).

T263 was reopened a final time as S9 because the S8 acceptance of `nt_error.c`,
`vrinit.c` and `vrnmpipe.c` was too permissive. S9 rebuilt them as cited,
reviewable original-body subsets. It removed the fabricated `VrInitialize` /
`VrUninitialize` success state: `57:00`, `57:01`, and `LoadVdmRedir` now fail
explicitly until the VDD/CCPU/NetBIOS/DLC/ICA lifecycle has an admitted owner
package. The fresh formal Ninja closure and all four focused fixtures passed;
the final evidence is [T263/S9](../etc/evidence/m0-t263-s9-three-file-original-body-recovery-ledger-001.md).
