# M0 T307 closure — Base VDM source-shaped broker recovery

## Result

M0 T307/S1 is closed. The directly reached one-session DOS Base VDM public
family now has one source-shaped owner:
`adapter-mvdm-host-out/basesrv`. It preserves original public spellings and
`VDMINFO` shape without importing a BaseClient/BaseSrv CSRSS product shell.

## Recovered contract

- `GetNextVDMCommand(VDMINFO *)` retains copied request/result handling,
  capacity feedback, environment retrieval, a single DOS record and reentry
  count handling.
- `GetNextVDMCommand(NULL)` retains the original first-VDM query-and-clear
  semantics in the one supported session.
- `SetVDMCurrentDirectories` / `GetVDMCurrentDirectories` retain copied
  `MULTI_SZ`, insufficient-size reporting and one-shot consumption.
- DOS `ExitVDM(FALSE, ...)` completes the bound session rather than terminating
  the CLI host process.

The formal Ninja fixture passed on MSVC `/MT` x86 and x64. It also proves
unbound and completed-session failure behavior, no-command/reentry handling,
and WOW rejection.

## Ownership sweep

- There is no production `app` or monitor command-provider route parallel to
  the Base VDM facade; monitor `NtVdmControl` remains a distinct control plane.
- `RegisterWowExec`, shared-WOW command wakeups and `ExitVDM(TRUE, ...)` belong
  to the queued WOW/broker package.
- `VDMOperationStarted` is called only by the excluded historical SoftPC
  executor route. Any Bochs lifecycle notification is a machine-owner decision,
  not Base VDM behavior.
- CSRSS capture buffers, console/global records, PIF, child record and
  cross-process behavior remain explicitly excluded; no local success is
  claimed for them.
