# M0 T202 Closure — owner-package DEM and COMMAND recovery

T202 closes the first host-integrated owner-package recovery wave after T201.
It intentionally used complete DEM and COMMAND package boundaries, rather
than creating tasks from individual trace hits.

- S1 installed the common mutation-profile consumer at the DEM package seam.
- S2 recovered the admitted direct host namespace/CWD/volume slice.
- S3 mapped the DEM file/handle/FCB/search ABI and failure surface.
- S4 closed the source-derived DEM whole provider with direct, readonly and
  explicit unbacked profile outcomes.
- S5 mapped all `54:00..10` COMMAND identities before implementation.
- S6 closed one COMMAND package session with implemented or explicit
  source-shaped deferred disposition for every identity.
- S7 rejected an invented host-child-to-DOS queue after mapping the historical
  BaseSrv/CSR broker lifecycle.

The result is not a broad NTVDM compatibility claim.  It does not recover
Redirector, DPMI, WOW, interactive COMMAND/VDD, a historical VDM broker, or
continuous native guest execution.  Those remain distinct owner-package or
engine capabilities with their explicit dispositions.

source-derived bx-vdm provider. The atomic route owns all 27 local identities;

[S4 session and integration record](../../artifacts/documentation-archive/20260910/etc/research/t202-s4-dem-whole-provider-session-001.md).

# M0 T202 S6 Closure — COMMAND whole-provider recovery

S6 closes the admitted `54:00..10` COMMAND provider package.  Every callable
identity enters one COMMAND session and has one implemented or explicit
source-shaped deferred result.  The delivery includes copied host context and
environment, console/no-KEYB disposition, boot-input paths, opaque standard
stream tokens, checked `STD_HANDLES`, direct terminal child execution, and
typed declared-DOS return/next behavior.

The x64 `/MT` common-ingress regression covers all 17 identities; its direct
child case runs `cmd.exe /c exit 7` and observes CF clear with AL 7 without a
raw handle/PID, `SetStdHandle`, VDD, pipe worker, or VDM broker.  A bounded
current-source native run compiled and linked the complete manifest but did
not reach `54:xx`; it is retained as negative integration evidence only.

The closure does not claim interactive VDD/KEYB console, Redirector pipe
transport, or host-child→DOS re-entry queue.  The first is an opt-in console
capability, the second belongs to Redirector, and the third becomes S7's
complete lifecycle-contract admission rather than a trace-selected endpoint.

## m0-t202-s7-closure-20260815.md

# M0 T202 S7 Closure — COMMAND host-child re-entry admission

S7 closes with a **no-admission** decision for a CLI-owned host-child-to-DOS
re-entry queue.  The complete original `cmdExec32`, `cmdReturnExitCode`, and
`cmdGetNextCmd` map shows that the `CmdSize > 0` branch is owned by the NT4
BaseSrv/CSR VDM command broker, DOS-record state, wait handles, event thread
and Redirector completion—not by a local command list.

The current direct child capability remains a bounded terminal transaction.
It preserves the original `RETURN_ON_NO_COMMAND` form (`CF=0`, low completion
byte) without passing a host handle, pointer, callback, guest address or
Bochs state across the boundary.  The immutable declared DOS launch plan is
not repurposed as a child-completion queue.

Evidence: [S7 admission decision](../../artifacts/documentation-archive/20260910/etc/research/t202-s7-command-reentry-admission-decision-001.md).

This closure does not claim interactive COMMAND, a BaseSrv replacement,
Redirector pipe completion, VDD console support, or native guest closure.
