# T473 S9 closure — generic USER carrier identity

S9 closes the selected public-USER wrapper identity family after P1 delivery.
The [source and acceptance evidence](../etc/evidence/m0-t473-s9-generic-user-wrapper-audit.md)
records the original callers, native/public handle boundary, local changes,
individual failed attempts and the coherent r10 package. The per-entry
[mapped-wrapper index](../../artifacts/mvdm-audit/s9-mapped-wrapper-index.csv)
records 61 mapped entries, their null/result policy, product-map symbols and
test-source references; a reference is not a claim that every branch ran.

The existing owner maps original 16-bit HWND carriers to the published host
window identity. Null, pseudo Z-order and additional HWND parameters retain
their distinct contracts; destruction uses the existing no-publication return
path. The original DC cache retains the full acquired host HWND through
deferred release. No guest image was modified or rebuilt.

The 19-case native/real-CCPU supplementary group passed. Its extended
`wrapper-coverage-r6` validates actual native Unicode text, child Z-order,
window placement, drag cancellation and a modal EndDialog short carrier.
The visible `focus-visible-r8` validates activation/focus; USER refused the
foreground request, so foreground success is not claimed. The r10 real guest
dialog probe passed its eight phases, including two modal completions. The
product gate's 17 Console and 17 Window expected results all matched, all
11 Control gates passed, and the retained WINMINE, SOL gameplay/Options and
WRITE lifecycle probes passed. These are bounded witnesses, not proof of
every application, drag threshold, foreign-window race, foreground-policy
case, acquisition-generated callback or every exception path.

The same ten r10 images were published to `assets/release` and
`O:/winnt/system32`; all ten matched the release manifest and r10 staging
on the subsequent hash recheck. The last follow-up changed only test and
audit evidence, not the released product bytes.

The independent [whole-source audit](../../artifacts/mvdm-audit/README.md)
and its identified generic CallProc32 stack-contract discrepancy belong to
the next audit and approved subsequent owner packages. S9 closure does not assert
MVDM-wide completeness or fix that separate thunk.
