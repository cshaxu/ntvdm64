# Proposal: CPU40/NTDOS post-`54:0C` startup continuity

## Question

What is the smallest complete original COMMAND/CPU40/NTDOS owner cohort that
continues from the now-proven original `cmdGetConfigSys` return into the next
guest bootstrap transition?

## Evidence baseline

T352 proves that the complete original `54:05` scalar-registration cohort and
the reached original `54:0C` cohort return in the fixed CPU40/x86 container.
It does not establish the next guest instruction, a DOS workload, `EXEC`, or
graphics behavior.

## Scope

- Freeze the same selected CPU40/x86 product model, 39-character system-root
  invariant, immutable media and child-only durable observation mechanism.
- Walk original `cmdGetConfigSys`, its caller/guest continuation, CPU40/SAS,
  NTDOS bootstrap and actually reached immediate machine predecessors.
- Select a complete source owner package before implementation; recover only
  original source, smallest same-shaped binding or registered minimal overlay.

## Exclusions

No standalone BOP leaf repair, guest rewrite/rebuild, media mutation,
alternate executor, CPU30, Bochs, x64 runtime, kernel VDM, CSRSS/BaseSrv,
WOW scheduler, graphics workload, or DOS child/parent execution claim.

## Completion record

An admitted packet must prove the next original guest ingress or exact
source-owned terminal result after `54:0C`, with a selected CPU40/x86 formal
link and one fixed-container durable record.  It must explicitly distinguish
bootstrap continuity from workload execution.
