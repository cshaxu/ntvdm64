# Proposal — 从宿主启动 Windows 1.01 应用程序

## 状态与所有者目标

所有者要求在队尾增加独立候选任务，让本项目 NTVDM 支持从宿主启动
Windows 1.01 应用程序。本包是未编号候选，不改变当前活动任务。
按[执行规则](../rules/EXECUTION.md)准入后实施；队列位置以
[Queue](../states/QUEUE.md)为准。

用户在宿主指定一个 Windows 1.01 应用及参数后，通过产品正常启动
入口进入匹配的 Windows 1.01 guest 环境并执行该应用，无需先手动
启动 Windows 桌面再操作应用菜单。执行使用 Windows 1.01 自身的
kernel、USER/GDI 和应用合同，不把“能启动 Windows 桌面”当成
“能直接启动指定应用”，也不假设宿主 WOW32 可以正确承载这些程序。

## 已知基线与调查入口

[Windows 1.01 add-on closure](../history/m0-t435-win101-addon-closure.md)
已记录安装与 guest 内 Notepad 执行，但宿主直接 run16 Notepad 被
保留的原始分类规则拒绝：当时 SEC_IMAGE 返回 C000011B，经原分类
映射为 OS/2。该历史结果不是新基线的必然故障；准入时须复测。

审查实际原始可执行格式、Windows 版本标记、启动 stub、应用参数、
WIN.COM 启动语法与 guest 应用装载链，再确定分类与启动适配方案。
不能看到 NE 签名就一律视为现代 WOW Win16，也不能按 NOTEPAD.EXE
文件名、所在目录或单个成功样本建立应用白名单。

## 实施范围

1. 冻结合法的 Windows 1.01 安装/介质、匹配应用、驱动、当前正式
   产品包与哈希，复现宿主直接启动结果及 guest 内正常启动对照。
2. 恢复或最小适配源定义的格式/版本分类与错误合同，明确将应用
   路由到兼容 Windows 1.01 环境的依据。区分真正 OS/2、其他 Win16、
   DOS、PE、损坏和不支持映像；文件扩展名不能成为充分判据。
3. 明确安装环境的选择、缺失/歧义错误和启动请求合同；复用已有
   产品入口与运行实例机制，不硬编码驱动器、仓库路径或应用名。
   安装目录不同于应用 CWD，不能靠修改用户 PATH 偷换环境。
4. 由 guest 原始启动/装载流程执行目标，保留参数、工作目录、
   应用资源和 DLL 搜索、图形及鼠标输入。若需要独立适配工具，先
   证明最小边界和正式所有权，不能暗加常驻 helper 或第二模拟器。
5. 定义并验证默认启动返回、显式等待、启动失败及退出结果；按
   原始可观察事件表达，不把 Windows 桌面出现、launcher 退出或
   worker 存活当作应用启动/结束。共享 guest 环境中的应用不应
   被伪装为独立 Windows 进程。
6. 验证重复启动、已有环境是否可复用、多个应用、应用退出与
   Windows 退出的区别、资源释放及互不影响。实例复用取决于原始
   可行合同，不预设跨实例调度或强制复用。

## 验收与建议阶段

| 阶段 | 有界结果 |
| --- | --- |
| 分类与方案 | 复测历史拒绝路径；给出原始格式/装载链依据、环境选择和启动/等待/错误合同，列出真实测试矩阵。 |
| 生产实现 | 正式入口、分类、环境选择和 guest 启动实际接通；移除被替代的绕行，完成正负及错误传播测试。 |
| 应用与生命周期 | 从宿主启动 Notepad 和另一项经过确认的原始应用，完成实际交互、参数/CWD、重复启动、多应用及退出/失败验证。 |
| 综合交付 | 保留 DOS、现有 WOW/Win16、Win32、图形输入和控制生命周期回归，审核源/diff 与部署身份，交付可复现用户入口和限制。 |

每个实现阶段记录真实 production caller/provider、精确命令、前提、
测试断言、运行产物身份与结果。覆盖带空格/非 ASCII 路径、同名
应用、错误安装版本、缺失环境/资源、损坏映像及分类隔离。不能
只验证窗口标题、返回零或桌面截图；需证明指定应用被 guest 装载
并完成其实际操作。正常退出后输入、屏幕和宿主会话必须恢复正确。

采用准入时正式组件位宽与包清单，遵循既有构建、回归、发布和恢复
规则。原始 guest/固件保持不可变，按[来源政策](../etc/operations/policy/source-policy.md)
调查和选择源；既有补丁许可不自动扩展到新 guest 补丁。不以伪造
映像头、批量改分类、文件名特判、环境截断或吞掉错误实现表面成功。
禁止修改或重编译 guest；其他架构扩张需要明确准入。规划本身不
声称已经支持从宿主直接启动 Windows 1.01 应用。
