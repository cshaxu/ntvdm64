# Proposal — Win3.1 窗口化 DOS 异常文字调试

## 状态与目标

本项已由所有者准入 T479 S9，合并三种窗口/全屏切换显示故障。
见 [S8/S9 实施计划](../etc/operations/m0-t479-s8-s9-import-plan.md)。
不再作为独立 T 排队；S8 完成后执行 S9。

目标是定位并修复 Win3.1 增强模式 MS-DOS 窗口中的异常文字显示。
现象与当前桥接工作的关联以实际证据为准，不预设是编码、字体、
显存、VDD 或宿主绘制问题，也不把键盘输入、任务挂起或崩溃混为同一故障。

## 调查与修复范围

1. 冻结产品、独立 addon、安装配置和原始 guest 身份；从现有
   [S6 I/O 证据](../etc/operations/m0-t479-s6-io-audit.md)恢复复现入口。
2. 对照 DOS 窗口首次打开、命令输出、清屏、窗口化与全屏切换、
   宿主任务返回后的显示；保留实际错误文字及对应屏幕内容证据。
3. 沿实际字符/属性、字体/代码页、视频模式、guest VDD 和最终
   呈现链定位首个错误边界，区分错误内容与正确内容被错误绘制。
4. 仅修复已证明的宿主或独立 addon 缺陷，复用原版逻辑并登记
   必要镜像差异；不修改、重编译或热补丁原始 guest。
5. 验证重复切换、重绘、命令执行和正常退出，以及不引入鼠标、
   键盘、VM 隔离和任务链回归。

## 验收与交付

要求有明确复现与根因、修复前后同条件对照、真实窗口化 DOS
显示及生命周期验证。若无法复现，记录精确环境和覆盖边界，
不能宣称修复；若证明为原始 guest 缺陷，按源码政策登记并保持原样。
准入后按现行执行规范完成必要构建、测试、完整发布、提交和推送。
