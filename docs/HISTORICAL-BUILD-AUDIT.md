# Historical Build Audit

## Fixed Inputs

| Item | Evidence location | Finding |
| --- | --- | --- |
| OpenNT VDM source | `upstream/opennt/base/mvdm` | Contains historical makefiles for `ntio.sys`, `ntdos.sys`, SoftPC, DEM, and device components. |
| NTVDMx64 patch tree | `upstream/ntvdmx64/ntvdmpatch` | Contains patch/build/release scripts, not a complete independent NTVDM source tree. |

| Additional inputs | same | Requires a 7-Zip install plus SDK/Windows ISO material selected by the build script. |

## Product Evidence

The OpenNT BIOS makefile names `ntio.sys` as its output and uses `link16`,
`mapsym`, and `reloc`. The DOS-kernel makefile names `ntdos.sys`. Those are
historical build contracts, not inputs that can be regenerated by this owned
CMake project without the missing source/toolchain environment.

The NTVDMx64 release route adds loader, console, WOW64, registry and system
integration pieces. It is useful evidence for compatibility responsibilities,
but it is not a conforming implementation of this project's non-invasive
runtime rule.

## Decision

Do not acquire, import, compile, package, or redistribute missing protected
source archives automatically. An owner who supplies a lawful local copy may
authorize a separate isolated-VM reproduction experiment, but it remains a
historical build result, not a dependency of `ntdos64-run`.

The owned engine path must instead expose a BYOB manifest, load only files a
user selects, and reproduce required guest semantics without private Windows
loader/console dependencies.
