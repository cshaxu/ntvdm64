# Formal Build Entrypoint And Reconstructed-Monitor Fixture Repair

## Decision

The root `CMakeLists.txt` was an obsolete pre-component-layout target
catalogue. It named deleted `src/bx-vdm` and `src/cli` inputs and was not the
current MSVC x64 `/MT` formal build graph. It is removed rather than preserved
as executable-looking legacy code; Git history and T267 evidence retain its
provenance.

The formal route is the manifest-driven Ninja graph generated by
`tools/build/New-T260S8FullNinjaGraph.ps1`. Its component manifest is the
only current build-source inventory.

The reconstructed monitor is a retained legacy fixture, not a production
component. Its implementation, header, and fixtures use the semantic
`reconstructed_monitor_*` contract. This task removes incompatible historical
spellings and task-label identifiers, then keeps the package under one legacy
fixture root. It does not make the fixture part of the formal Ninja product
graph.

## Planned S Sequence

**S1 — entrypoint retirement, live-consumer reconciliation, and
reconstructed-monitor fixture closure.** Retire the root CMake graph, update
current build instructions, scan and repair all live generator, manifest,
tool, CI and instruction consumers of obsolete component roots or CMake, and
rename the monitor package and its fixtures to semantic names. Historical
prose remains indexed evidence rather than executable configuration.

## Acceptance Boundary

This package fixes build-entry and fixture-consistency debt only. It does not
claim that the old CMake target catalogue can build, nor does it alter the
formal Ninja component build semantics.
