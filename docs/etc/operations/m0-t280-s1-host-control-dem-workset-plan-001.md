# M0 T280 S1 — host-control and DEM workset admission plan

## Owner package

T280 is one original owner recovery packet, but it is not permission to
compile all historical `softpc.new/host/src` sources. The selected product
workset combines the complete original DEM provider package with only the
tracker-approved SoftPC host-control façade/control bodies.

The workset inherits these exact tracker outcomes:

- 16 DEM provider bodies are `adapter-backed`;
- 33 host-control bodies are `adapter-backed`;
- six host-control source bodies are `overlay-required` because they combine
  useful control flow with direct CPU/RAM/page transport;
- five declarations are `binding-only`; and
- 21 host/DEM paths are `not-host-runtime` because they are alternate
  executors, build controls or standalone historical product forms.

### Historical-count reconciliation

The earlier T276/S25 narrative describes **38 remaining SoftPC control
bodies**: 25 `adapter-backed`, six `overlay-required`, and seven
`not-host-runtime`.  It is not the same population as this workset.

T280 derives every selected `softpc.new/host/src` path from the final global
disposition ledger.  That source-path population is 59 paths: 33
`adapter-backed`, six `overlay-required`, one `binding-only`, and 19
`not-host-runtime`.  The additional 21 paths are source/declaration/build or
historical-product paths outside the earlier 38-body control subset.  S1 must
preserve both statements with their scopes; it must not rewrite the historical
38-body evidence or silently treat the counts as interchangeable.

## Dependency groups

S1 produces groups for subsequent bounded implementation, in this order:

1. fixed-width BOP ingress plus source-shaped host-control dispatch boundary;
2. checked guest-memory/SoftPC facade declarations, with session mapping only
   for actual DOS/VDM numerical addresses;
3. original DEM dispatch, data and namespace/file providers;
4. original host event, stop and public Win32 endpoint providers; and
5. the six narrow CPU/RAM/UMB overlays, after their adapter-softpc and
   adapter-bochs mechanical operations are independently proved.

Neither a historical CCPU executor nor a direct Bochs object may enter an
OpenNT source body. The workset uses existing `adapter-bop`,
`adapter-softpc -> adapter-bochs`, `adapter-win32`, `session` and named later
adapter boundaries only where the original caller evidence requires them.
