# M0 T357 — CPU40 staged boot and COMMAND-ready boundary

## Purpose

Activate the first selected runtime component chain under the formal product
contract: app/session package admission, immutable executable-relative media,
Base-VDM declaration, original SoftPC CPU40 entry and the earliest original
COMMAND-ready boundary.

## Sequence

1. **S1 — stage identity and owner admission.** Reuse a manifest-identified
   formal CPU40/x86 executable only if its source/build identity is proven;
   create a new task-owned runtime stage with
   `Stage-OriginalSoftpcRuntime.mjs`; verify every immutable media hash and
   app-visible adjacent layout. No product code change or runtime observation.
2. **S2 — frozen staged boot observation.** Invoke only the existing fixed
   console-owning observer through `ObserveSoftpcStartup.mjs`, once, with the
   staged product and fixed `--command` declaration. Record the first original
   source boundary or terminal.
3. **S3 — capacity-valid stage correction, immediate dependency activation or
   closure.** If S2 proves only an app-owned package-path-capacity rejection,
   create one fresh short-path stage using the same immutable product/media
   inputs and resume the frozen workload.  If it instead proves a named
   original owner component is missing from the formal graph, recover that one
   owner package through original source, same-shaped binding, formal link and
   the same workload before resuming this boot path. Otherwise close this T at
   the reached COMMAND-ready boundary and admit the COMMAND lifecycle package.

## Exclusions

No guest/media mutation, host alias, BOP leaf repair,
CPU/device semantic change, CPU30, Bochs, x64 runtime, CSRSS/kernel VDM,
WOW, external child or graphics work. The staged executable is a disposable
product copy; source media remains immutable.

## Completion

T357 is complete only with a staged runtime observation that reaches a
source-defined original COMMAND-ready boundary, or with a single exact missing
owner component activated and the resulting resumed observation classified.
An app rejection, formal link or staging manifest alone is not boot success.
