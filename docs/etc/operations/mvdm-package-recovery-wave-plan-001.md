# MVDM package recovery waves

Each wave is an unnumbered candidate T after the package tracker closes. A
wave imports complete original owner units and implements only the pre-recorded
same-shaped interface closure. Its order is dependency-led; an unresolved
tracker row blocks admission rather than inviting a local workaround.

## Wave 1: low-dependency support packages

`dirs`, `makefil0`, `inc`, `oemuni`, `suballoc` and `vdmutils`. Establish
original build-control forms, directly composable headers/utilities and their
x86/x64 library closure. No MVDM provider or BOP route is enabled.

## Wave 2: host control plane and DEM

Reached `softpc.new/host` control units plus the `dos/dem` owner package.
Requires the tracker-approved minimum BOP, SoftPC/SAS and Win32 boundaries.
It establishes original host control and DOS namespace/file/session semantics;
it does not import the old SoftPC CPU implementation.

## Wave 3: COMMAND local lifecycle

The `dos/command` owner package through source-shaped local process,
environment, re-entry and result paths. Cross-process BaseSrv-style behavior
waits for the separately tracked broker boundary; no alternate lifecycle
provider is admitted.

## Wave 4: XMS

The `xms.486` owner package. Requires a source-shaped A20/RAM/IVT/UMB machine
seam from `adapter-softpc`; unavailable physical spans retain the original
failure disposition.

## Wave 5: VDM monitor substrate

`sim16`, `sim32`, `v86` and `ieuvddex`, through `adapter-vdm-monitor`.
Completes same-shaped user-mode monitor/VDM_TIB/event/handler contracts without
recreating kernel VDM or CSRSS.

## Wave 6: DPMI

`dpmi` and `dpmi32`, after monitor and protected-machine requirements are
closed at whole-profile scope. Bochs enables only reached mechanical features.

## Wave 7: Redirector and brokered COMMAND extensions

`vdmredir` plus only the broker rows consumed by its and COMMAND's original
callers. `adapter-redir` preserves the interface boundary; it never becomes a
new redirector provider.

## Wave 8: WOW

`wow32` and `fax`, after their monitor, COMMAND, Redirector and adapter-wow
rows close. Guest WOW16 remains a separate load-only mirror.

## Wave 9: VDD and debugger products

`vdd`, `bde`, `dbg`, `vdmdbg` and `vdmexts`, after required monitor and
machine callback rows close. `adapter-vdd` and `adapter-debugger` contain only
the historical product boundaries.

## Wave 10: product composition and integrated verification

Create complete x86/x64 graphs for all admitted waves, audit every tracker row
and run declared host/guest integration profiles. Trace may classify a residual
after this point, but cannot create an unplanned leaf implementation.
