# M0 T230 DEM completion sequence 002

## Purpose

T230 does not close merely because the original `demdisp.c` table compiles or
because a representative fixture reaches each imported owner file.  It closes
only when the complete original 73-slot DEM dispatch family is source-shaped,
locally runnable to its documented contract, absent from the retained v1
runtime route, and bound to the native checked-memory composition path.

## Completion sequence

| S | Scope | Exit evidence |
| --- | --- | --- |
| S11 | Whole-table source/ABI/failure ledger | Each `00..48` slot is classified as an original implemented handler or an original `demNotYetImplemented`/ordinary-return slot; its source file, shim, register/guest-memory contract, fixture, and v1 route are recorded. |
| S12 | Namespace, handle, directory, search and FCB owners | Every slot owned by `demhndl.c`, `demfile.c`, `demdir.c`, `demsrch.c`, `demfcb.c` and `demlabel.c` has a source-shaped local success or original failure fixture. |
| S13 | Drive, DPB, raw-media and IOCTL owners | Every `demgset.c`, `demdasd.c` and `demioctl.c` slot has its original host capability path or exact original unavailable/error outcome exercised locally. |
| S14 | Lifecycle, error, lock, symbols, pipe and ordinary slots | Every `dem.c`, `demdata.c`, `demmisc.c`, `demerror.c`, `demlock.c`, `demmsg.c`, dispatcher ordinary-return and `demNotYetImplemented` slot has exact local behavior evidence. |
| S15 | v1 DEM route retirement | No `50:00..48` dispatch, provider, result bridge or startup composition route can call a `bop-v1` DEM implementation. Superseded DEM v1 code is removed where no retained comparison use remains; any retained comparison source is unreachable from formal and native product paths. |
| S16 | Native Direct DEM composition and final verification | The native engine binds the adapter Direct DEM session through the mantle checked-memory transport, does not install the v1 composition runtime for DEM dispatch, passes the full 73-slot local matrix, and records one bounded native observation. |

## Rule

The table's historical `demNotYetImplemented` and ordinary-return entries are
not silently rewritten into new behavior.  They still need one explicit local
witness that their original CF/register/return behavior is retained.  The
sequence uses no project-authored mutation profile; each real host action
follows the recovered OpenNT owner and its source-derived host-composition
shim.
