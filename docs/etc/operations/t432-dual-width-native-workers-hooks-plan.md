## Shared mechanism and ownership contract

NTVWM variants share worker-base/common project mechanisms and worker source;
Hook variants share discovery/classification and transaction logic with small
native ABI/install bindings. NTSRV stores native-machine identity and owns
selection, registration, task results, association and retirement. NTCON keeps
only current logical display/input state and zero/one authorized I/O pipe.
Each worker has a separate hidden execution Console. Ordinary mixed-width
native descendants may inherit one Console, but two workers never share it.

Reuse current final-state/input-return acknowledgement, old-pipe release,
incoming seed/acknowledgement and execution/parent-output resume order. Do not
add another protocol merely for width. Changes to actual wire/DTO need the
existing versioning/audit rules. All native child process/thread handles,
waits/exit codes, flags, streams, environment/CWD and requested suspension
retain Windows ownership; bitness alone does not cause Run16 replacement.
