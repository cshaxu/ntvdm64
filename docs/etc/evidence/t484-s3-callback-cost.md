# T484 S3 P50: native WOW callback diagnostic composition

B0053 no longer rewrites Ninja command text or invokes a compiler/linker from
PowerShell. The optional WOW32 diagnostic target reuses the product's229 ordered
object inputs, compile profile, imports and exports. Exactly one current
project-owned binding object is replaced by a reversible diagnostic projection.
The product image and original guest remain untouched; output lives under the
existing stable WOW build tree's diagnostics directory.

The former runtime script also contained obsolete13-image assumptions, wrong
helper paths and raw-versus-stamped hash comparison. It now uses the current
manifest's complete unique name set, checks every selected published hash and
compares raw worker/provider images against InputSha256. Helpers resolve to
their checked-in observation directory. These corrections do not claim the
downstream real-guest measurement has run.

The B0162 native recorder unit now delegates compilation to CMD. Its unchanged
assertions pass: nesting, exact result/error, rejection, exception, untracked
and overflow behavior, read-only sampling, nine negative states, three negative
identities, balanced85/85 handles and TLS phase tracking. The parser self-test
passes15 positive cases, signed negative lag, nesting and10 rejection controls.

[Final verification](../../../artifacts/build-migration/t484/s3-callback-cost/verification.json)
records projection identity,229-object substitution, a single diagnostic data
symbol and unchanged cached output. The first projection comparison failed
because CMake emitted CRLF; explicit LF fixed the generator and final comparison
passed. The first result is retained separately. Already passing unchanged unit
and parser results were reused rather than rerun solely for the newline fix.

Cached full host build,11 raw image hashes,22 published hashes and governance
are separate delivery evidence. No fresh guest latency or performance claim is
made. B0053 remains pending for downstream measurement-helper compilation and
runtime staging; B0162's standalone producer/runtime path is migrated. Historical
paired-version tooling still needs its own inventory disposition. S3 is active.
