# M0 T317 S3 P1 — COMMAND child stream boundary

## Question

Can the original COMMAND child and local redirection source retain its call
shape while avoiding a mutation of the app's own standard streams?

## Source review

`cmdCreateProcess` in original `cmdexec.c` has this required sequence:

1. increment the Base VDM re-entry count;
2. resolve the original `STD_HANDLES` fields;
3. select those standard streams;
4. create, resume and wait for the child;
5. restore standard streams, decrement re-entry, and return the exit result.

The source's x86 `SetStdHandle` calls changed the dedicated historical
`ntvdm.exe` process.  They cannot change the app process.  The local
translation-unit include is therefore the only mirror divergence: it preserves
the original expression order and arguments, but binds the selected handles
to a copied `STARTUPINFOA` at the public `CreateProcessA` call.  The parent
standard handles are never written.

`cmdredir.c` remains the original producer/consumer and pipe algorithm.  Its
record and handle identities continue to use the session host-resource mapping
manager; native `HANDLE` or record pointers never enter original packed fields
or guest registers.

## Verification

1. External x86 fixture generated by `New-T317CommandChildNinja.ps1` printed:

   ```text
   PASS: child-only COMMAND standard-stream binding
   ```

   It launches a real local `cmd.exe /d /c echo` child with three explicitly
   inherited pipe endpoints, verifies its output and exit code, then verifies
   the app's three original standard-handle values are unchanged.
2. The refreshed formal external `CPU_40_STYLE` graph compiled
   `original-mvdm-command.lib` and `softpc-win32-bindings.lib`, including the
   exact original four S3 translation units and the new bounded adapter.
3. The existing original `cmdredir.c` fixture was repaired only at its stale
   ABI include/link manifest and then rebuilt on x86.  It exercises original
   standard-handle record creation, session identity publication/resolution,
   handle register-pair output and record retirement.

## Disposition

The child-local stream binding and original local redirection identity route
are closed.  This does not claim a complete COMMAND child lifecycle: result
handoff/re-entry at an actual guest call, DOS `EXEC`/PSP parent restoration,
remote Redirector endpoints and full PIF/console-product behavior remain
separate S3/later-owner work.
