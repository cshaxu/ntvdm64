H002 ↔ G004, H005 ↔ G034. The two active interface comparison sources are now the exact SP1 blobs: dos/v86/cmd/command/tcode.asm (9fa20d35ec4082fd3526061ac01f736c3a257aa1) and dpmi/dxstrt.asm (881d741e372d0d61b20af0be9e2fe54fd4b7de9e). Both were unmodified OpenNT bytes before this migration. These are source-only early companions. No guest binary was rebuilt or installed. G004 and G034 still have other files outstanding.

XP COMMAND adds calls for SETWINTITLE in DBCS and GETCURSORPOS in NEC_98. The host dispatcher supplies slots 17 and 30. For normal CMDEXEC, XP MS_bop_4 consumes the service byte before entering CmdDispatch. Restored that ordering in H025 nt_bop.c and removed the duplicate IP advance from the compat VM ingress path. Consequently both the ordinary handler and the far callback receive the continuation IP. Removed the corresponding minus-one compensation from the diagnostic callback. H025 remains open as a batch. The cached product build passed (product10.log), and the freshly built x86 mvdm-vm-ingress test passed (build/t485-s2-guest-contract/ingress.log).

XP DOSX passes the four protected-mode far pointers to InitDosx in DS:SI stack order: small translation buffer, large translation buffer, stack frame pointer and DTA. This matches the packed DOSX_INIT_INFO fields in H005. The comparison covers source ABI; SP3 executable behavior is tracked by the package gate.

H003 LFN x86 ABI. The isolated diagnostic run of product10 attributes the stack-check failure to the epilogue of demIsShortPathName (worker RVA 0x1534b2). Its source conversion call used the default C function-pointer convention, while the linked RtlOemStringToUnicodeString@12 provider uses NTAPI. The call site also discarded twelve argument bytes. Both OEM and ANSI source conversion bindings now use the declared NTAPI pointer with a const counted-string input and no cast. The reverse conversions use separate, locally implemented C functions. The cached x86/x64 build passed and the twelve-image private package is 9fdd12dc-6eed-46f7-b676-586170ede079.

Product11's ordinary DOS4GW run with the same PIF and immutable guest inputs exits with 0xc0000005 before graphics. A diagnostic repeat shows COMMAND initialization on the worker stack; its terminal exception differs from product10. This does not establish the cause of the remaining fault. See dos4gw-product10-diagnostic/exceptions.txt, product11.log, dos4gw-product11/nesticle.txt and dos4gw-product11-diagnostic/exceptions.txt under the H008 build directory.
