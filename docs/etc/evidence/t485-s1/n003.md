# N003 XP RTL environment, status conversion and x86 primitives

Status: N003 validated for M0 T485 S5 P3 delivery. This brings the delivered migration sequence to 39/159.

The batch replaces the existing RTL environment and status implementation with pinned XP SP1, restores the complete i386 arithmetic and memory sources at their XP paths, and replaces the old checked-in error.h with the XP-generated table. Guest binaries are unchanged. All original functions are retained regardless of current callers.

The original sdktools/generr generator consumes the original RTL CodePairs object during the existing native-tool bootstrap. All error.c product consumers, including Hook64, use the generated header. No script interpreter is added to the production build. Required original ks386.inc, ntrtlpath.h and status.h are imported from the same fixed tree. The compat private process parameters provide ImagePathName for the original __APPDIR__ query. The existing native NTDLL RtlFindCharInUnicodeString supplies its original external operation.

## Necessary adaptations and evidence

1. RTL generr.c replaces seven kernel/SDK includes with one host binding include; its CodePairs data and algorithm are unchanged. The original generator and table compiled successfully with the current native-tool build. This is 1 point / 8 lines, within the owner's standing small-adaptation approval.
2. movemem.asm adds `option nokeyword:<sfence>` before the original sfence macro. Modern MASM rejects that definition as its reserved instruction (A2085, then A1008); build3.log records the failure. The directive preserves the original byte-emitting macro and algorithm. This is 1 point / 1 line, within the owner's standing approval. No wrapper or alternate algorithm is introduced.

Kernel allocation pragma exclusions and original #line anchors remain. Newly retained RTL last-error functions use the existing private thread carrier; no new product caller or export is added. Retention is not a claim that these functions replace the modern host last-error APIs.
