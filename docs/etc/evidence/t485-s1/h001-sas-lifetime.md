# H001 debugger memory lifetime

The production startup path establishes the PIF-selected SAS allocation before loading the debugger. In `src/mvdm-host/softpc.new/base/support/main.c`, `host_main` calls `config()` before `InitialiseDosEmulation`. The former processes the PIF, calls `sas_term`, then calls `sas_init` with the selected size. The latter reaches `scs_init` and `DBGInit`, which loads NTVDMD.DLL. The release in `nt_mem.c` during failed physical mapping initialization is also before that allocation is returned to its caller.

On debugger attachment, `VdmDbgAttach` passes the worker state address to `xxxDbgInit`, which obtains the current SAS base through `VdmMapFlat(0, 0, VDM_V86)`. The DLL publishes both addresses through `DbgGetContext`. Its thread and process detach cases do not dereference either pointer.

Two checks establish different parts of the contract:

- The private worker's real synchronous breakpoint event exposed the current SAS base and accepted an EAX writeback. The trace is in `build/t485-s2-h001-source/live-event-final/trace.txt`.
- The CCPU BIOS access fixture called the real SAS allocator, verified a null mapping after release, then allocated again and read back a physical write through the new mapping. A null protected-mode selector was rejected. The fixture passed 93 checks.

These results cover normal boot and the mapping provider across allocations. The allocator fixture does not load NTVDMD.DLL. A production caller audit finds no path that reinitializes SAS while the debugger is attached. The worker main in src/ntvdm-exe/softpc/mvdm_standalone_worker.c calls run_softpc once; its prepare call precedes softpc_run_initialized. The only product call to config is in host_main. config owns both calls to sas_term and sas_init before DOS initialization. The CCPU sas_term reaches FreeIntelMemory through host_sas_term in sim32.c. The other FreeIntelMemory call rolls back allocation failure in nt_mem.c. Neither host_reset nor DOS task reentry calls config. A new worker takes its own mapping on attachment. This is a source-level lifetime conclusion for the supported process entry points; the live event and allocator checks above provide independent runtime evidence.
