## Implemented local changes

- Adopt all three XP files; retain the existing early-native-return latch,
  original wait-event query and record-layout provider. XP zero-initializes
  CONSOLERECORD, so no separate latch initializer is needed.
- XP RegisterWowExec already owns empty-record shutdown; remove the NT4-only
  hand-added shutdown branch. Use its actual ConsoleHandle and task selection.
- Replace NTSRV singleton reads with a narrow C-owned sequence lookup, while
  retaining existing service/WOW locks and original record lifetime authority.
- Restore N004 client GetNext ConsoleHandle and select exit kind by iWowTask;
  retain only the distinct existing startup-notification marker.
- NTSRV binds the authenticated worker through XP UpdateVDMSequenceNumber with
  its registered process identity. Shared WOW uses the existing service Console
  allocator. Register/Get/Exit use that connection identity; no second identity
  or scheduler is created.
- Closing-WOW admission reuses XP's desktop lookup, rather than rejecting all
  desktops because an unrelated WOW is closing.
- Current host user32 exports ResolveDesktopForWOW. A direct native query for
  WinSta0/Default returned STATUS_SUCCESS, normalized length30. Bind that API
  with the existing host PostMessage/window-ID APIs, not a new desktop parser.
- XP now calls CsrImpersonateClient for desktop access. The standalone boundary
  has authenticated process handles rather than LPC thread handles. B uses the
  pinned process token and the original request ImpersonateCount. The existing
  C layout provider exposes those borrowed fields via one additional callback;
  no copied C layout, new TLS state, queue or authentication registry is added.
  The lifecycle fixture checks failed entry, actual thread token, nesting and
  final reversion. These checks passed in lifecycle2.
