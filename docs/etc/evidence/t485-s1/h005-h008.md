## S2 package build and first DOS4GW run

The cached x64/x86 product build passed (build/t485-s2-h008-three-way/product5.log). VCDEX and WOW32 now call the worker exports using the matching x86 ABI. WOW uses the shared XP W32 definition. Eighteen retained Win16 argument frames are still required by the current WOW32 consumers. Staging produced twelve manifest entries with package UUID 235c3ced-f14e-4965-903f-1557f8d594db.

The isolated DOS4GW PIF run with the archive guest stopped at a CONFIG.NT error dialog. With hash-qualified unmodified SP3 NTIO.SYS, NTDOS.SYS, COMMAND.COM and DOSX.EXE in the isolated copy, the worker exited with 0xc0000409 before the graphics handshake. The Application log for the same staging path reports RVA 0x2fa95, which maps to __report_gsfailure+0x18. That address is the failure reporter; the caller that damaged the stack remains unidentified. Evidence is in dos4gw and dos4gw-xp under the H008 build directory. No product acceptance or distribution is recorded.

The qualified PIF selects the local SYSTEM32 CONFIG.NT. Its device list requires SETVER.EXE, which was present in the fixture installation and absent from the staged guest archive. A single-variable control copied that exact fixture file into the private runtime (no archive change). With the same twelve host images and four XP guest files, the observer again recorded exit 0xc0000409 and no graphics handshake; see dos4gw-xp-setver/nesticle.txt. The matching prior WER report gives exception data 2. CONFIG.NT contains no shell= directive, so the optional shell-argument write is outside the exercised path. The investigation made no product change on that hypothesis.

The H001 debugger requires an early H025 companion in softpc.new/host/src/nt_msscs.c. The XP initialization clears VDM_BREAK_DEBUGGER before scs_init and merges the state flags written during initialization before loading NTIO.SYS. This preserves the flags set by DBGInit across the later state write. H025 remains separately scheduled.

The cached x64/x86 build with this change passed (product7.log). Staging passed for package 50d10f9e-3a23-49dd-b9e7-59adabacfbc3 (stage7.log). The existing DOS4GW PIF test used the same four qualified XP guest files and fixture SETVER.EXE in this private package. dos4gw-product7/nesticle.txt records exit 0xc0000409 before the expected graphics window. The debugger state correction therefore does not resolve the observed startup failure.

H005 protected-mode entry: the previous CCPU path cleared EFLAGS.NT before setting MSW.PE. XP separates this transition into SetPMExec and clears RF and NT. The initial port performed the clear after setting PE. Compiling both actual function bodies into the existing boundary test reproduced 32,769 failures in 65,538 cases. Moving the combined RF/NT clear before the PE write preserves the original CCPU ordering at both SetPMExec call sites. The final test exercises all low FLAGS combinations with RF clear and set, invalid IDT and absent GDT shadow: 131,074 cases passed (build/t485-s2-pm-order-final/result.txt). This fixture observes CPU calls using test providers.

The cached x64/x86 build passed (product9.log), and staging produced 12 images with UUID 812ad22b-8918-4a18-9e4c-d62ddf702ac7 (stage9.log). With the same qualified guest files, SETVER and PIF, dos4gw-product9/nesticle.txt records exit 0xc0000409 before graphics. The mode-entry correction resolves the demonstrated ordering regression only.
