# M0 T331 S3 — Original XMS package contract matrix

## Result

S3 is closed. The selected `xms.486` package remains the sole XMS policy
owner and its selected original bodies compose with the CPU40/session memory
boundary established by S2. No Bochs-era route, replacement allocator or raw
host-pointer guest-memory buffer is present.

## Exercised contract matrix

- Original initialization reaches the original XMS/SubAlloc callback setup;
  allocation, free and reallocation remain original `xmsblock.c`/SubAlloc
  control flow, with `c_sas_memory_size`, `c_sas_loads` and `c_sas_stores`
  supplied only by the bounded session lease provider.
- Original `xmsMoveMemory` overlap and descriptor forms are exercised through
  `xms_mapped_memory_fixture`: commit/zero, overlapping move, descriptor move,
  decommit/zero and malformed descriptor cancellation pass on x86 and x64.
  The fixture validates the common adapter boundary; it does not replace the
  original allocator or dispatcher.
- The original dispatch table retains its A20, UMB and INT15 owners.
  `xmsa20.c` writes the original state byte through the selected machine A20
  interface; `xmsumb.c` retains the original empty-UMB `B1/B2` failure;
  keyboard INT15 dispatch remains the original `UpdateKbdInt15` callback.
  These are machine-owner transfers where a live controller endpoint has not
  been observed, not fabricated XMS success.
- The selected original source set and the S2 CPU40/session binding formally
  compose in both architecture graphs. This does not claim a continuous DOS
  guest run or reachability of every XMS service from that guest.

## Reproduction

Run the generated x86 and x64 `xms-mapped-memory-fixture.exe` targets under
`build/M0-T331/S3/xms-mapped-memory/{x86,x64}`. Each exits zero with no
diagnostic output. The selected formal source graphs are regenerated by
`tools/build/New-T310OriginalSoftpcNinja.ps1` and use the original XMS,
SubAlloc, CPU40 and session boundary inputs.

## Transfer

S4 owns product-level x86/x64 link closure and the single fixed-container
observation allowed by the proposal. Controller delivery remains a named
original machine-owner concern; S3 neither moves it into XMS nor creates a
replacement service path.
