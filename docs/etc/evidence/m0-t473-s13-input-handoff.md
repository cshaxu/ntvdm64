# T473 S13 input-source handoff investigation

S12 was accepted by the owner and S13 admitted. This record is an investigation, not a completed fix. Guest media remains immutable.

## Production path

`frontend_session.c::collect_console` reads physical Console records, applies CAF filtering and appends accepted records to the shared frontend queue. `window_route` drains the Console before changing `window_active`, but neither records nor retires outstanding Console keys; subsequent `collect_console` calls discard the inactive physical source. `frontend_session_read` copies queue records and removes them only for a non-Peek read. `frontend_session_prepend` can put worker-returned records before existing input. The channel serializes operations through the frontend I/O lock. Original `nt_event.c::ReturnUnusedKeyEvents` can return unconsumed keyboard history through that prepend path. Native NTVWM uses the same frontend READ_INPUT stream, but forwards it to its own Console.

Window events have a separate `frontend_window_keyboard_state`: `frontend_keyboard_dispatch` updates it when its sink accepts records into the frontend queue and emits break records on source retirement. That sink is queue insertion, not proof of a worker read. A correction must account for queued versus read versus returned events and owner transitions; the successful enqueue is not itself a worker-delivery receipt.
