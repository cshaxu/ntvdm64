# M0 T96 S1 OpenNT BOP Provider and Module Map 001

## Scope and evidence boundary

This is the first static provider map for the active BOP host-service-plane
recovery package. It maps every identity in the immutable BOP inventory to
an OpenNT ingress family, original dispatcher/module, owner, and present CLI
disposition. It does **not** select a provider implementation or change a
guest result.

The complete, source-line keyed member lists are the immutable export
[`opennt-bop-inventory-005-20260811-001`](../../../artifacts/analysis/opennt-bop-inventory-005-20260811-001/)
and its human index
[`opennt-bop-definition-inventory-001.md`](opennt-bop-definition-inventory-001.md).
The inventory is the authoritative identity set: 16 top-level selectors;
74 DOS, 18 COMMAND, 12 XMS, 25 DPMI, 49 Redirector, and 16 Debugger service
identities; and 41 BIOS selector constants plus 349 annotated historical
BIOS-table rows.

The reproducible selector-, service-, and BIOS-level expansion is
[opennt-bop-provider-module-map-001-20260811-003](../../../artifacts/analysis/opennt-bop-provider-module-map-001-20260811-003/),
generated by
[Export-OpenNtBopProviderMap.ps1](../../../tools/Export-OpenNtBopProviderMap.ps1).
It retains all 16 selectors, resolves every one of the 194 inventory
service-definition rows to its original function-table handler, switch
dispatcher, or explicit dispatcher-bound sentinel, and carries all 41 BIOS
definitions plus 349 annotated BIOS-table rows. No ordinary service row is
left without an original routing classification.

## Proven original routing

`base/mvdm/softpc.new/host/src/nt_bop.c` is the historical top-level host
ingress. It reads a service byte only for selector families that have one,
calls their named dispatcher, and then performs the family-specific return
advance. This establishes a narrow adapter obligation: decode and copy the
fixed instruction window, preserve the CPU contract, and route to a provider;
it does not establish a new DOS, XMS, or BIOS implementation.

### Composition decision: reference, not a linked adapter object

`nt_bop.c` is **not** an adapter compilation unit and the adapter must not
call it as a runtime dispatcher.  The file intertwines selector routing with
CCPU/SAS register and memory access, IP mutation, dynamic DLL loading,
WOW/VDD/UI/debugger paths, and host idle scheduling.  Linking it would make
the non-invasive CLI composition inherit those historical NT-host bindings.

Instead, the host-service plane retains its demonstrated selector-family
structure, service-byte timing, order of delegation, and source-proven
failure/return contracts.  Each target dispatcher is assessed independently
under the provider-selection order below.  The adapter may call an admitted
provider through its own fixed ABI; it may not reproduce `nt_bop.c`'s CCPU,
SAS, Win32, GUI, VDD, or generic Bochs semantics.

## Dispatcher-shape evidence

The next-level source confirms that preserving the dispatcher structure does
not imply that the dispatcher files are immediately linkable:

| Plane | Original table/entry | Observed historic binding | Consequence for provider assessment |
| --- | --- | --- | --- |
| DEM | `apfnSVC[]` in `dos/dem/demdisp.c` | The dispatcher itself includes `softpc.h`, reads/writes carry state, and calls handlers through CCPU/SAS-era register contracts. It also contains explicit `demNotYetImplemented` slots. | Recover the table and its documented unavailable slots first; do not link it before an ABI-closure audit. |
| COMMAND | `apfnSVCCmd[]` in `dos/command/cmddisp.c` | Static 17-entry service table, but compiled against `softpc.h`; several handlers broker command-line, console, process, and environment state. | The table is a primary source map; individual services require CLI-capability assessment. |
| XMS | `apfnXMSSvc[]` in `xms.486/xmsdisp.c` | Static 12-entry table under `softpc.h`, covering A20, extended-memory and UMB operations. | These are Bochs-memory/CPU-adjacent semantics, not adapter memory emulation; assess against a native-machine provider. |
| DPMI | `DpmiDispatchTable[]` in `dpmi32/dpmi32.c` | Reads its service byte through `Sim32GetVDMPointer`, advances IP, and uses protected-mode state. | Preserve subfunction identities, but mode/descriptor semantics remain a monitor/CPU composition question. |
| Redirector | `VrDispatchTable[]` in `vdmredir/vrdisp.c` | Uses `nt.h`, `windows.h`, NT redirector, named-pipe, mailslot, NetAPI and DLC headers. | Not directly composable in the CLI profile; require an explicit unavailable/deferred disposition or a separately approved capability boundary. |
| Debugger | `DBGDispatch` in `dbg/dbg.c` | Reads guest stack frames via `Sim32GetVDMPointer` and applies debugger-specific segment/module operations. | No implicit debugging provider; retain only source-proven deferred behavior unless a CLI debugger profile is admitted. |

## Family-level completeness rule

Every defined service within a family row above inherits that row's original
ingress and semantic owner. Its individual original implementation, build
closure, and profile disposition will be recorded from the family dispatch
table in the corresponding plane subtask; it must never silently inherit
success merely because its selector is recognizable. This rule covers all
inventory members now, while retaining exact service-level evidence rather
than inventing a synthetic replacement dispatcher.

## Provider selection order

For every later service-level decision, use this fixed order:

1. Independently composable original OpenNT host implementation.
2. Original implementation with only a contained CLI host-capability backend.
3. Minimal source-derived rehost after its historical composition blocker is
   evidenced.
4. Original, evidenced unavailable/failure behavior or explicit deferral.

The adapter remains the ABI/router owner only. It must not absorb DOS kernel,
BIOS, device, CPU, PIC, or generic Bochs semantics.

## Immediate follow-up

The remaining S1 work is to extract each family dispatch table into a
machine-readable service-to-module matrix and record source/ABI blockers for
