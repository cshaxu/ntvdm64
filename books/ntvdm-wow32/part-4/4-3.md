# 4.3 — Ordinary dialog construction, routing, and termination

## Scope and audit state

This chapter covers selected ordinary USER16 dialog seams: converting a 16-bit template, creating modal/modeless instances, publishing dialog callback state, fake-dialog classification, preprocessing dialog messages, and ending/default-processing a dialog. It does not own common dialogs, menus, individual controls, or the general message scheduler; those are [4.6](4-6.md), [4.4](4-4.md), [4.5](4-5.md), and [4.2](4-2.md).

All source claims are bounded to OpenNT commit `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`. Static closure does not prove a built USER16/WOW32 image, complete template grammar, provider behavior, or runtime UI equivalence.

| Canonical identity | Class | Selected boundary |
| --- | --- | --- |
| `USER16_DIALOG_TEMPLATE::CONVERT_CREATE_MODAL_MODELESS_AND_CALLBACK_GATEWAY` | C | A Guest template is converted for one synchronous creation interval; modal result and modeless HWND have different result domains. |
| `USER_REGISTER::USER-REG-OUT-pfnServerCreateDialog` | D | The selected local/server creation branch passes typed converted data and projects failure as Guest zero HWND. |
| `USER_REGISTER::USER-REG-IN-pfnInitDlgCb` | D | Dialog procedure identity and init parameter are published as per-window typed metadata before routed callbacks. |
| `USER_REGISTER::USER-REG-IN-pfnWowSetFakeDialogClass` | D | Actual class identity and the fake-dialog marker are separate state. |

## 1. Template conversion and creation: a bounded synchronous lease

Dialog-related bindings are recorded in `wow32/wutbl2.h:118-120,275-276,300,303-305`. `wudlg.c:25-161,260-340` contains the selected callback gateway and creation route; the Guest modal/modeless resource and indirect wrappers are in `wow16/user/fastres.c:257-359`. The local/server provider boundary appears at `wudlg.c:300-339` and selected `USER` registration returns `InternalCreateDialog` through the typed OUT table.

The compatibility layer must parse and convert the 16-bit template into a typed native-template object. That object, dialog callback data, module identity, and procedure identity are leases valid only through the complete synchronous create/reentry interval; none becomes a raw host pointer exposed to Guest memory. Creation must retain the source distinction between modal return and modeless HWND result, local versus server route, and zero-HWND failure. Invalidation of the SendDlgItemMessage cache remains a distinct specified postcondition.

The source does not establish that a conversion size of zero or an allocation failure has a measured runtime return in the target image. Treat each as an explicit compatibility decision and test it; do not present either as a reproduced source defect. Likewise, zero Guest `hInst` follows a selected branch that can bypass WOW dialog initialization—its callback reachability is a named residual, not an equivalence assumption.

## 2. Initialization and fake-dialog state: publish meaning before admission

`pfnInitDlgCb` is typed in `wowuserp.h:102`, bound from `wow32.c:530`, and implemented locally in `wcall32.c:221-249`; selected USER code stores and invokes it in `client.c:2256-2269,2327-2332`. The creation carrier must represent the Guest dialog-procedure token and user init value as typed per-window metadata, never as a host HWND/function pointer/private-GWL address visible across a native64 boundary.

The selected local callback visibly returns zero for a null init payload or missing alias. Zero is therefore a valid Guest-visible result and must not be overloaded as internal setup failure. The carrier records setup failure locally, preserves separate WNDPROC and DLGPROC identities, admits callbacks only after metadata publication, and drains admitted routing before retirement.

The companion fake-dialog callback is registered at `wowuserp.h:114` / `wow32.c:542` and has a selected local provider in `wumsg.c:2183-2225`. USER invokes it only on the selected 16-bit non-dialog-class condition (`dlgmgr.c:215-233`). A fake-dialog marker must not overwrite actual class identity. A null procedure or missing alias follows the source-visible no-op path; a nonzero DLGPROC remains separately routable. Repeated marking must be idempotent.

## 3. Dialog message preprocessing and layout: processing is a control-flow decision

Selected bindings are in `wutbl2.h:123,138,286-287,306`, with base-unit, navigation, preprocessing, and rectangle conversion in `wudlg.c:775-784,975-1032,1036-1116,1159-1204`. The selected `IsDialogMessage` route maps an MSG16, thunks it, reacquires its frame/arguments, then unthunks; it visibly reuses the `pMsg16` view (`1072-1115`).

The correct modern rule is not “run ordinary dispatch afterwards.” If preprocessing reports handled, normal dispatch is skipped. Guest mappings must be retained or reacquired according to the real mapping/movement model across any operation that can reenter or move Guest memory. The source itself proves frame re-acquisition, not that reusing `pMsg16` is universally safe; no stale-view fault is asserted. Preserve base-unit packing and MapDialogRect round-trip separately from control navigation, which belongs to the control owner.

Test true/false preprocess results, changed payload, nested callback, tab/group navigation, `WM_GETDLGCODE`, destroyed dialog/control, stale-view simulation, and font/layout variation.

## 4. EndDialog and DefDlgProc: closing is deferred, default is dialog-specific

`EndDialog` and `DefDlgProc` have selected slots at `wutbl2.h:119,383`. `wudlg.c:695-739` is the EndDialog provider; `wumsg.c:258-352` covers selected DefDlgProc conversion/default processing. The source boundary requires a deferred dialog-instance transition, not immediate disposal of a Guest frame while a callback can still be active. It also requires a typed DefDlgProc path rather than substituting DefWindowProc.

The registry persists until dialog destruction and all admitted callback leases complete. Convert EndDialog's result according to the selected Guest surface even when the native provider Boolean is ignored in the wrapper; do not invent native-error semantics from that fact. Required cases include EndDialog during `WM_INITDIALOG`, EndDialog in nested callback, invalid/missing mapping, default message result, and destruction race.

## What this chapter does not infer

- A visible native dialog is not proof that template, initialization, modal return, or teardown semantics match.
- A Guest DLGPROC is not a native callback pointer.
- A fake-dialog marker is not an alternate class identity.
- EndDialog is not evidence that all callback work has drained.
- Selected source branch coverage is not emitted-image or runtime proof.
