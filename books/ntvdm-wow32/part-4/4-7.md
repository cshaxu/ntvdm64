# 4.7 — Graphics, DCs, DIBs, palettes, and synchronous paint

## Scope and audit state

This section bounds the selected GDI/USER drawing seams to six identities: DC/object alias lifecycle, BitBlt/StretchBlt, DIB bits/sections, palette aliases, UpdateWindow, and LockWindowUpdate. It is not an audit of the entire renderer, printer drivers, font shaping, metafiles, compositor, or display stack. Text/font specifics transfer to [4.8](4-8.md); printer drawing to [5.7](../part-5/5-7.md).

Evidence is OpenNT source at commit `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`. Each row is selected static closure, not final-image/runtime verification.

| Canonical identity | Class | Boundary |
| --- | --- | --- |
| `GDI16_DC_OBJECT::CREATE_SELECT_DELETE_ALIAS_LIFECYCLE` | C | Typed DC/object aliases preserve prior selection and deletion constraints. |
| `GDI16_BLIT::BITBLT_STRETCHBLT_DC_AND_ROP` | C | Source/destination DC order and ROP/BOOL projection are explicit. |
| `GDI16_DIB::GET_SET_AND_SECTION_GUEST_VISIBLE_BITS` | C | Guest-visible bits use a selector/mapping lease, never a raw native pointer. |
| `GDI16_PALETTE::CREATE_SELECT_REALIZE_ENTRY_SYSTEM_AND_COLOR_UPDATE_ALIAS` | B | Palette arrays and opaque aliases preserve copy direction and selected fallback. |

## 1. DC and object identity: host GDI validity is not a Guest capability

Selected GDI handlers live in `wow32/wgdi.c:332-385,960-1009,3324-3345` with dispatch rows `wgtbl2.h:67,76,94-95`; selected task/window DC caching is `wuser.c:1055-1120,2252-2272`. A native DC/object has a different width, reuse model, and selected-object rule from a Guest token.

Use session-scoped typed aliases carrying kind and generation. Creation/select returns the correctly projected prior token. Deletion does not retire a Guest token until native deletion succeeds; reject deletion while selected. Keep thread ownership for null-compatible DC paths explicit, preserve selected GetDC/ReleaseDC cache semantics, and force cache invalidation at original task/window boundaries. Test create/select/delete, selected-object delete rejection, cross-thread DC, failed release, task exit, and native-handle/Guest-alias reuse.

This does not close all GDI object kinds or raster behavior. It does establish that a global raw-HDC cache or a Guest-visible host handle is the wrong carrier.

## 2. Blit: both endpoints and the ROP are part of one call wire

`wgdi.c:106-132,3857-3905` and `wgtbl2.h:54-55` cover selected BitBlt/StretchBlt routes. Validate both source and destination DC tokens, selected-object liveness, geometry order, ROP order, and the selected Boolean return projection. A modern call's success does not hide invalid Guest aliases, clipping differences, incompatible DCs, or DIB selection constraints.

Focused runtime tests are compatible/incompatible DCs, clipping, selected DIB, failed source/destination alias, ROP edge values, and destruction/reentry while a draw is admitted. Full compositor and driver equivalence are expressly out of scope.

## 3. DIB: Guest-visible bits are a mapping lifecycle

Selected Get/Set DIB routes are `wgdi.c:2218-2280,3582-3655`, and the DIB.DRV implementation—including section mapping, selector, color table, and cleanup—is `wdib.c:14-835`; dispatch is `wgtbl2.h:542-545,599`. The source has x86/non-i386 address-publication branches. That is a build-variant fact, not evidence that native DIB bits may be placed into a Guest pointer field.

Model a DIB as a bitmap alias plus a selector/mapping lease. Map/copy headers and color tables with checked lengths, preserve null-bits query behavior, restore/release selector state in order, synchronize drawing before Guest access, and retire the lease with the bitmap token. Test null-bits query, header copyback, selector/mapping failure cleanup, DeleteObject while mapped, draw/write concurrency, and task/session teardown. Do not claim raw pointer compatibility or one build branch without target image evidence.

## 4. Palette: opaque HPALETTE, checked arrays, directional copyback

`wgpal.c:26-297` with `wgpal.h:16-27` establishes selected palette conversion. A native `HPALETTE` remains opaque to the Guest. Use the GDI alias registry, check palette-array counts before mapping, preserve the direction of entry/color copies, and retire the alias under normal GDI-object lifetime rules. The selected high-color GetSystemPaletteEntries fallback applies only on its evidenced error route; it is not a general modern display policy.

Test selection/realization across DCs, array mutation ordering, fallback output, cross-task palette/DC affinity, and alias teardown.

## 5. Paint update and lock: UI calls retain Guest result policy

`UpdateWindow` is bound in `wutbl2.h:163` and selected wrapper code is `wuwind.c:3037-3063`. The source calls native update but follows a fixed Guest return policy. Do not forward a modern host Boolean directly as the Guest result. Test empty/nonempty update regions, invalid HWND, synchronous `WM_PAINT`, reentrant paint, and actual return projection separately.

`LockWindowUpdate` uses a one-WORD guest frame and selected handler `wuser31.c:170-181` (`wutbl2.h:367`). Preserve handle conversion and Boolean narrowing, then explicitly choose how null unlock, competing locks, invalidation, desktop scope, invalid HWND, and destruction are represented. The selected source does not prove modern desktop isolation or full provider semantics.

## What this chapter does not infer

- Native HDC/HBITMAP/HPALETTE/HWND values are not Guest handles.
- A successful GDI call does not make a stale Guest alias valid.
- DIB mapping source code does not prove raw pointer sharing or a target build branch.
- Synchronous update/lock calls do not settle generic message or callback lifetime.
- Static coverage does not prove full raster, compositor, driver, or print equivalence.
