# 4.2 — Message transport, input, timers, and task-UI scheduling

## Scope and audit state

This chapter owns selected USER16/WOW32 message and task-UI seams: queue retrieval/conversion, send/post/reply/quit, default/procedure dispatch, keyboard and accelerator translation, USER timers, waits/yields, the WOWEXEC private wait, and hung-task recovery. It does **not** authorize a replacement USER scheduler, a synthetic message queue, or an autonomous `TranslateMessage`/`DispatchMessage` loop.

The evidence baseline is OpenNT commit `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`. The following are closed only for their selected static source routes; image membership and runtime behavior remain unverified.

| Contract group | Canonical identity | Class | Boundary rule |
| --- | --- | --- | --- |
| queue retrieval | `USER16_MESSAGE_QUEUE::RETRIEVE_TRANSLATE_DISPATCH` | C | A MSG16 is converted through message-specific rules, not copied as a native struct. |
| send/post/reply | `USER16_MESSAGE_SEND::SEND_POST_REPLY_QUIT_AND_TASK_POST` | C | Synchronous completion, posting, early reply, and task post are distinct states. |
| procedure delivery | `USER16_MESSAGE_DELIVERY::DEFAULT_AND_PROCEDURE_CALL` | C | Call/Def paths select Guest/native procedure routes and unthunk only after the matching synchronous return. |
| input resources | `USER16_KEYBOARD::STATE_STRING_CODEPAGE_AND_KEY_TRANSLATION`; `USER16_ACCELERATOR::TASK_SCOPED_ALIAS_CONVERSION_AND_RETIREMENT` | B | Key state/layout and accelerator aliases are task-scoped compatibility state. |
| USER timers | `USER16_TIMER::SET_KILL_CALLBACK_SLOT_AND_LATE_CALLBACK_RETIREMENT` | B | A killed timer can still have a late attempted callback; token retirement must account for it. |
| wait/yield | `USER16_WAIT::WAITMESSAGE_QUEUE_SIZE_AND_YIELD_BOUNDARY`; `USER16_YIELD::COOPERATIVE_AND_DIRECTED_TASK_SCHEDULING` | C/D | Yield policies and message-aware waits remain separate from raw thread waits. |
| shell wait / hung recovery | `WOWEXEC_WAIT::PRIVATE_MESSAGE_OR_INTERRUPT_EVENT`; `USER16_HUNG_TASK::NOTIFY_ESCAPE_AND_TERMINATION_ESCALATION` | D | Interrupt, message, timeout, cancellation, escalation, and final session retirement are separate outcomes. |

These are semantic protocols, not a count of all USER messages, callsites, or controls. The book's [evidence model](../evidence-model.md) gives the denominator rule.

## 1. Queue retrieval and procedure delivery: conversion has a lifetime

The selected retrieval slots appear in `wow32/wutbl2.h:143-144,150-151,156,159`; wrappers are in `wumsg.c:707-903,932-978,1110-1263,2103-2117`. `wstruc.c:717-799,858-927,1624-1644` records MSG16 conversion and why direct copying has limits. The shared message thunk selector/reverse entry is `wmsg16.c:114-166`.

The minimal-diff rule is simple but strict: do not retain a flat Guest mapping across retrieval, conversion, or dispatch if that call can reenter or move Guest memory. Use typed converters for each admitted message; preserve filter, `PM_REMOVE`/`PM_NOREMOVE`/`PM_NOYIELD`, `WM_QUIT`, timer, and selected DDE retry distinctions. A native peek used only to release sent-message work must not consume a posted message intended for the Guest loop.

`CallWindowProc`/`DefWindowProc` use selected table entries (`wutbl2.h:142,161`) and provider paths (`wumsg.c:165-250,642-674`). A native WNDPROC is never a raw Guest FAR pointer. Convert/thunk before the matching synchronous call and unthunk only after that call returns; procedure replacement ownership is deliberately transferred to [4.1](4-1.md), while callback stack/rundown belongs to [2.3](../part-2/2-3.md).

## 2. Send, post, reply, quit: one verb must not become another

Selected send/post/reply/task-post slots are in `wutbl2.h:147-148,152-153,245`; `wumsg.c:1008-1017,1302-1333,1396-1491,1524-1534,1627-1640,1803-1873` records the source branches. The source distinguishes an exceptional compatibility predicate that posts through a send route from ordinary post semantics. It also distinguishes `ReplyMessage` completion, receiver completion, and teardown.

Therefore an adapter must not turn Post into Send except under the recorded predicate, and must never enqueue a borrowed Guest pointer payload without an owned conversion/copyback policy. Conversion state stays alive through its actual synchronous consumer. Required runtime cases are same- and cross-thread send, early reply, nested reentry, failed post/retry after unthunk, task post, `WM_QUIT`, pointer-payload denial/copy, and teardown races. DDE-specific payload ownership stays in [4.10](4-10.md) and [5.4](../part-5/5-4.md).

## 3. Keyboard and accelerators: current task matters

`wkbman.c:21-225` contains the selected keyboard/codepage/string wrappers. It maps and flushes selected Guest buffers only for the host call, projects the MapVirtualKey dead-key bit, and has current-task layout semantics. Do not replace that with a process-global codepage cache. Test dead keys, ANSI/OEM paths, zero-length buffer requests, layout switches, and Guest buffer relocation.

`waccel.c:28-410` converts accelerator tables and maintains task-scoped aliases. A native `HACCEL` is not a Guest handle; key the registry by Guest task plus generation, preserve the packed final-entry marker on reverse conversion, and make resource-free and task-exit race to one retirement. Test equal numeric Guest handles in different tasks, GlobalFree-before-exit and exit-before-free, conversion failure, and alias reuse.

## 4. USER timers: KillTimer is not callback quiescence

`wutmr.c:50-60,62-216,219-256,286-315,393-520` provides the selected timer registry, 55 ms clamp, ID-zero paths, Guest callback gateway, set/kill operations, and late callback branches. The original route establishes a callback translation problem, not a safe native `TIMERPROC` target for a Guest procedure address.

Use a typed timer record/tombstone. `KillTimer` closes admission for that record but does not by itself prove a queued callback cannot attempt delivery. A task/VDM teardown must quiesce admitted callbacks before final registry destruction. Validate window and null-window IDs, replacement, kill with queued work, task exit during callback, nesting, and timer allocation exhaustion. Generic callback lifetime is [2.3](../part-2/2-3.md); final terminal sequencing is [1.3](../part-1/1-3.md).

## 5. Wait and yield: preserve scheduling distinctions without copying the scheduler

Selected queue/wait paths are in `wumsg.c:1038-1081,1120-1263,1881-1923,2130-2162`, with slots `wutbl2.h:149,333`. They show a build-dependent SetMessageQueue branch, a WaitMessage idle bracket, and `PM_NOYIELD` handling. Reacquire Guest mappings after any yielding wait before dereference. Do not claim resizable queue semantics when the selected non-`ONLY_API16` source does not establish them; choose bounded emulation, explicit rejection, or a documented policy.

Yield, OldYield, and DirectedYield are distinct selected policies in `wkman.c:601-690,3035-3056`, `wkgthunk.c:556-583`, and table slot `wutbl2.h:193`. Guest task IDs are not native thread handles. UI-owning scheduler threads need message-aware waiting, not an infinite raw object wait. Source tolerance for a task that disappears before directed yield applies only to that branch; it does not erase every wait failure.

The session-shell-only WOWEXEC wait is narrower again: `wkman.c:2566-2592,2598-2649,2709` pairs private USER registration with an interrupt/message event. Internally tag message, interrupt, timeout, and failure separately before projecting the proven Guest Boolean. Do not substitute raw `WaitMessage` and lose the interrupt reason. Test wrong HWND, new/old message, interrupt-only and simultaneous wakes, timer change, shell destruction, and shutdown race.

## 6. Hung-task recovery: cooperative request before isolated escalation

`wkman.c:2754-2995,3002-3032` and `wutbl2.h:364-366` establish the selected hung-controller/end-task route: target/current task choices, heartbeat/cancel/Escape actions, waits, IRQ, a second wait, and all-task escalation. The implementation rule is a session-owned recovery policy: track requested task, presently interrupted task, and terminal session state separately; correlate attempts by generation so a late callback cannot arm a reused task; bound cancellation and escalation; and retire the callback/event capability through the lifecycle barrier.

It is **not** evidence that ending a host process tree is equivalent, or that the original source contains a verified race/leak. Validate an already-dead target, task-switch success, 16-bit loop timeout, cancellation at both prompts, competing requests, late callback, and session shutdown. Final session retirement remains [1.3](../part-1/1-3.md).

## What this chapter does not infer

- Source wrappers do not prove a modern USER queue or scheduler is semantically identical.
- A requested timer kill or hung-task cancellation is not a callback-drain acknowledgement.
- Native thread handles, procedure pointers, `HACCEL`, and timer callbacks are not Guest representations.
- Selected source static closure does not prove emitted-image reachability, all converter branches, or runtime success.
