# 4.4 — Menus: template graphs, aliases, mutation, and tracking

## Scope and audit state

This chapter owns selected USER16 menu seams: named/indirect template conversion, create/load/attach/destroy, submenu-index lookup, item payload/mutation, and popup tracking. It does not own accelerator aliases (4.2), window/class binding (4.1), generic callback transport (2.3), or final message delivery (4.10).

The source baseline is OpenNT commit `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`. Every record below is static-source closed only; no emitted image or modern runtime equivalence is claimed.

## 1. Creation and template conversion: a temporary graph becomes a session alias

The server creation callback is typed at `wowuserp.h:132`, bound by `client.c:2302`, and called by selected WOW32 conversion code at `wumenu.c:1080-1116`; selected USER provider evidence is `clres.c:4035-4051`. It distinguishes resource ordinals from strings. An ordinal must not undergo string conversion; a string requires the selected conversion before the provider call.

The adapter parses and validates the 16-bit template/resource identifier inside the compatibility layer, then passes a typed native template to its one synchronous provider call. Temporary converted name/template storage remains live only until that call returns and is released exactly once. A typed session menu alias is published only after provider success; conversion/allocation/provider failure yields the source-visible zero result without exposing a partial native menu.

Selected lifecycle evidence spans `wutbl2.h:195-209,443,507-515`, `wumenu.c:479-625,768-849,1070-1161,1417-1472`, and menu template conversion in `wres16.c:384-476`. The source treats the format as version/header/options-aware, recursively nested for popups, aligned, and capable of carrying owner-draw 16:16 item data. A modern `HMENU` is therefore only the backing object; it is not a substitute for the original graph or payload interpretation.

For malformed/truncated/cyclicly deep input, select and document a checked-parser policy. Preserve established semantics for valid input and record any hardening divergence explicitly; static source alone does not establish all malformed-input behavior.

## 2. Aliases and lifecycle: no native HMENU in a Guest word

Native `HMENU` must never be serialized into a 16-bit Guest handle. Resolve aliases in the current session, pin the resolved menu/window objects during a query or tracking call, and reject aliases entering retirement. Retire parent, submenu, and attached-window tokens under an explicit lifecycle barrier; do not infer that a read-only lookup or `DestroyMenu` alone drains callbacks.

`pfnGetMenuIndex` is registered in `wowuserp.h:140` / `client.c:2310`; a selected WOW32 caller at `wmsg16.c:690-710` projects the provider's lookup result, whose validation/sentinel behavior is in `ntstubs.c:3176-3202`. Position zero is a legitimate zero result; invalid or not found is all ones. This operation transfers no ownership and performs no mutation. Test parent position zero, missing submenu, invalid alias, concurrent retirement, and raw-host-handle rejection.

The source distinguishes RemoveMenu from DeleteMenu and treats submenu ownership separately (`wumenu.c:556-570,588-625,1417-1471`). Preserve that distinction rather than treating both as a generic erase. Window destruction or task retirement must not make an alias resolve to a reused backing object.

## 3. Menu item payloads: a tagged union, not a string pointer

Selected item/mutation routes are in `wumenu.c:152-195,361-463,646-719,999-1041,1313-1375`. Each payload is one of a string, bitmap/pseudo bitmap, owner-draw data, popup relationship, or a compatibility-specific form. Keep an explicit tagged union. In particular, owner-draw item data is a Guest 16:16 identity and must not be reinterpreted as native text; bitmap ownership remains outside ordinary menu destruction.

Preserve the selected width/result rules:

- `HiliteMenuItem` carries WORD-width ID/flags and retains command-versus-position interpretation.
- `GetMenuCheckMarkDimensions` returns a packed 32-bit low-word width/high-word height result with no Guest arguments.
- `GetMenuString` has a selected unsigned-WORD host cap of 2000 distinct from the requested Guest mapping length; length, output capacity, host result, byte conversion, and flush must be tested independently.
- `CheckMenuItem` projects previous state/error through a signed `SHORT`, not through generic Boolean normalization.

Source text computes `strlen` after selected GetMenuString paths, but this is not proof of a runtime null/zero-length fault. Map extent, A/W binding, host failure, flush, and result interpretation require explicit target validation.

Owner-draw adds resource lifetime—not automatic pinning—to the contract. The selected source proves a Guest far-pointer-like value is stored and later delivered to measure/draw paths. It does not prove exactly when a backing selector is moved, discarded, faulted, or reloaded. A physical move alone is not proof of invalidity, and no use-after-free conclusion is made. Tie resource mapping questions to [2.2](../part-2/2-2.md), callback lifetime to [2.3](../part-2/2-3.md), and runtime validation to [6.3](../part-6/6-3.md).

## 4. Popup tracking: leases survive reentry

`wumenu.c:1591-1612` is the selected popup tracking provider. It converts the rectangle without writeback, preserves signed coordinates and selected return narrowing, and resolves an owner route. TrackPopup-style code must hold menu and owner-window leases across the tracking interval; the owner can receive messages and reenter while the popup remains active.

Do not assume more than the selected source flags establish about `TPM_RETURNCMD`-style behavior. Test cancellation versus selection, nested popup tracking, owner destruction, message reentry, task exit, and retirement during the tracking call.

## What this chapter does not infer

- A modern `HMENU` alone preserves neither original template grammar nor owner-draw payload semantics.
- A native handle value is not a valid Guest menu representation.
- Menu query does not prove alias ownership, callback drain, or destruction safety.
- Resource unlock/movement does not by itself prove a Guest owner-draw pointer is invalid.
- Static source routes do not establish effective image membership or runtime behavior.
