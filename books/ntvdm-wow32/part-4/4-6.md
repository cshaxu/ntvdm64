# 4.6 — Common dialogs: copied structures, hooks, and asynchronous ownership

## Scope and audit state

This chapter covers five selected COMMONDLG16 bridges: open/save, print, color, font, and Find/Replace. Each crosses a packed 16-bit structure, optional template and hook, owner/task identity, native resources, and result/cancellation projection. The source baseline is OpenNT commit `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`; static closure does not prove a loaded image, provider UI behavior, or runtime equivalence.

| `COMMDLG16_FILE_DIALOG::OPEN_SAVE_SHARED_TEMPLATE_HOOK_AND_BUFFER_BRIDGE` | D | Bounded OPENFILENAME marshal, task-local state, directory/template handling, and distinct false/buffer-too-small result paths. |
| `COMMDLG16_PRINT::DEVMODE_DEVNAMES_TEMPLATE_HOOK_AND_MUTATION_AWARE_COPYBACK` | D | Owned device-block conversion, hook/template state, mutation-aware selected copyback, typed output aliases. |

## 1. One common discipline: copy structures, lease capabilities, refresh views

No native common-dialog provider receives a raw Guest structure pointer, Guest hook FARPROC, Guest template pointer, or Guest HWND. Decode each input into a bounded native copy and represent hook, owner, template, and result buffers as typed capabilities. A capability is valid only during its admitted native call/callback interval; reentry or callback can move Guest state, so Guest views must be refreshed before post-hook/readback access. Task retirement closes admission, drains admitted hooks, and then releases state.

Every bridge needs three independently recorded outcomes: native success, ordinary cancellation/failure, and source-specific extended/buffer failure. A false native return is not permission to overwrite Guest output. Conversely, a selected temporary mapping/flush may have effects that require test even on failure; do not assume unchanged bytes solely because final success fields are not projected.

## 2. Open and Save: buffers, directory state, and hook payloads

Guest entry thunks are in `wow16/commdlg/commdlg.asm:46-47`; shared WOW32 logic is `wcommdlg.c:1143-1185,1550-1715,1721-1761`. It preserves separate native Open and Save routes behind a common bridge, task-local state stack, template ownership, directory synchronization, and post-hook view refresh.

Preserve the distinction between an ordinal and a string template/name, the bounded file buffer, `FILEOK` null/non-null payload handling, uppercase/copyback behavior where selected, and buffer-too-small versus ordinary false. `SHAREVISTRING` is structured callback data, not a C string or a reinterpreted OPENFILENAME pointer. Test null and non-null payloads, allocation failure, template failure, buffer too small, selector movement during hook, directory changes, and callback/task teardown.

## 3. Print, Color, and Font: payload-specific copyback

Print is not merely a file dialog with a printer. `wcommdlg.c:1235-1519` converts DEVMODE/DEVNAMES, templates/hooks, and selected results. Preserve `PD_RETURNDEFAULT` validation, selected hook branch, Guest min/max mutations, and freeing of native device blocks after reverse conversion. HDC or other native handles become typed aliases with retirement, never Guest raw values. Printer/device semantics themselves transfer to [5.7](../part-5/5-7.md).

Color (`wcommdlg.c:847-985`) copies exactly sixteen Guest custom colors into aligned native storage. Only a successful return projects the selected result and array back. An unaligned Guest array must never reach a native API directly; template/hook cleanup and task-state restoration occur on every selected exit.

Font (`wcommdlg.c:987-1140`) treats LOGFONT and style as bounded copied/view leases. Preserve the output flag mask, selected success-only fields/LOGFONT projection, private font messages, hook capability, and conditional style flush separately. A failed native result does not project the selected result fields, but actual style-buffer effects still require mapping/provider tests. Check handled/unhandled GETLOGFONT hook results, private-message suppression, and task retirement during a font callback.

## 4. Find/Replace: modeless state continues after the caller returns

Find/Replace is the exceptional lifecycle case. The selected WOW32 code (`wcommdlg.c:1187-1210,2241-2375,2378 onward`) maintains paired owner/dialog task records; the provider's selected normal termination and synchronous owner notification are in `shell/comdlg32/find.c:49-53,159-250,489-515,523-557,586-611,735-766,974-985`.

Use two typed task-local records keyed by owner and dialog identity, with copied strings/template leases retained until terminal destroy. A Guest hook is admitted through a typed capability; neither a late notification nor a callback can use a retired record. At termination distinguish `FR_DIALOGTERM` owner notification, physical window destruction, callback leases, and conditional bridge cleanup. Initial return from FindText/ReplaceText does not retire anything.

The source contains complex failure/cleanup branches, but static reading does not establish a double-free, leak, or use-after-free. Test pre-link and post-link allocation failures separately, template/native creation failure, sync initialization reentry, external/late destroy, repeated notifications, owner mutation, denied/intercepted destruction, and task exit. Preserve an explicitly chosen modern allocation-failure policy rather than falsely labeling it as observed original behavior.

## What this chapter does not infer

- A public modern common-dialog API proves neither the packed Guest wire nor hook/reentry/lifetime equivalence.
- Native structure pointers, hooks, HWNDs, HDCs, device handles, and templates are not Guest representations.
- Common-dialog cancellation is not a generic failure and does not authorize success copyback.
- Find/Replace initial return is not completion.
- Source cleanup branches alone do not prove a defect or exactly-once destruction.
