# 4.5 — Standard controls, class-specific messages, and CTL3D

## Scope and audit state

This chapter owns selected standard-control conversion rules: button, edit, listbox, combobox, static icon, scrollbar, dialog-item proxy, owner-draw, and CTL3D subclass seams. It does not claim to recreate every native control internally. The task is to preserve selected Win16 message wire semantics and lifecycle without leaking host pointers or inventing a parallel control-state store.

The OpenNT evidence baseline is commit `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`. The ledger closes individual selected static routes; effective build options, modern control behavior, and runtime callback interleavings remain unproved.

## 1. Class-specific message arithmetic is not a universal message translation

The selected edit route is `wmsgem.c:76-93,189-196`; list and combo routes are `wmsglb.c:76-94,183-189` and `wmsgcb.c:66-97`. They prove local arithmetic, reserved slots, and selected class dispatch—not a license to rewrite every `WM_USER` message. For EDIT, apply transformations only on the selected EDIT class path, preserve explicitly reserved-zero behavior, and retain out-of-range application messages as source-initialized on the local path. For LISTBOX, preserve the subtract-one WORD arithmetic and the `WM_USER+4` reserved result. For COMBOBOX, test private focus IDs before range arithmetic and retain the source `+25`/`CB_MSGMAX` variation as a build-dependent rule.

Test boundaries rather than only nominal messages: LB offsets `+0,+1,+4,+37,+38`; CB `+0,+24,+25,+26,+27,+28`; negative/high-bit `wParam` and `lParam`; synchronous versus posted delivery; subclassed and non-control windows. A pass-through does not prove the recipient supports the message. WIN31/WINVER branches remain build evidence for [6.3](../part-6/6-3.md).

## 2. Text, buffers, arrays, and rectangles: each message owns its length model

Edit `GetLine`, `ReplaceSel`, selection, line scrolling, tab stops, and rectangle messages; list/combo text, selection arrays, item heights, tab stops, searches, and rectangles are separate records because their input/output lengths, signedness, null rules, and ownership differ. Do not make a blanket “copy UTF-16 string” helper stand in for them.

For every admitted message, record: Guest buffer start and capacity; whether capacity is bytes, characters, WORD elements, or a packed coordinate; allocation/copyback owner; result count or sentinel; and release point after synchronous return. Reacquire Guest mappings after callbacks/reentry. For examples, `GetLine` result count is not an assumed C-string length; `ReplaceSel` needs a bounded temporary lifetime; selection arrays have an explicit capacity; and rectangle conversion has null/coordinate/copyback branches.

Validation must include zero, one, exact, short, maximum/overflow-adjacent capacity; null/invalid buffer; DBCS/encoding boundaries where selected; missing/destroyed control; nested callback; and task exit. Static source showing an unconditional `strlen` or a map macro does not establish an observed crash.

## 3. List/combo items and owner draw: payload kind survives both directions

`LISTCOMBO16_MESSAGE::INSERT_SEARCH_INPUT_STRING_OR_ITEMDATA` and the reverse list/combo records distinguish `HASSTRINGS`, owner-draw, strings, and DWORD item data. Preserve Add versus Insert, prefix versus exact search, start-index wrap, selected edit updates, and selected return sentinels. Do not truncate native pointer-sized data into Guest DWORD just because a modern control internally uses pointer-sized item data; use an explicit 32-bit Guest payload policy.

Owner-draw notification has its own payload lifecycle. Temporary text/payload conversions survive only to the matching synchronous callback, and Guest callback identity remains typed. Test ordinary and owner-draw styles with/without `HASSTRINGS`, null/high-bit values, string mutation, reentry, missing WOW metadata, sorted versus unsorted operations, and task/control destruction.

## 4. Dialog item helpers: child IDs, integer projection, and caches are not generic HWND calls

Selected helper evidence appears in `wutbl2.h:124-131,286-287`, `wudlg.c:193-255,805-1032,1141-1155,1394-1451`, and `wusercli.c:131-153`. Preserve output capacity and typed Boolean projection; navigation is distinct from dialog creation. Child IDs are zero-extended where selected, and a child control ID must not be treated as an arbitrary host handle.

The `WOWCF_DBASEHANDLEBUG` route is deliberately narrow: the selected task field is a 16-bit token, and its fallback behavior cannot be silently converted into a native HWND pass-through. `GetDlgItemInt`/`SetDlgItemInt` similarly require explicit sign/zero-extension and translated-BOOL treatment. Test values around `-32769`, `-32768`, `32767`, `32768`, `65535`, `65536`, and 32-bit limits; null translation output; valid zero; failure; stale/destroyed controls; and the real AX/DX return projection. No overflow fault is asserted by source inspection.

`SendDlgItemMessage` caching and `EM_GETRECT` compatibility belong to their own selected control-message contract. Invalidate cache at the specified lifecycle points and do not assume a cached HWND survives destruction/reuse.

## 5. Procedures, icons, scrollbars, local storage, and CTL3D

The edit word-break bridge uses a tagged Guest procedure and a native reverse trampoline; it is not a WNDPROC (`wcall32`/word-break evidence in the ledger). Preserve its short parameter widths, signed return, buffer bounds, code-page/index rules, nested callback handling, and procedure/module/task lifetime. The generic callback carrier is [2.3](../part-2/2-3.md).

Static-control `SETICON`/`GETICON` is bidirectional alias conversion (`wmsg16.c:21-55,1459-1493`; `wcntl32.c:1063-1088`), not icon ownership transfer. Test null, first/replacement/previous icon, stale/reused identity, and destruction. Scrollbar legacy IDs, signed range and packed return likewise retain their 16-bit fields rather than using an unexamined native struct.

For selected `WOWFASTEDIT`, `CONTROL_GUEST_LOCAL_HEAP_STORAGE` requires a typed Guest-local bridge: DS:handle/offset tokens, bounded four-byte entry mapping leases, exact movable/discarded/count behavior including `0xff` lock saturation, flush-before-release, and no substitution with modern LocalLock/LocalUnlock. CTL3D subclassing similarly owns a token, color/subclass routing, and retirement barrier—not a permanent native subclass or an unbounded hook.

## What this chapter does not infer

- Native controls are not automatically semantic substitutes for each selected Win16 control message.
- A host pointer, native callback, HICON, HACCEL, or HWND is not a Guest token.
- Control data width and message range rules cannot be globally normalized.
- Source mapping/string code alone does not prove a runtime failure or buffer bug.
- Static selected routes do not prove emitted-image reachability or all control styles/providers.
