# 3.1 — Tasks, modules, memory, and local objects

## Boundary

This section owns the KERNEL16-facing identity and local storage seams: task and
module aliases, cross-VDM task-handle reservation, selected module queries, and
the thin WOW32 local/global-memory wrapper family. It does not absorb file/path
services (3.2), communications (3.3), timers/system presentation (3.4), DOS/DEM
adapters (3.5), callback admission (2.3), or USER object ownership (Part 4).

| Canonical seam | Unit / class | Static conclusion | Handoff |
| --- | --- | --- | --- |
| `NTVDM_WOW_GET_MODULE_FILE_NAME_SERVICE` | protocol / D | Win16 module handles and task aliases are distinct identities with different path routes. | Path conversion policy: 3.2; alias retirement: 1.3/2.3. |
| `NTVDM_WOW_WINOLDAP_MODULE_HANDLE_SERVICE` | protocol / D | WOW fallback module lookup uses a session/task-owned child-application registry. | Launch/lifecycle details: 4.9/1.3. |
| `KERNEL16_THUNK::WOWRESERVEHTASK` | entry / D | Cross-VDM task-handle reservation uses reserve/fill/release, not native thread IDs. | Shared mapping/retirement: 2.1/1.3. |
| `KERNEL16_THUNK::GLOBALMEMORYSTATUS` | entry / D | One Guest pointer addresses an exact 32-byte, eight-DWORD output packet. | Modern sampling policy: 3.4/6.3. |
| Local/Global wrapper families | entries / D | Each selected operation has an operation-specific frame, width, route, and return conversion. | Heap semantics: Guest KERNEL owner; layout: 2.1. |

These closures identify selected source contracts. They do not mean that a
native Windows module, process, heap, or memory-status object may be passed
straight through as a Win16 identity.

## Task, module, and native process are not interchangeable

`GetModuleFileName` is a representative boundary. The Guest route in
`wow16/kernel31/ldaux.asm:453-516` distinguishes an ordinary current-session
module from a task alias. The `GETMODULEFILENAME16` wire is
`HAND16, VPSTR, SHORT` (`wowkrn.h:443-447`), and the selected WOW32 provider is
`wkernel.c:742-762`.

For the normal path, an implementation needs a bounded path query followed by
Guest-code-page conversion into the declared 16-bit capacity. For a task alias,
it needs project-owned task/process metadata or an explicitly authorized
cross-process query. A retired, inaccessible, or missing alias returns the
source-selected unavailable result; it does not become a host module handle.
In particular, an unbounded `strlen`-style source flush must not be copied as an
unbounded modern write.

The companion `WOWGETMODULEHANDLE` route is fallback-only: after the local
Win16 search fails, `WK32WowGetModuleHandle` scans the selected child list and
matches uppercased/case-insensitive names. A modern registry must preserve that
fallback order, child-exit cleanup, and zero-no-match behavior. It must not
replace all Guest module lookup with a process-wide native module table.

## Cross-VDM task reservation is a state machine

`WOWRESERVEHTASK` has a one-WORD `HTASK16` wire. Guest `CreateTask` reserves a
candidate selector, retries with a clone on zero collision, then later fills
metadata; `WK32KillTask` removes the owning registration. The selected sources
are `task.asm:442-536`, `wowkrn.h:1331-1334`, `wktbl2.h:343`, and
`wkman.c:1037,4104-4243,4958-4969`.

The compatibility requirement is an explicit state machine:

```text
available -> reserved -> filled -> retirement admission closed -> removed
```

Reservation must be atomic across active emulated instances; a zero collision
is the Guest retry signal. But a nonzero reservation is not proof of global
uniqueness when the registry is full or unavailable. The policy for that
condition must be explicit—strict rejection or source-compatible degradation—
and task exit must remove exactly the owning registration after callback and
delivery quiescence. Neither host thread IDs nor raw shared-map offsets are
valid Guest task handles.

## Local/global memory wrappers preserve per-operation ABI, not a new heap

The selected `wklocal.c` and `wkglobal.c` entries are thin wrappers around many
operations (`LocalAlloc`, `LocalLock`, `LocalReAlloc`, `GlobalAlloc`,
`GlobalLock`, `GlobalWire`, and others). Their static closure means each wrapper
has a selected operation-specific field width, host route, and result
conversion. It does **not** close the whole Guest local/global heap allocator,
compactor, owner sweep, or every API16 build fallback.

Therefore, preserve the individual wire/result contract and represent returned
handles or pointer-shaped results as session-local typed capabilities. Do not
map every operation to a convenient modern heap API, and do not silently erase
the API16/disabled conditional branch. Outstanding capabilities must be revoked
at task retirement; host allocator behavior is not a substitute for Guest heap
semantics.

`LOCALHANDLEENTRY`'s exact four-byte representation and lease rules are owned
by 2.1. This section receives that layout as an input and owns only the selected
KERNEL service semantics that consume it.

## Memory status is a fixed Guest packet

`GLOBALMEMORYSTATUS16` contains one `VPVOID` to a 32-byte Guest result packet.
The selected provider (`wkmem.c:158-170`) maps exactly that output, calls the
source host service, and releases the views. Guest `GetDPMIFreeSpace` then
projects the stated virtual/physical/pagefile fields into EDX/EAX. A modern
implementation must write eight 32-bit little-endian fields through a typed
facade and preserve `dwLength`; it must never pass the Guest 32-byte packet to
a native x64 `MEMORYSTATUS`-family ABI.

The audit does not choose whether a modern carrier reports host-wide or per-VDM
memory limits, nor does it prove historical large-memory saturation behavior.
Those are explicit policy and runtime-validation questions, not license to
overwrite the Guest packet with host-native layout.

## Validation receipts

6.3 validation must cover normal/null/alias `GetModuleFileName`, zero/exact-fit/
truncated Guest buffers, alias retirement and inaccessible process cases; local
module hit versus fallback child-module hit/no-hit; cross-instance reservation
collision, full/unavailable registry, failed startup after reservation, and
concurrent reserve/remove; representative Local/Global normal and API16
fallback branches; and the exact 32-byte memory-status wire plus DPMI EDX/EAX
projection. These tests are independent from simple host process/module calls.
