# 3.5 — DOS/DEM and direct device-query adapters

## Scope and audit state

This final Part 3 chapter is intentionally a narrow set of Win16-observable adapters into DOS/DEM state: initialization of the `DOSWOWDATA` view, one removable-media IOCTL, and FindFirst/FindNext enumeration state. It does **not** reopen the DOS machine, BIOS, V86 execution, physical device emulation, or arbitrary VDDs. Optional VDD extension loading is separately bounded by [5.8](../part-5/5-8.md).

The selected OpenNT baseline is commit `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`. The three canonical records below are source-contract closed. Their provider behaviour, target-image inclusion, and runtime observations remain independent work.

| Canonical identity | Boundary object | Class | Selected static closure |
| --- | --- | --- | --- |
| `NTVDM_WOW_DOSWOW_LINEAR_VIEW_INITIALIZATION` | a four-byte Guest pointer to packed DOS shared state | D | Bootstrap converts selected real-mode addresses before dependent services use the view. |
| `NTVDM_WOW_DOS_IOCTL_REMOVABLE_MEDIA_SERVICE` | two 16-bit fields and DOS AX/carry-style result convention | B | Only command `08h` is handled; drive selection and native-category collapse are explicit. |
| `NTVDM_WOW_FILE_FIND_FIRST_NEXT_SERVICE` | a mapped 43-byte DTA carrying search identity/state | D | WOW32 normalizes/project errors around DEM FindFirst/FindNext and DEM resets or advances DTA state. |

These are three protocol records, not a completion claim for all DOS APIs or a count of hardware interfaces. See the [evidence model](../evidence-model.md) for why entry, callsite, structure, protocol, mechanism, and build-variant counts remain distinct.

## 1. DOSWOW bootstrap: typed session state, never serialized host pointers

Guest protected-mode setup calls `WOWDosWowInit` (`wow16/kernel31/ldboot.asm:637-648`). KERNEL table slot `k271` binds it to `WK32DosWowInit` (`wow32/wktbl2.h:337-340`). Its entire external frame is one unaligned four-byte `VPVOID`, `WOWDOSWOWINIT16` (`inc/wowkrn.h:1294-1297`).

`DOSWOWDATA` is a packed ordered collection of nine DWORD fields (`inc/doswow.h:13-36`): current-directory count/table/buffer, current drive and PDB, driver error and extended-error locus, sync byte, and SFT address. `WK32DosWowInit` (`wow32/wkman.c:3518-3550`) maps the incoming Guest pointer, converts each selected fixed DOS address with `GetRModeVDMPointer`, and publishes the converted values in its local `DosWowData` representation.

This is a view-initialization seam, not authority to place a native64 address into Guest-visible memory. A modern carrier must decode the four-byte Guest field and the original field order, associate resolved views with precisely one session, require initialization before directory/file consumers use them, and invalidate the typed views before session storage can be reused. The source proves neither all consumers nor shutdown/reinitialization behavior; those are named lifecycle residuals rather than a reason to invent a general DOS platform.

Focused validation: prove each selected conversion before a directory service runs; start two sessions and show no view crosses sessions; retire a session and reject later reuse. The shared pointer-domain rules remain owned by [2.1](../part-2/2-1.md).

## 2. DOS IOCTL 4408h: a bounded removable-media classification

The internal `WOWDEVICEIOCTL16` frame is two WORDs, `wCmd` and `wDriveNum` (`inc/wowkrn.h:1263-1267`), bound at `wktbl2.h:324-334`. The Guest INT 21h quick route has separate command/flags evidence in `wow16/kernel31/i21entry.asm:1044-1058`. The selected handler, `WK32DeviceIOCTL` in `wow32/wdos.c:772-822`, is much narrower than its name:

1. It truncates both frame values to bytes and rejects every command except `08h` with `FFFF0001h` (invalid function).
2. Drive zero obtains the current drive from `DosWowData.lpCurDrv`; a nonzero value is converted from one-based to zero-based before constructing `?:\\`.
3. `GetDriveType` category `0` or `1` becomes `FFFF000Fh` (invalid drive).
4. Only `DRIVE_REMOVABLE` yields zero; every other accepted category yields one.

The exact high-word error encoding, AX-width truncation, current-drive behavior, and `DX`/carry presentation must be preserved at the Guest boundary. A modern implementation may have a supported volume-classification carrier, but it must map from the **Guest session drive**, not the host process's current directory. It must also keep root storage per call or serialize it: the historical static `pPath` buffer is evidence of source behaviour, not proof of safe concurrent use.

Acceptance cases are command `08h` versus another command, zero versus nonzero drive input, unknown/no-root/removable/fixed/remote/CD-ROM/RAM classifications, and the exact Guest return encoding. This does not claim modern drive mapping or all DOS/media semantics are complete.

## 3. FindFirst/FindNext: DTA state is an opaque capability, not a host pointer

WOW32 maps a `SIZEOF_DOSSRCHDTA` Guest DTA, normalizes the path against `DosWowData.lpCurDrv`, and invokes DEM in `WK32FileFindFirst` (`wow32/wkfileio.c:2106-2196`). It maps the same DTA and invokes `demFileFindNext` in the paired next routine. Success returns zero; errors are projected as `FFFF0000h | error`, with the special `-1` route using `GetLastError`.

The DEM side (`dos/dem/demsrch.c:270-358;428-478`) resets `FFindId` and `pFFindEntry` before a new search, handles volume-label-first behaviour, normalizes selected native errors, fills the fixed search DTA, and records a search identity for a successful continuation. The wire layout is a packed 43-byte `SRCHDTA` in `dos/dem/dosdef.h:64-81`.

The original implementation may store a provider search pointer/identity in that DTA. A modern 64-bit integration must not copy that pattern literally. Treat the DTA fields as a Guest-visible opaque token backed by a session-owned enumeration registry: reset/revoke it before a new FindFirst, reject missing/stale/mismatched identity on FindNext, clear it on exhaustion, and retire it on task/session teardown. Preserve DOS error normalization and high-word projection at the seam; filesystem/network provider semantics are outside this static closure.

Required acceptance covers FindFirst success/no-match/volume-label/malformed-path, FindNext after success and exhaustion, stale or mismatched DTA state, concurrent task enumeration, and task exit with a live enumeration. Runtime token retirement and provider behavior transfer to [6.3](../part-6/6-3.md).

## What this chapter does not infer

- `DOSWOWDATA` source conversion is not proof of a stable raw pointer ABI on a modern host.
- A source `GetDriveType` call is not a statement that every modern volume category has identical DOS meaning.
- DEM's use of a DTA identity does not authorize a native pointer in a 16-bit-visible field.
- No selected route proves a full DOS, BIOS, V86, device-driver, or VDD implementation.
- No callsite proves an emitted image, all build branches, or runtime success.
