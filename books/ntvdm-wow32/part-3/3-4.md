# 3.4 — Time, counters, and compatibility-valued system queries

## Scope and audit state

This chapter closes four selected OpenNT source contracts at the KERNEL16/USER16-to-WOW32 boundary. It is deliberately not an audit of virtual-machine timer hardware, the DOS clock, every USER scheduler wait, or a general modern system-information layer. Those would turn a Win16 compatibility seam into a SoftPC/V86 platform audit.

The source baseline is OpenNT commit `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`. Every identity below is closed for the stated static source route. “Closed” does not assert that a particular emitted image was built, that a modern carrier has been implemented, or that timing has been observed at runtime.

| Canonical identity | Boundary object | Class | What the selected source establishes |
| --- | --- | --- | --- |
| `NTDLL_HOST::NtQueryPerformanceCounter` | two optional Guest destinations, each eight bytes | D | WOW32 obtains a counter and frequency, stores low then high DWORD, and returns `TRUE`. |
| `KERNEL16_THUNK::GETCURRENTDATE` | packed 32-bit local-date result | B | WOW32 obtains local time and packs the fields in an exact source order. |
| `NTVDM_TIMER::SuspendTimerThread` | counted pause/resume request | D | Task and time-change paths request a pause or release it; they do not prove producer quiescence. |
| `USER16_SYSTEM_RESOURCES::GETFREESYSTEMRESOURCES_SELECTOR_AND_PERCENT` | one WORD selector and compatibility percentage | C | A source build branch either calls a legacy provider or returns literal `90`; the effective build is unknown. |

These are four entries, not a count of all time-related functions, callsites, mechanisms, structures, or build variants. The book's [evidence model](../evidence-model.md) defines those separate denominators.

## 1. Performance counter: an optional-output wire contract

`WOWQUERYPERFORMANCECOUNTER16` contains two `VPVOID` fields, `lpPerformanceFrequency` followed by `lpPerformanceCounter`, in `base/mvdm/inc/wowkrn.h:977-981`. The KERNEL dispatch table binds `WOWQueryPerformanceCounter` to `WK32WOWQueryPerformanceCounter` with that fixed frame size in `wow32/wktbl2.h:283`.

The handler in `wow32/wkman.c:2388-2421` is precise enough to guide a minimal modern adapter:

1. It maps an eight-byte Guest view only for each nonzero output pointer.
2. It obtains both native values once through `NtQueryPerformanceCounter`.
3. It writes each requested `LARGE_INTEGER` as `LowPart`, then `HighPart` using Guest DWORD stores.
4. It frees only the views it acquired and returns `TRUE` unconditionally.

The order of fields in the input record does not authorize a different order inside either eight-byte output. Likewise, a null counter output does not suppress the frequency request, and both-null is still an accepted source-level request. A modern implementation must use a supported counter/frequency source behind an adapter; it must never expose a host pointer, a private native status, or a native 64-bit layout directly to Guest memory.

Required validation is small but non-negotiable: counter only, frequency only, both outputs, both null, and recognizable low/high values. This is static-contract closure; counter monotonicity, clock adjustment behaviour, and the selected image/link path remain runtime/build evidence for [6.3](../part-6/6-3.md).

## 2. Date: a packed local-time compatibility value

The internal KERNEL function number `265` is `FUN_WOWGETCURRENTDATE` (`inc/wowkrn.h:273-277`) and is table-bound as `WOWGetCurrentDate` in `wow32/wktbl2.h:330`. `WK32GetCurrentDate` in `wow32/wdos.c:723-737` calls `GetLocalTime` and returns:

`(year << 16) | (day << 8) | (month << 4) | dayOfWeek`

That is the source contract even if the bit allocation looks unusual to a modern reader. It is not a `SYSTEMTIME` pass-through, UTC timestamp, locale-formatted date, or a license to replace it with an unrelated modern date API result. Test representative local dates, including boundary day/month values, against the exact packed expression.

The immediately following current-time wrapper is inside `#if 0` (`wdos.c:739` onward). Its text is useful negative evidence: selected-source date support does **not** prove that the disabled current-time path is present, callable, or suitable for restoration. Adding it would be a new compatibility decision, not a minimal-diff reproduction.

## 3. Timer thread: pause request is not a drain acknowledgement

`SuspendTimerThread` and `ResumeTimerThread` are declared host services in `inc/softpc.h:216-217`; the WOW32 export profile lists both names. The selected task routes call them at several lifecycle points:

- `wkman.c:549-557` requests suspension while a noninitial task starts, with the source comment tying it to DOS-time resynchronisation.
- `wkman.c:1110-1114` and `1394-1398` release the timer thread after task initialization, except for the first presumed `WOWEXEC` task.
- `wkman.c:1453-1456` requests suspension when the live task count falls below two.
- `wkman.c:2629-2638` performs a suspend/resume pair after `VDM_TIMECHANGE` while `WOWEXEC` is scheduled.

This records transitions in a task-count/time-change policy. It does not prove that acquisition blocks, that a callback queue is drained, that no heartbeat can arrive later, or that cancellation has completed. Treat the pair as balanced counted leases: define nested acquisition/release and underflow policy, make the request non-blocking, and keep late work inside the common callback admission/rundown discipline from [2.3](../part-2/2-3.md) and [1.3](../part-1/1-3.md). Do not silently manufacture a guarantee of timer-thread termination.

Validation must cover nested and concurrent leases, normal and failure unwind around modal hard-error/task routes, a time-change transition, and a late attempted delivery after a pause request. Full delivery/cancellation/quiescence validation belongs to [6.3](../part-6/6-3.md).

## 4. GetFreeSystemResources: branch-specific compatibility, not telemetry

USER ordinal 284 reaches the `GETFREESYSTEMRESOURCES` Guest thunk (`wow16/user/user.def:298`; `user4.asm:94`) and its fixed one-WORD frame (`inc/wowusr.h:2971-2974`). The USER table binds it to `WU32GetFreeSystemResources` in `wow32/wutbl2.h:355`.

The selected wrapper (`wow32/wuser31.c:730-752`) has two source variants:

| Source condition | Result |
| --- | --- |
| `APRIL15` defined | Call the then-existing `GetFreeSystemResources` provider with the selector and project the result to a 16-bit unsigned value. |
| `APRIL15` absent | Return literal `90`, independent of the selector. |

The audit has source evidence for the matrix, but not for the compiler command, macro definition, emitted USER/WOW32/TOOLHELP images, or the legacy provider's full semantics. Therefore the practical minimal-diff rule is intentionally narrow: for a proved non-`APRIL15` target, return the source literal `90`; do **not** substitute a current GUI, memory, or process-pressure metric. An `APRIL15` target needs separate provider and build proof before choosing a carrier. This is why the seam is class C rather than an API-shaped modern replacement.

## What this chapter does not infer

- A call in selected OpenNT source does not establish emitted-image membership or runtime success.
- A timer pause request does not establish callback cancellation, queue drain, or safe teardown.
- The disabled current-time wrapper is not a supported route.
- A familiar modern performance/timing API does not itself prove the Guest packing, optional-output, or return policy.
- `GetFreeSystemResources` is a compatibility-valued legacy query, not a measurement interface.

## Closure receipt and handoff

The four identities are static-source closed because their frame/dispatch or direct source route, build alternatives where applicable, preservation rule, negative inference boundary, and focused acceptance cases are recorded. Remaining build-image and runtime evidence is explicitly transferred to [6.3](../part-6/6-3.md); shared callback teardown remains in [2.3](../part-2/2-3.md) and [1.3](../part-1/1-3.md). USER message/wait scheduling is not pulled into this chapter and remains a Part 4 concern.
