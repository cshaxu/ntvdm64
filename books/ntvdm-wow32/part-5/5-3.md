# 5.3 — Timers, MCI, and remaining multimedia

## Boundary

This section contains multimedia timer, MCI, and remaining operation families whose commands combine tables, drivers, yields, callbacks, and teardown. It is not permission to treat all multimedia exports alike.

## Semantics that must survive

Preserve command-table selection, driver/device ownership, yield behavior, callback/cancel ordering, buffer lifetime, and exact unavailable results. A tick or loaded driver is not proof a command family is supported.

## Modern-host discipline

Keep family-specific conversion and completion in a named adapter. Reuse shared callback lifetime rules rather than adding another timer thread or scheduler.

## Handoff boundary

Initialization is 5.1; audio/MIDI 5.2; MCI/OLE 5.4; generic timer semantics 3.4.

## Review questions

1. Which original device, table, provider, or task owner decides this result?
2. Which data, callback, or handle crosses the seam and who releases it?
3. What happens on cancellation, device loss, task exit, or a late callback?
4. Is an unavailable service reported explicitly rather than simulated as success?

## Evidence and current limit

Relevant audit material: MCI command-table, close/yield, multimedia timer, and validation records.

This page is source-contract guidance; it does not certify a product image or runtime implementation.

## Evidence scope and canonical families

The selected source baseline is OpenNT commit `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`.
This chapter's relevant identities are the D-class Guest-private
`timer_message`, `mci_message`, `joystick_message`, and AUX family, together
with the B-class USER timer record in [4.2](../part-4/4-2.md). Each is a finite source
contract; the source tree does not supply selected private WinMM provider
bodies for the multimedia endpoints. A public modern API can be a possible
carrier, but its existence does not prove original parameter, cancellation,
or callback equivalence.

## 1. Timer setup, kill, and task identity

The Guest `timeSetEvent` path forms a local timer record and passes the Guest
task identity with the selector through `timeMessage`; `timeGetDevCaps`,
`timeBeginPeriod`, `timeEndPeriod`, `timeKillEvent`, and `timeGetTime` use
their own selectors (`time.c:145-382`). `stack.asm:1051-1097` first tests the
loaded module cache and then passes the cached `tid32Message` slot to the
fixed bridge. It does not locally test that individual slot for nonzero. This
requires two separate modern states—module loaded and endpoint resolved—yet it
does not prove a null call is reachable or an original fault exists.

Timer cancellation must be modelled as a lifecycle transition, not a boolean
toggle. Closing admission to future completions, cancelling the native carrier,
handling an already queued completion, retiring the callback identity, and
releasing Guest state have different evidence obligations. The generic NTVDM
`SuspendTimerThread`/`ResumeTimerThread` counter/event mechanism and task
activation gate are not multimedia timer cancellation acknowledgements; their
selected source explicitly lacks a quiescence guarantee. Do not substitute a
new scheduler or claim that a pause drains callbacks.

## 2. MCI has routing and result-combination rules

MCI is not an ordinary device-message pass-through. The selected Guest route
tries a private 32-bit endpoint for `MCI_OPEN`, with a 16-bit driver fallback
on nonzero result. Other commands may choose the 16-bit side first, then the
private endpoint. For `MCI_ALL_DEVICE_ID`, success from either side can make
the overall operation succeed. Send-string and get-error-string use their own
result/buffer rules. A modern adapter must retain these branches and result
combination semantics rather than replace them with one contemporary MCI call.

`THUNK_APP_EXIT` carries Guest task identity into the MCI route. That is proof
of notification, not proof that all private devices close, queued callbacks
drain, or failure cleanup succeeds. Command frames and output strings need
bounded Guest views, explicit write-back sizes, and retirement tied to the
logical Guest task—not merely the native thread that executes the request.

## 3. Joystick capture is a small state machine

The selected joystick source limits capture state to two devices, clamps the
poll interval, creates the timer before publishing the target window, and
releases in the order: kill timer, clear timer ID, clear target window
(`joy.c:401-509`). Polling finds state by timer ID, queries position, and
posts `MM_JOY*` messages. On an invalid target window it calls release first
and then continues its selected position-query sequence (`joy.c:657-720`).
This is an exact source order, not evidence of a confirmed race.

The carrier should therefore keep a session-owned capture record keyed by
device and timer generation, with a Guest window alias/generation and poll
configuration. It must prevent a late native tick from delivering to a
retired or reused Guest window. Killing the native timer is not enough without
an admission/rundown rule for work that was already queued.

## 4. AUX is small but typed

The AUX family covers count, capabilities, and volume selectors. Capability
and volume outputs use validated Guest pointers; the volume DWORD has left and
right channels in its low and high 16-bit halves. Zero-length capability query
is a distinct success case in the selected Guest source. These details rule
out blindly reinterpreting a native pointer-sized volume/capability object as
a Guest DWORD. They still do not demonstrate an available host device or a
private provider ABI.

## Required validation and handoff

Evidence for an implementation must cover unresolved timer endpoint, setup
failure, kill while a completion is pending, callback after logical task exit,
MCI private failure plus 16-bit fallback, MCI all-device result combination,
joystick release while a poll is admitted, invalid-window ordering, and AUX
null/zero-length/buffer failure cases. Record request, admission, cancellation,
delivery, and retirement separately.

Static closure here records only selected Guest selectors, local state order,
and exclusions. It does not close provider ABI, device behavior, image build,
late callbacks, or runtime drain. Fixed bridge and callback publication are
