# 2.3 — Callbacks, reentry, task context, and shared lifetime

## Boundary

This section owns the temporal contract of a native-to-Guest callback: task
identity, frame creation, nested return order, parameter/view lifetime,
admission, retirement, and the distinction between request and completion. It
does not own the business payload semantics of a USER, timer, multimedia, DDE,
or device callback; those remain with their service sections.

| Canonical seam | Unit / class | Static conclusion | Handoff |
| --- | --- | --- | --- |
| `CALLBACK_FRAME::VDMFRAME` | shared structure / C | The API frame is a fixed Guest wire with source-defined AX/DX adjacency. | Dispatch field semantics: 2.2. |
| `CALLBACK_FRAME::CBVDMFRAME` | shared structure / C | Callback frames carry full `PARM16`, descend with word alignment, and restore saved stack state LIFO on normal return. | Per-service parameter member: owner section. |
| `WOW_CALLBACK_LOGICAL_FRAME_CHAIN` | protocol / C | Ordinary and fast transport share one normal logical frame/return protocol. | Abnormal unwind/admission: this section. |
| `WOW32_PARAMETER_MAP_TASK_LIFETIME` | mechanism / D | Parameter aliases are task-owned refcounted map entries, not arbitrary persistent pointers. | Service payload ownership: 4.x/5.x. |
| `USER_REGISTER_TABLE_PUBLICATION_AND_SHARED_RETURN` | protocol / D | Table registration publishes typed callback slots but has no matching selected-source unregister operation. | Slot behavior: 4.1/4.2; retirement gate: this section. |

The closed status is a bounded static source conclusion. It does not prove
thread-safety, all callback producers, a universal drain, or runtime behavior.

## Callback frames are serialized Guest wires

`base/mvdm/inc/wow.h:364-406` defines selected `VDMFRAME` and `CBVDMFRAME`
layouts; the Guest construction/return route is in
`wow16/kernel31/wow16cal.asm:243-295`. The callback frame carries a full packed
`PARM16`, not a native universal argument vector. Individual union members such
as `PARMWP`, `PARMWBP`, and `PARMHKP` have distinct width, signedness, and
pointer/token rules.

The minimum-diff requirements are:

- encode and decode fixed Guest offsets, never host `sizeof`, packing, or
  pointer layout;
- copy the declared parameter member and flush it before Guest execution where
  the source route does so;
- maintain nested frames as distinct, aligned objects and restore saved
  `vpStack` state in LIFO order on normal callback return;
- read the specified AX/DX return channel only through the declared frame; and
- end a parameter/frame lease at normal return, or transfer it to a named
  abnormal-rundown protocol.

The source distinction matters: `tasking.asm:410-445` distinguishes callback
return from ordinary API return, including which saved segment registers are
repaired. A modern carrier must not simplify both into an undifferentiated OS
thread context switch.

## Admission is a separate state from publication

USER registration (`wow32.c:521-547`; `client.c:2256-2315`) copies native
function/resource tables and publishes shared information. The selected source
search found no matching unregister entry. Publication therefore cannot be
treated as a lifetime proof.

For each modern callback-capable adapter, make these states explicit:

```text
unpublished -> published -> admitted/in-flight -> admission closed -> drained -> retired
```

The source establishes the typed publication boundary. The modern carrier must
add an explicit admission/reference or epoch rule before replacing or releasing
provider code, aliases, views, and task state. That addition does not create a
second dispatcher: it is a guard around the original callback/return protocol.
No native64 pointer, table address, `FARPROC`, or `gSharedInfo` address may be
serialized to Guest storage or a broker.

## Parameter mapping is an owned lease map

`wparam.h:12-54` and `wparam.c:75-405` show the selected parameter-map,
refcount, alias, deletion, and task-sweep mechanism. Its purpose is to give
specific WOW thunk/message paths a session/task-owned representation; it is not
permission for any component to retain a raw Guest or native pointer.

A compatible modern implementation needs a typed map with the source-visible
normal refcount and task-sweep behavior, plus explicit synchronization,
revocation, alias-overflow policy, and late-callback handling. A moved Guest
mapping may refresh a bounded alias during a valid lease; task retirement must
revoke outstanding entries before backing views are released. The selected
source does not prove a complete concurrency or abnormal-cleanup policy, so the
book does not claim one on its behalf.

## Reentry and retirement rules

Callback work can reenter message dispatch, cleanup, or a second callback. The
implementation must bind admission to the original logical task/context—not
merely an arbitrary host OS thread—and refuse new work after retirement begins.
Existing work then either completes under a retained lease or follows the
documented cancellation/abnormal exit policy. A Guest pre-release notification
only establishes its ordering; it is not evidence that a native producer has
drained.

This section deliberately does **not** declare an original use-after-free bug.
It states the required modern safety property: no late callback may access a
retired Guest view, task identity, parameter map, or provider code. Individual
source families provide the cancellation and completion evidence needed to
realize that property.

## Validation receipts

Part 6.3 must retain tests for normal and nested callbacks, ordinary/fast
transport equivalence, return AX/DX values, each selected packed argument shape,
missing/invalid/retired Guest token, reentry during callback, publication
replacement, task retirement while a callback is in flight, late producer
arrival after admission closes, and provider unload after drain. Tests of a
single successful callback or a single normal task exit are insufficient.
