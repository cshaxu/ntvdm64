# 2.1 — Guest addresses, selectors, mapping, and fixed-width identity

## Boundary

This section owns the representation and bounded use of Guest addresses,
selectors, virtual pointers, fixed-width tokens, and shared-layout fields when
they cross a WOW boundary. A mapped view is a temporary capability, not an
unlimited native-pointer lifetime. Call-frame construction is 2.2; callback
admission/rundown is 2.3; individual USER/GDI/device semantic owners stay in
their later sections.

| Canonical seam | Unit / class | Static conclusion | Handoff |
| --- | --- | --- | --- |
| `GUEST_VIEW_DATA_VS_FLUSH_NOTIFICATION` | mechanism / D | View acquisition, data mutation, and dirty/code notification are distinct transitions. | Mapping provider/image validation: 6.2/6.3. |
| `GUEST_LOCALHANDLEENTRY` | shared structure / D | The selected movable local-handle entry is four serialized Guest bytes. | Heap allocation/compaction: 3.1. |
| `WOW_SHARED_HEADER::SHAREDTASKMEM` | shared structure / D | Shared layout has fixed-width header, capacity, and relative-offset rules. | Session retirement: 1.3; mapping lease: this section. |
| `WOW_SHARED_TASK_LAYOUT::SHAREDTASK` | shared structure / D | A task slot preserves fixed fields and 16-bit identity distinct from native IDs. | Task semantics: 3.1. |
| `WOW_SHARED_SLOT::SHAREDMEMOBJECT` | shared structure / D | A discriminated shared slot is serialized state, not an object pointer. | Consumer-specific policies. |

These are bounded static closures. They do not establish all Guest heap
semantics, an emitted layout, every selector fault outcome, or a runtime mapping
implementation.

## Four address domains must not be collapsed

The source distinguishes at least four kinds of value which a modern
implementation must keep typed:

1. **Guest virtual pointers** and selector:offset values: identities inside the
   Guest address model, not host addresses.
2. **Temporary native views**: leased mappings created for one checked use.
3. **Guest handles/tokens**: fixed-width identities with their own table or
   serialized layout semantics.
4. **Host-native pointers, handles, and function pointers**: never valid simply
   because their low 16 or 32 bits fit a Guest field.

A modern 64-bit carrier may introduce a named, bounded token/lease mechanism
where the source requires a value that cannot safely be represented directly.
It may not answer this problem by building a global pointer truncation map or
by serializing raw native addresses into Guest DWORDs. The token must preserve
the original owner, width, validation condition, failure result, release point,
and retirement rule.

## Mapping and flush are not the same operation

The selected macros in `base/mvdm/wow32/wow32.h:562-576` distinguish
`GetPModeVDMPointer`-style view acquisition from `Sim32FlushVDMPointer` dirty or
code notification. The selected software provider in
`base/mvdm/softpc.new/host/src/sim32.c:148-193` converts an address, handles the
video case, and may call `SetVideoMemory` or return failure. The source does
not say that a flush count proves the complete view was validated, nor that a
successful view makes code/data notification unnecessary.

Preserve the following state transitions independently:

```text
Guest token -> checked view lease -> data read/write -> optional dirty/code notice -> lease release
```

The code/data distinction, partial range, non-MONITOR video branch, nested
view use, memory movement, and late notification all need explicit behavior in
the modern carrier. No lease may survive into an asynchronous callback, another
thread, or task retirement without a separately defined ownership protocol.

## Fixed layouts are wire data, not host-language structures

The selected `LOCALHANDLEENTRY` evidence is unusually precise:
`wcall16.c:22-34,127-205`, `kernel.h:427-461`, and `kernel.api:35-41` define a
word address, byte flags, and byte lock count. The static contract is a
four-byte Guest layout used by selected fast-edit consumers. It does **not**
state that all Guest handles share it or that the entire local heap was audited.

Implementations must use byte/offset-aware serialization or a checked view,
preserve the field order and byte arithmetic, validate movable/fixed/discarded
and lock-count cases, flush mutations as required, and release the lease before
reentry. A native compiler's packing, alignment, object lifetime, or pointer
width is not evidence that it matches the Guest wire.

Likewise, `base/mvdm/inc/sharewow.h:14-46,84-101` declares a fixed shared header,
`MAX_SHARED_OBJECTS = 200`, task layout, and discriminated slots. Selected
consumers are in `wkman.c:3942-4040,3952-4039,4104-4249`. The layout must be
treated as a local compatibility-service codec: explicit fixed widths,
discriminants, checked relative offsets, mapping-lease admission, and mutex
discipline. It may not contain native64 pointers or handles and must not become
Guest program memory.

## Selector/string edge case: source behavior can be profile-specific

The `USER16_ANSINEXT` record demonstrates why familiar API names are not enough.
`WU32AnsiNext` maps a Guest string, calls a native `AnsiNext`, computes a delta,
and reconstructs the Guest offset while retaining the selector
(`wulang.c:108-145`). The selected DBCS Guest route and the selected native
`CharNextA` source differ for a lead byte followed by NUL under specific
build/profile conditions. The audit therefore does not claim that a modern
`CharNextA` is universally equivalent.

For any selected string/selector route, record the actual code page/profile,
DBCS and feature gates, NUL and malformed cases, offset wrap, selector-fault
behavior, and DEBUG/free-build distinction. If a modern safety check rejects an
old undefined or unchecked case, document the compatibility difference instead
of silently calling it source-equivalent.

## Validation receipts

Before Part 6.3 promotion, retain tests for: zero/invalid/not-present selectors;
16-bit offset wrap without assumed selector increment; software RAM and video
view/flush success and failure; nested mapping plus reentry; movable/fixed/
discarded local handles and boundary lock counts; every shared-slot
discriminant, capacity exhaustion, and out-of-range relative offset; and source
profile-specific DBCS/SBCS string cases. These are separate from successful API
calls or basic process startup.
