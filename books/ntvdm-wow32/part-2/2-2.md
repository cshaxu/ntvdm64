# 2.2 — Thunks, dispatch, call frames, and return ABI

## Boundary

This section owns the ABI-shaped transition from a selected Guest thunk/frame to
a WOW32 handler and its result path. It includes dispatcher selection, field
order, stack and calling-convention rules, normal return publication, and the
bounded exception/fallback split. It does not own address-view lifetime (2.1),
callback admission/rundown (2.3), or the business semantics of the selected
USER/KERNEL/multimedia service.

| Canonical seam | Unit / class | Static conclusion | Handoff |
| --- | --- | --- | --- |
| `NTVDM_DYNAMIC_WOW32::W32Dispatch` | entry / D | Frame, handler, image metadata, result, and fallback are one typed dispatch boundary. | Carrier/image validation: 6.2/6.3. |
| `WOW_ORDINARY_DISPATCH_FRAME_REMAP_AND_RESULT` | mechanism / D | The ordinary route maps the current stack frame, invokes selected handler, and publishes the source result. | Exception/terminal route: 1.3; callback chain: 2.3. |
| `WOW32_NATIVE_THUNK_INVOKE::trycall_pointer_invoke` | callsite / D | One selected indirect handler invocation is distinct from registration and resolution. | Target/service semantics stay with owner. |
| `WOW_CALLBACK_LOGICAL_FRAME_CHAIN` | protocol / C | Normal callback frame/save/return behavior is shared by ordinary and fast transport variants. | Reentry, admission, and abnormal exit: 2.3. |
| `WMM32CallProc32` fixed multimedia bridge | protocol / D | Its fixed message ABI is not the generic variable-argument CallProc32 ABI. | Multimedia endpoint/callback semantics: 5.1–5.3. |

Static closure here establishes selected source contracts, not an effective
compiler ABI, assembled object, original image, or runtime equivalence.

## Dispatch must carry typed metadata, not raw pointers

`W32Dispatch` is declared as a named WOW32 export in `wow32.def:8`, resolved and
invoked from the selected NTVDM route in `nt_bop.c:169-278`, and has the selected
local body at `wow32.c:953-1074`. The record separates module loading,
export-resolution, and the actual invocation; a lookup is not an invocation,
and an invocation is not proof that every table member is valid.

The modern carrier must retain the source roles as typed carrier-owned values:

- the Guest frame/view and its lease;
- the selected handler identity and declared ABI;
- current execution/image context;
- return values and failure/exception disposition; and
- retirement state.

No raw 32-bit source function address, stack pointer, or native64 pointer may
cross a process or bitness boundary. A valid façade may use a typed operation
identifier and a private native32 adapter, but it cannot call through a
truncated pointer or hide exception/retirement behavior behind an untyped
“dispatch” callback.

The selected source has a `NO_W32TRYCALL` conditional split. The i386
`fastwow.asm:283-315` direct call and the `W32TryCall` alternative are source
alternatives; the final flag/object selection is not proven. Therefore the
book records their common observable obligations—frame order, handler result,
and distinct exceptional path—without declaring either an active-image fact.

## The two CallProc families must remain separate

This distinction is mandatory.

### Generic KERNEL bridge

`WK32ICallProc32` in `wow32/wkgthunk.c` is a variable-argument generic bridge.
The Guest `kernel31/kthunks.asm:405-435` generates a `CallProc32W` return table
with `REPT 020h`, which appears to provide the 0–31 return forms. The generic
bridge accepts up to 32 parameters and has address-conversion masks plus calling
convention handling. The selected static evidence does **not** prove a fault:
the address-mask loop, register saves in `i386/callpr32.asm`, macro expansion,
assembled object, and actual callers still need compatible ABI evidence. A
modern implementation must neither proclaim a bug nor rewrite original Guest
code from this static suspicion.

### Fixed multimedia message bridge

`WMM32CallProc32` in `WOW32/wmmedia.c:135-170` is different. The selected
multimedia wire declared in `inc/wowmmed.h:762-771` and
`inc/WOWMMED.INC:515-523` contains seven DWORDs:

```text
fSetCurrentDirectory, lpProcAddress, p1, p2, p3, p4, p5
```

The five payload parameters are fixed: `p1` corresponds to `dwParam2` and `p5`
to `uDevId`; the host invokes the provider in `p5, p4, p3, p2, p1` order.
`wmmtbl2.h:18` binds the handler, and Guest `wow16/mmsystem/thunks.asm` uses
`MMCALLPROC32`. This is a fixed multimedia message contract with directory and
procedure context, not a convenient spelling of `WK32ICallProc32`.

Consequently, an implementation must preserve the seven-field wire, the
payload association, reverse host-call order, selected directory behavior,
return channel, and failure branch. It must not merge these bridges, substitute
a generic vararg helper, reorder values for host-language convenience, or infer
that every private multimedia export is supported merely because the bridge
exists.

## Normal callback return is a protocol, not a direct C return

The selected normal `CallBack16` body in `wcall16.c:581-819` records a logical
frame chain: save the current Guest stack state, construct/invoke the callback
route, process the return, and restore the saved state LIFO. `fastwow.h:14-38`
shows the selected fast-transport alternative. The minimum-diff requirement is
one logical protocol across ordinary and fast carriers, with identical normal
frame/RET/AX:DX observables.

This does not authorize a mapped frame view to live across an asynchronous
boundary. Nested normal callbacks require LIFO restoration; abnormal callback
unwinding and late callback refusal belong to 2.3's explicit admission/rundown
protocol.

## Acceptance and non-inferences

6.3 validation needs cases for normal dispatch, handler failure, the selected
exception/fallback route, nested dispatch, in-flight retirement, normal and
fast callback transport, every relevant generic argument count, and the fixed
multimedia `p1..p5` reverse-order call. It also needs a build/image receipt for
the active `NO_W32TRYCALL`/assembler profile.

None of the following follows from source inspection alone: that the original
32-bit object is callable on a modern host, that a static mask-loop observation
is a defect, that every dynamic provider/export succeeds, or that a C ABI can
replace the observed Guest frame/return protocol.
