# 6.2 — Private provider, native32 island, facade, and broker

## Purpose

When [6.1](6-1.md) finds that a public API is only a B candidate, C non-equivalent, D directly absent, or U, this chapter selects the smallest explicit compatibility shape. It does not move functional ownership out of Parts 1–5 and it does not authorize a generic “compat layer.” The design objective is minimal image difference and maximal original observable semantics: keep original guest exports, ordinal routes, records, and state owners wherever possible; isolate only the missing representation or host operation in a named adapter.

## Four distinct shapes

| Shape | Use when | Boundary rule | Non-claim |
| --- | --- | --- | --- |
| Native32 island | reached original 32-bit provider logic and its ABI can be retained in a 32-bit process | preserve source-shaped pointers/records inside the island | does not make it loadable in a 64-bit process |
| Typed facade | a current public API covers a known, bounded contract | convert only declared records/identities and retain guest state outside | not a generic forwarding of arbitrary private calls |
| Broker | bitness or isolation requires another process | marshal copied, versioned, bounded data and explicit completion messages | cannot transfer process-local pointers, HWNDs, module handles, or function addresses |
| Explicit unavailable provider | no carrier has a defined contract | fail at the original load/resolution/capability boundary | not synthetic success or host-global emulation |

These alternatives must remain separate in planning. A native32 island can reuse a private ABI but creates deployment/lifetime obligations. A facade avoids that ABI but must supply every lost semantic deliberately. A broker changes the address/handle domain and needs a protocol, not merely IPC plumbing.

## Representation and identity rules

Guest far pointers, host32 pointers, and host64 pointers are different domains. A native64 pointer cannot round-trip through a guest DWORD; a 32-bit and 64-bit DLL cannot be loaded together in-process. Thus a typed facade may pass only values whose width, encoding, alignment, and lifetime are specified. It must represent an opaque remote object by a guest-visible identity only when the original contract did not require direct pointer dereference.

The same rule applies to handles. Guest HDC/HWND/task/selector/DOS handles, provider handles, and native host handles require family-specific mapping with owner and release rules. A universal mapping table would hide semantic distinctions and expand the diff. For example, a multimedia callback needs its declared queue/task/window projection, whereas a file operation needs DOS-handle resolution plus buffer mapping; neither can consume the other’s identity simply because both are integers.

Every broker message therefore needs a stable operation ID, record version/size, declared endian/packing and text encoding, bounded payload length, request owner, cancellation token, completion state, and explicit result/error projection. Do not serialize guest flat pointers, module references, live callback addresses, or thread contexts. For callbacks, broker back into a named guest-visible event/queue mechanism with a documented lifetime lease instead of calling arbitrary guest code from a host worker.

## Loader and provider boundaries

Source evidence distinguishes module load from named endpoint resolution. The multimedia and RAS paths demonstrate that a loaded module does not prove every requested procedure exists. A facade must retain this distinction: load/capability failure, resolver failure, and invocation failure may have different guest-visible results. Current `GetProcAddress` returns an address or null; it is not a typed protocol, lifetime lease, or proof an ordinal/name has the original ABI.

For private providers, choose one of three honest placements: retain the original source-matched logic in a native32 island; define a facade only for known endpoint contracts; or broker a copied protocol. Do not offer a raw `GetVDMPointer`-like pointer merely because an opaque identifier can cross bitness. If an original client dereferences the returned address, a broker ID is not equivalent without a separately proved shared-memory/address contract.

## Lifecycle and concurrency

No mechanism may use module unload, `FreeLibrary`, cancellation request return, or process detach as proof that outstanding work is drained. The adapter owns an admission gate and a completion/reader lease for every request that can retain mapped memory, callback code, provider data, or a session namespace. Normal session retirement stops new work, allows already-admitted nested continuation under explicit rules, cancels or completes remaining work, retires callbacks and mappings, then releases the provider. A terminal VDM failure path is distinct and must not become an ordinary return that tears down unrelated sessions.

Avoid a global queue or global registry merely for convenience. Queue order, dispatch thread, task affinity, reentry, cancellation, and late-event behavior belong to each original family. [2.3](../part-2/2-3.md) owns generic callback/reentry constraints; [5.1](../part-5/5-1.md) and [5.5](../part-5/5-5.md) retain their multimedia and Winsock-specific delivery rules.

## Named-adapter checklist

For each material addition, create one named owner with: original seam IDs and build predicates; carrier class; input/output record definition; identity map; allocation and release rule; thread/callback context; cancellation/late-event policy; error mapping; unavailable behavior; image delta; and acceptance tests. A named adapter may call a public API, a retained native32 island, or a broker, but cannot silently become a new USER server, universal mapper, or task terminator.

The audit’s current carrier evidence supports this discipline, not an implemented choice. `ReadFile` needs a file-specific adapter; LOCAL* requires preservation of guest heap algorithms rather than a same-name forwarder; timer, driver, device-I/O, and private loader cases each retain their own state/termination questions. A valid proposal must cite those family chapters rather than flattening them into a shared abstraction.

## Closure

6.2 is statically closed as the architecture and admission rule for adapters. It is not a product design acceptance: no native32 island, facade, or broker is presumed built or runtime-verified. [6.3](6-3.md) records the required mirror/image/runtime receipts, while Parts 1–5 retain authority for whether a selected operation is semantically complete.
