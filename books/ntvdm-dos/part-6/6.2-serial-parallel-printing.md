# 6.2 Serial, Parallel, and Printing

## Boundary

This module owns DOS-visible COMM/LPT host handles, asynchronous notification,
timeouts, printer/port close behavior, and their finite host-service seams. It
does not audit physical device emulation, a spooler implementation, or a new
communications stack. Its ledger-based static closure is bounded to the fixed
module contracts; runtime/provider validation remains separate.

## Connection constraints

Port names and native handles are not sufficient semantics. Read/write mode,
timeout, partial transfer, asynchronous completion, error reporting, exclusive
or shared ownership, and close-versus-late-notification ordering are observable.
A modern serial or printing API must be selected per route, not treated as a
drop-in because it exposes similar calls. A close request does not by itself
prove a pending completion has been suppressed or drained.

## Minimum-diff direction and handoff

Keep original DEM/device ownership, request/response layout and DOS error
behavior; bridge only the concrete unavailable leaf. Do not create a generic
device queue or use a global token scheme to mask native identity. Timing/EOI
and cancellation are 6.1/2.3; files/paths and spool destinations follow Part
3; error/NLS is 7.3; provider, ABI, late completion and runtime evidence are
Part 8.
