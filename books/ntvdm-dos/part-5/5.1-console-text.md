# 5.1 Text, Screen, and Console State

## Boundary and result

This module owns text-mode character/attribute output, cursor and screen-buffer
state, and the host console-output boundary. Its frozen local denominator is
15 identities: 12 protocols, two shared structures and one mechanism. All are
statically closed; glyph mapping, chosen provider, ABI and runtime behavior are
not thereby proven.

## Semantics that a modern console must not erase

The DOS-visible contract includes more than rendered characters: attributes,
cursor position/shape/visibility, buffer dimensions, dirty/update sequencing,
code-page/glyph conversion, output failure, and text/graphics transition
ownership. A modern terminal stream can display similar text while breaking a
program that observes cursor or buffer state. Conversely, a source call to a
console API does not authorize wholesale reliance on historical console internals
or imply that all modern terminal hosts have the same behavior.

The audit separates source-owned text/attribute state from renderer/provider
work. Timer and idle delivery influence when output becomes visible, but do not
prove rendering completion or drain. A static declaration, display-related
field, or literal glyph is not an implementation-validation receipt.

## Minimum-diff direction and handoff

Keep original text-mode owners, data widths, update order, error policy and
mode-transition boundary. Use a finite rendering/console facade only where a
public modern leaf cannot preserve the named observation; do not introduce a
new terminal model or modify guest video code. Input remains 5.2, graphics
presentation 5.3, timing/idle 6.1, encoding/NLS 7.3, and actual provider and
end-to-end validation Part 8.
