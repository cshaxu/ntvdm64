# 4.1 Conventional Memory, UMB, and A20

## Boundary

4.1 is the host seam for conventional memory, UMB, A20 and guest-address
mapping. It does not audit CPU instructions, V86 control, BIOS algorithms or
the full memory manager. Sixteen fixed source contracts are statically closed;
their evidence establishes a bounded interface, not a safe native pointer
model or a running memory subsystem.

## Preserved semantics

Guest addresses, linear values, guest allocations, mapping leases and native
pointers are different domains. The original profile can make an i386 mapping
macro a computed linear value and a flush/free operation a no-op, while another
profile uses a mapping provider and BOOL/USHORT operations. A modern build must
not choose one form by name alone. A 16:16 address, a guest DWORD and a native
pointer do not become interchangeable merely because their numeric values fit.

UMB/A20 behavior also carries allocation, enable/disable, range and failure
rules. Preserving the visible DOS state does not require reconstructing a CPU
or V86 monitor, but it does require an explicit mapping ownership and lifetime
boundary. No raw pointer may silently escape into guest state or asynchronous
work.

## Minimum-diff direction and handoff

Keep source addresses, widths, mapper call shape, flag/error rules and lease
boundaries. Use one session-owned bounded mapping facility where direct native
mapping is unavailable; do not create a universal pointer-token system.
Extended-memory allocation/mapping is 4.2, DPMI is 4.3, service ABI is 2.1,
and selected build/object/lifetime/runtime proof is Part 8.
