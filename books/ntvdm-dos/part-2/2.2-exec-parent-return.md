# 2.2 EXEC and Parent/Child Return

## Boundary

This module owns DOS EXEC, COMMAND external execution, nested native child
launches, pipe/file bridge behavior, and return to the saved parent context.
It has eight frozen local identities, all statically closed. It does not turn a
source trace into a guarantee that every child process, pipe, or termination
case is operational on modern Windows.

## Required semantics

EXEC is a lifecycle protocol, not merely a process-creation call. Parent state,
first command consumption, command-tail/environment material, saved context,
pipe endpoints, wait/result mapping, and return ordering have distinct owners.
An inherited handle or duplicated native handle must retain the source-observed
object/position semantics; it cannot be replaced with a private queued command
framework. Pipe completion, EOF and error observations also have explicit DOS
flag/register effects, and an absent child context is not equivalent to a
generic launch failure.

The source boundary is deliberately narrower than guest program loading or all
shell behavior. It neither imports a modern command processor nor claims that
a native process can freely substitute for a DOS child.

## Minimum-diff direction and handoff

Retain original COMMAND/DEM continuation bodies and their state transition.
Adapt only the finite unavailable launch/wait/resource operation, preserving
which context owns cleanup and which error/partial side effect is visible.
File/pipe object policy goes to 3.2 and 7.1; initial loading to 1.3; process
exit/cancellation to 2.3; provider, cross-process identity, and execution
validation to Part 8.
