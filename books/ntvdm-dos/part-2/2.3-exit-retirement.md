# 2.3 Exit, Cancellation, and Session Retirement

## Boundary

The exit module covers normal DOS exit, Ctrl+C/Break, host-close paths, and
the ordering by which a session's host resources are retired. Eight fixed local
identities are statically closed. This is not proof that all workers have joined
or that late callbacks cannot arrive.

## Semantics to preserve

Retirement is ordered and owner-specific. A normal return, explicit abort,
host-close request, guest handle release, pipe worker, redirector context,
timer/EOI provider, and VDD callback may each have different cancellation and
cleanup responsibility. Closing a DOS slot is not automatically closing a
native object; signalling a worker is not automatically a drain; an unregister
operation is not automatically a no-in-flight guarantee.

The original error and partial-cleanup branches therefore matter. Modern code
must not convert every failure into immediate close-all cleanup, a synchronous
join, or a transaction rollback. Conversely, source evidence alone cannot
justify preserving an unsafe native use-after-free; concrete lifecycle evidence
is a Part 8 requirement.

## Minimum-diff direction and handoff

Preserve original ownership boundaries and observable ordering, then make any
modern cancellation, handle close, worker quiescence, and late-delivery policy
an explicit bounded provider contract. Timer/IRQ shutdown goes to 6.1;
console/input cancellation to Part 5; device/VDD callback retirement to 6.3;
network and diagnostics teardown to Part 7. Buildable lifetime, concurrency,
fault and runtime receipts belong to [8.2](../part-8/8.2-minimum-diff-validation.md).
