# 3.1 Drives, Directories, and Paths

## Boundary

This module owns the logical DOS drive/directory namespace, OEM naming and
normalization, current-directory behavior, and the finite path-to-host route.
It has 21 frozen local contracts, all statically closed. It does not equate the
historical namespace with the host filesystem or validate a chosen modern file
provider at runtime.

## Observed contract

The DOS logical system root, current drive, current directory, short-name and
OEM conversion paths are separate concepts. Original wrappers may report a
wide-character count while copying OEM bytes, use a TEB scratch conversion,
or have a PEB/current-directory fast path. `GetFullPathName`, `SearchPath`, and
short-name leaf names are therefore not proof of one common unit convention.
One wrapper's capacity adjustment cannot be mechanically copied to another.

The historical path policy has ordering, fallback, error, and partial-state
rules. A directory change before later failure is not necessarily rolled back.
Host `System32`, basename/prefix rewriting, a generic environment expansion,
or automatic Unicode normalization would change the observable DOS object
domain. A path API's success does not prove a DOS drive mapping or a Guest OEM
buffer is correct.

## Minimum-diff direction

Use one explicit DOS logical-root/object-domain mapping and keep original path
wrappers, conversion, search order, return counts and failure labels. Adapt
only the edge that cannot use a public API directly. Do not create another
drive manager or silently turn OEM data into a UTF-16-only protocol.

metadata is 3.3; volume behavior is 3.4; guest mapping is 4.1; codepage/NLS
and error policy is 7.3; selected public APIs and validation are Part 8.
