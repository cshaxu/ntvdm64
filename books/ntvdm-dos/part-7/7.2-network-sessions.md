# 7.2 Network Sessions and Identity

## Boundary

7.2 covers the finite DOS-host boundary for network session/name/identity
translation, including NetAPI/RAP-style roles where reached. It does not recreate
historical network services, authentication infrastructure, or a global account
manager. The static ledger identifies the source-facing contract; implementation
validation is a distinct future phase.

## Connection constraints

Names, OEM conversion, credential/session state, privilege failures, absence of
a service and teardown can all be observable to DOS callers. Native account or
token values must not be placed in guest fields or treated as transferable
numeric identity. An unavailable public interface is not a licence to invent a
different authentication policy; it is a D-class provider/compatibility question
with a finite owner.

## Minimum-diff direction and handoff

Preserve original API shape, buffers, byte encoding, status mapping and session
lifetime at the boundary. Provide the smallest supported service facade only if
the original contract requires it; otherwise retain an explicit unsupported or
failure disposition that matches source-observed behavior. Files/redirector
operation is 7.1, codepages/errors are 7.3, and provider/identity/lifetime/
runtime proof belongs to Part 8.
