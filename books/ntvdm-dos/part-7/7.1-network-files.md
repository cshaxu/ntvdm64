# 7.1 Network Files and Redirector

## Boundary

This module owns redirector-facing file/device/named-pipe operations, sharing,
locking and disconnect behavior at the DOS-host seam. It is not an audit of a
network stack or an authorization system. Static module conclusions remain
limited to the fixed ledger identities; they do not prove that a redirector DLL
loads, that a network is reachable, or that asynchronous traffic is safe.

## Contract constraints

Redirected file paths can have a different provider, error taxonomy, partial
read/write result, pipe framing, lock behavior and disconnect lifetime from a
local file. A source branch that calls a VR function pointer does not prove the
pointer was initialized, use the same ABI, or has drained at close. A modern
network API's availability similarly does not show that DOS sharing/locking or
pipe errors are equivalent.

The original route must preserve DOS-visible flags/errors and source-owned
buffer/handle responsibility. It cannot be folded into local CreateFile logic,
and it cannot be made reliable by silently retrying, reading to completion,
or adding a background queue. Pending I/O and disconnect are lifecycle matters.

## Minimum-diff direction and handoff

Retain original redirector boundary and finite function-pointer/provider
protocol. Adapt only the unavailable edge after ABI, load, failure, cancellation
and ownership evidence exists. Local file representation stays in Part 3;
network session identity is 7.2; errors/encoding 7.3; lifecycle 2.3/6.1; and
provider/runtime proof Part 8.
