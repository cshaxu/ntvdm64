# 1.2 DOS Session Creation and Startup Configuration

## Fixed contract boundary

This chapter covers the finite host work performed before and at entry to a DOS
session: initialization order, local CPU configuration, system-root role,
first-VDM state, PIF and boot configuration, initial environment, and initial
launch acquisition. DOS loading is 1.3; BOP/register ABI is 2.1; later EXEC,
paths, shutdown, console, and timing have separate owners.

The frozen local denominator is 23 identities: seven entries, one call site,
seven protocols, and eight mechanisms. All 23 are statically closed with
A2/B7/D14 dispositions. This is not a function count or a runtime claim. The
selected modern routes still have 0/13 implementation receipts.

## Semantics that must survive

Initialization ordering is observable. `TimerInit` lies outside the historical
try domain, while CPU/environment/NLS setup and `host_main` are inside it; the
default result and normal `host_main` result differ. CPU configuration searches
its local data chain rather than falling back to the process environment. It
retains preceding values on individual enumeration/conversion/allocation failure;
replacement by a convenient modern configuration dictionary changes failure and
ordering semantics.

System-directory users are not interchangeable. The COMMAND-facing path updates
a home-drive character under one length/return rule; DEM has a distinct failure
gate and error-mode sequence. The directory is a DOS logical-root role, not a
licence to write host `System32`. First-VDM state is historically service-wide:
a false result can mean either "not first" or acquisition failure, depending on
the paired error contract. Do not casually reset it per worker.

PIF and boot preparation preserve one-shot input consumption, original default
selection, old extension precedence, OEM/Unicode conversion accounting, and
partial side effects. The script path has its own behavior: it filters/rebuilds
COUNTRY and SHELL, distinguishes `/c` and `/e`, extracts selected AUTOEXEC
environment pairs while retaining the original lines, and uses original text
expansion rather than a generic modern environment expander. Short reads/writes,
temporary-file ownership, and capacity gates need explicit later validation;
they must not become silent truncation or an invented transaction.

## Minimum-diff direction and handoff

Retain the original parser, buffers, field layout, ordering, error labels, and
partially completed state. A bounded facade may map logical DOS roots and native
resources, but it may not become a second environment, drive, task, or CSR
manager. The closest modern APIs establish only leaf possibilities; they do not
prove equivalent PIF, path-search, OEM, exception, or first-session behavior.

Image loading transfers to [1.3](1.3-image-handoff.md), command continuation to
[2.2](../part-2/2.2-exec-parent-return.md), paths to 3.1, memory consumers to
Part 4, input/text consumers to Part 5, timing to 6.1, diagnostics to 7.3, and
provider plus concrete validation work to Part 8.
