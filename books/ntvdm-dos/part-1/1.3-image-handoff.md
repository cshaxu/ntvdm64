# 1.3 DOS Image Load and Initial Handoff

## Boundary

This module follows original host control only from `host_main` into the DOS
image service and the first command execution frame. COM/MZ/PSP/environment
details are used solely to explain that boundary; the audit does not recreate
or re-audit a guest loader. The fixed local denominator is three identities,
all statically closed; image and runtime proof remain separate.

## Preserved observations

The original startup has more than a generic "load DOS" call. `NTIO.SYS` and
`NTDOS.SYS` have distinct read behavior, ownership and error paths; a modern
adapter must not replace them with a universal read-full policy. First-command
construction carries the host/guest transition, registration and first-frame
ordering. OEM file naming, immutable media identity, and the error/termination
branch remain part of the contract even when the ultimate file provider is
modern.

The module confirms a bounded load handoff, not a universal executable-format
claim. It does not prove all images load, that a selected native handle is ABI
compatible, or that the guest will execute after handoff. Those are precisely
the mistakes avoided by separating 1.3 from Part 2, Part 3, and Part 8.

## Minimum-diff direction

Keep the original load wrappers, file-object separation, initial-frame shape,
and failure policy. Reconnect only the unavailable host operations through the
same path/object owner defined by file services. Do not change guest code or
use a new DOS loader to conceal a host seam.

Handoffs are explicit: call ABI and register/segment representation go to
[2.1](../part-2/2.1-dos-host-abi.md); subsequent command execution and parent
context to [2.2](../part-2/2.2-exec-parent-return.md); file semantics to Part
3; address translation to 4.1; and concrete provider/object/ABI/runtime proof
to Part 8.
