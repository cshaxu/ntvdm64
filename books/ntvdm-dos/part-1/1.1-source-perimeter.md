# 1.1 Source Perimeter and Build Identity

## Boundary

This module establishes what the DOS-host audit is allowed to reason about.
It closes a limited static perimeter: OpenNT source identity, source/build
membership, conditional families, and the handoffs needed before any service
semantics are read. It does not close DOS runtime support.

The sole source baseline is OpenNT `5c5b979ec08c17d3ca2eb70e8aad62d26515d01c`.
The initial host/support/declaration candidate set was 488 paths and became
489 only when the exact `host_main` support file was added. That denominator
event is recorded; it is not a claim that 489 files were semantically audited.
The ledger reports all 489 candidate files routed and 64/64 selected build
recipes inspected, but zero whole-file service-contract reviews at this stage.

## Source facts that constrain implementation

`DOS/COMMAND` in this tree supplies host `command.lib` code; it is not the
immutable `COMMAND.COM` guest binary. DEM similarly has its own host library.
The object recipe has historical MONITOR/386 and non-386 software-CPU branches;
the latter has further CCPU choices. A modern x86 host does not by itself select
the original MONITOR path, nor does an NMAKE `386` setting prove a C preprocessor
`i386` profile. DPMI32 and XMS also have architecture-specific back ends.

Some apparent absences are routing traps: an empty `sim32/sources` does not
make address service absent when `host/src/sim32.c` is actually compiled; VDD
contains samples and non-default paths that are not core runtime. `obj.vdm`
links `base/support/MAIN.obj` and `ntvdm.c` calls its `host_main`, so that
precise file is in scope without admitting all support/CPU internals.

## Minimum-diff consequence

Modern x64 Windows does not supply the historical NTVDM execution environment.
That makes the three historical build variants a bounded D-class compatibility
need, not a verdict that DOS behavior cannot be preserved. Retain original
DEM/COMMAND/host service bodies and their exports, aliases, DATA-versus-code
distinction, macro conditions, and widths. Connect only the needed execution
and service boundary; do not use a missing build recipe to justify a new guest,
kernel VDM, CSR/CSRSS, or unrelated subsystem.

The original tree lacks the complete `makefile.def`/`makefile.plt` chain needed
to reproduce the NT4 build. Therefore an inferred PE/export table is not
evidence. Build identity must later be validated through selected sources, DEF
and import inputs, actual objects, and produced images.
